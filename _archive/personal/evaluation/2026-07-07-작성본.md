## 1. 업무 성과

### 주요 업무 성과 (고객사 전달 산출물 중심)

상반기 대부분을 **순천향대학교병원(SCHMC) CDW 구축 프로젝트에 현장 파견**되어 수행했습니다. 처음에는 **예정 작업자의 진행이 지연되던 EMR 뷰어 작업에 대체 투입**되었고, 이후 **담당 인력 2명의 공백이 겹치면서 해당 업무까지 함께 맡아**, EMR·연구검색·가명화·인증·레지스트리·헬프센터 등 **다수 솔루션을 단독으로 재정비·안정화하고 오픈까지 완수**했습니다. 3월 중순 순천향 상주에서 철수한 뒤에는 본사(혜화)로 복귀해 서울대병원 연구검색 업무 — 긴급대응, 스누허브 연동, 서식지 적재 오류 대응 및 재구축 — 를 진행했고, 순천향 유지보수와 오픈이 다가오면서 이 작업들이 서로 겹쳐 병행하게 되었습니다. 여기에 **서울대병원 K-ERAS 임상연구 데이터 시스템 개발(개발 담당)**을 상반기에 걸쳐 유지보수·개선했고, **대외 인프라·정부 사업 과제(SHINE·건강정보고속도로 등)**도 간헐적으로 병행했습니다.

**월별 진행 내역**
- **1월** — 순천향 투입·현황 파악, 신규 EMR 개발 착수, 초기 중간보고, 전임자 인수인계(1월 말~2월 초)
- **2월** — R-BAY IRB 연동 개발, EMR 링크 작업, K-ERAS·SHINE 이슈 대응
- **3월** — (순천향) RID/GID 연계·가명화 다기관 재정비, 방화벽·운영 테스트 — 중순 상주 철수(이후 폐쇄망 특성상 방문으로 대응) / (서울대) 철수 후 연구검색 서식지 적재(Logstash) 재작업 착수
- **4월** — (순천향) 하순 재투입·도메인 이관, EMR 오픈 준비(월·화 서울대 / 수·목·금 순천향 방문) / (서울대 연구검색) 스누허브 연동·서식지 적재(Elastic 증분)·가명 ID 누락 건 대응 / (대외) SHINE 공공기관 이관 및 기타 이슈 대응
- **5월** — (순천향) EMR 다기관·누락 의무기록 서식(입원·외래·응급 기록지) 작업, 2차 인증 외부 연동(동은정보시스템), 중간보고+오픈(5/29) / (서울대) K-ERAS 리뉴얼 건 마무리 전달
- **6월** — 순천향 오픈 대응, EMR 의무기록 서식 가명화 모듈 작업 및 연동, REX 비정형 데이터 조회 및 다운로드 이슈 대응

**① 순천향 CDW 현장 구축 — 단독 대응 (메인)**

서로 얽혀 있던 여러 시스템(의무기록 조회·데이터 추출·로그인/인증·헬프센터·가명화 등)을 처음부터 다시 점검·정비했습니다. 이 중 **신규 의무기록 뷰어 구축, 외부 연구윤리심의(IRB)·인증 시스템 연동, 가명화 다기관 지원**이 특히 공수가 큰 신규 개발이었습니다.

- **의무기록(EMR) 조회 화면 신규 구축** — 순천향에서 쓰던 **기존 구 EMR 시스템(.NET)을 분석**해, 연구자가 연구검색 안에서 환자 진료기록을 바로 열람할 수 있는 **웹 기반 조회 화면으로 새로 개발**하고 연구검색과 연동했습니다. 순천향 산하 **4개 병원** 진료기록을 연결하고, 개인정보는 **가명화·마스킹 처리**해 안전하게 표시. (상반기 개발 비중이 가장 큼)
- **외부 IRB·인증 시스템 신규 연동** — 순천향의 신규 IRB(연구윤리심의) 시스템 연동 요구에 따라, **외부 업체(R-BAY)와 협업하여** 연동을 **새로 구축**. 조회할 때마다 반복 로그인하던 불편을 **'병원별 한 번만 로그인'**으로 개선하고 공용 PC에서도 안전하게 처리. 병원 인증 체계와도 연동해 **4개 병원을 한 화면에서 조회·구분**할 수 있게 함. (연동 대상이 많고 병원별 예외가 많아 공수가 큰 작업이었음)
- **2차 인증(다중인증) 외부 연동** — 병원 보안 요건인 2차 인증을 **외부 업체(동은정보시스템)와 협업하여 연동 구축**함.
- **가명화 시스템 다기관 대응 전면 재작업** — 환자 식별정보를 연구용 가명 ID로 바꾸는 시스템의 **다기관(순천향 4개 병원) 지원 부분이 인계 시점 미완성·다수 오류 상태였던 것을 전면 재작업**함. 제대로 작동하지 않던 기능을 새로 개발해 4개 병원의 가명 ID 신규 생성·적재 연동까지 처리하고, 오류·속도 문제도 함께 해결.
- **헬프센터(공지·QnA) 화면 전면 개편** — 부사장(김영관)이 현장 방문 시 요청한 건으로, 공지·QnA 게시판, FAQ, 댓글, 게이트, 사이드바 등 헬프센터 UI를 전면 개편함.
- **중복 기능 공통화** — **프로젝트마다 중복 코드가 쌓여 유지보수를 어렵게 하던 회사의 고질적 문제**를, 이번 순천향 프로젝트를 진행하며 직접 손대 개선한 건. 여러 시스템에 흩어져 중복돼 있던 기능을 공통 부품으로 묶어, 앞으로의 유지보수·오류 대응 부담을 줄임.
- **서버·도메인·보안 인프라 단독 담당** — 개발뿐 아니라 순천향 운영 인프라 전반을 혼자 도맡음: 운영 서버 2대 구성, **5개 서비스 도메인 연결·프록시 설정**, 방화벽 등 병원 보안 요건 대응, 데이터 적재(ETL) 서버 운영.

**② 서울대 연구검색 긴급대응 (본사 혜화 근무) — 병행**

서울대병원 연구검색에도 이슈가 많아, **담당 인력 공백으로 남겨진 작업을 인계받아** (본사 혜화에서) 데이터 처리와 긴급 대응을 함께 수행했습니다.

- **외부 데이터허브(스누허브) 연동 — 담당 인력 공백분 인계받아 대응** — 스누허브와 연구검색이 서로 자료를 주고받는 연동을 협력사(애니모비)와 협업해 구축·안정화. 비정형(문서·이미지 등) 데이터 신청 시 저장 경로를 함께 전달하도록 처리하고, **파일 전송 인증 오류·전송 포맷(엑셀/CSV) 변환·대용량 다운로드 속도 저하** 등 여러 문제를 순차 해결. 테스트 환경까지 반영해 협력사 테스트를 지원함. (남겨진 작업이 많아 비중이 큰 과제였음)
- **서식지 적재 모듈 재구축** — 영상·병리·기능검사 등 **검사 기록의 긴 텍스트(판독문 등)를 검색 엔진(Elasticsearch)에 등록해 빠르게 검색되도록** 하는 서식지 적재 모듈. 기존 모듈의 버그를 수정하려다 구조적 한계가 드러나 **아예 새로 만듦**(Logstash 기반). 매번 전체를 다시 넣던 방식을 **'바뀐 부분만 넣는' 방식**으로 바꿔, **며칠씩 걸리던 적재를 30분 수준으로 단축**하고 서버 부하도 크게 낮춤.
- **가명 ID 누락 이슈 원인 규명·복구** — 가명화 ID가 누락됐다는 이슈가 제기되자 **직접 원인을 규명하고 복구 방안을 도출·주도**해, 누락돼 있던 **약 1.8만 건을 복구**함. 함께 제기된 조회 오류·타 병원 인증 이슈도 처리.
- **비정형 데이터 추출(REX) 모듈 문제 해결 — 담당자 출산휴가로 이어받음** — 담당자가 만들던 모듈에서 **비정형(문서·이미지 등) 데이터의 목록·정보(메타) 조회가 크게 느려지는 문제**가 있어 이를 넘겨받음. **조회 방식(쿼리)이 잘못 짜인 것이 원인**임을 찾아 바로잡아 해결하고, 처리 과정에서 **파일 다운로드 진행률이 중간에 멈추는 버그**까지 함께 수정. (데이터 신청 시 정형/비정형 구분·출력 항목·신청 라벨 처리 포함)

**③ 서울대병원 K-ERAS 임상연구 데이터 시스템 개발 — 개발 담당**

서울대병원의 **ERAS(수술 후 환자 조기회복 프로그램) 임상연구용 데이터 관리·분석 시스템(K-ERAS)** 을 **2023년부터 단독으로 개발·유지보수해 온 담당자**로서, 현재 **3년 유지보수 계약의 2년차를 맡아** 상반기 동안 대규모 기능 추가·개선을 수행했습니다. 개선 결과에 대해 담당 교수(이호진 교수)로부터 **"수정해주신 부분 모두 만족스러우며 훨씬 나은 프로그램이 될 것"**이라는 만족 회신을 받았습니다.

- **분석(Outcomes) 대시보드 신규 구축** — 연구 버전별 환자 수·수행률·합병증·재원기간·회복 마일스톤·재수술/재입원율 등을 비교하는 분석 화면을 처음부터 새로 구축.
- **데이터 입력 폼 강화** — 선택 항목 토글, 조건에 따른 자동 활성/비활성, 잠금 표시 등 연구간호사가 쓰기 쉬운 입력 방식으로 개선.
- **연구 진행 상태 관리** — 연구 완료·중도 종료(Drop-out) 처리 흐름 신설, 단계별 수동 완료·미검증 데이터 상태 관리.
- **계정 보안 강화** — 로그인 실패 횟수 추적·계정 잠금, 비밀번호 재설정 흐름 등.
- **화면 전면 개편** — 메인·사이드바·공지 UI 정비, 다크 테마 통일 등.

**④ 대외 인프라·자문 및 기타 병행**

- **SHINE(공공기관 시스템)** — 공공기관용 클라우드로 서버를 이전하고 도메인·보안 인증서까지 셋업, 보안성 검토 대응 및 계약(명의 변경) 조율.
- **건강정보고속도로(정부 사업)** — 보안 인증서 교체(현장 방문 포함), 접속자수 집계, 정부 사업 현장 의견청취 자문 답변 작성.
- **타 병원(계명대·강원대) 레거시 시스템 유지보수 긴급 대응** — 타 담당 인력의 지원 요청을 받아, 운영 중 발생한 긴급 이슈에 투입됨. 계명대 동산병원 태블로 포탈 이슈 대응 등 레거시 시스템 유지보수 성격의 작업을 긴급 대응함.
- **기타** — 충북대 보안인증(ISMS) 요청 대응, 건강관리협회 대응, 연구검색 권한 관리 기능 개선, 사업 제안서 정비, 운영위원회(Supreme) 참여, 인하대 CDW/EDW 사업 미팅 참여, 국립병원 문서 작성 지원.

### 업무성과에 대한 본인 평가

**우수한 점**
- **여러 곳에서 동시에 발생한 인력 공백을 연쇄적으로 맡아, 인계받은 미완성 작업까지 정상화함** — 지연되던 순천향 의무기록 화면에 투입된 뒤 담당 2명의 공백이 겹쳐 해당 업무까지 맡았고, 서울대 데이터허브(스누허브)·비정형 데이터(출산휴가) 담당 공백분도 인계받음. 인계받은 작업 상당수가 미완성·오류 상태(가명화 다기관 대응, 비정형 데이터 추출 등)였는데, **원인까지 규명해 재작업·정상화**하고 순천향은 **일정 내 오픈까지 완수**함.
- **난도 높은 신규 개발을 단독 완수** — 순천향 구 EMR(.NET)을 분석해 웹 기반으로 새로 개발·연구검색 연동했고, 서식지 적재를 재구축해 며칠 걸리던 적재를 30분대로 단축하는 등 핵심 신규 개발을 혼자 마무리함.
- **다중 과제 병행** — 순천향 현장 대응과 함께 서울대병원 연구검색 긴급대응·K-ERAS 개발, SHINE·건강정보고속도로 등 대외 과제까지 병행 소화함.
- 화면(프론트)·서버(백엔드)·데이터베이스·로그인/인증·서버/클라우드 인프라까지 **한 사람이 전 영역을 커버**함.
- 현장 철수 시 상세 **인수인계 문서**를 남겨 후임자가 무리 없이 이어받게 함.

**보완이 필요한 점**
- 순천향 전용으로 급히 손댄 부분이 회사 공통 버전과 많이 벌어져, 나중에 다시 합치려면 정리 작업이 필요함. 병원 전용 변경과 공통 변경을 처음부터 더 나눠 관리했다면 부담이 적었을 것.
- 촉박한 일정 탓에 여러 성격의 작업(기능 추가·오류 수정·구조 개선)을 한꺼번에 진행한 구간이 있어, 나중에 이력 추적이 다소 어려움. 작업 단위를 더 잘게 나눴다면 리뷰·인수인계가 쉬웠을 것.
- 여러 근무지·과제가 겹치며 일부 후속 추적 과제(가명화 지속 모니터링 등)가 남음. 우선순위 조율과 인력 배정은 제안했으며, 향후엔 부하가 누적되기 전 더 이른 분업·에스컬레이션으로 리스크를 줄이려 함.

### 협업 및 커뮤니케이션에 대한 본인 평가

**팀 내 협업 (일정/이슈 공유 포함)**
- 상사(박동현)께 **매일 업무 보고**하며 진행·이슈·리스크를 상시 공유 → **리스크를 조기에 가시화**하고 다중 근무지 일정 변동을 사전 협의함.
- 동료 요청 시 KCURE·연구검색 메타 동기화 확인·수정 등을 지원하며 **팀 내 상호 백업**에 기여함.
- 공통 부품을 팀이 함께 가져다 쓸 수 있는 구조로 배포하고, 사용 시 주의사항을 문서로 정리해 공유함.

**고객 커뮤니케이션**
- 순천향 현장에 상주·방문하며 병원 DW 담당(김관중 책임 등)과 직접 소통, **요구사항을 조율하고 중간보고로 진척을 투명하게 공유해 일정 내 오픈을 함께 달성**함.
- 애니모비(장희준 과장), R-BAY(외부 IRB 연동 업체), 동은정보시스템(2차 인증 연동), 메가존/네이버클라우드(SHINE), 담당 교수·선생님(최재림·백재은·김남규 책임 등) 등 **외부 협력사·이해관계자와 폭넓게 조율**.
- **보안성 검토·ISMS·2차 인증** 등 규제·보안 요건을 **병원이 이해할 수 있게 설명하고 증빙을 정리·전달**함.
- 서울대병원 K-ERAS는 요구사항을 먼저 제안·조율하며 개발했고, 담당 교수로부터 **개선 결과에 대한 긍정 피드백**을 받음.

## 2. AI 활용 설문

1. **업무 시간 중 평균 AI 사용 비율:** 약 **70%**
2. **월간(최근 30일) 클로드 맥스 토큰 사용량:** `(⚠️ 상사 요청 변경 — 클로드 앱에서 최근 30일 토큰량 확인 후 기입)`
3. **주로 사용하는 업무 영역:** 낯선/레거시 코드 파악(전임자 시스템·구 EMR(.NET) 분석), 코드 작성·리팩터링, 코드 리뷰·디버깅(오류 원인 규명), 개발 환경·설정 정리, 문서화(인수인계·자문 답변·보고서), 기술 리서치.
4. **AI 활용 생산성 향상 체감:** 약 **50%**
5. **(옵션) 가장 효과를 본 사례 1가지:**
   순천향에 긴급 투입됐을 때, 전임자들이 남긴 **낯선 여러 시스템(EMR·연구검색·가명화·인증)의 코드를 AI로 빠르게 파악**하고 문제 원인을 짚어 재작업 속도를 크게 높인 것. 특히 구 EMR(.NET) 분석·서식지 적재 재구축·가명 ID 누락 원인 규명처럼 낯선 코드를 짧은 기간에 파고들어야 하는 작업에서, 혼자 다수 시스템을 재정비해 일정 내 오픈까지 가는 데 결정적이었음.
6. **AI를 더 적극적으로 활용함에 있어서 어려운 점:**
   병원 폐쇄망/보안망 환경이라 현장에서는 외부 AI 도구 사용에 제약이 큼(반입·연결 통제). 의료 EMR·가명화 규정 등 도메인 특수성과 병원별 예외가 많아, 프롬프트만으로 맥락을 충분히 전달하기 어렵고 결과를 그대로 신뢰하기 어려움.
7. **AI 활용에서 스스로 개선이 필요한 부분:**
   AI가 만든 결과를 그대로 쓰기보다 **검증하는 습관을 더 체계화**할 필요가 있음. 또한 반복되는 맥락(도메인 규칙·프로젝트 구조·공통 부품)을 프롬프트·컨텍스트로 미리 정리해 두어 재사용성을 높이는 부분.
8. **회사/팀 차원에서 필요한 지원·개선:**
   폐쇄망 환경에서 쓸 수 있는 AI 활용 가이드·보안 정책 정립, 도구 라이선스 지원. 팀 내에서 프로젝트 컨텍스트·도메인 규칙을 공유·재사용할 수 있는 형태로 축적하는 체계.
