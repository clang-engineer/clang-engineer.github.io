## 1. 업무 성과

### 주요 업무 성과 (고객사 전달 산출물 중심)

상반기 대부분을 순천향대학교병원(SCHMC) CDW 구축 프로젝트에 현장 파견되어 수행했습니다. 처음에는 예정 작업자의 진행이 지연되던 EMR 뷰어 작업에 대체 투입되었고, 이후 담당 인력 2명의 연이은 퇴사로 공백이 겹치면서 연구검색·가명화·인증·레지스트리·헬프센터 등 그들이 맡던 솔루션까지 순차적으로 넘겨받아, 다수 솔루션을 대부분 홀로 재정비·안정화하고 오픈까지 완수했습니다.

3월 중순 순천향 상주에서 철수한 뒤에는 본사(혜화)로 복귀해 서울대병원 연구검색 업무(스누허브 연동, 서식지 적재 오류 대응·재구축 등)를 맡았고, 순천향 유지보수·오픈과 겹쳐 병행했습니다. 여기에 서울대병원 K-ERAS 임상연구 데이터 시스템 개발(개발 담당)과 대외 인프라·정부 사업 과제(SHINE·건강정보고속도로 등)도 상반기에 걸쳐 병행했습니다.

**월별 진행 내역**
- **1월** — 순천향 현장 투입, .NET 기반 구 EMR(레거시) 분석부터 착수, 이를 바탕으로 신규 EMR 설계·개발 시작, 전임자로부터 그 외 솔루션(연구검색·가명화·인증 등) 인계(1월 말~2월 초)
- **2월** — R-BAY IRB 연동 개발, 타 솔루션 → EMR 토큰 인증·조회 연동(어댑터) 개발, K-ERAS·SHINE 이슈 대응
- **3월** — (순천향) 가명화 다기관 로직 신규 구현·안정화 착수(인계 시점 미작동), 운영환경 구축 — 중순 상주 철수(이후 폐쇄망 특성상 방문 대응) / (서울대) 복귀 후 연구검색 서식지 적재 오류 대응
- **4월** — (순천향) 운영기 이관(도메인·nginx 프록시·방화벽 구성), 오픈 이슈 대응을 위해 근무지 병행(월·화 서울대 / 수·목·금 순천향 방문) / (서울대) 스누허브 연동·서식지 적재(Logstash 기반 신규 모듈 구축)·가명 ID 누락 건 대응 / (대외) SHINE 공공기관 이관, 타 병원(계명대·강원대) 레거시 유지보수 등 기타 이슈 대응
- **5월** — (순천향) EMR 다기관 조회(여러 병원) 추가 구현, 누락 의무기록 서식(입원·외래·응급 기록지) 작업, 2차 인증 외부 연동(동은정보시스템), 중간보고+오픈(5/29) / (서울대) K-ERAS 리뉴얼 건 마무리 전달
- **6월** — (순천향) 운영 이슈 대응, EMR 의무기록 서식 가명화 모듈 작업 및 연동 / (서울대) REX 비정형 데이터 조회·다운로드 이슈 대응

**① 순천향 CDW 현장 구축 (메인)**

서로 얽혀 있던 여러 시스템(의무기록 조회·데이터 추출·로그인/인증·헬프센터·가명화 등)을 처음부터 다시 점검·정비했습니다. 이 중 **신규 의무기록 뷰어 구축, 외부 연구윤리심의(IRB)·인증 시스템 연동, 가명화 솔루션 안정화·다기관 대응**이 특히 공수가 큰 작업이었습니다.

- **의무기록(EMR) 조회 화면 신규 구축** — 순천향에서 쓰던 기존 구 EMR 시스템(.NET)을 분석해, 연구자가 환자 진료기록을 바로 열람할 수 있는 웹 기반 조회 화면으로 새로 개발함. 개인정보는 가명화·마스킹 처리해 안전하게 표시하며, 이후 순천향 산하 4개 병원 다기관 조회까지 확장함. 이 조회 인터페이스는 토큰 인증 기반 어댑터로 연구검색·레지스트리 등 여러 솔루션에 연동함. (상반기 개발 비중이 가장 큼)
- **외부 인증 시스템 신규 연동 (IRB·2차 인증)** — 순천향의 신규 IRB(연구윤리심의) 시스템 연동 요구에 따라, 외부 업체(R-BAY)와 협업하여 각 병원 인증 체계와의 연동을 새로 구축. 여기에 병원 보안 요건인 2차 인증(다중인증)도 외부 업체(동은정보시스템)와 협업해 연동 구축. (두 외부 업체와 연동 규격·동작을 맞추고 검증하는 확인·커뮤니케이션 과정에 별도 공수가 크게 든 작업이었음)
- **가명화 시스템 안정화·다기관 대응 전면 재작업** — 환자 식별정보를 연구용 가명 ID로 바꾸는 시스템의 다기관(순천향 4개 병원) 지원 부분이 인계 시점 미완성·다수 오류 상태였고, 가명 ID 누락(로직의 동시성 문제)이 지속 발생하던 것을 전면 재작업함. 제대로 작동하지 않던 기능을 새로 개발해 4개 병원의 가명 ID 신규 생성·적재 연동까지 처리하고, 동시성·오류·속도 문제까지 해결해 안정화함.
- **헬프센터(공지·QnA) 화면 전면 개편** — PM 요청으로, 공지·QnA 게시판, FAQ, 댓글, 게이트, 사이드바 등 헬프센터 UI를 전면 개편함.
- **중복 기능 공통화 (실험적 도입·실효 검증)** — 프로젝트마다 중복 코드가 쌓여 유지보수를 어렵게 하던 회사의 고질적 문제를 어떻게 풀지 고민하다, 이번처럼 여러 프로젝트를 동시에 진행·연계할 일이 많은 상황에서 공통 부품화를 실험적으로 직접 도입함. 여러 시스템에 흩어져 중복돼 있던 기능을 공통 부품으로 묶었고, 실제로 유지보수가 훨씬 수월해지는 효과를 확인함. 아직 사내 전파 전 단계지만, 인계와 코드 공유 과정에서 자연스럽게 팀에 확산될 것으로 기대함.
- **서버·도메인·보안 인프라 담당** — 개발뿐 아니라 순천향 운영 인프라 전반을 도맡음: 운영 서버 2대 구성, 5개 서비스 도메인 연결·프록시 설정, 방화벽 등 병원 보안 요건 대응.

**② 서울대 연구검색 대응 (본사 혜화 근무) — 병행**

서울대병원 연구검색에도 이슈가 많아, 담당자 퇴사로 남겨진 작업을 넘겨받아 (본사 혜화에서) 데이터 처리와 이슈 대응을 함께 수행했습니다.

- **외부 데이터허브(스누허브) 연동 — 담당자 부재분 넘겨받아 대응** — 연구검색의 비정형(문서·이미지 등) 데이터를 조회·다운로드해 스누허브로 전송할 수 있도록 인터페이스를 만들고 연동함(협력사 애니모비와 협업). 이 과정에서 파일 전송 인증 오류·전송 포맷(엑셀/CSV) 변환 등 여러 문제를 순차 해결하고, 협력사와 연계 테스트를 진행함.
- **서식지 적재 모듈 재구축** — 영상·병리·기능검사 등 검사 기록의 긴 텍스트(판독문 등)를 검색 엔진(Elasticsearch)에 등록해 빠르게 검색되도록 하는 서식지 적재 모듈. 기존 모듈은 SQL 페이징 과정에서 일부 기록의 인덱싱이 누락되는 문제가 있었고, 누락이 생길 때마다 전체를 다시 적재해 메꿔왔는데 그 초기 적재조차 일주일씩 걸렸음. 버그를 고치려다 구조적 한계가 드러나 아예 새로 만듦(Logstash 기반). 재구축으로 인덱싱 누락을 해결하고 **초기 적재를 일주일에서 한 시간 내외로 단축**했으며, 이후에는 마지막 적재 날짜 이후 데이터만 넣는 증분 방식으로 바꿔 전체 재적재가 필요 없도록 함.
- **가명 ID 누락 이슈 원인 규명·복구** — 가명화 ID가 누락됐다는 이슈가 제기되자 원인(로직의 동시성 문제)을 규명(김명훈 선생님과 협업)하고, 누락된 가명화 대상 환자를 재생성하는 복구 방안을 제안·주도해 **약 1.8만 건을 복구**함(이원호 책임과 협업). 근본 원인인 동시성 문제는 서울대 코드에서 수정함.
- **비정형 데이터 추출(REX) 모듈 문제 해결 — 담당자 부재로 이어받음** — 담당자가 만들던 모듈에서 비정형(문서·이미지 등) 데이터의 목록·정보(메타) 조회가 크게 느려지는 문제가 있어 이를 넘겨받음. 조회 방식(쿼리)이 잘못 짜인 것이 원인임을 찾아 바로잡아 해결하고, 처리 과정에서 파일 다운로드 진행률이 중간에 멈추는 버그까지 함께 수정. (데이터 신청 시 정형/비정형 구분·출력 항목·신청 라벨 처리 포함)

**③ 서울대병원 K-ERAS 임상연구 데이터 시스템 개발 — 개발 담당**

서울대병원의 ERAS(수술 후 환자 조기회복 프로그램) 임상연구용 데이터 관리·분석 시스템(K-ERAS)을 2023년부터 단독으로 개발·유지보수해 온 담당자로서, 현재 3년 유지보수 계약의 2년차를 맡아 상반기 동안 대규모 기능 추가·개선을 수행했습니다. 개선 결과에 대해 담당 교수(이호진 교수)로부터 **"수정해주신 부분 모두 만족스러우며 훨씬 나은 프로그램이 될 것"**이라는 만족 회신을 받았습니다.

- **분석(Outcomes) 대시보드 신규 구축** — 연구 버전별 환자 수·수행률·합병증·재원기간·재수술/재입원율 등을 비교하는 분석 화면을 처음부터 새로 구축.
- **기능·사용성·보안 전반 개선** — 데이터 입력 폼 강화(조건부 활성/비활성 등), 연구 진행 상태(완료·중도 종료) 관리, 계정 보안 강화(계정 잠금·비밀번호 재설정), 화면 전면 개편(다크 테마 통일 등).

**④ 대외 인프라·자문 및 기타 병행**

- **SHINE(공공기관 시스템)** — 기존 민간 클라우드에서 공공기관용 클라우드로 서버를 이관하는 것이 주된 작업이었고, 그 외 도메인·보안 인증서 셋업·보안성 검토 대응·계약(명의 변경) 조율 등을 병행.
- **건강정보고속도로(정부 사업)** — 거점·에이전트 이슈 대응이 주된 업무였고, 그 외 보안 인증서 교체(현장 방문 포함)·접속자수 집계 등을 병행.
- **타 병원(계명대·강원대) 레거시 시스템 유지보수 긴급 대응** — 타 담당 인력의 지원 요청을 받아, 운영 중 발생한 긴급 이슈에 투입됨. 계명대 동산병원 태블로 포탈 이슈 등 레거시 시스템 유지보수 성격의 작업을 처리함.
- **기타** — 충북대 보안인증(ISMS) 요청 대응, 건강관리협회 제안서 작성 일부 참여, 연구검색 권한 관리 기능 개선, 운영위원회(Supreme) 참여, 인하대 CDW/EDW 사업 미팅 참여, 국립병원 문서 작성 지원.

### 업무성과에 대한 본인 평가

**우수한 점**
- **연이은 인력 이탈로 여러 곳에서 동시에 생긴 공백을 연쇄적으로 흡수해, 인계받은 미완성 작업까지 정상화함** — 지연되던 순천향 의무기록 화면에 투입된 뒤 담당 2명이 이탈하며 해당 업무까지 맡았고, 서울대 데이터허브(스누허브)·비정형 데이터 담당 몫도 넘겨받음. 인계받은 작업 상당수가 미완성·오류 상태(가명화 다기관 대응, 비정형 데이터 추출 등)였는데, 원인을 규명해 재작업·정상화함.
- **일정 리스크를 선제적으로 관리함** — 오픈이 임박한 시점에 모든 부담을 혼자 떠안지 않고, 리스크를 판단해 직접 추가 인력을 요청·배정함으로써 순천향이 일정을 차질 없이 맞춰 오픈까지 완수하도록 함.
- **재현·추적이 어려운 문제의 근본 원인을 규명해 해결함** — 가명 ID 누락(로직의 동시성 문제)·서식 인덱싱 누락(SQL 페이징) 등 원인 파악이 까다로운 이슈의 원인을 짚어, 누락 대상 재생성(약 1.8만 건)·코드 수정으로 근본 해결함.
- **난도 높은 신규 개발을 단독 완수** — 순천향 구 EMR(.NET)을 분석해 웹 기반으로 새로 개발·연구검색 연동했고, 서식지 적재를 재구축해 일주일씩 걸리던 초기 적재를 한 시간 내외로 단축하는 등 핵심 신규 개발을 완수함.
- **다중 과제 병행** — 순천향 현장 대응과 함께 서울대병원 연구검색 대응·K-ERAS 개발, SHINE·건강정보고속도로 등 대외 과제를 병행 소화함.
- 프론트엔드·백엔드·데이터베이스·로그인/인증·서버/클라우드 인프라까지 전 영역을 직접 다룸.

**보완이 필요한 점**
- 순천향 전용으로 급히 손댄 부분이 회사 공통 버전과 많이 벌어져, 나중에 다시 합치려면 정리 작업이 필요함. 병원 전용 변경과 공통 변경을 처음부터 더 나눠 관리했다면 부담이 적었을 것.
- 촉박한 일정 탓에 여러 성격의 작업(기능 추가·오류 수정·구조 개선)을 한꺼번에 진행한 구간이 있어, 나중에 이력 추적이 다소 어려움. 작업 단위를 더 잘게 나눴다면 리뷰·인수인계가 쉬웠을 것.
- 여러 근무지·과제가 동시에 겹쳐 부하가 몰린 구간이 있었음. 향후엔 부하가 누적되기 전 더 일찍 분업·에스컬레이션해 리스크를 줄이려 함.

### 협업 및 커뮤니케이션에 대한 본인 평가

**팀 내 협업 (일정/이슈 공유 포함)**
- 상사(박동현)께 매일 업무 보고하며 진행·이슈·리스크를 상시 공유 → 리스크를 조기에 가시화하고 다중 근무지 일정 변동을 사전 협의함.
- 전임자들이 퇴사해 인계받은 여러 솔루션 관련 문의가 본인에게 몰리는 상황에서, 확인 요청에 대응하며 동료들을 지원함.

**고객 커뮤니케이션**
- 순천향 현장에 상주·방문하며 고객사 담당(최서희 간사)에게 요구사항을 직접 확인해 작업을 진행함.
- 여러 외부 협력사(애니모비·R-BAY·동은정보시스템 등)와 연동 규격·일정을 조율함.
- 보안성 검토·ISMS·2차 인증 등 규제·보안 요건을 병원이 이해할 수 있게 설명하고 증빙을 전달함.
- 서울대병원 K-ERAS는 요구사항을 먼저 제안·조율하며 개발했고, 담당 교수로부터 개선 결과에 대한 긍정 피드백을 받음.

## 2. AI 활용 설문

1. **업무 시간 중 평균 AI 사용 비율:** 약 **70%**
2. **월간(최근 30일) 클로드 맥스 토큰 사용량:** `(⚠️ 상사 요청 변경 — 클로드 앱에서 최근 30일 토큰량 확인 후 기입)`
3. **주로 사용하는 업무 영역:** 낯선/레거시 코드 파악(전임자 시스템·구 EMR(.NET) 분석), 코드 작성·리팩터링, 코드 리뷰·디버깅(오류 원인 규명), 개발 환경·설정 정리, 문서화(인수인계·자문 답변·보고서), 기술 리서치.
4. **AI 활용 생산성 향상 체감:** 약 **50%**
5. **(옵션) 가장 효과를 본 사례 1가지:**
   순천향에 긴급 투입됐을 때, 전임자들이 남긴 낯선 여러 시스템(EMR·연구검색·가명화·인증)의 코드를 AI로 빠르게 파악하고 문제 원인을 짚어 재작업 속도를 크게 높인 것. 특히 구 EMR(.NET) 분석·서식지 적재 재구축·가명 ID 누락 원인 규명처럼 낯선 코드를 짧은 기간에 파고들어야 하는 작업에서, 다수 시스템을 빠르게 재정비해 일정 내 오픈으로 이어가는 데 큰 도움이 됨.
6. **AI를 더 적극적으로 활용함에 있어서 어려운 점:**
   병원 폐쇄망/보안망 환경이라 현장에서는 외부 AI 도구 사용에 제약이 큼(반입·연결 통제). 의료 EMR·가명화 규정 등 도메인 특수성과 병원별 예외가 많아, 프롬프트만으로 맥락을 충분히 전달하기 어렵고 결과를 그대로 신뢰하기 어려움.
7. **AI 활용에서 스스로 개선이 필요한 부분:**
   AI가 만든 결과를 그대로 쓰기보다 **검증하는 습관을 더 체계화**할 필요가 있음. 또한 반복되는 맥락(도메인 규칙·프로젝트 구조·공통 부품)을 프롬프트·컨텍스트로 미리 정리해 두어 재사용성을 높이는 부분.
8. **회사/팀 차원에서 필요한 지원·개선:**
   폐쇄망 환경에서 쓸 수 있는 AI 활용 가이드·보안 정책 정립. 팀 내에서 프로젝트 컨텍스트·도메인 규칙을 공유·재사용할 수 있는 형태로 축적하는 체계.
