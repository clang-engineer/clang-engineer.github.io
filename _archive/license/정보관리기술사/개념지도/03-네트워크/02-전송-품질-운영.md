# 전송·품질·운영 개념지도

이 지도는 **종단 간 데이터를 어떻게 전달하고, 혼잡과 품질 문제를 어떻게 제어하며, 운영 상태를 어떻게 관측하는지**를 하나의 문제 확장 흐름으로 본다.

## 1. 종단 간 전달

```text
IP
= 목적지 Host까지 Packet 전달
  ↓
Transport
= Host 안의 목적 Process까지 전달 특성 제공
  ↓
Port
= Process 식별
```

Transport Layer의 대표 선택은 TCP와 UDP다.

```text
Transport
├─ TCP
│   ├─ 연결 상태 유지
│   ├─ 신뢰성 있는 Byte Stream
│   ├─ 순서 보장
│   └─ 오류·흐름·혼잡 제어
└─ UDP
    ├─ 연결 상태 없음
    └─ Datagram 단위 전달
```

## 2. TCP는 문제 범위를 넓혀가며 본다

```text
연결을 만든다
3-Way Handshake
  ↓
연결을 끝낸다
FIN / 일반적인 4-Way 종료 흐름
  ↓
데이터가 제대로 갔는가?
오류 제어
  ↓
수신자가 감당할 수 있는가?
흐름 제어
  ↓
중간 Network가 감당할 수 있는가?
혼잡 제어
```

핵심 경계를 구분한다.

```text
오류 제어
= 전달 정확성·손실 대응

흐름 제어
= Sender가 Receiver 처리 능력을 넘지 않도록 조절

혼잡 제어
= Sender가 Network 수용 능력을 넘지 않도록 조절
```

→ [[TCP-연결-종료-흐름-혼잡제어]]

## 3. 연결 재사용은 상위 계층 문제다

```text
TCP Connection
  ↓
HTTP Request / Response
  ↓
매번 새 TCP 연결 생성 시 비용 발생
  ↓
Persistent Connection
  └─ HTTP Keep-Alive

Application / Server
  ↓
여러 TCP Connection 생성 비용 감소 필요
  ↓
Connection Pool
```

HTTP Keep-Alive와 Connection Pool을 TCP 자체 기능으로 놓지 않는다. 둘은 **TCP Connection을 상위 계층에서 재사용하는 방법**이다.

## 4. 혼잡에서 QoS로

TCP 혼잡 제어는 개별 TCP Sender가 Network 혼잡에 적응하는 관점이다. QoS는 Network가 여러 Traffic을 함께 다루면서 자원을 정책적으로 배분하는 관점이다.

```text
Traffic 증가
  ↓
Queue 증가
  ↓
Delay / Jitter 증가
  ↓
Packet Loss
  ↓
재전송·Throughput 저하
  ↓
Traffic별 요구 차이를 반영할 필요
  ↓
QoS
```

QoS는 회선 용량을 늘리는 기술이 아니다.

```text
QoS
= 한정된 Network 자원을 Traffic 특성에 맞게 관리
```

## 5. QoS 처리 흐름

```text
Traffic 유입
  ↓
Classification
  ↓
Marking
  ↓
속도 정책
├─ Policing
└─ Shaping
  ↓
Queueing
  ↓
Scheduling
  ↓
Delay / Jitter / Loss 측정
  ↓
QoE와 Service 목표로 보정
```

QoS와 QoE의 축도 구분한다.

```text
QoS
= Network 관점의 기술적 품질과 정책

QoE
= 사용자가 실제로 체감하는 Service 품질
```

QoS가 QoE에 영향을 주지만, Server·Application·Codec·단말 등도 QoE에 영향을 준다.

→ [[QoS와-QoE]]

## 6. 품질을 운영하려면 관측이 필요하다

```text
Network 상태 변화
  ↓
Metric / Event 수집
  ↓
NMS
├─ 저장
├─ 임계치 판단
├─ Alert
└─ 운영자에게 가시화
```

NMS와 SNMP를 같은 개념으로 놓지 않는다.

```text
NMS
= 여러 Network 장비를 중앙에서 통합 관리하는 시스템

SNMP
= NMS와 장비 Agent가 관리 정보를 주고받을 때 사용하는 대표 Protocol
```

## 7. Polling과 Event 통지

```text
정상 상태와 추세
Manager ── Polling ──→ Agent

즉시 알려야 할 Event
Manager ←─ Trap / Inform ─ Agent
```

둘은 대체 관계보다 보완 관계로 본다. Polling은 중앙 통제와 지속적인 상태 확인에 유리하고, Trap·Inform은 Event를 빠르게 전달하는 데 유리하다.

→ [[NMS와-SNMP]]

## 8. 학습 이동 경로

```text
IP만으로 무엇이 부족한가?
  ↓
TCP와 UDP는 어떤 전달 특성을 제공하는가?
  ↓
TCP는 정확성·수신자·Network 문제를 각각 어떻게 제어하는가?
  ↓
여러 Traffic이 동시에 경쟁하면 어떤 품질 문제가 생기는가?
  ↓
QoS는 한정된 자원을 어떻게 배분하는가?
  ↓
그 결과가 실제 사용자 QoE와 어떻게 연결되는가?
  ↓
Network 상태를 지속적으로 어떻게 관측하고 운영하는가?
```

TCP 상태 전이 전체, 혼잡 제어 Algorithm 세부, QoS Scheduling Algorithm, SNMP PDU와 OID 세부는 세부학습으로 내려간다.
