# 네트워크 전체 개념지도

네트워크는 **단말의 데이터를 인접 장비에 전달하고, 다른 네트워크까지 경로를 찾아 운반한 뒤, 종단 간 통신과 응용 서비스로 연결하는 구조**로 본다.

이 문서는 개별 Protocol의 동작을 설명하기보다 네트워크 개념이 어느 계층과 문제에 놓이는지 탐색하는 지도다.

## 1. 전체 좌표

```text
네트워크 통신
├─ 통신 기반
│   ├─ OSI 7 Layer / TCP/IP
│   ├─ Encapsulation / Decapsulation
│   └─ Physical Media / Ethernet
│
├─ 같은 Network 안에서 전달 — L2
│   ├─ MAC Address
│   ├─ Ethernet Frame
│   ├─ Switch
│   ├─ ARP
│   ├─ VLAN
│   └─ STP
│
├─ 다른 Network까지 전달 — L3
│   ├─ IP Address
│   │   ├─ IPv4 / IPv6
│   │   ├─ Subnet / Subnetting
│   │   ├─ CIDR
│   │   └─ VLSM
│   ├─ Default Gateway
│   ├─ Routing
│   │   ├─ Static / Dynamic
│   │   ├─ Distance Vector → RIP
│   │   ├─ Link State → OSPF
│   │   └─ AS 간 Routing → BGP
│   ├─ DHCP
│   └─ NAT / PAT
│
├─ 종단 간 데이터 전달 — L4
│   ├─ Port
│   ├─ TCP
│   │   ├─ 연결 설정 / 종료
│   │   ├─ 오류 제어
│   │   ├─ 흐름 제어
│   │   └─ 혼잡 제어
│   └─ UDP
│
└─ 응용 통신
    ├─ DNS
    ├─ HTTP / HTTPS
    └─ HTTP 연결 재사용
        └─ Keep-Alive / Connection Pool
```

이 흐름은 모든 개념의 발전 순서를 뜻하지 않는다. `L2 → L3 → L4 → 응용`은 데이터가 통신 과정에서 만나는 계층적 좌표이고, 각 계층 안의 Protocol과 기술은 목적에 따라 병렬적으로 선택된다.

## 2. 단말이 Internet까지 가는 흐름

```text
단말 접속
  ↓
DHCP
IP · Subnet Mask · Gateway · DNS 설정 획득
  ↓
목적지가 같은 Subnet인가?
  ├─ Yes → ARP로 MAC 확인 → Switch를 통해 L2 전달
  └─ No  → Default Gateway
              ↓
            Routing
              ↓
        필요 시 NAT / PAT
              ↓
           Internet
```

여기서 역할을 섞지 않는다.

- `Subnet`은 IP Network의 범위를 나눈다.
- `VLAN`은 L2 Broadcast Domain을 논리적으로 나눈다.
- `DHCP`는 Network 설정을 자동 할당한다.
- `Routing`은 다른 Network로 갈 경로를 선택한다.
- `NAT/PAT`는 주소 또는 주소·Port 대응을 변환한다.

## 3. 주소와 Network 분할

```text
IP Address
├─ IPv4
│   └─ 주소 부족
│       └─ NAT / PAT의 광범위한 활용
└─ IPv6
    └─ 128bit 주소 공간

IP Network 분할
└─ Subnetting
    ├─ Subnet Mask / Prefix Length
    └─ VLSM
        └─ 필요한 Host 수에 따라 서로 다른 크기로 분할

Classless 주소 표현·할당
└─ CIDR
    └─ Route Aggregation에도 활용
```

`Subnetting`, `VLSM`, `CIDR`은 같은 말이 아니다. Subnetting은 Network를 나누는 상위 개념이고, VLSM은 서로 다른 크기로 나누는 방법이며, CIDR은 Class 없이 Prefix로 주소 Block을 표현·할당·집약하는 방식이다.

## 4. L2와 L3의 경계

```text
같은 Subnet
Host
 ↓ ARP로 목적지 MAC 확인
Switch
 ↓ MAC Address 기반 전달
Destination

다른 Subnet
Host
 ↓ Default Gateway의 MAC으로 Frame 전달
Router
 ↓ IP Routing
다른 Network
```

```text
Network 분리의 서로 다른 축

L2: VLAN
    └─ Broadcast Domain 분리

L3: Subnet
    └─ IP Network 분리
```

실무에서는 `1 VLAN : 1 Subnet` 구성이 흔하지만 VLAN과 Subnet은 같은 개념이 아니다.

## 5. Routing의 큰 그림

```text
Routing
├─ Static Routing
│   └─ 관리자가 경로 지정
│
└─ Dynamic Routing
    ├─ AS 내부(IGP)
    │   ├─ Distance Vector
    │   │   └─ RIP
    │   └─ Link State
    │       └─ OSPF
    │
    └─ AS 간(EGP)
        └─ BGP
```

Routing Protocol을 단순 발전 순서로 외우지 않는다. RIP와 OSPF는 AS 내부 Routing이라는 같은 문제에 서로 다른 방식으로 접근하고, BGP는 AS 사이의 경로를 다루는 위치가 다르다.

## 6. TCP와 UDP의 위치

```text
Transport Layer
├─ TCP
│   ├─ 연결 상태 유지
│   ├─ 신뢰성 있는 Byte Stream
│   └─ 전송 과정의 문제를 단계적으로 제어
│       ├─ 데이터가 정확히 갔는가? → 오류 제어
│       ├─ 수신자가 감당하는가?    → 흐름 제어
│       └─ Network가 감당하는가?   → 혼잡 제어
│
└─ UDP
    ├─ 연결 상태 없음
    └─ Datagram 단위 전달
```

TCP 내부 학습은 다음 문제 흐름으로 내려간다.

```text
연결 설정
3-way Handshake
  ↓
연결 종료
FIN / 일반적인 4-way 종료 흐름
  ↓
오류 제어
Sequence / ACK / Retransmission
  ↓
흐름 제어
rwnd / Sliding Window
  ↓
혼잡 제어
cwnd / Slow Start / Congestion Avoidance
```

## 7. TCP 위에서 응용으로 올라가기

```text
TCP Connection
  ↓
HTTP Request / Response
  ↓
매 요청마다 TCP를 다시 연결하면 비용 증가
  ↓
Persistent Connection
  └─ HTTP Keep-Alive

Application / Server
  ↓
여러 TCP Connection을 반복 생성하는 비용 감소
  ↓
Connection Pool
```

HTTP Keep-Alive와 Connection Pool은 TCP 자체의 기능이 아니라 TCP Connection을 상위 계층에서 재사용하는 관점으로 본다.

## 8. 함께 보되 같은 축으로 놓지 않을 개념

네트워크에는 계층 흐름만으로 한 줄에 배치하기 어려운 주제가 있다.

```text
[성능·서비스 품질]
QoS / Traffic Control / Queueing / Scheduling

[보안]
Firewall / VPN / TLS / IPsec / IDS·IPS

[무선]
WLAN / Wi-Fi / 이동통신

[Network 제어·가상화]
SDN / NFV / Overlay / Network Virtualization
```

이들은 `L2 → L3 → L4`의 다음 단계가 아니다. 여러 계층에 걸쳐 적용되거나 별도의 목적·분류축을 가지므로 독립적인 학습 가지로 본다.

## 9. 학습 이동 경로

처음부터 모든 Protocol을 독립적으로 외우기보다 다음 질문을 따라 이동한다.

```text
데이터는 계층을 어떻게 내려가고 올라오는가?
  ↓
같은 Network 안에서는 어떻게 전달하는가?
  ↓
IP Network는 어떻게 나누고 주소를 부여하는가?
  ↓
다른 Network로 갈 경로는 어떻게 찾는가?
  ↓
종단 간 데이터를 어떻게 신뢰성 있게 전달하는가?
  ↓
그 연결 위에서 응용 Protocol은 어떻게 동작하는가?
  ↓
성능·보안·무선·가상화 요구는 어디에 개입하는가?
```

이 지도에서 개념의 위치와 관계를 잡은 뒤, 각 Protocol의 상세 동작·Algorithm·Header·Timer·상태 전이는 세부학습으로 내려간다.
