# 네트워크 전체 개념지도

네트워크는 **서로 떨어진 시스템 사이에서 데이터를 목적지까지 전달하고, 공유 자원의 손실·혼잡·지연·이동 문제를 제어하며, 서비스 요구에 맞게 망을 운영하는 구조**로 본다.

이 문서는 Protocol 목록을 계층별로 외우기 위한 목차가 아니다. **두 시스템이 통신해야 한다는 출발점에서 왜 다음 개념이 필요한지 따라가며**, 더 깊게 볼 학습 가지를 선택하는 지도다.

## 1. 가장 먼저 잡을 큰 그림

```text
두 시스템이 통신해야 함
  ↓ 역할을 한 덩어리로 구현하면 복잡함
계층 모델
OSI / TCP-IP
  ↓ 같은 Link 안에서 실제 Frame을 전달해야 함
Ethernet / WLAN · MAC · Switch
  ↓ 하나의 L2 영역이 커지면 Broadcast 범위와 관리가 커짐
VLAN
  ↓ 다른 Network까지 가려면 논리 주소와 경계가 필요
IP · Subnet · Default Gateway
  ↓ 목적지 Network까지 여러 경로 중 길을 선택해야 함
Routing
  ↓ Host까지 도착한 데이터를 목적 Process에 전달해야 함
TCP / UDP · Port
  ↓ 손실·수신자 처리 한계·Network 혼잡에 대응
오류 제어 · 흐름 제어 · 혼잡 제어
  ↓ 여러 Traffic이 한정된 자원을 경쟁
QoS
  ↓ 실제 사용자 체감까지 확인
QoE
  ↓ 품질과 장애를 지속적으로 운영하려면 상태를 봐야 함
NMS / SNMP
```

이 흐름은 기술의 역사적 발전 순서가 아니다. **통신 범위와 해결해야 할 문제가 넓어지는 학습 흐름**이다.

## 2. 계층은 통신 기능의 좌표다

```text
Application
= Service 의미와 응용 Protocol

Transport
= 종단 Process 사이의 전달 특성

Network
= IP 주소와 다른 Network까지의 경로

Link
= 같은 L2 영역에서 Frame 전달

Physical
= 실제 신호와 매체
```

데이터는 송신 측에서 계층별 정보를 붙여 Encapsulation되고, 목적지에서 역순으로 Decapsulation된다.

```text
응용 데이터
  ↓
Transport Segment / Datagram
  ↓
IP Packet
  ↓
Link Frame
  ↓
물리 매체
```

계층 번호 자체보다 **각 계층이 어떤 문제를 맡는가**를 먼저 본다.

## 3. 같은 망에서 다른 망으로

```text
같은 L2 영역
MAC Address
  ↓
Switch가 Frame 전달
  ↓
Broadcast 범위를 논리적으로 나눌 필요
VLAN

다른 Network까지 전달
IP Address / Subnet
  ↓
목적지가 다른 Subnet
  ↓
Default Gateway
  ↓
Router
  ↓
Routing
```

L2와 L3의 분리 기준을 섞지 않는다.

```text
VLAN
= L2 Broadcast Domain을 논리적으로 분리

Subnet
= IP Prefix를 기준으로 L3 Network 범위를 분리
```

실무에서 `1 VLAN : 1 Subnet` 구성이 흔하더라도 같은 개념은 아니다.

→ [[01-통신-주소-경로]]

## 4. 주소를 정하고 경로를 찾는다

```text
IP Address
├─ IPv4
│   └─ 주소 부족 → 사설 주소 · NAT / PAT
└─ IPv6
    └─ 더 큰 주소 공간

Network 범위
├─ Subnetting
├─ VLSM
└─ CIDR

Host 설정 자동화
└─ DHCP

다른 Network로 이동
└─ Routing
    ├─ AS 내부
    │   ├─ RIP
    │   └─ OSPF
    └─ AS 간
        └─ BGP
```

`Subnetting / VLSM / CIDR`, `RIP / OSPF / BGP`는 단순 나열이나 발전 순서로 보지 않고 각각의 역할과 적용 범위를 구분한다.

## 5. 목적지 Host에 도착한 뒤에도 문제가 남는다

IP가 Packet을 목적지 Host까지 전달해도 Application이 원하는 전달 특성이 자동으로 보장되는 것은 아니다.

```text
IP
  ↓ Host까지 전달
Transport
  ↓ Process와 전달 특성
Port
  ↓
TCP / UDP
```

```text
TCP
├─ 데이터가 제대로 갔는가? → 오류 제어
├─ 수신자가 감당하는가?    → 흐름 제어
└─ Network가 감당하는가?   → 혼잡 제어

UDP
└─ 연결 상태 없이 Datagram 전달
```

문제 범위가 `전달 정확성 → Receiver → Network`로 넓어진다는 흐름을 잡는다.

→ [[02-전송-품질-운영]]

## 6. 한정된 Network를 여러 Traffic이 공유한다

```text
Traffic 증가
  ↓
Queue 증가
  ↓
Delay / Jitter / Loss
  ↓
Traffic마다 요구 특성이 다름
  ↓
QoS
  ↓
사용자가 실제로 느끼는 품질
  ↓
QoE
```

TCP 혼잡 제어와 QoS는 같은 개념이 아니다.

```text
TCP 혼잡 제어
= 개별 Sender가 Network 혼잡에 적응

QoS
= Network가 여러 Traffic에 자원을 정책적으로 배분
```

품질을 지속적으로 관리하려면 현재 망 상태를 관측해야 한다.

```text
Network 상태
  ↓
Metric / Event 수집
  ↓
NMS
  └─ SNMP / Telemetry / API 등으로 장비와 정보 교환
```

## 7. 기본 전달 흐름 밖에서 추가되는 학습 가지

다음 주제들은 `L2 → L3 → L4` 뒤에 순서대로 등장하는 다음 계층이 아니다. **환경이나 서비스 목적이 달라지면서 추가되는 별도의 축**이다.

```text
[무선·이동]
공유 무선 Channel
  ↓ 충돌 탐지가 어려움
CSMA/CA
  ↓
WLAN
  ↓ 이동성 추가
Roaming / Handover
  ↓
이동통신 / 5G
```

→ [[03-무선-이동]]

```text
[서비스 전달]
HTTP / RTP · RTCP / CDN / VPN

[운영 자동화]
장비별 수동 제어의 한계
  ↓
SDN

[기능 가상화]
전용 Network Appliance 의존
  ↓
NFV

[제약 환경]
저전력 · 저성능 · 대규모 단말
  ↓
Sensor Network / IoT
```

→ [[04-서비스-가상화-제약환경]]

## 8. 큰 학습 가지

전체 좌표를 잡은 뒤 필요한 가지에서 탐색 밀도를 높인다.

```text
네트워크 전체
├─ [[01-통신-주소-경로]]
│   └─ 계층 → L2/L3 경계 → IP 주소 → Gateway → Routing
│
├─ [[02-전송-품질-운영]]
│   └─ TCP/UDP → 오류·흐름·혼잡 → QoS/QoE → NMS/SNMP
│
├─ [[03-무선-이동]]
│   └─ 공유 무선 매체 → CSMA/CA → WLAN → Handover → 이동통신
│
└─ [[04-서비스-가상화-제약환경]]
    └─ 서비스 전달 / VPN / SDN / NFV / Sensor Network·IoT
```

하위 지도는 세부 Protocol 설명을 반복하는 문서가 아니다. 그 가지 안에서 **왜 다음 개념이 등장하는지와 무엇을 비교해야 하는지**를 더 촘촘하게 보여준다.

## 9. 이 지도를 이용하는 방법

```text
전체 지도에서 현재 위치 확인
  ↓
왜 다음 개념이 필요한지 따라감
  ↓
큰 학습 가지 선택
  ↓
하위 지도에서 관계를 더 촘촘히 탐색
  ↓
필요한 개념은 세부학습에서 원리·동작을 깊게 이해
  ↓
새롭게 이해한 관계를 다시 상위 지도에서 확인
```

Header 필드, 상태 전이, Algorithm 계산 과정, Timer, 개별 표준 세부는 세부학습으로 내려간다.
