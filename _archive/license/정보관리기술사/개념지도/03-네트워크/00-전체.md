# 네트워크 전체 개념지도

네트워크는 **서로 떨어진 시스템이 데이터를 주고받을 수 있게 연결하고, 그 과정에서 생기는 주소·경로·전송·혼잡·운영 문제를 해결하는 구조**로 본다.

이 문서는 Protocol 이름을 외우기 위한 목차가 아니다. 먼저 **컴퓨터끼리 통신하려면 어떤 문제가 순서대로 생기는지** 큰 그림을 잡고, 필요한 가지에서 더 자세히 내려간다.

## 1. 가장 먼저 잡을 큰 그림

```text
컴퓨터끼리 데이터를 주고받고 싶다
│
├─ 데이터를 어떤 규칙으로 주고받지?
│   └─ 계층 모델
│
├─ 같은 망 안에서는 누구에게 보내지?
│   └─ MAC · Switch · VLAN
│
├─ 다른 망까지는 어떻게 찾아가지?
│   └─ IP · Subnet · Gateway · Routing
│
├─ 도착한 데이터를 어느 프로그램에 넘기지?
│   └─ Port · TCP / UDP
│
├─ Application은 Network 기능을 실제로 어떻게 사용하지?
│   └─ Socket API
│
├─ 손실되거나 너무 많이 보내면 어떻게 하지?
│   └─ 오류 제어 · 흐름 제어 · 혼잡 제어
│
├─ 여러 Traffic이 몰리면 중요한 것을 어떻게 먼저 보내지?
│   └─ QoS
│
└─ 망이 정상인지 어떻게 계속 확인하지?
    └─ NMS / SNMP
```

여기서 중요한 것은 이름보다 **문제의 위치**다.

```text
같은 망 안의 전달
→ 다른 망까지의 전달
→ 종단 프로그램까지의 전달
→ Application이 Network를 사용하는 경계
→ 품질과 혼잡
→ 운영과 관측
```

이 흐름은 기술의 역사적 발전 순서가 아니라, 통신 범위를 넓혀가며 어떤 문제가 추가되는지 보는 학습 흐름이다.

## 2. 계층은 역할을 나누는 좌표다

통신 기능을 한 덩어리로 만들면 복잡해지므로 역할을 나눈다.

```text
응용
= 사용자가 쓰는 Service의 의미

전송
= 어떤 Process로, 어떤 전달 특성으로 보낼지

Network
= 다른 Network까지 어떻게 갈지

Link
= 같은 L2 영역 안에서 어떻게 전달할지

Physical
= 실제 신호와 매체
```

정식 용어로는 OSI 7 Layer나 TCP/IP Model 같은 계층 모델로 표현한다.

데이터는 송신 측에서 계층별 정보를 붙여 내려가고, 목적지에서 반대로 풀어 올라간다.

```text
응용 데이터
  ↓
TCP / UDP
  ↓
IP
  ↓
Ethernet / WLAN
  ↓
물리 매체
```

세부 Header나 Encapsulation 형식은 하위 지도와 세부학습에서 본다.

## 3. 같은 망과 다른 망을 구분한다

먼저 같은 망 안에서의 전달과 다른 망으로 나가는 전달을 구분한다.

```text
같은 망 안
MAC Address
  ↓
Switch
  ↓
필요하면 VLAN으로 영역 분리

다른 망으로 이동
IP Address / Subnet
  ↓
Default Gateway
  ↓
Router
  ↓
Routing
```

핵심은 다음 정도만 먼저 잡는다.

```text
MAC
= 같은 L2 영역 안에서 전달할 때 쓰는 주소

IP
= 다른 Network까지 포함해 목적지를 식별하는 주소

Gateway
= 다른 Network로 나갈 때 처음 거치는 Router

Routing
= 목적지 Network까지 갈 경로를 정하는 것
```

→ [[01-통신-주소-경로]]

## 4. 주소와 경로를 더 자세히 보면

`01-통신-주소-경로`에서는 다음 관계를 더 자세히 본다.

```text
IP 주소
├─ IPv4 / IPv6
├─ Subnet
├─ CIDR / VLSM
├─ DHCP
└─ NAT / PAT

Routing
├─ Static / Dynamic
├─ AS 내부 → RIP / OSPF
└─ AS 간   → BGP
```

전체 지도에서는 이 용어들의 세부 차이보다 **주소를 나누고, 설정을 받고, 다른 망까지 경로를 찾는 하나의 묶음**이라는 위치만 잡는다.

## 5. Host까지 도착한 뒤에는 Process 전달 문제가 남는다

IP는 목적지 Host까지 Packet을 보내는 데 초점이 있다. 하지만 실제 Application은 Host 안의 특정 Process로 데이터를 받아야 한다.

```text
목적지 Host 도착
  ↓
어느 Process로 보낼까?
  ↓
Port
  ↓
TCP / UDP
```

TCP와 UDP는 전달 특성이 다르다.

```text
TCP
= 연결 상태와 신뢰성 있는 전달이 필요할 때

UDP
= 연결 상태 없이 가볍게 Datagram을 보낼 때
```

Application이 이 통신 기능을 실제로 사용하는 경계에는 Socket API가 있다.

```text
Application
  ↓
Socket API
  ↓
TCP / UDP
  ↓
Kernel Network Stack
```

서버가 `bind → listen → accept`로 연결을 기다리는 흐름과 Blocking / Non-blocking, I/O Multiplexing은 별도 횡단 지도에서 본다.

→ [[05-Socket-서버-IO]]

TCP를 더 깊게 보면 다음 문제가 이어진다.

```text
데이터가 제대로 갔는가?
→ 오류 제어

수신자가 감당하는가?
→ 흐름 제어

중간 Network가 감당하는가?
→ 혼잡 제어
```

→ [[02-전송-품질-운영]]

## 6. 여러 사용자가 Network를 같이 쓰면 품질 문제가 생긴다

```text
Traffic 증가
  ↓
Queue 증가
  ↓
Delay / Jitter / Loss 증가
  ↓
Traffic마다 중요도와 요구 특성이 다름
  ↓
QoS
```

QoS는 Network 자원이 부족한 상황에서 Traffic별로 우선순위와 처리 방식을 조정하는 관점이다.

사용자가 실제로 느끼는 품질은 QoE로 본다.

```text
Network에서 측정하는 품질
→ QoS

사용자가 실제로 느끼는 품질
→ QoE
```

그리고 품질을 운영하려면 상태를 계속 관측해야 한다.

```text
Network 상태
  ↓
Metric / Event 수집
  ↓
NMS
  └─ SNMP 등으로 장비와 정보 교환
```

## 7. 기본 전달 흐름과 별도로 붙는 학습 가지

다음 주제들은 `L2 → L3 → L4` 뒤에 순서대로 붙는 다음 단계가 아니다. 환경이나 목적이 달라지면서 추가되는 별도 축이다.

```text
[무선·이동]
무선을 여러 단말이 공유
  ↓
충돌을 피해야 함
  ↓
CSMA/CA
  ↓
WLAN
  ↓
이동하면서 연결 유지
  ↓
Roaming / Handover
```

→ [[03-무선-이동]]

```text
[서비스 전달]
HTTP / RTP · RTCP / CDN / VPN

[운영 자동화]
장비별 수동 설정의 한계
  ↓
SDN

[기능 가상화]
전용 Network 장비 의존
  ↓
NFV

[제약 환경]
저전력 · 저성능 · 대규모 단말
  ↓
Sensor Network / IoT
```

→ [[04-서비스-가상화-제약환경]]

## 8. 큰 학습 가지

```text
네트워크 전체
├─ [[01-통신-주소-경로]]
│   └─ 같은 망 / 다른 망 → MAC / IP → Gateway → Routing
│
├─ [[02-전송-품질-운영]]
│   └─ Process 전달 → TCP/UDP → 오류·흐름·혼잡 → QoS/QoE → 운영
│
├─ [[03-무선-이동]]
│   └─ 공유 무선 매체 → WLAN → 이동성
│
├─ [[04-서비스-가상화-제약환경]]
│   └─ 서비스 전달 / VPN / SDN / NFV / IoT
│
└─ [[05-Socket-서버-IO]]
    └─ Network ↔ OS ↔ Application 경계 → Socket → Server I/O
```

`05-Socket-서버-IO`는 시험 대분류를 추가한 것이 아니라, 네트워크와 운영체제·서버 Application 사이의 실제 연결 구조를 이해하기 위한 횡단 Zoom 지도다.

하위 지도에서는 여기서 본 문제를 정식 용어와 더 정확한 관계로 다시 펼친다.

## 9. 이 지도를 보는 순서

```text
먼저 큰 질문을 이해
  ↓
관련된 정식 용어 확인
  ↓
필요한 하위 지도 선택
  ↓
개념 사이의 차이와 경계 확인
  ↓
세부학습에서 원리·동작을 깊게 이해
  ↓
다시 전체 지도에서 위치 확인
```

전체 지도에서 모든 Protocol·Algorithm·Header·Timer를 이해하려 하지 않는다. **여기서는 어디에 무엇이 있고, 어떤 문제를 해결하는지만 잡으면 된다.**
