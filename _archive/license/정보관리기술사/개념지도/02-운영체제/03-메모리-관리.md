# 운영체제 메모리 관리 개념지도

이 지도는 [[00-전체|운영체제 전체 개념지도]]에서 **여러 Process에 Memory를 배치하고, 독립 주소 공간을 제공하며, 물리 Memory보다 유연한 실행환경을 만드는 관계**를 함께 본다.

메모리에서는 `배치`, `주소 공간`, `속도`라는 서로 다른 문제를 섞지 않는 것이 중요하다. 컴퓨터 구조의 [[../01-컴퓨터-구조/02-메모리-계층-가상메모리|메모리 계층과 가상 메모리]]와 겹치는 개념은 운영체제 관점의 자원관리·격리에 초점을 둔다.

## 1. 먼저 세 가지 문제를 구분한다

```text
Memory 관리
│
├─ [배치]
│   Process를 Physical Memory 어디에 둘까?
│   └─ 연속 할당 → Paging / Segmentation
│
├─ [주소 공간]
│   Process마다 독립된 Memory 공간을 어떻게 제공할까?
│   └─ Virtual Memory
│       └─ Demand Paging / Page Fault / Replacement
│
└─ [속도]
    CPU보다 RAM이 느린 문제를 어떻게 줄일까?
    └─ Cache
```

```text
Paging ≠ Virtual Memory ≠ Cache
```

세 개념은 함께 등장하지만 중심 목적이 다르다.

## 2. 처음에는 Process를 연속된 공간에 배치할 수 있다

```text
Physical Memory
┌──────────────┐
│ OS           │
├──────────────┤
│ Process A    │
├──────────────┤
│ Process B    │
├──────────────┤
│ Free         │
└──────────────┘
```

연속 할당은 직관적이지만 Process의 크기와 빈 공간의 모양 때문에 단편화와 배치 제약이 생긴다.

```text
연속 할당
├─ 고정 분할
│   └─ 내부 단편화 가능
└─ 가변 분할
    └─ 외부 단편화 가능
```

First Fit·Best Fit·Worst Fit의 반복 계산보다 **연속된 빈 공간을 찾아야 한다는 구조 자체가 외부 단편화와 배치 제약을 만든다**는 점을 먼저 기억한다.

## 3. 꼭 연속된 공간에 넣을 필요가 있는가?

```text
연속된 큰 공간이 필요
        ↓
외부 단편화 / 배치 제약
        ↓
Physical Memory에 흩어 배치하고 싶음
        ↓
불연속 할당
├─ Paging
└─ Segmentation
```

Paging과 Segmentation은 같은 방식이 아니다.

```text
Paging
= 고정 크기 Page / Frame 단위로 배치

Segmentation
= Code·Data·Stack 같은 논리 단위를 가변 크기 Segment로 배치
```

복습할 비교축은 다음이다.

```text
Paging ↔ Segmentation
├─ 분할 기준: 고정 크기 ↔ 논리 단위 가변 크기
├─ 배치와 관리 단위
├─ 내부 / 외부 단편화
└─ 보호·공유의 표현 방식
```

## 4. Paging은 Page와 Frame을 Mapping한다

```text
Process Address Space
Page 0
Page 1
Page 2
        ↓ Page Table
Physical Memory
Frame 4
Frame 1
Frame 7
```

Paging의 핵심 Node는 다음이다.

```text
Page
= Process 주소 공간의 고정 크기 단위

Frame
= Physical Memory의 같은 크기 단위

Page Table
= Page가 어느 Frame에 있는지 관리하는 Mapping 정보
```

Paging은 외부 단편화를 제거하지만 마지막 Page의 남는 공간 같은 내부 단편화와 주소 변환 비용은 남을 수 있다.

## 5. Process가 보는 주소와 실제 물리 위치를 분리한다

운영체제는 Process마다 독립적인 주소 공간을 제공하고 실제 Physical Memory 배치를 숨긴다.

```text
Process가 보는 Virtual Address
        ↓
주소 변환
        ↓
Physical Address
```

```text
Virtual Memory
├─ Process별 독립 주소 공간
├─ 보호·격리
├─ Physical Memory 배치와 주소 공간 분리
└─ 물리 Memory보다 유연한 실행환경 제공
```

주소 변환에는 Hardware 지원이 연결된다.

```text
Virtual Address
  ↓
Page Table
  ↓
MMU
  ↓
Physical Address

최근 변환 결과
  ↕
TLB
```

MMU·TLB의 Hardware 구조 자체는 컴퓨터 구조 영역과 직접 연결된다.

## 6. 모든 Page를 항상 RAM에 둘 필요가 있는가?

```text
Page 단위로 주소와 물리 위치를 Mapping 가능
        ↓
모든 Page를 동시에 RAM에 둘 필요가 있는가?
        ↓
Demand Paging
        ↓
필요한 Page를 실제 접근 시 적재
```

필요한 Page가 RAM에 없으면 Page Fault가 발생한다.

```text
Page 접근
  ↓
RAM에 존재?
├─ Yes → 계속 실행
└─ No  → Page Fault
          ↓
        필요한 Page 적재
          ↓
        실행 재개
```

Page Fault는 Virtual Memory의 정상 동작 과정에서 발생할 수 있는 사건이다. 하지만 Storage I/O가 필요하므로 비용이 크다.

## 7. 빈 Frame이 부족하면 Page Replacement가 필요하다

```text
Page Fault
  ↓
빈 Frame 없음
  ↓
어떤 Page를 내보낼까?
  ↓
Page Replacement
```

Replacement Algorithm의 세부 계산보다 이 지도에서는 **Frame이라는 한정 자원을 어떤 Page에 배분할 것인가**라는 위치를 잡는다.

```text
Page Replacement
= 필요한 Page를 적재할 Frame이 부족할 때 교체 대상을 선택하는 정책
```

## 8. Page Fault가 지나치게 많아지면 Thrashing이 된다

```text
Process가 필요한 Page 집합에 비해 Frame 부족
        ↓
Page Fault 증가
        ↓
Page In / Out 반복
        ↓
CPU가 실제 작업보다 Paging I/O를 기다리는 시간이 증가
        ↓
Thrashing
```

Thrashing은 단순히 Page Fault 한 번이 발생한 상태가 아니다. **Page Fault와 교체가 과도하게 반복되어 시스템 처리 성능이 크게 떨어지는 상태**다.

완화 관점은 다음 위치로 잡는다.

```text
Thrashing 완화
├─ Working Set 관찰
├─ Frame 조정
└─ 동시에 실행하는 Workload / Process 수 조절
```

## 9. Cache는 같은 Memory 주제지만 해결하는 문제가 다르다

```text
CPU가 RAM보다 빠름
        ↓
Memory 접근 대기
        ↓
Locality 활용
        ↓
Cache
```

```text
Cache
= 자주 다시 사용할 Data를 빠른 계층에 두어 접근시간을 줄임

Virtual Memory
= Process 주소 공간과 Physical Memory를 분리해 보호·격리·용량 활용을 제공
```

Cache의 Write-through / Write-back과 Cache Coherence·MESI·Directory는 운영체제 학습등급표에도 있지만, Hardware 동작 원리는 컴퓨터 구조와 강하게 겹친다. 운영체제에서는 **공유 자원 성능과 일관성 문제의 연결점**으로 위치를 잡는다.

## 10. 전체 문제 해결 흐름

```text
Process를 Memory에 배치
        ↓
연속 할당
        ↓ 외부 단편화·연속 공간 제약
불연속 할당
├─ Paging
└─ Segmentation
        ↓
주소와 실제 물리 위치를 Mapping
        ↓
Virtual Memory
        ↓
Demand Paging
        ↓
Page Fault
        ↓ Frame 부족
Page Replacement
        ↓ 과도한 Fault
Thrashing
```

이 흐름 옆에 별도 속도 축이 붙는다.

```text
CPU-RAM 속도 격차
→ Cache
→ Write Policy / Cache Coherence와 연결
```

## 11. 복습용 핵심 좌표

```text
[배치]
연속 할당
├─ 내부 / 외부 단편화
└─ 불연속 할당
    ├─ Paging
    │   ├─ Page / Frame
    │   └─ Page Table
    └─ Segmentation

[주소 공간]
Virtual Memory
├─ Virtual ↔ Physical Address
├─ MMU / TLB
└─ Demand Paging
    ├─ Page Fault
    ├─ Page Replacement
    └─ Thrashing
        └─ Working Set / Frame / 부하 조절

[속도]
Cache
├─ Write Policy
└─ Cache Coherence → MESI / Directory
```

이 Node를 보고 `Paging과 Virtual Memory가 왜 다른가`, `Page Fault가 왜 발생하는가`, `Thrashing은 왜 생기는가`, `Cache는 왜 별도 축인가`를 설명할 수 있으면 된다. Page Replacement 손계산과 Cache 상태 전이 상세는 세부학습으로 내려간다.
