# 분산 · 확장 개념지도

> 단일 DB의 용량·처리량·가용성 한계를 넘을 때 **데이터를 복제하거나 나누면서 새로 생기는 일관성 문제**를 보는 지도다.

```text
단일 DB의 한계
├─ 저장 용량
├─ 처리량
└─ 가용성
      ↓
분산을 검토
├─ Replication
│   └─ 같은 데이터를 복제
│      → 가용성 · 읽기 확장
├─ Sharding
│   └─ 데이터를 분할
│      → 저장 · 처리 부하 분산
└─ 분산 DB
    └─ 여러 Node를 하나의 데이터 시스템으로 운영
          ↓
       새로 커지는 문제
       ├─ 일관성
       ├─ 네트워크 분할
       ├─ 장애 처리
       └─ 분산 Transaction
```

## 핵심 Trade-off

```text
분산
├─ 확장성 ↑
├─ 가용성 ↑ 가능
└─ 운영 복잡성 ↑
      ↓
CAP
= Consistency · Availability · Partition Tolerance의 관계
```

`Replication`은 복제, `Sharding`은 분할이다. 둘은 함께 사용할 수도 있지만 해결하려는 중심 문제가 다르다.
