# 정보관리기술사 개념지도 공통 원칙

> 지식을 묶고 나누는 상위 기준은 [`docs/KNOWLEDGE_ORGANIZATION.md`](../../../../docs/KNOWLEDGE_ORGANIZATION.md), 문체·용어·표기는 [`docs/WRITING_STYLE.md`](../../../../docs/WRITING_STYLE.md)를 따른다.

개념지도는 **학습할 개념의 위치와 관계를 연결해, 큰 그림에서 필요한 개념으로 파고들고 나중에는 핵심 Node를 보고 세부 이해를 다시 떠올릴 수 있게 만드는 탐색·복습 지도**다.

학습 대상과 A/B/C 우선순위는 `../학습등급표/`에서 정하고, 상세한 동작 원리와 이해 기록은 `../세부학습/`에서 다룬다.

## 1. 자료별 역할

```text
교재 · 기출 · 공식 출제기준
        ↓
학습등급표
= 무엇을 얼마나 우선해서 공부할 것인가
        ↓
개념지도
= 개념이 어디에 있고 무엇과 연결되는가
  + 복습할 때 무엇을 떠올려야 하는가
        ↓
세부학습
= 선택한 개념을 왜 필요한지부터 깊게 이해
```

개념지도는 교재 목차를 다시 나열하거나 세부학습을 압축한 요약본이 아니다.

## 2. 함께 보면 이해가 좋아지는 관계를 지도 단위로 묶는다

상위 공통 지식 구성 원칙에 따라, 개념 수나 복잡성보다 **함께 보았을 때 위치·차이·경계·의존성이 더 잘 이해되는가**를 우선한다.

```text
개념지도에서 자주 쓰는 관계
├─ 계층형   : 상위 → 하위
├─ 비교형   : A ↔ B ↔ C
├─ 경계형   : 비슷해 보이는 개념의 역할·범위 구분
├─ 의존형   : 선행 → 다음 개념
├─ 스토리형 : 문제 → 해결 → 한계 → 확장
└─ 조합형   : 여러 개념이 실제 시스템에서 합류
```

스토리는 관계 표현 방식 중 하나일 뿐이다. **스토리를 만들기 위해 관계를 왜곡하지 않는다.**

## 3. 상위·하위·인접 관계를 우선한다

개념은 이름이 비슷하거나 교재 번호가 가깝다는 이유로 연결하지 않는다.

```text
상위 개념
  ↓
현재 개념
├─ 하위 개념 A
├─ 하위 개념 B
└─ 하위 개념 C

인접 개념
↔ 목적·방법·적용 조건 비교
```

예:

```text
Machine Learning
├─ 지도학습
│   ├─ 분류
│   └─ 회귀
├─ 비지도학습
│   ├─ 군집
│   └─ 차원축소
└─ 강화학습
    └─ MDP → Q-Learning → DQN
```

`지도학습 → 비지도학습 → 강화학습`은 발전 순서가 아니다. 반면 `MDP → Q-Learning → DQN`처럼 실제 학습 의존성이 있으면 흐름으로 연결할 수 있다.

## 4. 실제 인과가 있으면 짧은 `왜`를 남긴다

실제 문제·해결·한계 관계가 있다면 다음 개념이 왜 등장하는지 읽히게 한다.

```text
문제
 ↓
개념 A
 ↓ 새 한계
개념 B
```

예:

```text
RNN
 ↓ 장기 의존성 학습이 어려움
LSTM / GRU
```

반대로 실제 인과가 없는 병렬 개념은 분기·비교·분류로 표현한다.

> **관계가 있다면 그 관계가 읽혀야 하지만, 모든 관계를 한 줄의 스토리로 만들 필요는 없다.**

## 5. 분류축을 섞지 않는다

서로 다른 기준의 개념을 한 줄의 발전 단계처럼 배치하지 않는다.

```text
[학습 방식]
지도 / 비지도 / 강화

[Architecture]
CNN / RNN / Transformer

[생성 방식]
Autoregressive / GAN / Diffusion

[활용 방식]
Prompt / RAG / Fine-tuning / Agent
```

```text
CNN → RNN → GAN → Transformer   X
```

서로 다른 축이 실제 시스템에서 조합된다면 그 조합 관계를 별도로 보여준다.

## 6. 개념지도 Node와 세부학습 File은 1:1이 아니다

```text
RAG
└─ Vector Search
    └─ ANN
        ├─ HNSW
        └─ IVF
```

각 Node는 파고들 개념 꼭지지만, 세부학습에서는 하나의 이해 흐름이면 여러 Node를 한 문서에서 함께 다룰 수 있다.

> **개념지도 Node = 파고들 개념 꼭지 + 복습할 때 세부 이해를 꺼내는 인출 단서**
>
> **세부학습 File = 함께 이해할 때 좋은 학습 단위**

## 7. 적정 깊이

개념지도는 목차보다 깊고 세부학습보다 얕다.

적극적으로 남긴다.

- 학습할 가치가 있는 핵심 용어
- 세부학습의 주요 내용을 떠올리게 하는 핵심 Node·Keyword
- 상위·하위·인접 관계
- 비교·대안·경계
- 직접 의존 관계
- 다음 개념을 선택하는 데 필요한 짧은 이유·조건
- 여러 개념이 실제 시스템에서 합류하는 핵심 관계

세부학습으로 내린다.

- 수식 전개
- 내부 Algorithm 상세 단계
- Parameter별 동작
- 긴 예제
- 구현 Code
- 제품별 설정
- 핵심 Node를 보고 연상할 수 있는 상세 설명 자체

예를 들어 Routing 지도에는 `Longest Prefix Match`, `Distance Vector`, `Link State`, `RIP`, `OSPF`, `BGP`처럼 세부 이해를 다시 꺼내는 핵심 좌표를 남길 수 있다. 반면 RIP Timer 값, Dijkstra 계산 과정, BGP Message Format은 세부학습으로 내린다.

## 8. 하위 개념지도는 고정 단계가 아니라 필요한 Zoom 단위다

전체 지도 아래에 하위 지도를 기계적으로 만들지 않는다.

```text
전체 지도
  ↓
연관 개념을 한 번 더 함께 보면 이해가 좋아지는가?
  ├─ Yes → 하위 개념지도
  │          ↓
  │        세부학습
  └─ No  → 세부학습으로 직접
```

하위 개념지도는 개념이 많거나 복잡해야만 만드는 것이 아니다. **몇 개의 개념이라도 함께 보았을 때 위치·차이·경계가 더 잘 이해된다면 하나의 Zoom 단위가 될 수 있다.**

반대로 다음 이유만으로는 만들지 않는다.

- 파일이 길다.
- Keyword가 많다.
- 교재 Chapter가 나뉘어 있다.
- 개별 Keyword마다 파일을 만들고 싶다.
- 상위 지도와 거의 같은 내용을 반복한다.

> **파일 수를 늘리는 것이 목적이 아니라 필요한 곳에서만 탐색 밀도를 높이는 것이 목적이다.**

## 9. 영역 전체 지도와 하위 지도의 역할을 구분한다

```text
영역 전체 개념지도
= 어느 학습 가지로 들어갈지 선택
  + 큰 가지의 핵심 Keyword로 세부 내용을 연상
        ↓
필요한 하위 개념지도
= 연관 개념을 함께 보며 관계를 더 촘촘히 탐색
  + 세부학습을 복원할 인출 단서를 충분히 제공
        ↓
세부학습
= 원리·동작·차이·Trade-off를 깊게 이해
```

영역 전체 지도는 가능한 많은 하위 개념을 담는 문서가 아니다. 큰 가지의 위치와 관계를 잃지 않는 것이 우선이지만, **복습할 때 해당 가지에서 무엇을 배웠는지 떠올릴 핵심 좌표까지 지워서는 안 된다.**

## 10. 쉬운 큰 그림과 복습용 핵심 Node를 함께 유지한다

진입 난도를 낮추는 것과 핵심 용어를 제거하는 것은 다르다.

```text
쉬운 큰 질문
  ↓
정확한 핵심 개념명과 관계
  ↓
복습 때 세부 내용을 꺼내는 핵심 Node·Keyword
  ↓
필요한 하위 지도에서 관계를 더 촘촘히 Zoom-in
  ↓
세부학습의 원리·동작·예제
```

상위 지도는 처음 보는 학습자가 핵심 질문과 큰 관계를 잡을 수 있게 시작한다. 동시에 나중에 지도를 다시 열었을 때 세부학습의 주요 내용을 연상할 수 있도록 **핵심 개념명·비교축·분류·연결점은 충분히 남긴다.**

예:

```text
다른 Network까지 어떻게 찾아가지?
        ↓
Gateway / Router / Routing
        ├─ Routing ↔ Forwarding
        ├─ Longest Prefix Match
        ├─ Static / Dynamic
        └─ Dynamic
             ├─ AS 내부
             │   ├─ Distance Vector → RIP
             │   └─ Link State → OSPF
             └─ AS 간 → BGP
```

처음 학습할 때는 위에서 아래로 필요한 만큼 따라가고, 복습할 때는 `Longest Prefix Match`, `Distance Vector`, `Link State` 같은 Node를 보고 세부 원리와 차이를 머릿속에서 복원한다.

> **Zoom-in은 핵심 Node를 삭제하는 과정이 아니라, 설명의 상세도와 관계의 밀도를 단계적으로 높이는 과정이다.**

## 11. 처음 보는 핵심 용어 때문에 탐색이 끊기지 않게 한다

정확한 용어는 유지하되, 처음 보는 학습자가 다음 Node로 이동할 수 있을 정도의 짧은 설명을 제공한다.

- 핵심 약어는 필요할 때 처음 한 번 원어와 역할을 설명한다.
- 낯선 공식 용어는 지도를 읽는 데 필요한 최소한의 의미를 붙인다.
- 이미 충분히 익숙한 `CPU`, `RAM`, `API` 등을 기계적으로 풀어 쓰지 않는다.

개념지도에서 용어 하나를 이해하기 위해 계속 다른 검색이 필요하면 탐색 지도로서의 역할이 약해진다.

## 12. Text/ASCII Diagram을 기본으로 한다

모바일 GitHub, Obsidian, Terminal 등 어디서든 읽을 수 있도록 Text/ASCII Diagram을 기본으로 한다.

```text
상위
├─ 현재 A
│   ├─ 하위 A-1
│   └─ 하위 A-2
└─ 인접 B
```

분기·합류가 복잡해 Mermaid가 명확한 이점을 줄 때만 선택적으로 사용한다. 비교가 핵심이면 Markdown 표를 우선할 수 있다.

## 13. 학습등급표에서 출발하되 그대로 복사하지 않는다

```text
학습등급표 Topic
 ↓
상위 개념 확인
 ↓
하위·인접 개념 확장
 ↓
실제 관계 확인
 ↓
개념지도에 재배치
```

학습등급표의 A/B/C는 **정보관리기술사 학습에서 개별 Topic에 투입할 깊이와 우선순위**를 정하는 기준이다. 개념지도 포함 여부를 정하는 등급이 아니다.

따라서 다음을 구분한다.

```text
학습등급표
= 개별 Topic의 학습 우선순위와 깊이

개념지도
= 정보관리기술사 관점에서 필요한 큰 개념군·관계·학습 경로
```

- B/C Topic이 지도에 직접 나타나지 않는다는 이유만으로 누락으로 판단하지 않는다.
- 반대로 등급이 낮거나 학습등급표에 없는 개념이라도 큰 그림을 연결하는 데 필요하면 Node로 포함할 수 있다.
- 개념지도 누락 여부는 `학습등급표 Topic의 개별 커버리지`보다 **정보관리기술사 관점에서 필요한 큰 개념군과 관계가 빠졌는가**를 우선해 판단한다.
- 학습등급표의 출발 자료가 여러 시험을 함께 다루는 겸용 교재라면, 교재의 Chapter·Part·개념군 자체를 개념지도의 필수 범위로 간주하지 않는다. 학습등급표에서 정보관리기술사 관점으로 보정된 범위와 실제 큰 그림을 기준으로 다시 구성한다.

### 기출됐다는 이유만으로 지도에 올리지 않는다

기출 여부는 중요도를 판단하는 근거지만, **한 번 출제됐다는 사실만으로 개념지도 Node가 되어야 하는 것은 아니다.** 지엽적인 단독 Topic을 기출마다 추가하면 개념지도는 큰 그림을 잃고 기출 목록에 가까워진다.

```text
기출 Topic
  ↓
정보관리기술사에서 반복·핵심성이 있는가?
  ├─ Yes → 핵심 Node 후보
  └─ No
      ↓
다른 핵심 개념의 위치·관계를 이해하는 데 필요한가?
      ├─ Yes → 연결 Node 후보
      └─ No  → 학습등급표 또는 세부학습에서 관리
```

따라서 개념지도 포함 여부는 **출제 여부 자체보다 반복·핵심성, 큰 그림 기여도, 다른 핵심 개념과의 관계**를 함께 보고 판단한다. 단발성·세부 구현·특정 규격처럼 지엽성이 큰 Topic은 실제 기출됐더라도 큰 그림에 기여하지 않으면 지도에서 생략할 수 있다.

학습등급표에 없더라도 주요 Topic 사이를 이해하는 데 꼭 필요한 연결 개념은 지도에 추가할 수 있다. 시험 중요도와 우선순위 판단은 다시 학습등급표에서 한다.

## 14. 세부학습과 왕복하며 지도를 보정한다

개념지도는 처음부터 완성된 정답 구조가 아니다.

```text
개념지도에서 위치·관계 파악
        ↓
세부학습에서 원리·동작 이해
        ↓
새로운 관계·경계·의존성 발견
        ↓
개념지도 보정
        ↓
새로운 인접 개념 탐색
```

세부학습에서 기존 분류가 부정확하거나 새로운 연결을 발견하면 상위 지도도 다시 수정한다. 이때 세부학습에서 반복해서 중요하게 등장한 개념이 복습용 인출 단서로 가치가 있다면 지도 Node로 보강할 수 있다.

## 15. Obsidian 내부 링크는 실제 학습 경로에만 둔다

개념지도에서 실제로 세부학습으로 이동할 가치가 있는 지점에만 `[[...]]` 링크를 둔다.

- 존재하지 않는 세부학습 파일을 가정해 링크하지 않는다.
- 단순 관련성만으로 모든 Node에 링크를 붙이지 않는다.
- 하나의 세부학습 문서가 여러 Node를 함께 다루면 필요한 위치에서 같은 문서로 연결할 수 있다.

## 16. 작성 후 확인

```text
[ ] 교재 목차를 그대로 옮긴 것은 아닌가?
[ ] 학습등급표의 B/C Topic이 없다는 이유만으로 기계적으로 추가하지 않았는가?
[ ] 정보관리기술사 관점에서 필요한 큰 개념군이나 관계가 빠지지는 않았는가?
[ ] 겸용 교재의 Chapter·Part 자체를 필수 학습 가지로 간주하지 않았는가?
[ ] 기출됐다는 이유만으로 지엽적인 Topic을 지도에 올리지 않았는가?
[ ] 포함한 기출 Topic이 반복·핵심성 또는 큰 그림의 연결 역할을 갖는가?
[ ] 함께 보면 이해가 좋아지는 개념이 적절히 묶였는가?
[ ] 실제 인과가 없는 개념을 억지 스토리로 만들지 않았는가?
[ ] 서로 다른 분류축을 한 줄에 섞지 않았는가?
[ ] 상위·하위·인접·비교·경계가 읽히는가?
[ ] 처음 학습할 때 큰 그림에서 진입할 수 있는가?
[ ] 복습할 때 핵심 Node를 보고 세부학습의 주요 내용을 연상할 수 있는가?
[ ] 진입 난도를 낮춘다는 이유로 중요한 핵심 Keyword를 지우지 않았는가?
[ ] 다음 학습 대상으로 이동하는 데 필요한 최소한의 이유가 있는가?
[ ] 세부 Algorithm·수식·예제가 과도하게 들어오지 않았는가?
[ ] 하위 지도가 실제로 이해에 도움을 주는 Zoom 단위인가?
[ ] 세부학습에서 새롭게 발견한 관계가 상위 지도에 반영됐는가?
```

## 17. 한 문장 원칙
