# 정보관리기술사 개념지도 공통 원칙

개념지도는 **학습할 개념을 상위·하위·인접 관계로 연결해, 하나의 개념에서 주변으로 파고들 수 있게 만드는 탐색 지도**다.

학습 대상과 A/B/C 우선순위는 `../학습등급표/`에서 정하고, 각 개념의 상세한 동작 원리와 이해 기록은 `../세부학습/`에서 다룬다.

## 1. 자료별 역할

```text
교재 · 기출 · 공식 출제기준
        ↓
학습등급표
= 무엇을 얼마나 우선해서 공부할 것인가
        ↓
개념지도
= 어떤 개념을 주변으로 어떻게 파고들 것인가
        ↓
세부학습
= 선택한 개념을 왜 필요한지부터 깊게 이해
```

| 자료 | 핵심 질문 |
|---|---|
| 학습등급표 | 무엇을 공부하고 어느 정도 깊이까지 볼 것인가? |
| 개념지도 | 이 개념의 상위·하위·인접 개념은 무엇이며 다음에 무엇을 파야 하는가? |
| 세부학습 | 왜 필요한가, 어떻게 동작하는가, 무엇과 다른가? |

## 2. 개념지도의 목적

개념지도는 교재 목차를 다시 나열하는 문서가 아니다. 다음 질문에 답할 수 있어야 한다.

1. 이 개념의 상위 개념은 무엇인가?
2. 바로 아래에서 파고들 핵심 꼭지는 무엇인가?
3. 같은 수준에서 비교하거나 함께 봐야 할 인접 개념은 무엇인가?
4. 실제로 직접 의존하는 흐름은 무엇인가?
5. 서로 다른 분류축의 개념을 잘못 한 줄에 놓고 있지는 않은가?
6. 현재 개념에서 다음 학습 대상으로 어디로 이동할 수 있는가?
7. 왜 그 다음 개념으로 이동해야 하는가?

## 3. 개념 Node와 세부학습 File은 1:1이 아니다

개념지도에 존재하는 모든 Node를 별도 파일로 만들 필요는 없다.

```text
RAG
└─ Vector Search
    └─ ANN
        ├─ HNSW
        └─ IVF
```

위 개념들은 개념지도에서 각각 학습 꼭지로 보이더라도, 실제 세부학습에서는 `임베딩-벡터검색-RAG.md` 하나 안에서 함께 다룰 수 있다.

> **개념지도 Node = 파고들 개념 꼭지**
>
> **세부학습 File = 한 번에 이해하기 좋은 개념 흐름 단위**

## 4. 상위 · 하위 · 인접 관계를 우선한다

개념은 이름이 비슷하거나 교재 번호가 가깝다는 이유로 연결하지 않는다.

```text
상위 개념
  ↓
현재 개념
├─ 하위 개념 A
├─ 하위 개념 B
└─ 하위 개념 C

인접 개념
↔ 목적·방법·적용 조건을 비교
```

예:

```text
Machine Learning
├─ 지도학습
│   ├─ 분류
│   └─ 회귀
├─ 비지도학습
│   ├─ 군집
│   └─ 차원축소
└─ 강화학습
    └─ MDP → Q-Learning → DQN
```

여기서 `지도학습 → 비지도학습 → 강화학습`은 발전 순서가 아니다. 반면 `MDP → Q-Learning → DQN`은 실제 학습 의존 흐름으로 연결할 수 있다.

## 5. 직접 인과가 있으면 흐름을 살린다

개념 사이에 실제 문제·해결 관계가 있으면 그 이유가 보이도록 연결한다.

```text
문제
 ↓
개념 A로 해결
 ↓
새 한계 또는 다음 문제
 ↓
개념 B 필요
```

예:

```text
RNN
 ↓
긴 Sequence에서 장기 의존성 학습이 어려움
 ↓
LSTM / GRU
```

하지만 실제 인과가 없는 병렬 Algorithm을 억지로 발전 사슬로 만들지 않는다.

## 6. 탐색에 필요한 최소한의 이유와 선택 관계는 남긴다

개념지도는 단순 계층 Tree가 아니다. **왜 인접 개념으로 이동해야 하는지 판단하는 데 필요한 짧은 이유·조건·선택 관계**는 지도에 남긴다.

예:

```text
LLM 활용
├─ 규칙·역할 지정       → System Prompt
├─ 몇 개 예제로 유도    → Few-shot
├─ 최신·사내 지식 필요  → RAG
├─ 반복 행동 자체 조정   → Fine-tuning
└─ 외부 세계에서 행동    → Tool / Agent
```

또는:

```text
RNN
 ↓ 장기 의존성 문제
LSTM / GRU
```

이 정도의 이유는 세부 설명이 아니라 **다음 학습 꼭지를 선택하기 위한 탐색 정보**다.

반면 내부 Algorithm의 상세 단계, 수식, Parameter별 동작은 세부학습으로 내린다.

## 7. 분류축을 섞지 않는다

개념지도에서 가장 조심할 오류다.

```text
[학습 방식]
지도 / 비지도 / 강화

[Architecture]
CNN / RNN / Transformer

[생성 방식]
Autoregressive / GAN / Diffusion

[활용 방식]
Prompt / RAG / Fine-tuning / Agent
```

따라서 다음처럼 그리지 않는다.

```text
CNN → RNN → GAN → Transformer   X
```

필요하면 서로 다른 축이 실제 시스템에서 어떻게 조합되는지 별도로 연결한다.

## 8. 적정 깊이

개념지도는 목차보다 깊고 세부학습보다 얕다.

다음 수준까지는 적극적으로 남긴다.

- 학습할 가치가 있는 핵심 용어
- 상위·하위·인접 개념
- 직접 의존 관계
- 대표 비교 대상
- 다음에 파고들 Algorithm·Architecture·Protocol
- 다음 개념으로 이동하는 데 필요한 짧은 이유·조건
- 여러 개념이 실제 시스템에서 합류하는 핵심 관계

반면 다음은 세부학습으로 내린다.

- 수식 전개
- 내부 Algorithm 단계의 상세
- Parameter별 동작
- 긴 예제
- 구현 Code
- 제품별 설정

예를 들어 `RAG → Vector Search → ANN → HNSW / IVF`는 개념지도에 남기지만, HNSW의 Graph 탐색 Algorithm 상세는 세부학습에서 다룬다.

## 9. 개념지도가 커지면 얕게 만들기보다 계층화한다

한 영역의 개념지도가 커져 **전체 관계를 한 번에 파악하기 어려워지면 중요한 학습 꼭지를 삭제하거나 지나치게 얕게 만들기보다 하위 개념지도로 분리**한다.

```text
영역 전체 개념지도
        ↓
독립적인 큰 학습 가지
        ↓
하위 개념지도
        ↓
세부학습
```

예:

```text
09-인공지능/
├─ 00-전체.md
├─ 01-ML-DL.md
└─ 02-생성형AI-LLM.md
```

분리 기준:

- 하나의 가지가 독립적으로 여러 학습 꼭지를 가진다.
- 전체 지도에서 그 가지의 세부를 펼치면 다른 영역의 좌표를 파악하기 어려워진다.
- 하위 지도 하나만 읽어도 해당 영역의 상위·하위·인접 관계를 탐색할 수 있다.

분리하지 않는 경우:

- 단지 파일이 길다는 이유만으로 나눈다.
- 개별 키워드마다 지도를 만든다.
- 상위 지도와 하위 지도가 거의 같은 내용을 반복한다.

> **파일 수를 늘리는 것이 목적이 아니다. 전체 좌표를 잃지 않으면서 탐색 밀도를 유지하는 것이 목적이다.**

## 10. Text/ASCII Diagram을 기본으로 한다

모바일 GitHub, Obsidian, Terminal 등 어디서든 읽을 수 있도록 Text/ASCII Diagram을 기본으로 한다.

```text
상위
├─ 현재 A
│   ├─ 하위 A-1
│   └─ 하위 A-2
└─ 인접 B
```

짧고 단순한 `문제 → 원리 → 해결 → Trade-off` 흐름은 Text/ASCII를 유지한다.

분기·합류·계층·다수 개념 간 관계처럼 시각화 이점이 큰 경우에만 Mermaid로 전환할 수 있다. Mermaid가 오히려 복잡하거나 화면만 크게 차지하면 Text/ASCII를 유지한다. 비교가 핵심이면 Mermaid보다 Markdown 표를 우선한다.

Mermaid는 구조 시각화에 사용하고, 문서 이동을 위한 Obsidian 내부 링크는 가능한 본문 `[[...]]` 링크로 분리한다.

## 11. 학습등급표에서 출발하되 그대로 복사하지 않는다

학습등급표는 학습할 Topic의 Source다.

```text
학습등급표 Topic
 ↓
상위 개념 확인
 ↓
하위·인접 개념 확장
 ↓
실제 의존 관계 확인
 ↓
개념지도에 재배치
```

교재의 Part 번호나 Topic 순서를 그대로 Tree로 옮기지 않는다. 학습 이해에 맞는 개념 관계로 재구성한다.

학습등급표에 없더라도 상위 개념을 이해하거나 주요 Topic 사이를 연결하는 데 꼭 필요한 개념은 개념지도에 추가할 수 있다. 이 경우 시험 중요도와 학습 우선순위 판단은 다시 학습등급표에서 한다.

## 12. 개념지도에서 세부학습으로 내려가는 기준

Node 하나를 선택했을 때 다음 질문을 깊게 설명해야 하면 세부학습으로 내려간다.

```text
왜 필요한가?
어떻게 동작하는가?
내부 구성은 무엇인가?
어떤 Trade-off가 있는가?
비슷한 개념과 정확히 무엇이 다른가?
```

단, 다음 개념을 선택하기 위해 필요한 짧은 `왜`는 개념지도에 남길 수 있다.

학습 중 새로운 하위·인접 개념을 발견하면 다시 개념지도에 연결한다.

```text
학습등급표
   ↓
개념지도
   ↓
세부학습
   ↓
새로운 연결 발견
   └────────→ 개념지도 보강
```

## 13. Obsidian 내부 링크는 실제 학습 경로에만 둔다

개념지도에서 세부학습으로 이동할 때는 Obsidian `[[...]]` 내부 링크를 사용한다.

링크 기준:

- 실제로 존재하는 세부학습 문서만 연결한다.
- 학습등급표의 A/B급 핵심 개념을 우선 연결한다.
- C급이나 단순 용어까지 기계적으로 링크하지 않는다.
- 링크를 만들기 위해 빈 문서나 Placeholder를 만들지 않는다.
- 같은 개념을 다루는 세부학습 문서가 여러 개면 해당 개념을 가장 직접적으로 설명하는 문서를 연결한다.
- 같은 문서로 이어지는 하위 용어가 여러 개면 각 용어마다 반복 링크하지 않고, Section 끝의 `세부학습:` 등 자연스러운 위치에 한 번 연결할 수 있다.
- 링크 때문에 문장의 가독성이 떨어지면 링크 수를 줄인다.
- 링크 작업만을 이유로 기존 개념지도 내용, A/B/C 등급, 개념 구조를 바꾸지 않는다.

파일명이 저장소 안에서 유일하면 짧은 `[[파일명|표시명]]`을 사용할 수 있다. 같은 파일명이 여러 위치에 존재해 대상이 모호하면 경로를 포함해 정확한 문서를 지정한다.
