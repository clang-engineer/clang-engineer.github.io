# 성능과 신뢰성 개념지도

이 문서는 [[00-전체|컴퓨터 구조 전체 개념지도]]에서 **성능과 신뢰성** 가지를 선택했을 때, `측정 → 병목 식별 → 개선 → 한계 → 신뢰성` 흐름으로 시스템을 평가하기 위한 지도다.

## 먼저 알아둘 용어

```text
CPI(Cycles Per Instruction)
= 명령 하나를 처리하는 데 필요한 평균 Clock Cycle 수

SPEC(Standard Performance Evaluation Corporation)
= 컴퓨터 시스템 성능을 비교하기 위한 대표 Benchmark를 만드는 단체와 그 Benchmark 계열

Amdahl 법칙
= 일부 구간만 개선할 때 전체 성능 향상에는 상한이 있음을 보여주는 법칙

MTBF(Mean Time Between Failures)
= 고장과 다음 고장 사이의 평균 시간

MTTR(Mean Time To Repair)
= 장애 발생 후 평균 복구 시간

Watchdog
= 시스템 응답을 감시하다 문제가 생기면 Reset이나 복구 동작을 유도하는 Mechanism
```

처음에는 `성능을 측정한다 → 병목을 찾는다 → 개선한다 → 전체 효과의 한계를 본다 → 장애와 복구까지 본다`는 흐름부터 잡으면 된다.

## 1. 전체 좌표

```text
시스템 평가
│
├─ 성능
│   ├─ 처리량(Throughput)
│   ├─ 응답시간(Response Time)
│   ├─ 이용률(Utilization)
│   ├─ CPI
│   └─ SPEC
│
├─ 병목과 개선 효과
│   └─ Amdahl 법칙
│
└─ 신뢰성·가용성
    ├─ MTBF
    ├─ MTTR
    └─ Watchdog
```

## 2. 먼저 무엇을 측정할 것인가

성능은 하나의 숫자로 표현되지 않는다.

```text
처리량
→ 단위 시간에 얼마나 많은 작업을 처리하는가

응답시간
→ 하나의 요청이 완료되기까지 얼마나 걸리는가

이용률
→ 자원이 얼마나 바쁘게 사용되는가

CPI
→ 명령 하나를 처리하는 데 필요한 평균 Clock Cycle 수
```

같은 시스템이라도 어떤 지표를 보느냐에 따라 평가가 달라질 수 있으므로 워크로드와 목표를 먼저 정해야 한다.

## 3. 병목을 찾고 개선한다

```text
워크로드 정의
        ↓
성능 지표 측정
        ↓
병목 구간 식별
        ↓
구조 개선
├─ 파이프라이닝 / 병렬처리
├─ 캐시 / 메모리 계층
├─ DMA
└─ RAID 등
        ↓
개선 효과 재측정
```

부분 최적화가 전체 시스템 성능 향상으로 그대로 이어지는 것은 아니다.

## 4. Amdahl 법칙: 개선 효과의 상한

```text
전체 작업
├─ 개선 가능한 부분
└─ 개선되지 않는 부분
        ↓
개선 가능한 부분만 계속 빨라져도
나머지 구간이 전체 성능을 제한
        ↓
Amdahl 법칙
```

따라서 병렬 자원이나 특정 장치 성능을 계속 높여도 전체 속도가 비례해서 증가하지 않는다.

Amdahl 법칙은 CPU 병렬성에서도 중요하지만, 더 넓게는 **부분 개선이 전체 시스템에 미치는 최대 효과를 판단하는 법칙**으로 본다.

## 5. SPEC과 Benchmark

SPEC은 대표적인 시스템 성능 Benchmark 계열이다.

개별 Clock이나 부품 사양만 비교하지 않고 실제 Workload에 가까운 Benchmark를 통해 시스템 수준의 성능을 비교한다는 위치를 이해한다.

```text
부품 사양
≠ 실제 시스템 성능 전체
        ↓
대표 Workload 실행
        ↓
Benchmark 결과 비교
```

기술사 관점에서는 세부 Benchmark 항목 암기보다 **무엇을 어떤 Workload로 측정했는가**를 먼저 본다.

## 6. 신뢰성과 가용성

성능이 높아도 장애가 잦거나 복구가 늦으면 서비스 품질은 떨어진다.

```text
MTBF
→ 고장과 고장 사이의 평균 시간

MTTR
→ 장애 발생 후 평균 복구 시간
```

```text
가용성을 높이려면
├─ 고장 빈도를 줄임 → MTBF 증가
└─ 복구 시간을 줄임 → MTTR 감소
```

따라서 성능과 신뢰성은 별개의 평가축이지만 실제 시스템 설계에서는 함께 판단한다.

## 7. Watchdog의 위치

Watchdog은 시스템이 정상적으로 동작하는지 감시하다가 정해진 시간 안에 응답이 없으면 Reset이나 복구 동작을 유도하는 Mechanism이다.

```text
시스템 동작
        ↓
정상 응답 여부 감시
        ↓
응답 없음 / Hang
        ↓
Watchdog Timeout
        ↓
Reset / 복구 동작
```

Watchdog은 장애 자체를 없애는 기술이 아니라 **장애를 탐지하고 복구를 빠르게 시작해 영향 시간을 줄이는 기술**로 본다.

## 8. 기억 흐름

```text
무엇을 개선할 것인가?
        ↓
처리량 / 응답시간 / 이용률 / CPI 측정
        ↓
병목 식별
        ↓
구조 개선
        ↓
Amdahl 법칙으로 전체 효과의 상한 확인
        ↓
Benchmark로 시스템 수준 평가
        ↓
MTBF / MTTR로 신뢰성·가용성 평가
        ↓
Watchdog 등으로 장애 영향 축소
```
