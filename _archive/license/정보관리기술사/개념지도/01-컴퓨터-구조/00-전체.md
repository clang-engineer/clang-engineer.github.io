# 컴퓨터 구조 개념지도

컴퓨터 구조는 **프로그램의 명령과 데이터가 실제 하드웨어에서 어떻게 처리되고, 하드웨어의 속도·용량 한계를 어떤 구조로 완화하는가**를 보는 영역이다.

이 지도는 교재 순서보다 `명령 실행 → 병렬성 → 메모리 계층 → I/O → 성능·신뢰성`의 관계를 중심으로 탐색한다. 학습 우선순위와 깊이는 `../../학습등급표/01-컴퓨터-구조.md`에서 판단하고, 실제로 존재하는 세부학습 문서만 연결한다.

## 1. 전체 좌표


## 2. 명령 실행에서 병렬성으로

프로그램은 결국 CPU가 이해하는 명령으로 실행된다.

```text
Program
  ↓
ISA에 정의된 Instruction
  ↓
Fetch → Decode → Execute
  ↓
CPU가 순차적으로 처리
  ↓
한 번에 처리할 수 있는 명령 수가 성능 한계
  ↓
Pipelining
= 여러 명령의 실행 단계를 중첩
  ↓
처리량 증가
  ↓
의존성·분기·공유 자원 문제
  ↓
Hazard
```

Pipelining 이후의 구조들은 모두 같은 분류축의 단순 발전 단계는 아니다.

```text
[명령 수준 병렬성 확대]
Pipelining
├─ Superscalar
└─ VLIW

[더 큰 실행 단위의 병렬성]
Multicore / SMT

[병렬화 효과의 한계]
Amdahl 법칙
```

즉 `Pipelining → Superscalar → Multicore → Amdahl`을 하나의 Architecture 발전 순서로 외우기보다 **병렬성을 어느 수준에서 확보하는가**를 구분한다.

## 3. Memory 쪽은 세 가지 문제를 구분한다

Memory 관련 개념은 모두 비슷해 보이지만 해결하는 문제가 다르다.

```text
CPU보다 RAM이 느림
        ↓
Memory Hierarchy / Cache
= 접근시간 문제

Process를 연속된 Physical Memory에 넣어야 함
        ↓
Paging / Segmentation
= 배치 문제

Process의 모든 내용을 항상 RAM에 둘 필요가 있는가?
        ↓
Virtual Memory / Demand Paging
= 주소 공간 분리 + 필요한 부분만 적재
```

### Cache

```text
CPU와 Memory 속도 차이
        ↓
Locality 활용
        ↓
Cache
        ↓
Cache를 운영하려면
├─ 어디에 넣을까?       → Mapping
├─ 자리가 없으면?       → Replacement
└─ 수정하면 언제 반영?  → Write Policy
        ↓
Multicore
        ↓
같은 데이터가 여러 Cache에 복제
        ↓
Cache Coherence → MESI
        ↓
여러 Memory 연산의 관찰 순서
        ↓
Memory Consistency
```

세부학습: [[../../세부학습/01-컴퓨터-구조/캐시-메모리와-쓰기-일관성|캐시 메모리와 쓰기·일관성]]

### Paging과 Virtual Memory

```text
연속 Physical Memory 요구
        ↓
외부 단편화와 배치 제약
        ↓
Paging
= Page ↔ Frame 불연속 배치
        ↓
Logical/Virtual Address와
Physical 위치를 Mapping
        ↓
"모든 Page가 지금 RAM에 있어야 하나?"
        ↓
Demand Paging 기반 Virtual Memory
        ↓
Page Fault / Page Replacement
```

Paging과 Virtual Memory는 같은 개념이 아니다. Paging은 불연속 배치와 주소 변환의 기반이고, Virtual Memory는 Process의 주소 공간을 Physical Memory와 분리하여 필요한 Page만 적재할 수 있게 확장한다.

세부학습: [[../../세부학습/01-컴퓨터-구조/메모리-할당-Paging-Virtual-Memory|메모리 할당·Paging·Virtual Memory]]

## 4. 지속 저장은 Cache·Virtual Memory와 다른 축이다

RAM 아래의 지속 저장장치에서는 접근시간뿐 아니라 **장애와 용량 효율**도 중요해진다.

```text
Persistent Storage
├─ 여러 Disk를 묶음
│   ↓
│  RAID
│   ├─ Striping  → 병렬 I/O / 성능
│   ├─ Mirroring → 복제 / 가용성
│   └─ Parity    → 복구 정보 / 용량 효율
│
└─ Flash 기반 저장장치
    ↓
   SSD
    └─ FTL
       → Logical Block과 Flash Physical 위치 Mapping
```

RAID Level 숫자를 먼저 외우기보다 Striping·Mirroring·Parity의 조합으로 내려간다.

세부학습: [[../../세부학습/01-컴퓨터-구조/RAID-스트라이핑-미러링-패리티|RAID - Striping, Mirroring, Parity]]

## 5. I/O는 CPU의 기다림을 줄이는 문제다

외부 장치는 CPU보다 훨씬 느릴 수 있다. CPU가 장치 작업을 계속 확인하거나 데이터 전송에 직접 개입하면 CPU 시간이 낭비된다.

```text
느린 I/O Device
        ↓
CPU가 계속 기다리거나 확인하면 비효율
        ↓
Interrupt
= 장치가 필요한 시점에 CPU에 알림
        ↓
대량 Data 전송에도 CPU가 계속 개입하면 비효율
        ↓
DMA
= Device ↔ Memory 전송에서 CPU 개입 축소
```

Interrupt와 DMA는 같은 개념이 아니다.

```text
Interrupt
→ "처리가 필요하다 / 끝났다"를 CPU에 알리는 Mechanism

DMA
→ 실제 Data Block 전송에서 CPU의 반복 개입을 줄이는 Mechanism
```

## 6. 성능 향상은 항상 Trade-off와 한계를 가진다

컴퓨터 구조의 여러 기술은 결국 병목을 줄이려는 시도다.

```text
병목 발견
  ↓
구조 개선
├─ Pipelining / Parallelism
├─ Cache / Memory Hierarchy
├─ DMA
└─ RAID 등
  ↓
Throughput / Response Time 개선
  ↓
하지만
├─ 복잡도 증가
├─ 전력 증가
├─ 비용 증가
└─ 일부 구간은 개선되지 않음
  ↓
Amdahl 법칙
= 전체 성능 향상의 상한 확인
```

성능만 높이면 끝나는 것도 아니다.

```text
System
├─ Performance
│   ├─ Throughput
│   ├─ Response Time
│   ├─ CPI
│   └─ SPEC
│
└─ Reliability / Availability
    ├─ MTBF
    ├─ MTTR
    └─ Watchdog
```

## 8. 탐색 순서

처음 전체 구조를 잡을 때는 다음 순서가 가장 자연스럽다.

```text
Computer 5대 구성요소
        ↓
폰노이만 구조
        ↓
CPU / ISA / 명령어 Cycle
        ↓
Pipelining / Hazard
        ↓
Memory Hierarchy / Cache
        ↓
Paging / Virtual Memory
        ↓
Interrupt / DMA
        ↓
Persistent Storage / RAID / SSD
        ↓
성능평가 / Amdahl
        ↓
MTBF / MTTR / Watchdog
```

이 순서는 모든 기술의 역사적 발전 순서를 뜻하지 않는다. **프로그램 실행의 기본 구조에서 시작해 병목과 해결 방법을 따라가며 전체 좌표를 잡기 위한 학습 탐색 순서**다.
