# 컴퓨터 구조 전체 개념지도

이 문서는 `../../학습등급표/01-컴퓨터-구조.md`에서 정한 학습 범위를 **개념 관계로 재배치한 최상위 탐색 지도**다.

컴퓨터 구조는 프로그램의 명령과 데이터가 실제 하드웨어에서 어떻게 처리되고, CPU·메모리·I/O의 속도와 용량 한계를 어떤 구조로 완화하는지를 본다.

여기서는 세부 기술을 모두 펼치기보다 **어느 큰 학습 가지를 파고들 것인지**를 먼저 잡는다. 각 가지의 관계는 하위 개념지도에서 더 펼치고, 동작 원리·수식·예제는 `../../세부학습/01-컴퓨터-구조/`에서 다룬다.

---

## 1. 컴퓨터 구조 전체 좌표

```text
컴퓨터 구조
│
├─ 명령 실행과 CPU 병렬성
│   ├─ 컴퓨터 구성 / 폰노이만 구조
│   ├─ ISA / 명령어 사이클
│   ├─ 파이프라이닝 / 해저드
│   ├─ Superscalar / VLIW
│   ├─ Multicore / SMT
│   └─ Amdahl 법칙
│
├─ 메모리 계층과 가상 메모리
│   ├─ 지역성 / 캐시
│   ├─ 메모리 할당
│   ├─ Paging / Segmentation
│   └─ 가상 메모리 / MMU / TLB
│
├─ I/O와 저장장치
│   ├─ Interrupt / DMA
│   ├─ I/O 주소 지정
│   ├─ RAID
│   └─ SSD / FTL
│
└─ 성능과 신뢰성
    ├─ CPI / 처리량 / 응답시간 / 이용률
    ├─ Amdahl 법칙 / SPEC
    └─ MTBF / MTTR / Watchdog
```

이 네 가지는 교재 Part를 그대로 옮긴 것이 아니라, **정보관리기술사 관점에서 함께 이해할 가치가 있는 큰 학습 가지**로 묶은 것이다.

---

## 2. 명령 실행과 CPU 병렬성

핵심 질문은 **CPU가 명령을 어떻게 실행하고, 한정된 실행 자원에서 처리량을 어떻게 높이는가**다.

```text
프로그램
  ↓
ISA에 정의된 명령
  ↓
명령어 사이클
  ↓
CPU 실행
  ↓
처리량을 높이려면?
  ↓
파이프라이닝과 병렬성 확대
  ↓
의존성·분기·공유 자원 문제
  ↓
해저드와 병렬화 한계
```

이 가지에서는 파이프라이닝·해저드를 중심으로 Superscalar, VLIW, Multicore, SMT가 **어느 수준에서 병렬성을 확대하는지**를 구분하고, Amdahl 법칙으로 성능 향상의 한계를 연결한다.

---

## 3. 메모리 계층과 가상 메모리

메모리 쪽은 비슷해 보이는 개념들이 서로 다른 문제를 해결한다는 점이 핵심이다.

```text
CPU보다 RAM이 느림
        ↓
메모리 계층 / 캐시
= 접근시간 문제

프로세스를 연속된 물리 메모리에 배치해야 함
        ↓
Paging / Segmentation
= 배치 문제

프로세스의 모든 내용을 항상 RAM에 둘 필요가 있는가?
        ↓
가상 메모리
= 주소 공간 분리 + 필요한 부분만 적재
```

현재 이 가지는 세부학습으로 바로 내려갈 수 있다.

- [[../../세부학습/01-컴퓨터-구조/메모리-할당-Paging-Virtual-Memory|메모리 할당·Paging·Virtual Memory]]

## 4. I/O와 저장장치

CPU 밖의 장치에서는 **CPU가 느린 장치를 기다리는 문제**와 **지속 저장장치의 성능·가용성 문제**를 함께 본다.

```text
느린 외부 장치
        ↓
CPU가 계속 기다리거나 전송에 개입하면 비효율
        ↓
Interrupt / DMA

지속 저장장치
        ↓
성능·장애·용량 효율 문제
        ↓
RAID / SSD
```

Interrupt는 장치가 필요한 시점에 CPU에 알리는 방식이고, DMA(Direct Memory Access, CPU의 반복 개입 없이 장치와 메모리 사이의 데이터 전송을 지원하는 방식)는 대량 데이터 전송에서 CPU 개입을 줄인다.

RAID는 여러 Disk를 묶어 Striping·Mirroring·Parity를 조합하면서 성능·가용성·용량 효율 사이의 Trade-off를 선택한다.

세부학습: [[../../세부학습/01-컴퓨터-구조/RAID-스트라이핑-미러링-패리티|RAID - Striping, Mirroring, Parity]]

## 5. 성능과 신뢰성

컴퓨터 구조의 여러 기술은 결국 시스템의 병목을 줄이려는 시도지만, 개선 효과에는 한계와 대가가 있다.

```text
병목 식별
  ↓
구조 개선
  ↓
처리량·응답시간 개선
  ↓
개선되지 않는 구간 존재
  ↓
Amdahl 법칙으로 성능 향상 상한 확인

동시에
  ↓
전력 · 비용 · 복잡도 · 장애
  ↓
MTBF / MTTR / Watchdog 등으로 신뢰성·가용성 검토
```

따라서 단순히 CPU Clock이나 개별 장치 속도만 보는 것이 아니라 **워크로드 → 병목 → 개선 효과 → 한계 → 신뢰성**의 흐름으로 본다.

## 6. 어떤 가지를 먼저 팔 것인가

```text
컴퓨터가 명령을 어떻게 실행하고
병렬화하는지 궁금하다
        ↓
명령 실행과 CPU 병렬성

캐시·Paging·가상 메모리가
어떻게 연결되는지 궁금하다
        ↓
메모리 계층과 가상 메모리

Interrupt·DMA·RAID·SSD가
어디에 위치하는지 궁금하다
        ↓
I/O와 저장장치

성능 개선이 실제로 얼마나 효과가 있고
신뢰성과 어떤 Trade-off가 있는지 궁금하다
        ↓
성능과 신뢰성
```

이 지도에서 큰 가지를 선택한 뒤, 관계를 더 펼쳐야 하는 가지는 하위 개념지도로 내려간다. 이미 하나의 세부학습 문서에서 충분한 이해 흐름을 제공하는 개념은 별도 지도를 거치지 않고 바로 세부학습으로 연결할 수 있다.
