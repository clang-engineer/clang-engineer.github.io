# 컴퓨터 구조 개념지도

컴퓨터 구조는 **프로그램의 명령과 데이터가 실제 하드웨어에서 어떻게 처리되고, 하드웨어의 속도·용량 한계를 어떤 구조로 완화하는가**를 보는 영역이다.

이 지도는 교재 순서보다 `명령 실행 → 병렬성 → 메모리 계층 → I/O → 성능·신뢰성`의 관계를 중심으로 탐색한다. 학습 우선순위와 깊이는 `../../학습등급표/01-컴퓨터-구조.md`에서 판단하고, 실제로 존재하는 세부학습 문서만 연결한다.

표기의 의미는 다음과 같다.

```text
★ 핵심축   : 정보관리기술사 관점에서 원리·문제·Trade-off까지 우선 이해
○ 연결개념 : 핵심축의 위치와 비교 관계를 이해하기 위한 개념
```

개념지도 자체가 학습등급표를 대체하지는 않는다. `★/○`는 A/B/C 등급을 새로 부여하는 표기가 아니라 **지도를 읽을 때 중심 흐름과 확장 가지를 구분하기 위한 탐색 표기**다.

## 1. 전체 좌표

```text
컴퓨터 구조
│
├─ ★ 명령을 어떻게 실행하는가
│  ├─ ★ 컴퓨터 5대 구성요소
│  │  ├─ CPU
│  │  ├─ 메모리
│  │  └─ I/O
│  ├─ ★ 폰노이만 구조
│  │  └─ 저장 프로그램 방식 / 폰노이만 병목
│  ├─ ★ ISA
│  ├─ ★ 명령어 사이클(Instruction Cycle)
│  └─ ○ 시스템 버스(System Bus)
│
├─ ★ CPU 처리량을 어떻게 높이는가
│  ├─ ★ CPI / 성능 지표
│  ├─ ★ 파이프라이닝(Pipelining)
│  │  └─ ★ 해저드(Hazard)
│  │      ├─ 데이터 해저드(Data Hazard)
│  │      ├─ 제어 해저드(Control Hazard)
│  │      └─ 구조 해저드(Structural Hazard)
│  ├─ ○ Superscalar / VLIW
│  ├─ ★ Multicore / SMT
│  └─ ★ Amdahl 법칙
│
├─ ★ CPU와 메모리의 속도·용량 차이를 어떻게 다루는가
│  ├─ ★ 메모리 계층(Memory Hierarchy)
│  │  └─ ★ 지역성(Locality)
│  │      └─ ★ 캐시(Cache)
│  │          ├─ 매핑(Mapping)
│  │          ├─ 교체(Replacement)
│  │          ├─ 쓰기 정책(Write Policy)
│  │          └─ Multicore
│  │              ├─ 캐시 일관성(Cache Coherence)
│  │              │   └─ MESI
│  │              └─ 메모리 일관성(Memory Consistency)
│  │
│  ├─ ○ 메모리 할당(Memory Allocation)
│  │  ├─ 연속 할당(Contiguous Allocation)
│  │  │   ├─ 고정 분할(Fixed Partition)
│  │  │   └─ 가변 분할(Variable Partition)
│  │  └─ 불연속 할당(Non-contiguous Allocation)
│  │      ├─ Paging
│  │      └─ Segmentation
│  │
│  └─ ★ 가상 메모리(Virtual Memory)
│      ├─ 가상주소 ↔ 물리주소
│      ├─ ○ MMU
│      ├─ ○ TLB
│      └─ Demand Paging
│          ├─ Page Fault
│          └─ Page Replacement
│
├─ ★ 지속 저장장치의 성능·가용성을 어떻게 높이는가
│  ├─ ★ RAID
│  │  ├─ Striping
│  │  ├─ Mirroring
│  │  └─ Parity
│  └─ ○ SSD
│      └─ FTL
│
├─ ★ CPU와 느린 외부 장치가 어떻게 협업하는가
│  ├─ ★ Interrupt I/O
│  ├─ ★ DMA
│  └─ ○ I/O 주소 지정(I/O Addressing)
│
└─ ★ 시스템 개선 효과와 신뢰성을 어떻게 판단하는가
   ├─ ★ 처리량·응답시간·이용률
   ├─ ★ CPI
   ├─ ★ Amdahl 법칙
   ├─ ○ SPEC
   ├─ ★ MTBF / MTTR
   └─ ★ Watchdog
```

## 2. 명령 실행에서 병렬성으로

프로그램은 결국 CPU가 이해하는 명령으로 실행된다.

```text
프로그램
  ↓
ISA에 정의된 명령
  ↓
Fetch → Decode → Execute
  ↓
CPU가 순차적으로 처리
  ↓
한 번에 처리할 수 있는 명령 수가 성능 한계
  ↓
★ 파이프라이닝(Pipelining)
= 여러 명령의 실행 단계를 겹쳐 처리
  ↓
처리량 증가
  ↓
의존성·분기·공유 자원 문제
  ↓
★ 해저드(Hazard)
```

정보관리기술사 관점에서는 먼저 **파이프라이닝이 처리량을 높이는 이유와 그 결과 해저드가 왜 생기는지**를 중심축으로 잡는다.

파이프라이닝 이후의 구조들은 모두 같은 분류축의 단순 발전 단계는 아니다.

```text
[핵심축]
파이프라이닝
  ↓
해저드
= 병렬 실행이 만드는 의존성·분기·자원 문제

[명령 수준 병렬성의 확장]
○ Superscalar
○ VLIW

[더 큰 실행 단위의 병렬성]
★ Multicore / SMT

[병렬화 효과의 한계]
★ Amdahl 법칙
```

따라서 `파이프라이닝 → Superscalar → Multicore → Amdahl`을 하나의 Architecture 발전 순서로 외우지 않는다.

```text
파이프라이닝 / 해저드
→ 명령 실행을 겹칠 때 생기는 핵심 원리와 한계

Superscalar / VLIW
→ 명령 수준 병렬성을 더 확대하는 대표 구조
→ 위치와 차이를 우선 이해

Multicore / SMT
→ Core·Thread 수준으로 병렬 범위 확대

Amdahl 법칙
→ 병렬화해도 순차 구간 때문에 전체 성능 향상에는 상한 존재
```

## 3. 메모리 쪽은 세 가지 문제를 구분한다

메모리 관련 개념은 모두 비슷해 보이지만 해결하는 문제가 다르다.

```text
CPU보다 RAM이 느림
        ↓
★ 메모리 계층 / 캐시
= 접근시간 문제

Process를 연속된 물리 메모리에 넣어야 함
        ↓
Paging / Segmentation
= 배치 문제

Process의 모든 내용을 항상 RAM에 둘 필요가 있는가?
        ↓
★ 가상 메모리 / Demand Paging
= 주소 공간 분리 + 필요한 부분만 적재
```

### 캐시

```text
CPU와 메모리 속도 차이
        ↓
지역성 활용
        ↓
캐시
        ↓
캐시를 운영하려면
├─ 어디에 넣을까?       → 매핑
├─ 자리가 없으면?       → 교체
└─ 수정하면 언제 반영?  → 쓰기 정책
        ↓
Multicore
        ↓
같은 데이터가 여러 Cache에 복제
        ↓
캐시 일관성 → MESI
        ↓
여러 메모리 연산의 관찰 순서
        ↓
메모리 일관성
```

세부학습: [[../../세부학습/01-컴퓨터-구조/캐시-메모리와-쓰기-일관성|캐시 메모리와 쓰기·일관성]]

### Paging과 가상 메모리

```text
연속 물리 메모리 요구
        ↓
외부 단편화와 배치 제약
        ↓
Paging
= Page ↔ Frame 불연속 배치
        ↓
가상주소와 물리 위치를 Mapping
        ↓
"모든 Page가 지금 RAM에 있어야 하나?"
        ↓
Demand Paging 기반 가상 메모리
        ↓
Page Fault / Page Replacement
```

Paging과 가상 메모리는 같은 개념이 아니다. Paging은 불연속 배치와 주소 변환의 기반이고, 가상 메모리는 Process의 주소 공간을 물리 메모리와 분리하여 필요한 Page만 적재할 수 있게 확장한다.

세부학습: [[../../세부학습/01-컴퓨터-구조/메모리-할당-Paging-Virtual-Memory|메모리 할당·Paging·Virtual Memory]]

## 4. 지속 저장은 캐시·가상 메모리와 다른 축이다

RAM 아래의 지속 저장장치에서는 접근시간뿐 아니라 **장애와 용량 효율**도 중요해진다.

```text
지속 저장장치(Persistent Storage)
├─ 여러 Disk를 묶음
│   ↓
│  ★ RAID
│   ├─ Striping  → 병렬 I/O / 성능
│   ├─ Mirroring → 복제 / 가용성
│   └─ Parity    → 복구 정보 / 용량 효율
│
└─ Flash 기반 저장장치
    ↓
   ○ SSD
    └─ FTL
       → 논리 Block과 Flash의 물리 위치를 Mapping
```

RAID Level 숫자를 먼저 외우기보다 Striping·Mirroring·Parity의 조합으로 내려간다.

세부학습: [[../../세부학습/01-컴퓨터-구조/RAID-스트라이핑-미러링-패리티|RAID - Striping, Mirroring, Parity]]

## 5. I/O는 CPU의 기다림을 줄이는 문제다

외부 장치는 CPU보다 훨씬 느릴 수 있다. CPU가 장치 작업을 계속 확인하거나 데이터 전송에 직접 개입하면 CPU 시간이 낭비된다.

```text
느린 I/O 장치
        ↓
CPU가 계속 기다리거나 확인하면 비효율
        ↓
★ Interrupt
= 장치가 필요한 시점에 CPU에 알림
        ↓
대량 Data 전송에도 CPU가 계속 개입하면 비효율
        ↓
★ DMA
= 장치 ↔ 메모리 전송에서 CPU 개입 축소
```

Interrupt와 DMA는 같은 개념이 아니다.

```text
Interrupt
→ "처리가 필요하다 / 끝났다"를 CPU에 알리는 Mechanism

DMA
→ 실제 Data Block 전송에서 CPU의 반복 개입을 줄이는 Mechanism
```

## 6. 성능 향상은 항상 Trade-off와 한계를 가진다

컴퓨터 구조의 여러 기술은 결국 병목을 줄이려는 시도다.

```text
병목 발견
  ↓
구조 개선
├─ 파이프라이닝 / 병렬처리
├─ 캐시 / 메모리 계층
├─ DMA
└─ RAID 등
  ↓
처리량 / 응답시간 개선
  ↓
하지만
├─ 복잡도 증가
├─ 전력 증가
├─ 비용 증가
└─ 일부 구간은 개선되지 않음
  ↓
★ Amdahl 법칙
= 전체 성능 향상의 상한 확인
```

성능만 높이면 끝나는 것도 아니다.

```text
시스템
├─ 성능(Performance)
│   ├─ 처리량
│   ├─ 응답시간
│   ├─ CPI
│   └─ ○ SPEC
│
└─ 신뢰성·가용성(Reliability / Availability)
    ├─ MTBF
    ├─ MTTR
    └─ Watchdog
```

## 7. 현재 세부학습 문서의 위치

```text
컴퓨터 구조
│
├─ 메모리 계층 / 캐시
│  └─ [[../../세부학습/01-컴퓨터-구조/캐시-메모리와-쓰기-일관성|캐시 메모리와 쓰기·일관성]]
│
├─ 메모리 할당 / 가상 메모리
│  └─ [[../../세부학습/01-컴퓨터-구조/메모리-할당-Paging-Virtual-Memory|메모리 할당·Paging·Virtual Memory]]
│
└─ 지속 저장장치 / RAID
   └─ [[../../세부학습/01-컴퓨터-구조/RAID-스트라이핑-미러링-패리티|RAID - Striping, Mirroring, Parity]]
```

현재 세부학습 문서는 메모리·저장장치 가지에 집중되어 있다. CPU 명령 실행, 파이프라이닝·해저드, I/O·DMA, 성능·신뢰성은 개념지도에서 위치를 먼저 잡고, 세부학습 문서는 실제 학습이 깊어질 때 추가한다.

## 8. 탐색 순서

처음 전체 구조를 잡을 때는 **핵심축을 먼저 통과하고 연결개념을 옆으로 확장**한다.

```text
★ 컴퓨터 5대 구성요소
        ↓
★ 폰노이만 구조
        ↓
★ CPU / ISA / 명령어 사이클
        ↓
★ 파이프라이닝 / 해저드
        ├─ 필요할 때 → ○ Superscalar / VLIW
        ↓
★ 메모리 계층 / 캐시
        ↓
★ 가상 메모리
        ↓
★ Interrupt / DMA
        ↓
★ RAID
        ├─ 필요할 때 → ○ SSD / FTL
        ↓
★ 성능평가 / Amdahl
        ↓
★ MTBF / MTTR / Watchdog
```

이 순서는 모든 기술의 역사적 발전 순서를 뜻하지 않는다. **프로그램 실행의 기본 구조에서 시작해 병목과 해결 방법을 따라가며 전체 좌표를 잡기 위한 학습 탐색 순서**다.
