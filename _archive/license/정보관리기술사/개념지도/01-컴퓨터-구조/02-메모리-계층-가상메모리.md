# 메모리 계층과 가상 메모리 개념지도

이 문서는 [[00-전체|컴퓨터 구조 전체 개념지도]]에서 **메모리 계층과 가상 메모리** 가지를 선택했을 때, `속도 격차 → 배치 문제 → 주소 공간 분리`라는 서로 다른 문제를 구분해 파고들기 위한 지도다.

## 1. 전체 좌표

```text
메모리 관련 문제
│
├─ CPU보다 RAM이 느림
│   ↓
│  메모리 계층
│   ↓
│  지역성
│   ↓
│  캐시
│
├─ 프로세스를 연속된 물리 메모리에 배치해야 함
│   ↓
│  메모리 할당
│   ├─ 연속 할당
│   └─ 불연속 할당
│       ├─ Paging
│       └─ Segmentation
│
└─ 프로세스의 모든 내용을 항상 RAM에 둘 필요가 있는가?
    ↓
   가상 메모리
    ├─ 가상주소 ↔ 물리주소
    ├─ MMU / TLB
    └─ Demand Paging
        ├─ Page Fault
        └─ Page Replacement
```

캐시와 가상 메모리는 모두 계층과 매핑을 이용하지만 해결하려는 중심 문제가 다르다.

```text
캐시
→ 접근시간 단축

Paging
→ 물리 메모리의 연속 배치 요구 제거

가상 메모리
→ 프로세스 주소 공간과 물리 메모리를 분리
```

## 2. 속도 격차: 메모리 계층과 캐시

```text
CPU가 매우 빠름
        ↓
RAM 접근이 상대적으로 느림
        ↓
매번 RAM을 기다리면 성능 저하
        ↓
지역성(Locality) 활용
        ↓
캐시(Cache)
```

캐시를 실제로 운영하려면 다음 문제가 생긴다.

```text
어디에 넣을까?      → 매핑(Mapping)
자리가 없으면?      → 교체(Replacement)
수정하면 언제 반영? → 쓰기 정책(Write Policy)
```

멀티코어에서는 같은 데이터가 여러 Core의 Cache에 복제되면서 캐시 일관성(Cache Coherence) 문제가 추가되고, MESI 같은 Protocol로 복제본 상태를 관리한다.

세부학습: [[../../세부학습/01-컴퓨터-구조/캐시-메모리와-쓰기-일관성|캐시 메모리와 쓰기·일관성]]

## 3. 배치 문제: 연속 할당에서 Paging으로

```text
연속 메모리 할당
        ↓
큰 연속 공간이 필요
        ↓
외부 단편화와 배치 제약
        ↓
"꼭 연속해서 배치해야 하나?"
        ↓
불연속 할당
├─ Paging
└─ Segmentation
```

Paging은 논리 주소 공간을 Page로, 물리 메모리를 같은 크기의 Frame으로 나눠 서로 떨어진 Frame에 배치할 수 있게 한다.

```text
Page 0 → Frame 4
Page 1 → Frame 1
Page 2 → Frame 7
```

이때 Page Table이 Page와 Frame의 대응 관계를 관리한다.

## 4. 주소 공간 분리: 가상 메모리

Paging으로 불연속 배치가 가능해지면 다음 질문으로 이어진다.

```text
Page를 여러 Frame에 흩어 배치할 수 있음
        ↓
논리 주소와 물리 위치를 Mapping
        ↓
"모든 Page가 지금 RAM에 있어야 하나?"
        ↓
Demand Paging 기반 가상 메모리
```

가상 메모리(Virtual Memory)의 본질은 프로세스가 보는 주소 공간을 실제 물리 메모리 배치와 분리하는 것이다.

```text
프로세스의 가상주소
        ↓
MMU / Page Table / TLB
        ↓
물리주소
```

필요한 Page가 RAM에 없으면 Page Fault가 발생하고, RAM에 빈 Frame이 부족하면 Page Replacement가 필요하다.

세부학습: [[../../세부학습/01-컴퓨터-구조/메모리-할당-Paging-Virtual-Memory|메모리 할당·Paging·Virtual Memory]]

## 5. 서로 비슷해 보이는 개념의 경계

```text
캐시
= CPU-RAM 속도 차이를 줄이는 성능 계층

Paging
= Page/Frame 단위의 불연속 배치 기법

가상 메모리
= 가상 주소 공간과 물리 메모리를 분리하는 메모리 관리 구조

TLB
= 최근 주소 변환 결과를 저장하는 빠른 Cache
```

TLB가 Cache라고 해서 일반 Data Cache와 같은 역할을 하는 것은 아니다. TLB는 **주소 변환 결과**를 빠르게 찾기 위한 Cache다.

## 6. 기억 흐름

```text
[속도]
CPU ↔ RAM 격차
→ 지역성
→ 캐시

[배치]
연속 공간 요구
→ 불연속 할당
→ Paging / Segmentation

[주소 공간]
논리 주소 ↔ 물리 위치 Mapping
→ 가상 메모리
→ MMU / TLB
→ Demand Paging
→ Page Fault / Replacement
```
