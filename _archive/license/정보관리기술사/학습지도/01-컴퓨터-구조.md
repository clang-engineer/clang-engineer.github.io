# Vol. 1 컴퓨터 구조 학습지도

> 기준: 정보관리기술사 단독 대비를 위한 1차 분류다. 출제 여부를 단정하지 않으며, 공식 출제기준과 최근 기출을 분석한 뒤 등급을 보정한다.

## 이 권의 역할

컴퓨터 구조는 프로그램이 실제 하드웨어에서 어떻게 실행되는지 설명한다. CPU·메모리·입출력장치의 속도와 용량에는 한계가 있으므로, 시스템 성능과 신뢰성을 이해하려면 이 물리적 기반을 알아야 한다.

핵심 질문은 세 가지다.

1. 명령과 데이터는 CPU·메모리·I/O 사이에서 어떻게 처리되는가?
2. 속도 차이와 병목을 병렬성·계층화·지역성으로 어떻게 줄이는가?
3. 성능 향상이 전력·복잡도·비용·신뢰성에 어떤 대가를 만드는가?

## 권 내부 큰 그림

```text
프로그램을 명령어로 표현
→ 명령어 집합(ISA)에 따라 CPU가 명령을 가져와 해석하고 실행
→ 성능을 제한하는 문제에 따라 서로 다른 방법 적용
   ├─ 한 번에 처리할 수 있는 명령이 적음
   │  → 파이프라이닝·슈퍼스칼라·멀티코어로 병렬성 확대
   │  → 의존성·분기·공유 자원 때문에 대기와 복잡도 증가
   ├─ CPU보다 메모리가 느림
   │  → 지역성·캐시·메모리 계층으로 속도 차이 완화
   └─ CPU가 느린 외부 장치를 기다림
      → 인터럽트·DMA로 CPU의 대기와 개입 축소
→ 지표와 Amdahl 법칙으로 개선 효과와 한계 측정
→ 전력·비용과 MTBF·MTTR·Watchdog을 함께 검토
```

중심은 **명령 실행, 지역성, 병렬성, 병목, 성능과 신뢰성의 트레이드오프**다. 논리회로 계산과 개별 규격은 이 흐름을 설명하는 데 필요한 만큼만 본다.

### 먼저 알아둘 약어

| 약어 | 원어·쉬운 뜻 |
|---|---|
| CPU | Central Processing Unit, 명령을 해석하고 실행하는 중앙처리장치 |
| I/O | Input/Output, CPU와 메모리가 외부 장치와 데이터를 주고받는 입출력 |
| ISA | Instruction Set Architecture, CPU가 이해하는 명령과 레지스터 등의 약속 |
| CPI | Cycles Per Instruction, 명령 하나를 처리하는 데 필요한 평균 클록 주기 수 |
| DMA | Direct Memory Access, CPU를 계속 거치지 않고 장치와 메모리가 데이터를 전송하는 방식 |
| MMU | Memory Management Unit, 가상주소를 물리주소로 바꾸고 메모리 접근을 보호하는 장치 |
| TLB | Translation Lookaside Buffer, 최근 주소 변환 결과를 저장하는 빠른 Cache |
| MTBF·MTTR | Mean Time Between Failures·Mean Time To Repair, 평균 고장 간격과 평균 복구 시간 |

## 권장 학습 순서

아래 구분은 관련 주제를 함께 공부하기 위한 권장 순서다. 실제 기술·업무의 처리 절차를 뜻하지 않으며, 선행관계가 약한 단계는 병행해도 된다.

### 1단계: 시스템과 명령 실행

`5대 구성요소(1) → 폰노이만 구조(3·4) → CPU(5) → ISA(14) → 명령어 사이클·인터럽트(11·17) → 시스템 Bus(9)`

소프트웨어가 하드웨어에서 실행되는 최소 흐름을 먼저 잡는다. 주소별 명령어 작성과 제어신호 상세보다 저장 프로그램 방식의 병목과 CPU·메모리·I/O의 협업을 우선한다.

### 2단계: 성능과 명령 수준 병렬성

`CPI와 성능(10) → Pipelining(49) → Hazard(56) → Superscalar·VLIW(50·52) → 멀티코어·SMT(23·113) → 병행성과 병렬성(180) → Amdahl 법칙(168)`

성능 지표를 먼저 세우고 파이프라인이 처리량을 높이는 이유와 해저드 비용을 연결한다. 병렬화 비율이 전체 개선을 제한한다는 결론까지 이어간다.

### 3단계: 메모리·저장장치 계층

`CPU와 메모리의 속도 차이 → 지역성·메모리 계층·Cache(25·26) → 물리 메모리의 한계 → Virtual 메모리·MMU·TLB(27·32·33) → 지속 저장의 성능·가용성 → RAID·SSD·FTL(35·40·44)`

빠른 속도·큰 용량·낮은 비용을 동시에 얻기 어렵기 때문에 저장 공간을 계층화한다. 캐시는 접근시간을 줄이고, 가상메모리는 주소 공간과 보호를 제공하며, RAID·SSD는 지속 저장장치의 성능·가용성 문제를 다룬다.

### 4단계: I/O와 장치 협업

`Interrupt I/O(62·63) → DMA(60) → I/O 주소 지정(82) → 인터페이스 필요성(23)`

CPU가 느린 장치를 직접 기다리는 문제에서 인터럽트와 DMA가 등장한다. RS-232C·USB 버전·영상 규격은 원리의 사례로만 식별한다.

### 5단계: 시스템 수준 평가와 신뢰성

`성능평가(178) → CPU 지표(179) → Amdahl 법칙(168·169) → SPEC(86) → MTBF·MTTR(167) → Watchdog(126)`

개별 부품 속도가 아니라 워크로드와 측정 범위로 시스템을 평가한다. 장애 간격과 복구시간이 가용성을 결정하고 감시 장치가 장애를 탐지·복구하는 흐름을 본다.

### 선택 보강

GPU·가속이 필요하면 `벡터 처리(53·55) → GPGPU(181)`, 분산 인프라가 필요하면 `그리드·클라우드·에지(170·174·175)`, 하드웨어 보안·임베디드가 필요하면 `SoC(115)·FPGA·ASIC(159~161)`의 통합 범위와 유연성·성능·전력·개발비 차이를 위치만 보강한다. 논리식 간소화, 플립플롭·카운터 설계, 핀·프로토콜 규격과 소비자 기기 응용은 기출 근거가 생길 때 깊게 본다.

## 토픽 간 연결

### 명령 실행과 병렬화

```text
저장 프로그램 구조 → 명령어와 데이터가 같은 경로를 경쟁
→ Cache·Bus 개선과 명령어 Pipelining
→ 단계 중첩으로 처리량 증가
→ 데이터·제어·구조 Hazard 발생
→ 예측·전달·정지로 완화하되 복잡도와 전력 증가
→ 멀티코어·SMT·GPU로 병렬 범위 확대
→ 순차 구간이 Amdahl 법칙에 따라 전체 향상을 제한
```

### 메모리와 I/O

```text
CPU가 데이터와 외부 장치를 기다림
├─ CPU와 메모리의 속도 차이
│  → 지역성을 이용한 Cache와 메모리 계층
├─ 가상주소 변환 비용
│  → MMU·TLB로 주소 변환과 보호 지원
├─ 지속 저장장치의 성능·장애 문제
│  → RAID·SSD로 성능과 가용성 보완
└─ 느린 외부 장치의 처리 대기
   → Interrupt로 완료를 알리고 DMA로 CPU 개입 축소
```

Cache와 가상메모리는 모두 계층을 이용하지만 각각 **접근시간**과 **주소 공간·격리**가 중심이다. RAID는 백업 자체가 아니며 장애 범위와 복구 목표를 별도로 설계해야 한다.

### 평가와 신뢰성

```text
워크로드와 서비스 목표 정의
→ 처리량·응답시간·이용률 측정
→ 병목 구간 식별
→ Amdahl 법칙으로 개선 상한 검토
→ 전력·비용·복잡도까지 비교
→ MTBF·MTTR로 가용성 평가
→ 감시·이중화·복구로 장애 영향 축소
```

## 1차 회독 통과 기준

첫 회독에서는 다음 흐름만 설명할 수 있으면 된다.

1. CPU는 메모리에서 명령을 가져와 해석하고 실행한다.
2. 파이프라이닝과 병렬 처리는 처리량을 높이지만 의존성과 분기 때문에 대기와 복잡성이 생긴다.
3. 캐시와 메모리 계층은 CPU와 저장장치의 속도 차이를 줄인다.
4. 인터럽트와 DMA는 CPU가 느린 장치를 계속 기다리는 일을 줄인다.
5. 성능 개선은 병목과 개선 한계를 측정한 뒤 전력·비용·신뢰성과 함께 판단한다.

## 보정 기록

`1차 분류`에서 `3단계(현행성 보정)` 항목을 일부 반영했다.

- `[현행]` `North Bridge·South Bridge`는 과거 칩셋 분리 개념으로, 현재 설명은 SoC/통합 메모리·I/O 구조와 성능 병목 이동 관점으로 재정렬한다.
- `Watchdog Timer`는 단순 탐지 장치가 아니라 장애 탐지-복구 승인-운영 이력의 책임 흐름이 함께 보이는 장애 대응 문항으로 정리한다.
- `GPGPU`/분산 연산은 병렬 처리 패턴이 데이터 크기, 지연 요구, 비용 제약을 만족할 때만 선택한다는 `선택 기준` 중심으로 정리한다.
- 변경 시 `기존 등급 → 새 등급`, 근거 회차, 질문 형태를 기록한다.
- `[현행]`/`[최신]` 표기는 용어 교체보다 성능·운영 책임 정렬을 우선한다.

아직 공식 출제기준과 최근 기출을 반영하지 않은 1차 분류다.

- 구조 원리와 함께 반복 출제된 계산은 필요한 범위만 B로 승급한다.
- 회로·규격·시스템응용 항목은 정보관리 통합 질문의 근거가 확인될 때만 승급한다.
- 최신 가속기·메모리·양자 주제는 제품명이 아니라 구조적 변화와 관리 영향으로 보정한다.
- 변경 시 `기존 등급 → 새 등급`, 근거 회차, 질문 형태를 기록한다.
