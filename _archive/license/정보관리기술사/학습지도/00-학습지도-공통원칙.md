# 정보관리기술사 학습지도 공통 원칙

학습지도는 **학습할 개념을 상위·하위·인접 관계로 연결해, 하나의 개념에서 주변으로 파고들 수 있게 만드는 탐색 지도**다.

학습 대상과 A/B/C 우선순위는 `../학습등급표/`에서 정하고, 각 개념의 상세한 동작 원리와 이해 기록은 `../세부학습/`에서 다룬다.

## 1. 자료별 역할

```text
교재 · 기출 · 공식 출제기준
        ↓
학습등급표
= 무엇을 얼마나 우선해서 공부할 것인가
        ↓
학습지도
= 어떤 개념을 주변으로 어떻게 파고들 것인가
        ↓
세부학습
= 선택한 개념을 왜 필요한지부터 깊게 이해
```

| 자료 | 핵심 질문 |
|---|---|
| 학습등급표 | 무엇을 공부하고 어느 정도 깊이까지 볼 것인가? |
| 학습지도 | 이 개념의 상위·하위·인접 개념은 무엇이며 다음에 무엇을 파야 하는가? |
| 세부학습 | 왜 필요한가, 어떻게 동작하는가, 무엇과 다른가? |

## 2. 학습지도의 목적

학습지도는 교재 목차를 다시 나열하는 문서가 아니다. 다음 질문에 답할 수 있어야 한다.

1. 이 개념의 상위 개념은 무엇인가?
2. 바로 아래에서 파고들 핵심 꼭지는 무엇인가?
3. 같은 수준에서 비교하거나 함께 봐야 할 인접 개념은 무엇인가?
4. 실제로 직접 의존하는 흐름은 무엇인가?
5. 서로 다른 분류축의 개념을 잘못 한 줄에 놓고 있지는 않은가?
6. 현재 개념에서 다음 학습 대상으로 어디로 이동할 수 있는가?

## 3. 개념 Node와 세부학습 File은 1:1이 아니다

학습지도에 존재하는 모든 Node를 별도 파일로 만들 필요는 없다.

```text
RAG
└─ Vector Search
    └─ ANN
        ├─ HNSW
        └─ IVF
```

위 개념들은 학습지도에서 각각 학습 꼭지로 보이더라도, 실제 세부학습에서는 `임베딩-벡터검색-RAG.md` 하나 안에서 함께 다룰 수 있다.

> **학습지도 Node = 파고들 개념 꼭지**
>
> **세부학습 File = 한 번에 이해하기 좋은 개념 흐름 단위**

## 4. 상위 · 하위 · 인접 관계를 우선한다

개념은 이름이 비슷하거나 교재 번호가 가깝다는 이유로 연결하지 않는다.

```text
상위 개념
  ↓
현재 개념
├─ 하위 개념 A
├─ 하위 개념 B
└─ 하위 개념 C

인접 개념
↔ 목적·방법·적용 조건을 비교
```

예:

```text
Machine Learning
├─ 지도학습
│   ├─ 분류
│   └─ 회귀
├─ 비지도학습
│   ├─ 군집
│   └─ 차원축소
└─ 강화학습
    └─ MDP → Q-Learning → DQN
```

여기서 `지도학습 → 비지도학습 → 강화학습`은 발전 순서가 아니다. 반면 `MDP → Q-Learning → DQN`은 실제 학습 의존 흐름으로 연결할 수 있다.

## 5. 직접 인과가 있으면 흐름을 살린다

개념 사이에 실제 문제·해결 관계가 있으면 그 이유가 보이도록 연결한다.

```text
문제
 ↓
개념 A로 해결
 ↓
새 한계 또는 다음 문제
 ↓
개념 B 필요
```

예:

```text
RNN
 ↓
긴 Sequence에서 장기 의존성 학습이 어려움
 ↓
LSTM / GRU
```

하지만 실제 인과가 없는 병렬 Algorithm을 억지로 발전 사슬로 만들지 않는다.

## 6. 분류축을 섞지 않는다

학습지도에서 가장 조심할 오류다.

```text
[학습 방식]
지도 / 비지도 / 강화

[Architecture]
CNN / RNN / Transformer

[생성 방식]
Autoregressive / GAN / Diffusion

[활용 방식]
Prompt / RAG / Fine-tuning / Agent
```

따라서 다음처럼 그리지 않는다.

```text
CNN → RNN → GAN → Transformer   X
```

필요하면 서로 다른 축이 실제 시스템에서 어떻게 조합되는지 별도로 연결한다.

## 7. 적정 깊이

학습지도는 목차보다 깊고 세부학습보다 얕다.

다음 수준까지는 적극적으로 남긴다.

- 학습할 가치가 있는 핵심 용어
- 상위·하위·인접 개념
- 직접 의존 관계
- 대표 비교 대상
- 다음에 파고들 Algorithm·Architecture·Protocol

반면 다음은 세부학습으로 내린다.

- 수식 전개
- 내부 Algorithm 단계의 상세
- Parameter별 동작
- 긴 예제
- 구현 Code
- 제품별 설정

예를 들어 `RAG → Vector Search → ANN → HNSW / IVF`는 학습지도에 남기지만, HNSW의 Graph 탐색 Algorithm 상세는 세부학습에서 다룬다.

## 8. Text/ASCII Diagram을 기본으로 한다

모바일 GitHub, Obsidian, Terminal 등 어디서든 읽을 수 있도록 Text/ASCII Diagram을 기본으로 한다.

```text
상위
├─ 현재 A
│   ├─ 하위 A-1
│   └─ 하위 A-2
└─ 인접 B
```

Mermaid는 관계가 복잡해 Text보다 명확해질 때만 선택적으로 사용한다.

## 9. 학습등급표에서 출발하되 그대로 복사하지 않는다

학습등급표는 학습할 Topic의 Source다.

```text
학습등급표 Topic
 ↓
상위 개념 확인
 ↓
하위·인접 개념 확장
 ↓
실제 의존 관계 확인
 ↓
학습지도에 재배치
```

교재의 Part 번호나 Topic 순서를 그대로 Tree로 옮기지 않는다. 학습 이해에 맞는 개념 관계로 재구성한다.

학습등급표에 없더라도 상위 개념을 이해하거나 주요 Topic 사이를 연결하는 데 꼭 필요한 개념은 학습지도에 추가할 수 있다. 이 경우 시험 중요도와 학습 우선순위 판단은 다시 학습등급표에서 한다.

## 10. 학습지도에서 세부학습으로 내려가는 기준

Node 하나를 선택했을 때 다음 질문이 생기면 세부학습으로 내려간다.

```text
왜 필요한가?
어떻게 동작하는가?
내부 구성은 무엇인가?
어떤 Trade-off가 있는가?
비슷한 개념과 정확히 무엇이 다른가?
```

학습 중 새로운 하위·인접 개념을 발견하면 다시 학습지도에 연결한다.

```text
학습등급표
   ↓
학습지도
   ↓
세부학습
   ↓
새로운 연결 발견
   └────────→ 학습지도 보강
```
