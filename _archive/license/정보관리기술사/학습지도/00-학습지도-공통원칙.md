# 정보관리기술사 학습지도 공통 원칙

> 학습지도로 전체 구조와 개념 간 관계를 먼저 이해해 지식의 뼈대를 만든다. 이후 중요도와 기출에 따라 교재에서 필요한 세부 지식을 선택적으로 확장한다.

## 1. 학습지도의 목적

성안당 교재의 목차는 많은 토픽을 책의 편집 순서로 나열한다. 학습지도는 이 토픽을 모두 요약하는 문서가 아니다. 다음 질문에 답할 수 있도록 학습의 방향과 순서를 제시한다.

1. 이 권은 정보기술 전체에서 어떤 문제를 다루는가?
2. 각 개념은 전체 흐름에서 어디에 위치하는가?
3. 앞 개념만으로 해결할 수 없는 어떤 문제 때문에 다음 개념이 필요한가?
4. 서로 비슷한 개념은 목적·책임·적용 조건이 어떻게 다른가?
5. 시험 중요도에 따라 어디까지 공부해야 하는가?

지엽적 지식을 버리는 것이 목적은 아니다. 먼저 세부 지식을 걸어둘 구조를 만들고, 필요한 내용을 교재에서 찾아 확장하는 것이 목적이다.

## 2. 학습지도와 자료별 역할

| 자료 | 역할 |
|---|---|
| 학습지도 | 전체 구조, 개념의 위치와 관계, 중요도, 회독 경로를 제시한다. |
| 성안당 교재 | 정의·구성요소·절차·비교·사례·계산 등 세부 지식을 확장한다. |
| 기출문제 | 실제 질문 형태와 반복 출제를 확인하고 A/B/C 등급을 보정한다. |
| 최신 공식 자료 | 법령·표준·제도·제품·Architecture의 현행성을 확인한다. |
| 개인 학습노트 | 이해한 내용을 자신의 언어와 답안 구조로 다시 작성한다. |

학습지도만 외우거나 교재를 처음부터 같은 깊이로 읽지 않는다. 학습지도에서 위치와 관계를 확인하고, 교재에서 필요한 깊이만큼 세부 내용을 찾아본 뒤 다시 전체 지도에 연결한다.

## 3. 기본 학습 순환

```text
거시적 구조 파악
→ 개념의 위치 확인
→ 앞뒤 개념과의 관계 이해
→ 중요도에 따라 학습 깊이 결정
→ 교재에서 정의·구성요소·절차·사례 보강
→ 기출문제로 질문 형태 확인
→ 자신의 언어로 다시 설명
→ 전체 구조에 재연결
```

처음부터 모든 세부 내용을 암기하지 않는다. 먼저 “무슨 문제를 해결하는 개념인가”를 설명할 수 있게 하고, 이후 시험에 필요한 전문용어와 답안 요소를 붙인다.

## 4. 거시 지도 작성 원칙

각 권의 첫 부분에는 토픽 목록보다 해당 분야의 큰 흐름을 먼저 제시한다.

- **스파인**: 시간이나 처리 순서에 따라 이어지는 중심 흐름
- **분기**: 같은 기반에서 서로 다른 문제를 해결하는 병렬 흐름
- **횡단 기준**: 보안·품질·위험·Governance처럼 전 과정에 반복 적용되는 기준
- **적용 영역**: 기본 흐름을 특정 기술·산업·환경에 적용한 사례
- **피드백**: 운영·측정 결과가 앞 단계의 요구와 설계에 되돌아가는 관계

모든 개념을 하나의 긴 화살표로 만들지 않는다. 실제 선후관계, 병렬관계, 횡단관계, 적용 사례를 구분한다.

## 5. 개념 연결 원칙

개념은 이름의 유사성이나 교재 번호가 아니라 문제와 해결 관계로 연결한다.

```text
현재 상황과 문제
→ 기존 방식의 한계
→ 필요한 개념
→ 이 개념이 제공하는 해결 방법
→ 새로 생기는 비용·위험·Trade-off
→ 다음 개념 또는 통제의 필요성
```

예를 들어 데이터베이스에서는 다음처럼 연결한다.

```text
여러 사용자가 동시에 Data를 변경한다.
→ 갱신 유실이나 Dirty Read가 발생할 수 있다.
→ Transaction과 동시성 제어가 필요하다.
→ Lock과 직렬성으로 올바른 결과를 보장한다.
→ 대기시간과 Deadlock이 생길 수 있다.
→ Lock 범위·격리수준·Deadlock 통제가 필요하다.
```

## 6. 중요도 등급

등급은 개념의 절대적 가치가 아니라 **정보관리기술사 1차 학습에서 투자할 깊이**를 뜻한다.

| 등급 | 학습 깊이 | 완료 기준 |
|---|---|---|
| A | 답안으로 작성할 핵심 | 목적·구조·절차·비교·적용·한계를 설명한다. |
| B | 관계 이해와 대표 비교 | 역할과 앞뒤 관계를 설명하고 핵심 차이를 비교한다. |
| C | 위치만 확인 | 명칭과 전체 지도상의 위치만 확인하고 기출 근거가 있을 때 보강한다. |

기초 개념이라는 이유만으로 A를 부여하지 않는다. 중요도와 학습 순서는 태그로 구분한다.

## 7. 태그 사용 기준

| 태그 | 의미 |
|---|---|
| `[선행]` | 다른 개념보다 먼저 이해해야 한다. |
| `[횡단]` | 여러 단계와 주제에 반복 적용된다. |
| `[중복]` | 같은 권의 다른 번호와 내용이 겹친다. |
| `[타권중복]` | 다른 Vol.에서 더 깊게 다룬다. |
| `[세부]` | 계산·코드·도식 등 반복 실습 비중이 크다. |
| `[현행]` | 낡은 용어·제품·표준일 가능성이 있어 현재 유효성을 확인한다. |
| `[최신]` | 최신 법령·표준·Architecture·기출 맥락으로 보강한다. |

`[현행]`과 `[최신]`은 모든 최신 기술을 추가로 공부하라는 지시가 아니다. 답안에 사용하기 전에 현재 유효한 명칭·적용 조건·책임·절차를 공식 자료로 확인하라는 표지다.

## 8. 쉬운 표현 작성 원칙

학습지도는 해당 용어를 처음 접하는 사람도 흐름을 따라갈 수 있어야 한다.

1. 쉬운 상황과 문제를 먼저 설명한다.
2. 전문용어는 쉬운 설명 뒤에 붙인다.
3. 처음 나오는 낯선 용어에는 한 줄 뜻을 제공한다.
4. 영어를 장식처럼 섞지 않고 필요한 정식 명칭에만 사용한다.
5. 압축된 명사 나열보다 주어와 동사가 있는 문장을 사용한다.
6. 도식 아래에는 화살표가 의미하는 관계를 문장으로 설명한다.

```text
쉬운 상황 설명
→ 해결해야 할 문제
→ 필요한 개념과 전문용어
→ 앞뒤 개념과의 관계
→ 중요도에 따른 학습 범위
```

## 9. 회독 방법

### 1차 회독: 지도 형성

- 각 권의 역할과 거시 구조를 이해한다.
- A급도 세부 암기보다 목적과 앞뒤 관계를 먼저 본다.
- B급은 전체 지도상의 역할과 대표 비교를 확인한다.
- C급은 명칭과 위치만 표시한다.

### 2차 회독: 세부 확장

- A급을 중심으로 교재의 정의·구성요소·절차·비교·사례를 보강한다.
- 유사 개념 비교표와 핵심 도식을 만든다.
- B급은 A급을 설명하는 데 필요한 범위까지 확장한다.
- 계산·코드·Diagram은 대표 문제로 원리를 한 번 확인한다.

### 3차 회독: 기출과 답안화

- 기출에서 어떤 형태로 결합되어 묻는지 확인한다.
- 배경·문제점·개념·구성·절차·비교·기대효과·한계로 답안을 구성한다.
- 반복 출제와 최신 사례를 근거로 A/B/C를 조정한다.
- 조정한 근거를 각 권의 보정 기록에 남긴다.

## 10. 최신성·근거 검증 원칙

법령·표준·제도·제품·기술 세대는 학습 시점에 달라질 수 있으므로 공식 자료를 우선 확인한다.

- 법령·행정규칙: 국가법령정보센터 등 현행 원문
- 국제표준: ISO·IEC·IEEE 등 발행기관
- Framework: 관리기관 또는 공식 발행처
- 기술 사양: 공식 문서와 표준
- 시험 중요도: 공식 출제기준과 실제 기출

공식 근거를 확인하지 않은 추정은 등급 변경의 확정 근거로 사용하지 않는다.

## 11. 권간 연결 원칙

같은 개념이 여러 권에 나오면 내용을 반복 복사하지 않고 각 권의 관점을 구분한다.

- Vol.4 보안: 위협·통제·보호 관점
- Vol.5 SW공학: 생명주기·품질·변경 관점
- Vol.7 IT경영: 가치·책임·Governance 관점
- Vol.8 DB: 구조·정합성·성능·품질 관점
- Vol.9 AI: Data·Model·평가·운영 위험 관점
- Vol.10 Cloud: 공유책임·탄력성·운영 서비스 관점

다른 권에서 깊게 학습할 내용은 `[타권중복]`으로 표시하고, 현재 권에서는 연결 위치와 해당 관점만 이해한다.

## 12. 보강 실행계획과 진행 현황

아래 계획은 초안 반영 여부와 공식 근거 검증 상태를 구분한다.

### 1단계: 통합형 즉시 보강

출제 연결성이 높고, 다른 권과의 결합이 많은 항목을 먼저 정리한다.

1. **Vol.8 ↔ Vol.9 ↔ Vol.10의 데이터-서비스 축 — 초안 반영 완료, 근거 검증 필요**
   - Vol.8(데이터) `데이터 표준화`, `메타데이터`, `데이터 품질`, `CDC` 관련 서술을 기준으로 공통 템플릿을 맞춘다.
   - Vol.9(AI) `훈련/평가/편향`, `보안 위협`, `운영 통제` 문장을 위 템플릿에 연결한다.
   - Vol.10(클라우드) `멀티테넌시`, `규제`, `SLA`를 데이터 거버넌스 관점으로 정합한다.

2. **Vol.4 ↔ Vol.7의 보안/거버넌스 축 — 초안 반영 완료, 근거 검증 필요**
   - Vol.4(보안) `PIA`, `개인정보/법률`, `Cloud Computing 보안` 항목에 의사결정 흐름을 붙인다.
   - Vol.7(IT 경영) `IT Governance`, `Compliance`, `감리`, `SLA/SLM` 항목을 동일 흐름(목표→측정→보고→개선)으로 맞춘다.

3. **Vol.2 ↔ Vol.3 ↔ Vol.10 운영·인프라 축 — 초안 부분 반영, Vol.10의 Vol.2/3 연계 확인 필요**
   - Vol.2(운영체제) 가상화/HA/튜닝 항목을 Vol.10(클라우드)로 이어지는 책임·가용성 축으로 묶는다.
   - Vol.3(네트워크) SDN/NFV/IoT 운영 특성을 Vol.10 네트워크·스토리지 항목과 매칭한다.

### 2단계: 단권 내 보강 (최종 정돈)

각 권에서 현재 한 줄만 덧붙이면 답안 품질이 올라가는 항목.

- **Vol.1 컴퓨터 구조**: GPU/벡터/분산, `Watchdog`의 운영 관점(장애 탐지/대응 책임) 1~2문장으로 정리. — 초안 반영 완료, 근거 검증 필요
- **Vol.2 운영체제**: 실시간 OS/임베디드 관련 항목에 — 일부 반영, 정책·우선순위 역전·동기화 압축 문단 미반영
  - 워크로드 유형 → 정책 선택 → 부작용(우선순위 역전/세마포어/교착) 순서로 압축 문단 추가.
- **Vol.3 네트워크**: `SDN`·`NFV`·`5G` 최신 적용 시나리오를 기존 Layer/전송/보안 축과 함께 요약. — 일부 반영, 5G 적용 시나리오 미반영
- **Vol.4 보안**: `PIA`는 처리 전 영향평가 흐름으로, `Cloud Security`는 탐지→격리→근절·완화→복구→재발방지 흐름으로 각각 정리한다. — 초안 반영 완료, 근거 검증 필요
- **Vol.5 소프트웨어 공학**: `DevOps/AGILE/운영 피드백`, `테스트/검증·반복주기`를 시험에서 바로 쓰는 문장으로 고정. — 초안 반영 완료, 근거 검증 필요
- **Vol.6 알고리즘**: 정렬·탐색·트리/그래프의 `선택 기준`만 남기고, 반복 손계산은 한 번의 대표 예시로 축소. — 초안 반영 완료, 근거 검증 필요
- **Vol.8 DB**: 분산/샤딩/복구에서 `오류·복구비용`을 운영 지표와 함께 써서 `성능만능` 판단을 방지. — 초안 반영 완료, 근거 검증 필요
- **Vol.9 AI**: 설명가능성(XAI), 모델 위험, 공격면에서 `조치 항목`(탐지·차단·회귀평가)으로 묶는다. — 초안 반영 완료, 근거 검증 필요
- **Vol.10 클라우드**: `멀티/하이브리드/서버리스`, `VM vs Container`, `Auto Scaling`에 운영 KPI와 책임 분리 기준을 붙인다. — 초안 반영 완료, 근거 검증 필요

### 3단계: 교재 단어 정리(현행성 보정)

`[현행]` 태그가 붙은 항목은 폐기·개정 여부를 한 번 확인하고 사용 조건·운영 책임·평가 지표만 남긴다.

- Vol.1: `North Bridge`/`South Bridge`의 SoC 이전 표기 정리.
- Vol.2: `OpenStack`은 Cloud 운영체제 개념으로 통합(커널 OS와 구분).
- Vol.3: `Mobile IPv4`, `FMC/FMS`, `Wi-Fi` 세대 표기 중 핵심만 남기고 최신 아키텍처로 대치.
- Vol.4: `CPO`, `ESM`, `NIST` 등 제도/기술 명칭은 최신 명칭·절차가 무엇인지 한 줄 주석화.
- Vol.5: `BIModal`·`TRIZ` 등 교재 유행어는 질문 적합성 기준으로만 설명.
- Vol.7~10: `ITIL v3`, 폐기·개정된 보안기술·표준·인증은 현행 문헌/가이드에서 최신 기준을 추적해 병행 표기.

#### 3단계 대상 진행 지침(권장)

- 보강 대상은 각 권의 `보정 기록`에 항목별 1~2줄만 추가해, 1차 분류 구조를 깨지 않는다.
- `[현행]`/`[최신]` 변경은 용어 대체가 아니라 `사용 조건·운영 책임·평가 지표`의 문장 보강으로 처리한다.
- Vol.1/5/6/9/10은 5건 동시 마감 후, `grep "보정 기록"`으로 변경 범위를 재점검한다.

### 근거 검증 기록

공식 출제기준이나 기출을 실제로 확인해 등급을 변경할 때만 각 권의 `보정 기록`에 다음 내용을 남긴다.

- `기존 등급 → 새 등급`
- `근거 회차 또는 공식 자료`
- `변경한 이유와 질문 형태`
