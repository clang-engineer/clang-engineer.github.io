# Vol. 5 소프트웨어 공학 학습지도

> 기준: 정보관리기술사 단독 대비를 위한 1차 분류다. 공식 출제기준과 최근 기출을 분석한 뒤 등급을 보정한다. A는 답안 골격, B는 비교·연결, C는 식별 또는 선택 보강이다.

## 이 권의 역할

소프트웨어 공학은 불확실한 요구를 운영 가능한 제품으로 바꾸고, 변경·품질·일정·비용 위험을 생명주기 전체에서 통제하는 방법을 제공한다.

핵심 질문은 세 가지다.

1. 요구에서 설계·구현·검증·운영까지 추적 가능한 흐름을 어떻게 만드는가?
2. 개발 방식과 아키텍처를 상황에 맞게 선택하고 변경 비용을 어떻게 낮추는가?
3. 품질·일정·비용·라이선스·표준 위험을 어떻게 측정하고 통제하는가?

## 권 내부 큰 그림

```text
사업 목표와 이해관계자 요구
→ 요구 도출·분석·명세·검증·변경관리
→ 위험과 불확실성에 맞는 생명주기·방법론 선택
→ 모델·아키텍처·모듈화로 책임과 변경 영향 분리
→ 구현·통합·형상관리와 자동화
→ Verification·Validation·Test로 결함을 조기 발견
→ 품질 지표·표준·프로세스 개선
→ PM이 범위·일정·원가·위험·이해관계자를 통합 통제
→ 운영 피드백을 요구와 설계에 환류
```

중심은 **추적성, 피드백, 분리와 결합, 위험 기반 선택, 품질의 내재화**다. 방법론·표준 이름은 이 인과관계에 배치한다.

## 권장 학습 순서

### 1단계: 공학화와 생명주기

`SW 위기·공학 → SDLC → 모델 선정 → Review·Inspection·Walkthrough → Baseline·형상통제`

개발이 개인 코딩이 아니라 반복 가능한 조직 활동이어야 하는 이유부터 잡는다. 폭포수·증분·나선형은 암기 목록이 아니라 요구 안정성, 위험, 피드백 주기에 따른 선택지로 비교한다.

### 2단계: 요구·설계·아키텍처

`요구공학 → Modeling·UML → 모듈화·응집도/결합도 → 객체지향 원칙 → Architecture·View`

요구의 모호성과 변경을 추적성으로 통제하고, 모델과 아키텍처로 이해관계자 관점을 분리한다. Java 코드 변환은 표기 의미를 확인하는 보조 실습이지 정보관리 답안의 목표가 아니다.

### 3단계: 개발 방법과 전달 흐름

`전통 방법론 → Agile·Scrum·XP·Kanban → TDD → DevOps → CI·Daily Build·Test Automation`

짧은 피드백이 불확실성을 줄이는 흐름을 본다. 행사·도구 목록보다 작은 배치, 자동 검증, 운영 피드백, 조직 책임 공유를 답안 축으로 삼는다.

### 4단계: 품질과 시험

`품질 목표 → V&V → Test 전략·설계 → Coverage·Oracle → Risk·Regression Test → 품질보증·개선`

품질 특성에서 검증 목표와 시험 수준·기법을 도출한다. 코드 커버리지는 관측 지표이지 요구 충족이나 결함 부재의 증명이 아님을 구분한다.

### 5단계: 프로젝트 통제

`Project·Program·Portfolio → PM Process·PMO → Scope·WBS → Schedule·CPM → Risk·Stakeholder → EVM`

범위가 작업과 일정·원가 기준선을 만들고, 실적 데이터가 예측과 시정조치로 이어지는 구조를 익힌다. CPM·EVM 계산은 지표 의미를 설명할 수 있을 만큼만 손으로 확인한다.

### 6단계: 생태계·표준

`OSS·License·IP → SW 품질모델 → 생명주기·프로세스 평가 표준 → 기능안전·서비스 품질`

라이선스는 사용·수정·배포 조건과 공급망 통제로, 표준은 목적·적용 대상·산출물 관계로 학습한다. 버전·폐지·대체 여부는 최신 공식 문서로 교체한다.

## 토픽 간 연결

```text
요구가 불완전하고 변경됨
→ 짧은 Feedback과 Prototype·Increment 필요
→ 변경이 구조 전체로 전파될 위험
→ 모듈화·정보은닉·낮은 결합·Architecture View 적용
→ 변경 단위를 형상항목과 Baseline으로 통제
→ 자동 Build·Test로 회귀 위험 관측
→ 운영 결과를 다음 요구와 Backlog에 환류
```

```text
품질 목표 정의
→ 요구의 검증 가능 조건으로 구체화
→ Review로 정적 결함 예방
→ Test 수준·기법·Oracle 설계
→ Coverage·결함·운영 지표 측정
→ 위험이 큰 영역에 시험 집중
→ 원인 분석과 Process 개선
```

```text
승인된 Scope
→ WBS·Activity·의존관계

→ 수행 실적 PV·EV·AC 수집

→ 원인·예측·시정조치·변경통제
```

## 기출 보정 기록

아직 공식 출제기준과 최근 기출을 반영하지 않은 1차 분류다.

- 요구·Architecture·Agile/DevOps·Test·PM이 결합된 사례형 질문은 구성 요소별 깊이를 함께 승급한다.
- PMBOK, ISO/IEC, IEEE, 품질모델, License는 출제 시점의 최신 공식 판과 대체 관계를 확인한다.
- 코드 작성·Diagram 변환·CPM/EVM 계산은 반복 출제된 형식만 최소 실습으로 승급한다.
- 구형 표준은 역사적 개념 가치와 현재 적용 가능성을 분리하고, 폐지·대체 사실을 답안에 명시한다.
- 변경 시 `기존 등급 → 새 등급`, 근거 회차, 질문 형태를 기록한다.
