# Vol. 7 IT 경영 학습지도

> 기준: 정보관리기술사 단독 대비를 위한 1차 분류다. IT 경영은 기술을 사업 목표·투자·거버넌스·운영·위험에 배치하는 거시 좌표계다. 유행어와 제도 세부는 현재 유효성을 확인한 뒤 학습한다.

## 이 권의 역할

IT 경영은 회사의 목표를 실제 IT 투자와 운영으로 연결하는 방법을 다룬다. 쉽게 말하면 **왜 이 기술에 돈을 쓰는지, 어떤 일을 먼저 할지, 누가 책임질지, 성과와 위험을 무엇으로 확인할지** 결정하는 체계다.

핵심 질문은 세 가지다.

1. 사업 목표에 맞춰 IT의 전체 구조를 설계하고, 어떤 과제에 먼저 투자할 것인가?
2. 시스템을 구축하거나 외부에 맡기고 운영할 때 비용·품질·책임을 어떻게 관리할 것인가?
3. 장애, 법규 위반, 품질 저하 등의 위험을 어떻게 측정하고 개선할 것인가?

이 지도는 용어를 책순으로 외우기보다 **앞 개념의 한계가 왜 다음 개념을 필요로 하는지**를 이해하는 데 목적이 있다.

```text
사업 목표만으로는 구현할 수 없다.
→ EA·ISP로 목표 구조와 실행 실행계획을 만든다.

후보 과제를 모두 수행할 수는 없다.
→ Business Case·PPM으로 가치·위험·자원을 비교한다.

구축 완료만으로 서비스 가치가 보장되지 않는다.
→ SLA·SLM·ITSM으로 운영 수준과 책임을 관리한다.

장애 예방만으로 업무 중단에 대비할 수 없다.
→ BIA·RTO/RPO·BCP/DR로 복구 우선순위와 목표를 설계한다.

실행했다는 사실만으로 성과와 적정성을 증명할 수 없다.
→ KPI·BSC·컴플라이언스·감리/감사로 측정하고 검증한다.
```

## 권 내부 큰 그림

IT 경영의 모든 개념이 한 줄로 이어지는 것은 아니다. 중심에는 **목표를 세우고 → 과제를 골라 실행하고 → 서비스를 운영하고 → 성과를 확인하는 흐름**이 있다. 거버넌스·위험·컴플라이언스는 마지막에 한 번 확인하는 단계가 아니라, 이 흐름 전체에서 계속 적용하는 판단 기준이다.

```text
[횡단 의사결정 체계: 전 과정에 교차]
● IT 거버넌스(누가 어떤 원칙으로 결정하고 책임지는지 정하는 체계)  ● 감수할 위험의 범위  ● 컴플라이언스(준수 요구→통제 적용→증거 보관)
● Data 거버넌스(소유권·품질·보안)      ● 성과체계(KPI·BSC·성과)

[전략→실행→운영 스파인]

외부 환경과 사업 전략 분석
→ 목표 달성에 필요한 업무 능력과 예상 성과 정의
→ EA·ISP(현행/목표 구조·Gap·실행계획)
→ 예상 성과·위험·예산·인력을 비교해 수행할 과제 선택
→ Program/프로젝트 실행
│  ├─ Process 혁신: BPR·PI·BPM
│  ├─ 조달·계약: Build/Buy/Outsource → RFP·SOW·SLA
│  ├─ 전사 시스템: ERP·SCM·CRM
│  └─ 통합: EAI·API·Platform
→ ITSM·SLM 운영(Incident 복구·Problem 원인 제거)
→ 성과와 품질을 측정하고 감리·감사로 독립적으로 확인
→ 전략·아키텍처·포트폴리오에 환류

[업무 중단 위험 분기]

업무 중단 위협
├─ 위험 Assessment: 위협·취약성·발생 가능성 분석
└─ BIA: 핵심 업무·중단 영향·복구 우선순위 분석
   → RTO/RPO 등 복구 목표
   → BCP/DR/HA·Backup 전략
   → 훈련·시험·개선

[변화 적용 영역]

데이터·디지털·AI·플랫폼은 앞의 의사결정과 관리 체계를 적용하는 영역이다. 모든 활동이 반드시 이 기술들로 끝나는 것은 아니다.
```

### 먼저 알아둘 용어

| 용어 | 쉬운 뜻 |
|---|---|
| 거버넌스(거버넌스) | 누가 어떤 원칙으로 결정하고 그 결과를 책임지는지 정하는 체계 |
| 아키텍처(아키텍처) | 조직의 업무·Data·Application·기술이 어떻게 구성되고 연결되는지 나타낸 전체 구조 |
| EA | 기업 전체의 현재와 목표 아키텍처, 원칙과 전환 방향을 관리하는 체계 |
| ISP | 사업 전략에 맞는 정보화 과제와 실행 실행계획을 만드는 계획 |
| Business Case | 투자 비용·편익·위험을 비교해 과제를 수행할 근거를 만드는 것 |
| 포트폴리오 | 여러 후보 과제를 함께 비교하여 우선순위와 자원 배분을 정하는 것 |
| SOW | 공급자가 수행할 업무 범위·산출물·역할·일정을 적은 문서 |
| SLA | 서비스 수준과 측정방법·보고·위반 대응을 합의한 문서 |
| 컴플라이언스 | 법·규정·계약·내부 정책의 요구를 통제로 구현하고 준수 증거를 남기는 활동 |
| BIA | 업무가 중단됐을 때 피해와 복구 우선순위를 분석하는 활동 |
| RTO | 업무 또는 시스템을 언제까지 복구해야 하는지를 나타낸 목표시간 |
| RPO | 복구할 때 어느 시점까지의 데이터가 보존돼야 하는지를 나타낸 목표 |

## 권장 학습 순서

전체 학습 흐름: `IT 가치·전략·Capability → ROI/TCO → 거버넌스·위험·컴플라이언스 역할 → EA/ISP·Business Case·포트폴리오 → 실행 분기(Process·조달·전사 시스템·통합) → ITSM 운영 → BIA·BCM/DR → 성과·품질 → 감리/감사 독립성 → Data·Digital 종합 적용`

아래 번호는 선행 학습 순서다. `→`는 이해 순서이며, 거버넌스·위험·컴플라이언스는 전 과정에 교차하는 **횡단 기준**으로 1단계에서 역할을 잡고 이후 반복 적용한다. BCM/DR은 보편적 마지막 단계가 아니라 **업무 중단 위험 분기**로 본다.

1. `정보·System·IT 경영 → 환경분석·전략 → ROI/TCO`로 의사결정 언어를 만든다. 이 단계에서 거버넌스·위험·컴플라이언스의 횡단 역할을 먼저 정리한다.
2. `EA/ISP`로 전략을 정보System 구조와 실행계획으로 내리고, `Business Case·PPM`으로 후보 과제를 선택한다. `BPR/PI`(Process 변화)·`EAI/API`(통합)는 단일 계보가 아닌 실행 분기로 본다.
3. `ERP/SCM/CRM/BPM`은 제품 목록이 아니라 전사 Process·Data 통합 사례로 본다.
4. `Outsourcing·RFP/SOW/SLA → ITSM/ITIL/ISO 20000`으로 조달과 서비스 책임을 연결한다.
5. `위험 → BIA → RTO/RPO → BCP/DR·HA → 시험·개선`을 업무 중단 위험에 대한 특수 분기로 설계한다.
6. `BSC·성과`으로 실행 성과를 측정하고 `거버넌스·컴플라이언스·품질·감리`를 의사결정·통제·독립 검증 관점에서 종합한다.
7. `Data 거버넌스·Analytics·Platform·Digital 전환`은 위 체계를 적용하는 최신 영역으로 보정한다.

## 2단계 보강 반영(Vol.7)

### 핵심 템플릿

먼저 사업이 이루려는 목표를 확인한다. 그다음 누가 결정하고 책임질지 정하고, 투자·조달·서비스 수준을 결정한다. 운영 결과는 지표로 측정하고, 감사와 개선 활동을 통해 다시 의사결정에 반영한다.

`사업목표 → 책임과 의사결정 구조 → 투자·조달·SLA 결정 → 운영 지표 → 감사·개선`

### Vol.4 + Vol.7 연계 정리

`Security Oversight`의 감시체계와 `SLA`, `컴플라이언스`는 분리된 항목이 아니라 `위험 수용 기준·책임·측정`을 묶는 한 흐름이다.
- 보안 통제는 기술 항목이 아니라 경영 의사결정의 근거와 감사 추적 가능성으로 설명한다.
- 개인정보, 감사, ISMS 계열의 요구는 `규칙 준수`보다 `경영 목표와 충돌하는 업무 우선순위`에서 어떻게 조정되는지가 중요하다.

### Vol.7 + Vol.10 연계 정리

클라우드·외부용역 의존이 커질수록 `SOW/SLM/ITSM`의 문구가 아니라 `책임 범위·전이 조건·측정 주기`가 핵심이다.
- `SLA`는 서비스 수준의 측정·보고·위반 대응을 정하고, 업무연속성 요구가 있으면 RTO/RPO·DR 기준과 연계한다.
- `Sourcing` 위험은 계약 종료/업체 이탈까지 포함해 BIA와 연결해야 실제 경영 답안이 된다.

## A/B/C 분류

번호 범위는 양 끝을 포함하며 모든 원본 번호를 한 번만 배정한다. **등급은 학습 깊이**, 태그는 **학습 순서와 역할**을 뜻한다.

- A: 정의·구조·절차·비교·적용까지 답안화한다.
- B: 핵심 개념과 거시적 연결, 대표 비교를 이해한다.
- C: 명칭과 지도상의 위치만 확인하고 기출 근거가 있을 때 승급한다.
- `[선행]`: 등급과 별개로 다른 개념보다 먼저 이해한다.
- `[횡단]`: 여러 단계에 반복 적용되는 기준·기법이다.
- `[타권중복]`: 이 권에서는 위치만 잡고 관련 권에서 깊이를 보완한다.
- `[최신]`: 현행 표준·법제·아키텍처로 확인한다.

## 1차 회독 통과 경로

아래 흐름은 용어 암기용 목록이 아니다. 각 화살표를 **앞 단계만으로 해결할 수 없는 문제가 무엇인지** 생각하며 읽는다.

첫 회독은 161개 토픽을 같은 깊이로 읽지 않는다. 다음 여섯 관계를 설명할 수 있을 정도로만 통과한다.

1. `전략 → EA/ISP → Business Case·PPM → 프로젝트 → 성과`
2. `BPR/PI → BPM → 전사 System → EAI/API → Process Mining`
3. `Sourcing → RFI/RFP → SOW/SLA → SLM/ITSM`
4. `Incident 복구 → Problem 원인 제거 → 지속 개선`
5. `위험 Assessment·BIA → RTO/RPO → BCP/DR/HA → 시험·개선`
6. `거버넌스·컴플라이언스 → KPI/BSC → 감리·감사`

첫 회독에서 C급은 정의를 암기하지 않고 어느 흐름에 놓이는지만 표시한다. A급도 세부 산식·법 조문보다 **목적, 앞뒤 관계, 의사결정 기준**을 먼저 잡는다.

## 보정 기록

- 전략 도구 이름보다 사례에서 의사결정 논리와 성과·위험를 요구하는지로 승급한다.
- 법령·감리·공공제도·ISO·ITIL은 출제 시점의 최신 공식 문서로 명칭·대상·절차를 확인한다.
- RTE, BI 세대, O2O/O4O, Bimodal 등 낡은 유행어는 현재 아키텍처나 운영모델을 설명할 가치가 없으면 C를 유지한다.
- Data·AI·Platform·Digital 전환은 최신 기출의 거버넌스·품질·윤리·성과 관점을 추가한다.
- 변경 시 `기존 등급 → 새 등급`, 근거 회차, 질문 형태를 기록한다.
- `[최신]` 표기는 용어 교체보다 의사결정 책임 구조를 최신 맥락에 맞춰 정렬한다.
  - `SLA/SLM`는 수치 준수 항목이 아니라 측정·보상·복구 검증의 R&R이 포함되어야 한다.
  - `ITIL/ISO 20000`은 버전 암기보다 가치 흐름과 개선 루프 중심으로 정비한다.
  - `BSC/PMO/감리`는 독립성·통제·보고 책임을 문장 한 줄로 구분해 답안에 넣는다.
