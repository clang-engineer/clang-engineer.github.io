# Vol. 7 IT 경영 학습지도

> 기준: 정보관리기술사 단독 대비를 위한 1차 학습지도다. IT 경영은 사업 목표가 IT 투자·구축·운영·성과로 이어지는 전체 흐름을 다룬다. 과거의 경영 유행어나 변경 가능한 제도는 현재도 유효한지 확인한 뒤 학습한다.

## 이 권의 역할

IT 경영은 회사의 목표를 실제 IT 투자와 운영으로 연결하는 방법을 다룬다. **왜 IT에 투자하는지, 어떤 과제를 먼저 수행할지, 누가 결정하고 책임질지, 투자와 운영의 성과를 어떻게 확인할지**를 정하는 체계다.

핵심 질문은 세 가지다.

1. 사업 목표를 어떤 IT 과제와 투자로 바꿀 것인가?
2. 선택한 과제를 어떻게 구축하고 안정적으로 운영할 것인가?
3. 투자 성과와 위험을 어떻게 측정하고, 누가 그 결과를 책임질 것인가?

이 지도는 용어를 책순으로 외우기보다 **앞 개념의 한계가 왜 다음 개념을 필요로 하는지**를 이해하는 데 목적이 있다.

```text
사업 목표만으로는 무엇을 어떻게 정보화할지 알 수 없다.
→ EA로 현재와 목표 구조를 정리하고, ISP로 IT 과제와 실행계획을 만든다.

필요한 과제를 모두 수행할 수는 없다.
→ 투자 비용·예상 성과·위험을 검토하고, PPM으로 우선순위를 정한다.

시스템을 구축했다고 서비스 가치가 저절로 보장되지는 않는다.
→ SLA로 기대 수준을 합의하고, SLM·ITSM으로 운영하고 개선한다.

장애를 예방하는 것만으로 업무 중단에 대비할 수는 없다.
→ BIA로 복구 우선순위를 정하고 RTO·RPO에 맞는 BCP·DR 대책을 마련한다.

과제를 실행했다는 사실만으로 투자 성과와 적정성을 증명할 수는 없다.
→ KPI·BSC로 성과를 측정하고 컴플라이언스·감리·감사로 적정성을 확인한다.
```

## 권 내부 큰 그림

IT 경영의 모든 개념이 한 줄로 이어지는 것은 아니다. 중심에는 **목표를 세우고 → 과제를 골라 실행하고 → 서비스를 운영하고 → 성과를 확인하는 흐름**이 있다. 거버넌스·위험·컴플라이언스는 마지막에 한 번 확인하는 단계가 아니라, 이 흐름 전체에서 계속 적용하는 판단 기준이다.

```text
[전 과정에서 계속 확인할 질문]
● 누가 어떤 원칙으로 결정하고 책임지는가? → IT 거버넌스
● 어떤 위험까지 감수하고 어떤 규칙을 지켜야 하는가? → 위험관리·컴플라이언스
● 무엇을 성과로 측정하고 다음 결정에 반영할 것인가? → KPI·BSC·성과관리
● 데이터의 소유권·품질·보안을 누가 관리할 것인가? → 데이터 거버넌스

[전략에서 실행과 운영으로 이어지는 중심 흐름]

외부 환경과 사업 전략 분석
→ 목표 달성에 필요한 업무 능력과 예상 성과 정의
→ EA로 현재 구조와 목표 구조, 공통 원칙 정리
→ ISP로 정보화 과제와 실행계획 도출
→ 예상 성과·위험·예산·인력을 비교해 수행할 과제 선택
→ 프로그램·프로젝트로 실행
│  ├─ 업무 절차 개선: BPR·PI·BPM
│  ├─ 직접 구축·구매·외부 위탁: RFP·SOW·SLA
│  ├─ 전사 시스템 도입: ERP·SCM·CRM
│  └─ 시스템 연계: EAI·API·플랫폼
→ SLA에 맞춰 IT 서비스를 운영하고 개선
→ 성과와 품질을 측정하고 감리·감사로 독립적으로 확인
→ 결과를 다음 전략·구조·투자 결정에 반영

[업무 중단 위험 분기]

업무가 중단될 가능성이 있음
├─ 위험평가: 어떤 위협이 얼마나 발생할 수 있는지 분석
└─ 업무영향분석(BIA): 중단 피해와 복구 우선순위 분석
   → 복구 목표시간(RTO)과 허용할 데이터 손실 범위(RPO) 결정
   → 업무연속성·재해복구·고가용성·백업 대책 마련
   → 훈련과 시험으로 실제 복구 가능 여부 확인

[변화 적용 영역]

데이터·디지털·AI·플랫폼은 앞의 의사결정과 관리 체계를 적용하는 영역이다. 모든 활동이 반드시 이 기술들로 끝나는 것은 아니다.
```

### 먼저 알아둘 용어

| 용어 | 쉬운 뜻 |
|---|---|
| IT 거버넌스 | IT와 관련해 누가 결정하고 책임질지 정하는 체계 |
| EA(Enterprise Architecture, 전사 아키텍처) | 기업의 현재 IT 구조와 목표 구조, 공통 원칙을 정리하는 활동 |
| ISP(Information Strategy Planning, 정보전략계획) | 사업 전략에 맞는 IT 과제와 실행계획을 만드는 활동 |
| 투자타당성 분석(Business Case) | 예상 비용·성과·위험을 비교해 과제를 수행할 근거를 만드는 것 |
| PPM(Project Portfolio Management, 프로젝트 포트폴리오 관리) | 여러 후보 과제를 비교해 우선순위와 예산·인력을 배분하는 것 |
| SOW(Statement of Work, 과업기술서) | 공급자가 수행할 업무 범위·산출물·역할·일정을 적은 문서 |
| SLA(Service Level Agreement, 서비스 수준 협약) | 서비스 수준과 측정방법, 위반 시 대응을 합의한 문서 |
| ITSM(IT Service Management, IT 서비스 관리) | IT 서비스를 안정적으로 제공하고 계속 개선하는 관리체계 |
| 컴플라이언스 | 법·규정·계약·내부 정책을 지키고 그 증거를 관리하는 활동 |
| BIA(Business Impact Analysis, 업무영향분석) | 업무 중단 피해와 복구 우선순위를 분석하는 활동 |
| RTO(Recovery Time Objective, 목표 복구 시간) | 업무나 시스템을 언제까지 복구해야 하는지 나타낸 목표시간 |
| RPO(Recovery Point Objective, 목표 복구 시점) | 복구할 때 어느 시점까지의 데이터가 보존돼야 하는지 나타낸 목표 |
| KPI(Key Performance Indicator, 핵심성과지표) | 목표 달성 정도를 판단하기 위해 지속해서 측정하는 지표 |
| BSC(Balanced Scorecard, 균형성과표) | 재무·고객·내부 절차·학습과 성장 관점에서 성과의 원인과 결과를 함께 보는 체계 |

## 권장 학습 순서

전체 학습 흐름: `IT의 가치와 사업 전략 → 투자 비용·성과 검토 → EA·ISP → 과제 우선순위 결정 → 업무 개선·조달·시스템 구축·연계 → IT 서비스 운영 → 업무연속성과 재해복구 → 성과 측정·감리·감사 → 데이터·디지털 영역에 적용`

아래 번호는 선행 학습 순서다. `→`는 이해 순서이며, 거버넌스·위험·컴플라이언스는 전 과정에 교차하는 **횡단 기준**으로 1단계에서 역할을 잡고 이후 반복 적용한다. BCM/DR은 보편적 마지막 단계가 아니라 **업무 중단 위험 분기**로 본다.

1. `정보와 정보시스템 → IT 경영 → 환경분석과 전략 → ROI·TCO` 순서로 IT 투자 판단에 필요한 기본 개념을 익힌다. 이때 누가 결정하고 책임지는지, 어떤 위험과 규칙을 고려해야 하는지도 함께 본다.
2. EA로 현재와 목표 구조를 정리하고, ISP로 정보화 과제와 실행계획을 만든다. 각 과제의 타당성을 검토한 뒤 PPM으로 우선순위를 정한다. BPR·PI는 업무 절차 개선, EAI·API는 시스템 연계라는 서로 다른 실행 방법이다.
3. ERP·SCM·CRM·BPM은 제품 이름을 외우기보다 회사 전체의 업무와 데이터를 통합하는 사례로 본다.
4. 외부 위탁, RFP·SOW·SLA를 통해 발주자와 공급자의 책임을 구분하고, ITSM·ITIL·ISO 20000으로 운영과 개선 체계를 연결한다.
5. 업무 중단에 대해서는 위험평가와 BIA로 피해와 우선순위를 분석하고, RTO·RPO에 맞춰 BCP·DR·고가용성 대책을 마련한 뒤 시험하고 개선한다.
6. KPI·BSC로 실행 성과를 측정하고, 거버넌스·컴플라이언스·품질관리·감리가 각각 어떤 책임을 맡는지 구분한다.
7. 데이터 거버넌스·분석·플랫폼·디지털 전환은 앞에서 배운 투자·책임·운영·성과관리 체계를 적용하는 영역으로 본다.

## 2단계 보강 반영(Vol.7)

### 핵심 템플릿

먼저 사업이 이루려는 목표를 확인한다. 그다음 누가 결정하고 책임질지 정하고, 투자·조달·서비스 수준을 결정한다. 운영 결과는 지표로 측정하고, 감사와 개선 활동을 통해 다시 의사결정에 반영한다.

`사업목표 → 책임과 의사결정 구조 → 투자·조달·SLA 결정 → 운영 지표 → 감사·개선`

### Vol.4 + Vol.7 연계 정리

보안 감독 체계와 `SLA`, `컴플라이언스`는 분리된 항목이 아니라 `위험 수용 기준·책임·측정`을 묶는 한 흐름이다.
- 보안 통제는 기술 항목이 아니라 경영 의사결정의 근거와 감사 추적 가능성으로 설명한다.
- 개인정보, 감사, ISMS 계열의 요구는 `규칙 준수`보다 `경영 목표와 충돌하는 업무 우선순위`에서 어떻게 조정되는지가 중요하다.

### Vol.7 + Vol.10 연계 정리

클라우드·외부용역 의존이 커질수록 `SOW/SLM/ITSM`의 문구가 아니라 `책임 범위·전이 조건·측정 주기`가 핵심이다.
- `SLA`는 서비스 수준의 측정·보고·위반 대응을 정하고, 업무연속성 요구가 있으면 RTO/RPO·DR 기준과 연계한다.
- 외부 조달 위험은 계약 종료/업체 이탈까지 포함해 BIA와 연결해야 실제 경영 답안이 된다.

## A/B/C 분류

번호 범위는 양 끝을 포함하며 모든 원본 번호를 한 번만 배정한다. **등급은 학습 깊이**, 태그는 **학습 순서와 역할**을 뜻한다.

- A: 정의·구조·절차·비교·적용까지 답안화한다.
- B: 핵심 개념과 거시적 연결, 대표 비교를 이해한다.
- C: 명칭과 지도상의 위치만 확인하고 기출 근거가 있을 때 승급한다.
- `[선행]`: 등급과 별개로 다른 개념보다 먼저 이해한다.
- `[횡단]`: 여러 단계에 반복 적용되는 기준·기법이다.
- `[타권중복]`: 이 권에서는 위치만 잡고 관련 권에서 깊이를 보완한다.

## 1차 회독 통과 경로

아래 흐름은 용어 암기용 목록이 아니다. 각 화살표를 **앞 단계만으로 해결할 수 없는 문제가 무엇인지** 생각하며 읽는다.

첫 회독은 161개 토픽을 같은 깊이로 읽지 않는다. 다음 여섯 관계를 설명할 수 있을 정도로만 통과한다.

1. `전략 → EA/ISP → Business Case·PPM → 프로젝트 → 성과`
2. `BPR/PI → BPM → 전사 System → EAI/API → Process Mining`
3. `Sourcing → RFI/RFP → SOW/SLA → SLM/ITSM`
4. `Incident 복구 → Problem 원인 제거 → 지속 개선`
5. `위험 Assessment·BIA → RTO/RPO → BCP/DR/HA → 시험·개선`
6. `거버넌스·컴플라이언스 → KPI/BSC → 감리·감사`

첫 회독에서 C급은 정의를 암기하지 않고 어느 흐름에 놓이는지만 표시한다. A급도 세부 산식·법 조문보다 **목적, 앞뒤 관계, 의사결정 기준**을 먼저 잡는다.

5. ITSM에서 Incident 복구와 Problem 원인 제거, 지속 개선을 연결할 수 있는가?
6. BIA·RTO·RPO·BCP·DR·HA를 업무 영향과 복구 전략으로 설계할 수 있는가?
7. IT 거버넌스·컴플라이언스·PMO·감리의 의사결정권과 독립성을 비교할 수 있는가?
8. Data 거버넌스와 Digital Transformation을 기술 도입이 아닌 사업 가치·운영모델·책임 변화로 설명할 수 있는가?

## 보정 기록

- 전략 도구 이름보다 사례에서 의사결정 논리와 성과·위험을 요구하는지로 승급한다.
- 법령·감리·공공제도·ISO·ITIL은 출제 시점의 최신 공식 문서로 명칭·대상·절차를 확인한다.
- RTE, BI 세대, O2O/O4O, Bimodal 등 낡은 유행어는 현재 아키텍처나 운영모델을 설명할 가치가 없으면 C를 유지한다.
- Data·AI·Platform·Digital 전환은 최신 기출의 거버넌스·품질·윤리·성과 관점을 추가한다.
- 변경 시 `기존 등급 → 새 등급`, 근거 회차, 질문 형태를 기록한다.
- `[최신]` 표기는 용어 교체보다 의사결정 책임 구조를 최신 맥락에 맞춰 정렬한다.
  - `SLA/SLM`는 수치 준수 항목이 아니라 측정·보상·복구 검증의 R&R이 포함되어야 한다.
  - `ITIL/ISO 20000`은 버전 암기보다 가치 흐름과 개선 루프 중심으로 정비한다.
  - `BSC/PMO/감리`는 독립성·통제·보고 책임을 문장 한 줄로 구분해 답안에 넣는다.
