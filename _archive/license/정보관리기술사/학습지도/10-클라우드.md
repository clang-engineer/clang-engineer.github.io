# Vol. 10 클라우드 학습지도

> 기준: 정보관리기술사 단독 대비를 위한 1차 분류다. 출제 여부를 고정값으로 두지 않고, 공식 출제기준·최신 기출을 보며 A/B/C를 보정한다.

## 이 권의 역할

클라우드는 소프트웨어 구축·운영의 인프라를 구매형/서비스형 자원으로 전환해 민첩성·확장성·회복탄력성의 좌표를 만든다.

핵심 질문은 세 가지다.

1. 언제 온프레미스 자산을 Cloud로 이동하고, 어느 경계까지 서비스 위임해야 하는가?
2. 가상화·스토리지·네트워크를 어떤 패턴으로 조합해 성능·비용·안정성 비용곡선을 관리하는가?
3. 멀티테넌시·규모성·규제 요구가 있는 환경에서 어떤 통제와 거버넌스로 운영할 것인가?

## 권 내부 큰 그림

```text
사업 목표와 워크로드 정의
        ↓
Cloud/On-Premise Boundary 결정
        ↓
서비스 모델 설계(IaaS/PaaS/SaaS/XaaS) + 전달 방식
        ↓
가상화 계층(컴퓨팅/스토리지/네트워크)로 탄력성 확보
        ↓
보안·규제·SLA·감사 설계
        ↓
자동확장·관측·운영전환 + DR/성능/비용 보정
```

클라우드는 기술목록의 집합이 아니라, 운영 책임이 어디로 이동하는지 정의하는 프레임이다.

## 권장 학습 순서

### 1단계: 클라우드 기본 체계

`클라우드 개요(1~4) → 핵심기술·주변기술(5~6) → 클라우드 유형(7~13) → Multi/Hybrid/Meta Cloud(8~16) → 계산 패러다임(17~20)`

서비스 모델과 경계가 선행되어야 다음 단계의 비용·성능 판단이 고정된다.

### 2단계: 서비스 모델과 전달 방식

`Cloud 서비스 분류(21~24) → XaaS 확장(25~27) → BaaS 계열(28~29) → 비교 검토(30~33) → Serverless(34)`

전달방식은 비용보다 가시성·책임위임의 경로가 더 중요하다.

### 3단계: 가상화 핵심 구조

`가상화 원리/유형(35~37) → Server/DDesktop/OS/Application 가상화(38~43,47~53) → 하이퍼바이저·VM·컨테이너(50~55) → Serverless 연동(34)`

동일한 워크로드라도 가상화 선택에 따라 오케스트레이션 난이도와 장애 모드가 바뀐다.

### 4단계: 인프라 네트워크·스토리지

`SDN·NFV/가상화(59~61) → 아키텍처(62~67) → Network Storage와 iSCSI/NFS(CF 66~68) → Edge/Neutron(69~70) → 스토리지 티어링·프로비저닝(71~77) → DAS/NAS/SAN/RAID(78~85)`

경계 네트워크와 저장 체계가 맞지 않으면 자동확장도 비용 폭증으로 귀결된다.

### 5단계: 보안·거버넌스로 결합

`Cloud 보안 기본(87~90) → CSAP/ISO 인증군(88~92) → CASB·Forensic·Hypervisor 대응(93~95) → 멀티테넌시/BYOD(89,96)`

보안 항목은 항상 SLA·감사 근거로 되돌아가야 한다.

### 6단계: 운영 기반기술과 전환 의사결정

`Auto Scaling(97~100) → Cloud Native·MSA·K8s(99~104) → HCI·OpenStack·VDI(106~115) → 조직 전환(115~116)`

자동화가 목적이 아니라, 실패·확대·통제 관측이 가능한 운영 구조를 확보하는 데 목적이 있다.

## 토픽 간 연결

### 자원 경계와 운영 책임

```text
Cloud 유형 선택(1~20)
→ 서비스 모델 결정(21~34)
→ 가상화 계층 설계(35~58)
→ 네트워크·스토리지 정책(59~86)
→ 보안·SLA·규제 대응(87~96)
→ 자동확장·운영 전환(97~116)
```

초기 설계에서 경계를 확정하지 않으면 SLA와 책임 분할이 무너진다.

### 신뢰성 설계 흐름

```text
성능/비용 목표
→ Auto Scaling 정책
→ 인프라 선택(서버/스토리지/네트워크)
→ HA/DR/백업 정책(다른 권과 연결)
→ 모니터링·감사 로그·인시던트 대응
```

클라우드에서 성능은 비용, 보안은 법규/책임 분리와 함께 판단해야 한다.

### 전환 의사결정

```text
현재 전산실 구조 진단
→ 분할/적용 대상 선정
→ HCI/VDI/컨버지드 도입대안 비교
→ 이전 계획과 테스트·롤백
→ 운영 KPI/보안 KPI로 성과 환류
```

## 기출 보정 기록

- 공통 흐름은 Cloud/AI/Data/보안이 맞물린 통합형 질문이 많으므로, 각 파트는 서비스 모델-가상화-보안 루프 중심으로 압축한다.
- Multi-Cloud/Hybrid/Serverless는 최신 기출에 자주 나와 A 우선순위를 상향한다.
- Docker/Kubernetes/CI/CD는 과거 구현 스택보다 운영 책임 분리와 모니터링 관점으로 서술한다.
- ISO/IEC 27017/27018, VDI, HCI 등은 최신 제도·지원 환경 여부를 기출 회차마다 갱신한다.
- `기존 등급 → 새 등급`, 근거 회차, 질문 형태를 남겨 누락과 역전 위험을 줄인다.
