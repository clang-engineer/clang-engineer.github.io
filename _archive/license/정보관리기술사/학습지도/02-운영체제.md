# Vol. 2 운영체제 학습지도

> 기준: 정보관리기술사 단독 대비를 위한 1차 분류다. 출제 여부를 단정하지 않으며, 공식 출제기준과 최근 기출을 분석한 뒤 등급을 보정한다.

## 이 권의 역할

운영체제는 CPU·메모리·저장장치·I/O 같은 물리 자원을 애플리케이션이 사용할 수 있는 실행 환경으로 추상화하고, 여러 작업이 자원을 안전하고 효율적으로 공유하게 한다.

핵심 질문은 세 가지다.

1. 여러 실행 주체가 한정된 자원을 어떻게 나누어 쓰는가?
2. 공유 때문에 발생하는 충돌·대기·장애를 어떻게 통제하는가?
3. 이 원리가 가상화·클라우드·고가용성·성능 관리로 어떻게 확장되는가?

## 권 내부 큰 그림

```text
하드웨어 자원을 직접 사용하기 어려움
→ 운영체제가 자원을 추상화하고 공통 실행환경 제공
→ 실행 단위를 프로세스·스레드로 관리
→ 자원의 종류와 문제에 따라 서로 다른 관리 방법 적용
   ├─ CPU: 스케줄링·문맥 교환으로 실행 순서와 시간 배분
   ├─ 공유 자원: 동기화·상호배제로 충돌 방지
   │  → 잘못 설계하면 대기·교착상태 발생
   ├─ 메모리: 할당·페이징·가상메모리로 주소 공간과 보호 제공
   │  → 페이지 부재·스래싱·주소 변환 비용 발생
   └─ 저장장치·외부 장치: 시스템 콜·파일 시스템·I/O로 접근
→ 가상화로 자원 추상화를 시스템 단위로 확장
→ 성능·용량·가용성을 측정하고 튜닝·HA·체크포인팅으로 개선
```

운영체제의 중심 개념은 **추상화, 자원 배분, 격리, 동시성, 성능과 안전성의 트레이드오프**다. 개별 알고리즘 이름은 이 다섯 축 위에 배치한다.

### 먼저 알아둘 약어

| 약어 | 원어·쉬운 뜻 |
|---|---|
| IPC | Inter-Process Communication, 프로세스 사이에 데이터와 신호를 주고받는 방법 |
| FCFS | First-Come, First-Served, 먼저 도착한 작업부터 실행하는 스케줄링 |
| SJF | Shortest Job First, 실행시간이 짧은 작업부터 실행하는 스케줄링 |
| MLFQ | Multi-Level Feedback Queue, 작업의 실행 특성에 따라 여러 우선순위 큐 사이를 이동시키는 방식 |
| RM | Rate Monotonic, 실행 주기가 짧은 실시간 작업에 높은 우선순위를 주는 방식 |
| EDF | Earliest Deadline First, 마감시간이 가까운 작업을 먼저 실행하는 방식 |
| HA | High Availability, 장애가 발생해도 서비스를 계속 제공하도록 구성하는 고가용성 |

## 권장 학습 순서

아래 구분은 관련 주제를 함께 공부하기 위한 권장 순서다. 실제 기술·업무의 처리 절차를 뜻하지 않으며, 선행관계가 약한 단계는 병행해도 된다.

### 1단계: 운영체제와 실행 단위

`운영체제 개요(1·2) → 프로세스(4) → 스레드·멀티스레드(5·6) → 문맥 교환(8) → 시스템 콜(10) → 커널 구조 비교(14)`

운영체제의 역할을 이해한 뒤 프로세스·스레드와 문맥 교환을 배운다. 시스템 콜과 커널 구조를 연결하면 애플리케이션이 하드웨어를 직접 다루지 않는 이유가 보인다.

### 2단계: CPU 자원 배분

`CPU 스케줄링 개요·스케줄러(24·25) → 선점·비선점(26) → FCFS·SJF(30) → Round Robin·MLFQ(27·32) → 우선순위 역전과 방지(35·36) → 실시간 스케줄링 RM·EDF(37)`

스케줄링의 평가 기준과 선점 여부를 먼저 이해하고 대표 정책을 비교한다. 평균 대기시간 손계산보다 처리량·응답시간·공정성·예측 가능성 사이의 선택을 설명하는 것이 우선이다.

### 3단계: 동시성과 교착상태

`동기화·상호배제(54) → 세마포어(40) → 프로세스 간 통신 IPC(55) → 교착상태(42) → 은행가 알고리즘(41)`

병렬 실행이 왜 충돌하는지부터 시작하여 상호배제·세마포어·프로세스 간 통신(IPC)을 연결한다. 교착상태의 발생 조건과 예방·회피·탐지·복구를 구분한 뒤 은행가 알고리즘은 회피의 예로 둔다.

### 4단계: 메모리 추상화

`연속 메모리 할당(60) → 단편화(7) → 페이징·세그멘테이션(61·63) → 가상메모리와 사용 이유(59·62) → 스래싱(64) → 캐시와 쓰기 정책(56·57) → 캐시 일관성과 MESI·Directory(53·58)`

연속 할당의 외부 단편화 문제에서 페이징으로, 물리 메모리 한계와 격리 요구에서 가상메모리로 이어간다. 페이징은 외부 단편화를 없애지만 내부 단편화와 주소 변환 비용을 만든다. 캐시는 속도 차이, 가상메모리는 주소 공간 추상화라는 목적 차이를 먼저 구분한다.

### 5단계: 파일과 I/O

`시스템 콜(10) → 파일 시스템·inode(11) → Blocking·Non-blocking·비동기 I/O(12·13) → Programmed I/O·Interrupt·Polling(67·68) → Journaling 파일 시스템(79) → Buffer·Cache(23)`

시스템 콜을 경계로 파일 시스템과 I/O 방식이 어떻게 제공되는지 본다. Blocking/Non-blocking과 Synchronous/Asynchronous는 서로 다른 분류 축임을 비교한다. 버퍼와 캐시도 목적과 일관성 위험을 함께 본다.

### 6단계: 확장 적용과 운영 품질

`자원 추상화 확장: 가상화(72) → 스토리지 가상화(77) → 클라우드 운영체제·OpenStack(15)`

`운영 품질 관리: 성능 지표(82) → 성능 분석·용량 산정(80) → 시스템 튜닝(74) / Clustering·HA(70) → 체크포인팅(83)`

두 흐름은 선후관계가 아니다. 가상화는 자원 추상화를 시스템 단위로 확장하고, 운영 품질 관리는 성능·용량·장애 대응을 측정하고 개선한다.

### 선택 보강

실시간 시스템이 필요할 때 `실시간 운영체제(17) → RM·EDF 스케줄링(37)`, 임베디드가 필요할 때 `임베디드 OS(16) → 임베디드 시스템·SW 특성(20) → 메모리 최적화(21)`를 보강한다. 세부 부팅 순서, C 언어 코드, 버스 중재 신호, 특정 모바일 개발 절차는 기출 근거가 생길 때 학습한다.

## 성안당 책순 회독 안내

위의 권장 학습 순서는 개념의 선행관계를 이해하기 위한 지도다. 실제 회독에서는 책을 앞에서부터 읽되, 다음 표로 각 Part의 위치와 학습 깊이를 확인한다. 책을 여러 번 왕복할 필요는 없다.

| 교재 구간 | 전체 그림에서의 위치 | A급 중심 | B급에서 연결할 내용 | 빠르게 통과할 내용 |
|---|---|---|---|---|
| Part 1. 운영체제 | 실행 환경과 기본 추상화 | 운영체제, 프로세스·스레드, 문맥 교환, 시스템 콜, I/O 분류, Buffer·Cache | 파일 시스템, 커널 구조, 임베디드·실시간 OS 개념 | 부팅 상세, TinyOS, 교차 개발, 임베디드 구현 상세 |
| Part 2. 스케줄링 | CPU 자원 배분 | 스케줄링 목적, 선점·비선점 | 대표 알고리즘과 선택 기준, 우선순위 역전, 실시간 스케줄링 | 반복 손계산, HDD 접근시간·스케줄링 상세 |
| Part 3. 동기화와 개발 세부 | 공유 자원 통제 | 세마포어, 교착상태 | 은행가 알고리즘 원리, 앱 유형, OSS 거버넌스의 위치 | C 언어·임베디드 코드, 플랫폼별 등록·개발도구 |
| Part 4. 병렬 처리와 메모리 | 동시성과 주소 공간 관리 | 병렬 동기화, IPC, 가상메모리, Paging, Thrashing | 캐시·쓰기 정책·일관성, Segmentation | 연속 할당 알고리즘 계산 |
| Part 5. I/O와 운영 기술 | 자원 제어와 서비스 품질 | HA, 가상화, 튜닝, 성능·용량 산정, 성능 지표 | I/O 방식, 클라우드·스토리지 가상화, Journaling, 체크포인팅 | 버스 중재 상세, UEFI·XIP 상세, UI·UX |

각 Part를 읽기 전에는 `전체 그림에서의 위치`를 확인하고, 읽은 뒤에는 아래 `토픽 간 연결`에서 해당 내용을 다시 연결한다. A는 원리와 트레이드오프까지, B는 흐름 속 위치와 용도까지 보고, C는 제목을 식별한 뒤 넘어간다.

## 토픽 간 연결

### 실행과 CPU 배분

```text
프로그램을 실행해야 함
→ 프로세스: 자원을 소유하는 실행 인스턴스
→ 스레드: 프로세스 자원을 공유하는 실행 흐름
→ 동시 실행 주체가 CPU보다 많음
→ 스케줄링: CPU 사용 순서를 결정
→ 작업 전환이 필요함
→ 문맥 교환: 상태 저장·복원, 대신 오버헤드 발생
→ 처리량·응답시간·공정성·마감시간에 따라 정책 선택
```

답안에서는 알고리즘 이름부터 나열하지 않는다. 먼저 어떤 작업을 처리하는지 확인하고, 중요하게 볼 성능 지표를 정한 뒤, 알맞은 스케줄링 정책과 그 부작용·보완책을 설명한다.

### 동시성과 교착상태

```text
스레드·프로세스가 자원을 공유
→ 실행 순서에 따라 결과가 달라지는 경쟁상태 발생
→ 임계구역을 상호배제로 보호
→ 세마포어 등으로 실행 순서를 동기화
→ 여러 자원을 서로 점유하고 기다리면 교착상태 가능
→ 발생 조건을 기준으로 예방·회피·탐지/복구 선택
```

동기화는 공유를 안전하게 만드는 해결책이지만 대기, 경합, 교착, 우선순위 역전이라는 새 비용을 만든다. 이 트레이드오프가 핵심이다.

### 메모리 관리

```text
여러 프로세스에 연속 메모리를 할당
→ 가변 크기 빈 공간에 외부 단편화 발생
→ 고정 크기 페이지로 비연속 할당
→ 외부 단편화는 없어지지만 내부 단편화와 주소 변환 비용 발생
→ 세그멘테이션은 논리 단위 보호·공유에 유리하지만 외부 단편화 가능
→ 가상메모리로 물리 메모리보다 큰 독립 주소 공간 제공
→ 필요한 페이지가 없으면 페이지 부재와 디스크 I/O 발생
→ 부재가 과도하면 스래싱
→ 작업집합·프레임 조정·부하 제어로 완화
```

```text
CPU와 주기억장치의 속도 차이
→ 캐시 사용
→ Write-through·Write-back 등의 쓰기 정책으로 하위 메모리 반영 방식 결정

여러 프로세서 캐시가 같은 데이터를 보유
→ 복제본 사이에 일관성 문제 발생
→ MESI·디렉터리 기반 프로토콜로 무효화·갱신 조정
```

가상메모리와 캐시는 모두 계층형 저장장치를 활용하지만, 전자는 **주소 공간·보호·용량**, 후자는 **접근 속도**가 중심 목적이다.

### I/O와 파일

```text
애플리케이션이 보호된 장치에 직접 접근할 수 없음
→ 시스템 콜로 커널 서비스 요청
→ 장치 속도가 CPU보다 느림
→ Buffering으로 생산자·소비자 속도 차이 완화
→ 파일 시스템으로 저장장치를 이름·권한·메타데이터 구조로 추상화
→ Journaling으로 장애 후 파일 시스템 일관성 복구 지원
```

I/O 제어는 하나의 순차 단계가 아니라 서로 다른 세 축으로 구분한다.

| 구분 축 | 선택지 | 핵심 질문 |
|---|---|---|
| 장치 완료 감지 | Polling / Interrupt | 장치 상태 변화를 어떻게 알아내는가? |
| 호출 대기 여부 | Blocking / Non-blocking | 호출한 실행 흐름이 결과를 기다리는가? |
| 완료 처리 방식 | Synchronous / Asynchronous | 완료 결과를 어떤 제어 흐름으로 전달받는가? |

Journaling의 복구 범위는 모드에 따라 다르다. 메타데이터 저널링은 파일 시스템 구조의 일관성을 빠르게 복구하지만 사용자 데이터의 최신 내용까지 항상 보장하지는 않는다.

### 가상화와 운영

```text
운영체제가 프로세스별 실행환경을 추상화
→ 가상화가 서버·스토리지 등 시스템 자원을 논리 자원으로 확장
→ 자원 풀링·격리·이동·탄력적 할당 가능
→ 클라우드가 이를 서비스와 운영모델로 제공
→ 공유 자원 경합·장애 범위·보안 위험 증가

운영 중 성능·용량·장애 위험을 측정
→ 모니터링·튜닝·용량 산정으로 성능 관리
→ HA·체크포인팅으로 장애 영향과 복구시간 축소
```

관련 권은 컴퓨터 구조의 CPU·메모리·I/O, 클라우드의 가상화·자원 풀링, 네트워크의 통신, 보안의 접근통제, IT 경영의 SLA·가용성·재해복구다.

## 2단계 보강 반영(Vol.2)

### 핵심 템플릿

`요구(워크로드)` → `자원 제한` → `OS 정책` → `운영 품질(처리량·응답·가용성)` → `회복/책임` 순서로 설명한다.

### Vol.2 + Vol.3 + Vol.10 연계 정리

프로세스·스케줄링·메모리의 기본 결정은 네트워크 지연/혼잡 제어와 클라우드 자원 운영으로 이어진다.
- 워크로드 특성은 CPU 스케줄링의 정책 선택을 바꾸고, 네트워크 품질은 I/O 지연과 사용자 체감에 반영된다.
- 가상화·클러스터링·체크포인팅은 `HA`, `DR`, `SLO`로 이어지며 IT 경영의 연속성 문항까지 연결한다.

### Vol.2 + Vol.10 연계 정리

클라우드 환경에서 `OpenStack`이나 `클라우드 운영체제`는 OS 자체보다 자원 운영 모델 해석의 대상이다.
- `vCPU/메모리/IOPS` 오버커밋은 스케줄링 정책과 성능 튜닝 우선순위를 변경한다.
- 체크포인팅은 장애 복구 기술이며, 저장 시점·데이터 일관성·복구시간과 복구 책임을 함께 설계한다.

## 연결 복습 묶음

묶음은 토픽의 연결 순서만 제시한다. 포함된 C급은 명칭과 연결 위치만 확인하고 깊게 학습하지 않는다.

## A급 완료 기준

운영체제 학습을 마쳤다는 것은 다음 질문에 자료 없이 답할 수 있다는 뜻이다.

1. 프로세스와 스레드를 자원 소유, 격리, 통신, 전환 비용 관점에서 비교할 수 있는가?
2. 워크로드와 서비스 목표에 따라 스케줄링 정책을 선정하고 이유를 설명할 수 있는가?
3. 경쟁상태에서 교착상태까지의 인과관계와 각각의 대응 방법을 설명할 수 있는가?
4. 페이징과 가상메모리가 해결한 문제 및 페이지 부재·스래싱이라는 비용을 설명할 수 있는가?
5. Blocking/Non-blocking과 Synchronous/Asynchronous를 서로 다른 축으로 비교할 수 있는가?
6. 운영체제의 자원 추상화가 가상화와 클라우드로 확장되는 과정을 설명할 수 있는가?
7. 처리량·응답시간·가용성 목표를 기준으로 측정, 병목 분석, 튜닝, 용량 산정을 연결할 수 있는가?

## 보정 기록

아직 공식 출제기준과 최근 기출을 반영하지 않은 1차 분류다. 기출 분류 후 다음 원칙으로 갱신한다.

- 반복 출제되거나 다른 분야와 결합해 출제되는 B/C 토픽은 승급한다.
- 과거 특정 제품·규격에 한정된 토픽은 최신 개념으로 대체하거나 C를 유지한다.
- A급이라도 실제 답안에서 요구되는 깊이가 낮으면 암기 범위를 줄인다.
- 변경 시 `기존 등급 → 새 등급`, 근거 회차, 질문 형태를 기록한다.
- `[최신]` 표기가 붙은 항목은 명칭 정리보다 운영 모델로 재해석한다.
  - `OpenStack`은 OS 커널이 아닌 클라우드 자원 제어 레이어로 본다.
  - `클라우드 표준화 동향`은 상호운용성 전략으로 정리하고 규격명 암기는 부차화한다.
  - `모바일 클라우드`는 Edge·온프레미스 연계 맥락으로 재배치해 본다.
