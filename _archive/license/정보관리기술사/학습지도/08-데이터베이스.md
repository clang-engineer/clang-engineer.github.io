# Vol. 8 데이터베이스 학습지도

> 기준: 정보관리기술사 단독 대비를 위한 1차 분류다. 출제 여부는 고정값이 아니며, 공식 출제기준/최신 기출에서 조정한다.

## 이 권의 역할

DB는 조직의 데이터 자산을 추상화·정합·성능·품질까지 아우르는 운영체계로 바꿔, 업무 의사결정과 시스템 통합의 기초를 만든다.

핵심 질문은 세 가지다.

1. 데이터가 구조적으로 다루어질 수 있도록 어떤 모델을 쓰는가?
2. 트랜잭션, 회복, 동시성 통제는 신뢰성·가용성·일관성을 어떻게 보장하는가?
3. 운영 성능과 품질을 위해 인덱스, 저장, 분산, 보안, 거버넌스를 어떻게 설계하는가?

## 권 내부 큰 그림

```text
비정형 원천 데이터
        ↓
개념/논리/물리 모델링(ER, 정규화)
        ↓
SQL 질의와 관계 해석
        ↓
트랜잭션·회복·동시성 통제
        ↓
해시/인덱스/파티셔닝으로 성능 보정
        ↓
DB 유형·보안·거버넌스로 운영 성숙
        ↓
데이터 품질·DM·클라우드/분산/BI로 가치 실현
```

DB는 설계와 운영이 한 문장으로 끝나지 않는다. `정의→설계→질의→무결성/성능→질 관리`의 고리 전체를 봐야 한다.

## 권장 학습 순서

### 1단계: 데이터와 DBMS 기본

`DB 정의(2~4) → ANSI/SPARC(5·12) → DBMS 정의·역할(7) → 생명주기(10) → Data 독립성(13) → 스키마/인스턴스(8)`

데이터 독립성·스키마 개념 없이 쿼리나 트랜잭션을 본다면 설계/운영 판단 근거가 약해진다.

### 2단계: 모델링 기반 구조 정리

`Data Modeling 절차(16) → ER 표기(17) → EER/일반화(21) → 정규화(29~34) → 반정규화(41~43)`

표기와 관계 제약을 먼저 정리하면 정규화·반정규화가 무슨 비용-이득을 갖는지 설명할 수 있다.

### 3단계: SQL과 질의 모델

`SQL 3언어(44) → 질의 작성 45~54 → 관계 연산/조인 개념(23~24) → 뷰(54)`

질의 작성은 문법 암기가 아니라 **무엇을 걸러내고 집계·결합하는지가 문제 해결에 맞는지**를 본다.

### 4단계: 무결성·회복·동시성

`ACID와 상태(61) → 병행제어 정의·문제(62~63) → 스케줄링·직렬화(64~70) → 회복 기법(55~60)`

동시성은 성능을 얻는 대신 이상상태를 유발한다. 충돌 직렬화, 락, 데드락을 선후관계로 묶어 본다.

### 5단계: 성능·저장·운영 품질

`해시(78~83) → 성능평가(122~127) → 인덱스 계열(B+Tree, R-Tree: 128~139) → DB 보안/감사(140~153) → 데이터 품질·거버넌스(114~121,154~183)`

성능/보안/품질은 서로 독립된 파트가 아니다. 운영 지표와 거버넌스 요구가 쿼리 설계·트랜잭션 정책을 바꾼다.

### 선택 보강

기출에서 빅데이터·데이터 엔지니어링이 붙으면 `DW·Data Mining(84~97)`과 `분산 DB(109~113)`를 집중 보강한다.

## 토픽 간 연결

### 설계에서 무결성으로

```text
요구사항 분해
→ ER 모델(엔터티·관계)
→ 정규화 및 Key 제약
→ SQL 질의의 정확성 확보
→ 동시성·회복 통제로 일관성 유지
→ 감사·품질 지표로 운영 상태 확인
```

설계 단계에서 빠진 제약은 트랜잭션 이상으로 돌아온다.

### 성능과 저장 구조

```text
쿼리 패턴
→ 필요한 인덱스(균형트리, 해시)
→ 파티셔닝/샤딩/스토리지 배치
→ 병렬성·I/O 비용 비교
→ Tuning/계측
→ 품질 지표와 운영 규칙 갱신
```

성능은 항상 트랜잭션 처리량만으로 보는 게 아니라 회복·감사 비용까지 포함한다.

### 분산·클라우드로 확장

```text
단일 DB 제약
→ 분산/멀티테넌시/CDC 요구
→ 데이터 거버넌스와 보안 통합
→ 감사, 정책, 책임 경계 정리
→ 클라우드 운영 지표와 결합
```

## 1단계 보강 반영(Vol.8)

### 핵심 템플릿

`요건(업무/서비스)` → `데이터 모델` → `품질 규칙` → `복구·동시성` → `클라우드 책임 경계`로 5단계를 한 문단에서 설명한다.

### Vol.8 + Vol.9 연계 정리

- 데이터 설계는 AI 학습 데이터의 편향·누락이 지표로 바로 들어오므로, `데이터 표준화`, `메타데이터`, `품질(정확성·완전성·일관성)`을 먼저 점검한다.
- 모델 보안 질문은 `XAI`보다 앞서 `학습 데이터 수집/라벨링·품질 통제`가 선행되어야 한다는 흐름으로 정리한다.

### Vol.8 + Vol.10 연계 정리

- CDC, 샤딩, 분산 DB는 멀티테넌시 환경에서 `RTO/RPO`, `책임 분리`, `감사 추적성`이 함께 언급되어야 한다.
- Multi/Hybrid 전환은 성능 비교보다 `이동 데이터량`, `규제 적용 구간`, `운영권한 변경점`을 우선 확인한다.
