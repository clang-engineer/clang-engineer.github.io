# 정보관리기술사 전체 학습지도

## 목적

성안당 10권을 처음부터 같은 깊이로 외우지 않는다. 먼저 정보시스템의 전체 구조를 이해하고 각 권과 토픽의 위치를 잡는다. 그다음 중요도와 기출에 따라 교재에서 필요한 세부 지식을 선택적으로 넓힌다.

구체적인 작성·학습 기준은 [학습지도 공통원칙](00-학습지도-공통원칙.md)에 둔다. 이 문서는 열 권의 관계와 권장 이동 경로만 보여준다.

이 지도에서 등급은 출제 여부를 단정하는 표시가 아니라 **현재 학습에 투입할 깊이**를 뜻한다. 실제 기출과 최신 출제기준을 확인하면서 계속 보정한다.

## 전체 그림

```text
기업·사회가 해결하려는 문제
        ↓
IT 전략·거버넌스·투자·성과                         [IT 경영]
        ↓
요구사항 → 설계 → 구현 → 시험 → 배포·유지보수       [소프트웨어 공학]
        ↓
애플리케이션이 다루는 데이터의 구조·품질·활용        [데이터베이스]
        ↓
컴퓨팅 자원의 추상화·실행·통신                      [운영체제·네트워크]
        ↓
CPU·메모리·I/O라는 물리적 기반                       [컴퓨터 구조]

보안       : 위 모든 계층의 위험과 통제를 관통한다.
클라우드   : SW·데이터·인프라를 서비스 형태로 통합·운영한다.
AI         : 데이터로부터 예측·생성·자동화를 수행한다.
알고리즘   : 데이터 처리와 문제 해결의 계산 원리를 제공한다.
```

권 사이의 관계 자체를 외울 필요는 없다. 개별 토픽을 공부할 때 “어떤 문제를 해결하며 전체 시스템의 어디에 있는가”를 찾는 안내도로 사용한다.

## 권별 역할

| 권 | 역할 | 정보관리 관점의 중심 질문 |
|---|---|---|
| Vol. 1 컴퓨터 구조 | CPU·메모리·I/O의 물리적 기반 | 시스템 성능과 신뢰성의 물리적 제약은 무엇인가? |
| Vol. 2 운영체제 | 실행 자원 추상화와 배분 | 한정된 자원을 어떻게 안전하고 효율적으로 공유하는가? |
| Vol. 3 네트워크 | 시스템 사이의 연결과 전달 | 데이터를 목적지까지 품질과 보안을 지키며 어떻게 전달하는가? |
| Vol. 4 보안 | 전 영역의 위험 관리와 통제 | 자산의 기밀성·무결성·가용성을 어떻게 보장하는가? |
| Vol. 5 소프트웨어 공학 | 정보시스템 구축 생명주기 | 요구를 품질 있는 소프트웨어로 어떻게 전환하는가? |
| Vol. 6 알고리즘 | 계산 절차와 자료구조 | 문제를 정확하고 효율적인 계산으로 어떻게 표현하는가? |
| Vol. 7 IT 경영 | 전략·거버넌스·투자·운영·감리 | IT가 조직의 목표와 성과에 어떻게 기여하는가? |
| Vol. 8 데이터베이스 | 데이터 구조·저장·품질·거버넌스 | 데이터를 신뢰할 수 있는 자산으로 어떻게 관리하는가? |
| Vol. 9 인공지능 | 데이터 기반 추론과 자동화 | 데이터에서 가치를 만들고 모델 위험을 어떻게 관리하는가? |
| Vol. 10 클라우드 | 현대 서비스 인프라의 통합 운영 | 자원을 서비스화하여 민첩성·확장성·회복탄력성을 어떻게 얻는가? |

## 권장 진행 순서

교재 순서가 아니라 큰 그림과 선행관계를 기준으로 한다.

```text
1. 전 권 개관
   7 IT 경영 → 5 소프트웨어 공학 → 8 데이터베이스 → 4 보안
             → 2 운영체제·3 네트워크 핵심 → 10 클라우드 → 9 인공지능
             → 6 알고리즘·1 컴퓨터 구조 선택 보강

2. 권별 A급 학습
   권 내부 지도 → 토픽 연결 → 원리 → 얻는 효과와 생기는 부담 → 적용 사례

3. 기출 보정
   실제 질문을 분야·토픽에 연결 → 등급 조정 → 누락된 최신 주제 추가

4. 답안화
   A급 1교시형 → 비교·절차·아키텍처형 → 2교시 통합형
```

IT 경영을 첫 번째로 두는 것은 세부 경영 기법을 먼저 암기하기 위해서가 아니다. 정보시스템을 **목표·투자·구축·운영·통제·성과**의 생명주기로 보는 좌표를 먼저 얻기 위해서다. 이해가 어려운 세부 토픽은 개관 단계에서 넘긴다.

## 학습 등급

| 등급 | 학습 깊이 | 완료 기준 |
|---|---|---|
| A | 핵심 원리와 답안까지 학습 | 배경→정의→구조/절차→장단점→적용·고려사항을 설명한다. |
| B | 위치·원리·용도를 학습 | 무엇이며 왜 필요한지, A급 주제와 어떻게 연결되는지 설명한다. |
| C | 1차 학습에서 보류 | 무엇을 가리키는지 식별한다. 기출이나 선행 필요가 확인되면 승급한다. |

등급과 별도로 판단 근거를 태그로 기록한다. 태그는 예외적인 학습 지침이 있을 때만 사용하며, 한 토픽에는 핵심 태그를 최대 2개까지 붙인다.

| 태그 | 의미 |
|---|---|
| `[선행]` | 후속 A급 토픽을 이해하는 데 필요 |
| `[횡단]` | 여러 권 또는 생명주기를 관통하는 주제 |
| `[중복]` | 대표 권에서 깊게 배우고 다른 권에서는 해당 관점만 추가 |
| `[세부]` | 개념은 유효하지만 계산·코드·규격 상세는 우선순위가 낮음 |
| `[현행]` | 교재 시점 이후 유효성·후속 규격·현재 적용 여부를 확인해야 하는 표준·제도·제품명 |
| `[최신]` | 교재 이후의 변화와 최신 사례 보완 필요 |

예를 들어 `가상메모리 A[선행]`는 시험 빈도만이 아니라 클라우드 가상화와 시스템 성능을 이해하는 기반이라는 뜻이다. `스케줄링 계산 C[세부]`는 스케줄링 원리까지 버린다는 뜻이 아니라 손계산 연습을 보류한다는 뜻이다.

## 토픽 학습 방법

각 토픽은 정의부터 외우지 않고 다음 질문 순서로 학습한다.

```text
1. 어떤 문제가 있었는가?
2. 해결을 위해 어떤 원리를 사용하는가?
3. 주요 구성요소와 동작 흐름은 무엇인가?
4. 무엇을 얻는 대신 어떤 비용·위험이 생기는가?
5. 어떤 대안과 비교하여 언제 선택하는가?
6. 실제 정보시스템과 다른 권의 어떤 주제로 이어지는가?
```

이 흐름을 이해한 뒤에만 정의, 분류, 절차명, 표준명처럼 이해로 복원하기 어려운 요소를 암기한다.

## 권별 문서 구성

각 권별 학습지도는 분야의 특성에 맞게 구성하되 다음 요소를 공통으로 포함한다.

1. 권의 역할과 핵심 질문
2. 권 내부의 큰 그림
3. 교재와 다른 권장 학습 순서
4. 토픽 간 인과·선행·비교·적용 연결
5. 원본 목차 전체의 A/B/C 등급과 판단 이유
6. A급 토픽의 학습 완료 기준
7. 기출 확인 후 등급 변경 기록

## 회독 방식

### 구조 회독

- 권 내부 지도를 먼저 읽는다.
- 각 Part가 어떤 문제 영역인지 확인한다.
- A/B/C 표에서 이미 학습한 항목의 등급과 연결 위치를 찾는다.
- 세부 정의나 계산은 아직 외우지 않는다.

### 이해 회독

- A급 토픽을 연결 흐름 단위로 묶어 학습한다.
- B급은 흐름을 설명하는 데 필요한 깊이까지만 본다.
- C급은 A급 이해를 방해하지 않는 한 보류한다.

### 답안 회독

- 연결 흐름을 보지 않고 말하거나 그린다.
- A급을 1교시형 답안 골격으로 압축한다.
- 여러 권이 만나는 주제는 2교시형 사례와 아키텍처로 확장한다.

### 권 연계 핵심 보강 포인트

`데이터베이스(8)`는 `인공지능(9)`과 `클라우드(10)`에서 데이터를 저장·관리하는 기반이 된다. `클라우드(10)`는 `운영체제(2)`, `네트워크(3)`, `보안(4)`의 원리를 실제 서비스 운영 환경으로 확장한다.

필요 시 아래 순서로 동시 점검한다.

- 데이터 설계·거버넌스가 먼저 필요한 영역: `데이터 품질/메타데이터(8)` → `AI 품질관리(9)` → `클라우드 감사(10)`
- 서비스/운영 연계가 필요한 영역: `SLA·보안(10)` ↔ `BCP/BCM(4,7)` ↔ `운영 통제(2,3)`
- 알고리즘이 설득력을 바꾸는 영역: `추천/군집/최적화(9)` ↔ `DB 성능·색인·분산(8)` ↔ `인프라 스케일링(10)`
