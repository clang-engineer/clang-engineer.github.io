# Vol. 4 보안 학습지도

> 기준: 정보관리기술사 단독 대비를 위한 1차 분류다. 출제 여부를 단정하지 않으며, 공식 출제기준과 최근 기출을 분석한 뒤 등급을 보정한다.

## 이 권의 역할

보안은 정보시스템 전 계층의 자산과 업무 목표를 위협으로부터 보호하기 위해 위험을 식별하고 관리적·기술적·물리적 통제를 설계·운영·개선하는 횡단 영역이다.

핵심 질문은 세 가지다.

1. 어떤 자산과 업무가 어떤 위협·취약점 때문에 어느 정도 위험에 놓이는가?
2. 예방·탐지·대응·복구 통제를 어떻게 계층적으로 선택하고 운영하는가?
3. 보안성과 업무 편의·비용·프라이버시·법적 책임 사이를 어떻게 조정하는가?

## 권 내부 큰 그림

```text
업무 목표와 자산 식별
→ 위협·취약점·영향으로 위험 평가
→ Governance·정책·책임·허용 수준 결정
→ 암호·인증·접근통제·Network·System 통제 적용
→ Log·IDS·관제로 이상 탐지
→ Incident 대응·Forensics·복구
→ 점검·감사·인증·교육으로 개선
→ Privacy·Cloud·공급망·Application 변화에 맞춰 재평가
```

중심은 **위험 기반 의사결정, 심층방어, 최소권한, 신뢰 검증, 생명주기 개선**이다. 공격명과 장비 목록은 이 구조에 배치한다.

## 권장 학습 순서

### 1단계: 보안 목표와 위험관리

`정보보호 목표·필요성(1·3) → 위험요소·대책(4·5) → 보안 Cycle·Framework(8·9) → Governance(10) → Risk Management(70)`

CIA만 암기하지 않고 자산·위협·취약점·가능성·영향에서 통제를 선정하고 잔여 위험을 수용·이전·회피·감소하는 흐름을 잡는다.

### 2단계: 암호와 신뢰 기반

`대칭키·비대칭키(19) → Block·Stream(18) → AES(23) → Block 운용모드(27) → Hash(31) → 전자서명(32) → PKI(86)`

기밀성·무결성·인증·부인방지 중 무엇을 제공하는지로 기법을 구분한다. 수론 계산과 특정 Algorithm 내부 Round보다 Key 관리와 조합을 우선한다.

### 3단계: 인증과 접근통제

`접근통제 방안·절차·유형(79~81) → AAA(83) → SSO(77·78) → Kerberos(82) → 생체인식(84) → PKI(86)`

식별·인증·인가·기록을 분리하고 최소권한과 직무분리를 적용한다. 편의성을 높이는 SSO가 장애·침해 집중 위험도 키운다는 점을 연결한다.

### 4단계: 위협과 Application 보안

`Malware(45) → APT(49) → DDoS(39·40) → Sniffing·Spoofing(42) → SQL Injection(51) → XSS·CSRF(52·53) → OWASP(120) → SW 보안 Testing(113)`

공격을 **자산→공격표면→취약점→행위→영향→예방·탐지·대응**으로 정리한다. 공격 도구·Payload 암기보다 개발 생명주기에서 결함을 제거하는 방법을 우선한다.

### 5단계: Network·System 심층방어

`Firewall(87·88) → IDS·IPS(89~92) → VPN·IPSec(93·94) → TEE·TPM·TrustZone(103~105) → WLAN 보안(106~108) → DB·Cloud 보안(111·112)`

경계 통제 하나가 아니라 단말·Network·Application·Data에 통제를 겹친다. 각 통제의 가시 범위와 우회·오탐·운영 비용을 함께 본다.

### 6단계: 관리체계·Privacy·대응

`ISO 27001·ISMS(57·58) → 정책(60) → PIA(66) → 개인정보 법·원칙(73·75) → Forensics(116·117) → Anti-Forensics(119)`

통제를 일회성 구축이 아니라 관리체계로 반복하고, Privacy는 보안의 하위 항목이 아니라 처리 목적·최소 수집·정보주체 권리를 포함하는 별도 목표로 본다.

## 토픽 간 연결

### 위험에서 통제로

```text
자산과 업무 영향 식별
→ 위협이 취약점을 악용할 가능성 평가
→ 고유 위험 산정
→ 예방·탐지·대응·복구 통제 선택
→ 통제 후 잔여 위험 평가·승인
→ 지표·감사·사고를 통해 지속 개선
```

통제 목록부터 고르면 과잉 통제나 사각지대가 생긴다. 답안은 **업무·자산→위험→통제 목표→통제 조합→잔여 위험** 순서로 쓴다.

### 암호·인증·접근통제

```text
Data 노출 위험 → 대칭키 암호로 효율적 기밀성
→ Key 배송 문제 → 공개키·PKI로 신뢰 관계 보완
→ 변조 위험 → Hash·MAC·전자서명
→ 사용자·System 신원 확인 → 인증
→ 허용 행위 결정 → 인가·접근통제
→ 행위 추적 → Accounting·Log
```

암호화는 접근통제와 Key 관리를 대신하지 않는다. Hash만으로 송신자 인증이 되지 않으며, 전자서명과 인증서도 개인키 보호와 폐기 상태 확인이 전제다.

### 공격과 심층방어

```text
취약한 입력·Protocol·계정·구성
→ Malware·Spoofing·Injection·DDoS 등 공격
→ Secure Coding·Patch·Hardening·접근통제로 예방
→ Firewall·WAF·IDS·EDR·Log로 탐지
→ 격리·차단·근절·복구
→ Forensics와 원인분석
→ 규칙·설계·교육 개선
```

### 관리체계와 Privacy

```text
조직 목표·법적 의무
→ Governance와 정책·책임
→ Risk 기반 통제 구축
→ ISMS 운영·측정·검토
→ 개인정보 처리는 목적·최소화·보유기간·권리 추가
→ PIA로 변경 전 Privacy 위험 평가
→ 사고·감사 결과로 개선
```

## 기출 보정 기록

아직 공식 출제기준과 최근 기출을 반영하지 않은 1차 분류다.

- 법·인증·표준은 현행 명칭과 시행 기준을 확인하여 교재의 폐지 제도를 교체한다.
- 공격명은 빈도만으로 승급하지 않고 위험관리·Architecture·Secure SDLC 답안에 결합되는지를 본다.
- Cloud·Application·공급망·Zero Trust 등 교재 이후 핵심 주제는 최신 기출에서 별도 토픽 추가 여부를 판단한다.
- 변경 시 `기존 등급 → 새 등급`, 근거 회차, 질문 형태를 기록한다.
