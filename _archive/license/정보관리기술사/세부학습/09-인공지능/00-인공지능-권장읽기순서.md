## 왜 이 순서인가

처음부터 RAG나 Agent로 들어가면 각각이 별개의 AI 기술처럼 보이기 쉽다. 먼저 AI 전체에서 LLM의 위치를 잡고, Foundation Model을 이해한 뒤 LLM 자체의 동작으로 내려가는 편이 좋다.

특히 다음 세 문서는 연속해서 읽는 것을 권장한다.

```text
LLM의-동작원리.md
        ↓
"Transformer 내부에서 무엇이 일어나는가?"

LLM-추론과-Token-생성.md
        ↓
"Transformer의 결과가 실제 다음 Token으로 어떻게 바뀌는가?"

LLM-내부운영과-GPU-메모리.md
        ↓
"이 거대한 계산을 실제 Hardware에서 어떻게 실행하는가?"
```

이 세 문서를 읽으면 다음 흐름이 연결된다.

```text
Token
 ↓
Embedding
 ↓
Transformer / Attention
 ↓
문맥화된 Hidden Vector
 ↓
LM Head
 ↓
Logit
 ↓
Softmax
 ↓
Decoding
 ↓
다음 Token
 ↓
KV Cache를 이용해 반복 생성
 ↓
이를 빠르게 처리하기 위한 GPU / VRAM
```

그 뒤에는 **이미 만들어진 LLM을 어떻게 활용하는가**로 넘어간다.

```text
LLM
 ↓
Prompt / Context
 ↓
RAG
 ↓
Fine-tuning
 ↓
Agent / MCP
 ↓
Agent Harness
 ↓
Text2SQL 같은 실제 응용
```

`에이전트와-MCP.md`를 먼저 읽고 `Agent-Harness.md`를 읽는 이유는, Harness를 별도의 새로운 AI 알고리즘으로 오해하지 않기 위해서다. 먼저 Agent의 핵심인 `LLM → Tool → Observation → LLM` 반복 Loop를 이해한 뒤, 그 Agent를 어떤 Rule·Skill·Hook·Workflow·권한·Orchestration으로 운용할 것인지 보는 것이 자연스럽다.

## 읽는 방법

모든 내용을 한 번에 암기하려 하지 않는다.

```text
1. 이 문서에서 다음에 읽을 파일 확인
2. 상세 문서 읽기
3. 이해되지 않는 부분은 원리까지 확인
4. 다시 00-인공지능-개념지도.md로 돌아오기
5. 전체 지도에서 방금 배운 개념의 위치 확인
6. 다음 문서로 이동
```

즉 `00-인공지능-개념지도.md`는 **개념의 위치를 확인하는 지도**, 이 문서는 **실제로 걸어갈 순서를 알려주는 경로 안내**로 사용한다.
