# 인공지능 세부학습 개념지도

이 문서는 `학습지도/09-인공지능.md`에서 학습할 개념 꼭지를 가져와, **하나의 개념에서 상위·하위·인접 개념으로 파고들며 학습할 수 있도록 연결하는 탐색 지도**다.

단순한 AI 분류표나 시험 범위 요약이 목적이 아니다. 학습할 때 `이 개념의 상위는 무엇인가`, `바로 아래에는 무엇이 있는가`, `옆의 비슷한 개념은 무엇인가`, `다음에는 무엇을 파야 하는가`를 찾는 데 사용한다.

GitHub 모바일 앱, Obsidian, Terminal 등 어떤 Markdown Viewer에서도 바로 읽을 수 있도록 **Mermaid에 의존하지 않고 Text/ASCII Diagram을 기본**으로 한다.

## 1. 가장 먼저 볼 전체 지도: AI는 LLM보다 크다

```text
AI
│
├─ 명시적 지식·규칙으로 판단
│   ├─ Rule 기반
│   └─ 전문가 시스템
│
└─ Data / Feedback에서 Pattern 학습
    └─ Machine Learning
        │
        ├─ 지도학습
        │   ├─ 분류
        │   └─ 회귀
        │
        ├─ 비지도학습
        │   ├─ 군집
        │   └─ 차원축소
        │
        └─ 강화학습
            └─ 순차 의사결정

Machine Learning
│
├─ 고전 ML 계열
│   ├─ 회귀 · 통계 · 거리 기반
│   ├─ Tree · Ensemble · KNN
│   ├─ SVM · Bayesian
│   └─ 군집 · 차원축소
│
└─ Neural Network / Deep Learning
    ├─ MLP
    ├─ CNN
    ├─ RNN → LSTM / GRU
    └─ Transformer
        └─ Foundation Model / LLM과 연결

AI 응용
├─ 예측 · 분류 · 추천
├─ Vision · Pattern Recognition
├─ NLP · 음성
├─ 생성형 AI
└─ 자동화된 의사결정 / Agent

[전 영역 횡단]
평가 · Data 품질 · 공정성 · XAI · 보안 · 윤리 · Governance
```

RAG·Agent·MCP를 중심으로 공부하면 `AI = LLM`처럼 느껴질 수 있지만, LLM은 이 전체 지도에서 **Deep Learning과 Foundation Model의 발전이 언어 영역에서 크게 확장된 가지**다.

## 2. 학습 방식: 어떤 Feedback을 가지고 있는가

Model 이름보다 먼저 학습 조건을 본다.

```text
문제를 해결해야 함
 ↓
무엇을 이용할 수 있는가?
│
├─ 사람이 정의한 명시적 지식
│   └─ Rule / 전문가 시스템
│
├─ 입력과 정답 Pair
│   └─ 지도학습
│       ├─ 분류
│       └─ 회귀
│
├─ 정답 없는 Data의 구조
│   └─ 비지도학습
│       ├─ 군집
│       └─ 차원축소
│
└─ 행동 결과의 보상
    └─ 강화학습
        ↓
       MDP
        ↓
    Q-Learning
        ↓
       DQN
```

`지도 → 비지도 → 강화`가 발전 순서는 아니다. **어떤 학습 신호가 주어지는가에 따른 병렬 패러다임**이다.

강화학습에서는 `MDP → Q-Learning → DQN`처럼 직접 파고들 수 있는 흐름이 생긴다. 반면 HMM, MCTS 등은 같은 순차·탐색 영역에서 만날 수 있지만 이 사슬의 하위 단계로 억지로 넣지 않는다.

## 3. 고전 Machine Learning: 병렬 Algorithm 계열을 탐색한다

학습 패러다임을 잡은 뒤 실제 문제에 맞는 Algorithm을 선택한다.

```text
Machine Learning
│
├─ 회귀 · 통계 기반
│   └─ 연속값 예측과 변수 관계
│
├─ 거리 기반
│   └─ KNN 등
│
├─ Tree 기반
│   ├─ Decision Tree
│   └─ Ensemble
│       ├─ Bagging
│       └─ Boosting
│
├─ 경계 기반
│   └─ SVM
│
├─ 확률 기반
│   └─ Bayesian 계열
│
├─ Pattern / 관계 발견
│   └─ 연관규칙
│
└─ 정답 없는 구조 탐색
    ├─ Clustering
    └─ 차원축소
```

이 영역은 `회귀 → KNN → Tree → SVM` 같은 하나의 발전 사슬이 아니다. **각 꼭지를 잡고 문제 조건·장단점·비교 대상을 옆으로 파는 영역**이다.

## 4. Neural Network와 Deep Learning: 표현을 Model이 학습한다

```text
Machine Learning
 ↓
Neural Network
 ↓
MLP / Deep Neural Network
 ↓
Forward Propagation
 ↓
Loss
 ↓
Backpropagation
 ↓
Weight 갱신
```

학습이 깊어지면서 함께 파야 할 꼭지:

```text
Training
├─ Activation Function
├─ Loss Function
├─ Optimizer / Learning Rate
├─ Overfitting
│   ├─ Regularization
│   └─ Dropout
└─ Generalization
```

Data 구조에 따라 Network Architecture도 갈라진다.

```text
Deep Learning
│
├─ 공간적 특징
│   └─ CNN
│
├─ 순서 · 시계열
│   └─ RNN
│       ├─ 장기 의존성 문제
│       └─ LSTM / GRU
│
└─ Token 간 관계
    └─ Attention
        └─ Transformer
```

## 5. 서로 다른 분류축을 섞지 않는다

AI를 파다 보면 CNN, RNN, Transformer, GAN, Diffusion, LLM, Multimodal, Foundation Model이 함께 등장한다. 하지만 같은 축의 용어가 아니다.

```text
[학습 방식]
지도 / 비지도 / 강화

[Architecture]
MLP / CNN / RNN / Transformer

[생성 원리·구조]
Autoregressive / GAN / Diffusion

[Modality]
Text / Image / Audio / Video

[범용성]
Task-specific Model / Foundation Model

[활용 방식]
Prompt / RAG / Fine-tuning / Tool / Agent / MCP
```

따라서 다음처럼 외우면 안 된다.

```text
CNN → RNN → GAN → Transformer          X
LLM → GAN → Diffusion → Multimodal     X
```

실제 시스템에서는 서로 다른 축이 조합된다.

```text
GPT류 LLM
= Text Modality
+ Transformer Architecture
+ Autoregressive Generation
+ 대규모 Pre-training
```

## 6. 평가: Model을 학습하면 반드시 성능을 검증한다

```text
Data
 ↓
Train / Validation / Test 분리
 ↓
Training
 ↓
Validation · Hyperparameter 조정
 ↓
Test / 최종 평가
```

Data가 제한적이면 다음으로 파고든다.

```text
Validation
└─ Cross Validation
    └─ K-Fold 등
```

분류 문제에서는 오류 비용에 따라 지표를 선택한다.

```text
Classification Metrics
├─ Accuracy
├─ Precision
├─ Recall
└─ F1
```

`Accuracy → Precision → Recall → F1`은 발전 순서가 아니다. **문제에서 어떤 오류가 중요한지에 따라 함께 비교하는 지표**다.

평가에서 자연스럽게 이어지는 주변 꼭지는 `Overfitting`, `Generalization`, `Bias`, `Data Leakage`, `Data 품질` 등이다.

## 10. LLM 활용: 무엇이 부족한가에 따라 주변 기술로 내려간다

```text
                         LLM
                          │
        ┌─────────────────┼─────────────────┐
        ↓                 ↓                 ↓
      지시·예제           외부 지식            행동
        │                 │                 │
System Prompt             RAG           Tool Calling
Prompt / Few-shot          │                 │
        │             Embedding             Agent
        │             Retrieval              │
        │                                   MCP
        │                                    │
        └────────────── Context ─────────────┘

반복적인 Model 행동 자체 조정
→ Fine-tuning
```

선택 질문으로 보면:

```text
역할·규칙을 지정하고 싶은가?       → Prompt / System Prompt
몇 개 예제로 Pattern을 보여줄까?  → Few-shot
최신·사내 지식이 필요한가?        → RAG
반복 행동 자체를 조정할까?        → Fine-tuning
외부 세계에서 행동해야 하는가?     → Tool / Agent
```

상세: `LLM-프롬프트와-Context-제어.md`, `Fine-tuning과-PEFT-LoRA.md`

## 11. RAG: 외부 지식을 찾는 가지를 끝까지 따라간다

```text
RAG
│
├─ 사전 구축
│   └─ 문서
│       ↓
│     Chunking
│       ↓
│     Embedding Model
│       ↓
│     Chunk Vector
│       ↓
│     Vector DB
│       ├─ Vector
│       ├─ 원문 Chunk
│       └─ Metadata / 권한
│
└─ 질문 시
    └─ Query
        ↓
      Query Embedding
        ↓
      Retrieval
        ├─ Keyword / BM25
        ├─ Vector Search
        │   ├─ Exact Search
        │   └─ ANN
        │       ├─ HNSW
        │       └─ IVF / IVFFlat
        └─ Hybrid Search
        ↓
      Re-ranking
        ↓
      Top-K 원문 Chunk
        ↓
      LLM Context
        ↓
      Generation
```

검색용 Vector는 LLM에 답변 재료로 직접 전달하는 압축 Data가 아니다. **관련 원문을 찾기 위한 의미적 검색 표현**이다.

긴 Chunk가 Vector 하나가 되는 흐름도 RAG에서 자연스럽게 파고드는 꼭지다.

```text
Chunk
 ↓
Tokenization
 ↓
문맥화된 Token 표현
 ↓
Pooling / 집약
 ↓
고정 길이 Chunk Vector
```

상세: `임베딩-벡터검색-RAG.md`

## 12. Fine-tuning: SFT와 PEFT는 다른 분류축이다

```text
Fine-tuning
│
├─ [학습 신호 관점]
│   └─ SFT
│       └─ 입력-정답 Pair
│
└─ [Parameter 효율 관점]
    ├─ Full Fine-tuning
    └─ PEFT
        └─ LoRA

SFT Data + LoRA 방식
→ 함께 사용 가능
```

주변 개념과의 경계:

```text
Prompt / Few-shot / RAG
→ Inference Context 변경
→ 기본 Model Weight 변경 없음

Fine-tuning
→ Training 수행
→ Weight 또는 추가 학습 Parameter 변경
```

상세: `Fine-tuning과-PEFT-LoRA.md`

## 13. Agent: LLM에 행동과 반복 Loop를 붙인다

```text
사용자 목표
 ↓
LLM 판단
 ↓
Tool이 필요한가?
 ├─ 아니오 → 최종 답변 / 종료
 └─ 예
      ↓
    Tool Call
      ↓
    실제 Tool 실행
      ↓
    Observation
      ↓
    Context에 결과 추가
      ↓
    LLM 재판단
      └──────── 반복
```

Agent를 잡으면 다음 주변 꼭지로 내려간다.

```text
Agent
├─ LLM
├─ Tool
│   ├─ File
│   ├─ Shell
│   ├─ DB
│   └─ API
├─ Observation / Context
├─ Memory
├─ Agentic RAG
└─ Runtime / Harness
    ├─ Rules / Context
    ├─ Skills
    ├─ Hooks
    ├─ Tool / Permission
    ├─ Workflow
    └─ Orchestration
```

상세: `에이전트와-MCP.md`, `Agent-Harness.md`

## 14. MCP: Agent가 외부 기능을 사용하는 연결 규격

```text
Agent / AI Client
 ↓
MCP
├─ Tools
├─ Resources
└─ Prompts
 ↓
MCP Server
 ↓
기존 API / DB / File / 외부 System
```

MCP가 없어도 Agent가 외부 API를 직접 호출할 수 있다. MCP는 Agent 자체나 Tool 자체가 아니라 **Tool·Resource를 발견하고 호출하는 공통 Protocol**이다.

RAG와도 계층이 다르다.

```text
Agent
 ↓
