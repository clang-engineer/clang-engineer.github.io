# 인공지능 세부학습 개념지도

이 문서는 `학습지도/09-인공지능.md`에서 정한 범위를 바탕으로, 인공지능의 큰 개념들이 **어디에 있고 어떻게 연결되는지** 빠르게 잡는 지도다.

학습지도는 `무엇을 공부할 것인가`를 정하고, 이 개념지도는 `그 개념들이 어떻게 연결되는가`를 보여준다. Algorithm·Parameter·구현 상세는 각 세부학습 문서에서 다룬다.

---

## 1. 가장 먼저 잡을 전체 구조

```text
AI
│
├─ 명시적 지식으로 판단
│   └─ 규칙 · 전문가 시스템
│
└─ Data / Feedback으로 학습
    └─ Machine Learning
        ├─ 정답 Data      → 지도학습
        ├─ 정답 없이 구조 → 비지도학습
        └─ 행동 · 보상     → 강화학습

문제와 Data 형태에 따라
↓
고전 ML · 신경망 / Deep Learning · 기반모델 활용
↓
학습 · 평가
↓
배포 · 추론 · 모니터링
↓
예측 · 분류 · 군집 · 생성 · 의사결정

[전 과정 횡단]
Data 품질 · 개인정보 · 공정성 · 보안 · XAI · 책임 · 감사
```

핵심은 **AI = LLM이 아니라는 것**이다. LLM과 생성형 AI는 이 전체 구조 안의 한 영역이다.

---

## 2. 어떤 조건으로 학습하는가

가장 먼저 Model 이름이 아니라 **어떤 학습 신호가 있는가**를 본다.

```text
문제
 ↓
사용 가능한 정보는?
│
├─ 명시적인 규칙·지식
│   └─ 규칙 / 전문가 시스템
│
├─ 입력 + 정답
│   └─ 지도학습
│       └─ 분류 · 회귀 등
│
├─ 정답 없는 Data
│   └─ 비지도학습
│       └─ 군집 · 차원축소 등
│
└─ 상태에서 행동하고 보상을 받음
    └─ 강화학습
        └─ MDP → Q-Learning → DQN 등
```

지도·비지도·강화학습은 특정 Algorithm 이름이 아니라 **학습 문제를 나누는 큰 패러다임**이다.

---

## 3. 학습 방법을 정한 뒤 Model 계열을 선택한다

학습 패러다임과 구체적인 Model/Algorithm은 같은 분류축이 아니다.

```text
학습 문제와 Data 조건
 ↓
학습 패러다임 결정
 ↓
구체적인 방법 선택
│
├─ 고전 Machine Learning
│   ├─ 회귀 · 통계 기반
│   ├─ 거리 기반
│   ├─ Tree · Ensemble
│   ├─ SVM
│   ├─ Bayesian
│   └─ 군집 · 차원축소 등
│
└─ Neural Network / Deep Learning
    ├─ MLP
    ├─ CNN
    ├─ RNN → LSTM / GRU
    └─ Transformer 등
```

고전 ML의 여러 방법은 하나의 발전 사슬이라기보다 **문제와 Data 특성에 따라 고르는 병렬 선택지**에 가깝다.

---

## 4. Deep Learning은 Machine Learning 안의 표현력 확장

```text
AI
└─ Machine Learning
    ├─ 고전 ML
    └─ Neural Network
        └─ Deep Learning
            ├─ CNN      → 공간적 특징
            ├─ RNN      → 순서가 있는 Data
            │   └─ LSTM / GRU
            └─ Transformer
                └─ Attention 기반 관계 표현
```

Deep Learning에서는 Model 구조뿐 아니라 학습 과정도 함께 본다.

```text
입력
 ↓
Forward Propagation
 ↓
예측
 ↓
Loss
 ↓
Backpropagation
 ↓
Weight 갱신
```

과적합·일반화·Regularization은 이 학습 과정과 연결된다.

상세: `딥러닝-대표구조-CNN-RNN-Transformer-GAN.md`

## 5. Model을 만들었으면 반드시 평가하고 운영해야 한다

AI의 흐름은 Model Training에서 끝나지 않는다.

```text
문제 정의
 ↓
Data 준비
 ↓
Training
 ↓
Validation / Evaluation
 ↓
배포
 ↓
Inference
 ↓
Monitoring
 ↓
성능 저하 · 위험 발생?
 ├─ 아니오 → 운영 지속
 └─ 예     → 사용 제한 · Rollback · 재학습
```

평가 지표도 하나의 절대 순서가 아니다.

```text
Accuracy
Precision
Recall
F1
...
```

어떤 오류의 비용이 큰지에 따라 적절한 지표를 선택한다.

그리고 다음은 마지막 단계가 아니라 **전체 Lifecycle을 가로지르는 통제**다.

```text
Data 품질 / 개인정보
공정성 / Bias
AI 보안
XAI / 설명가능성
책임 / 감사 / Governance
```

## 6. 생성형 AI와 Foundation Model은 어디에 있는가

Deep Learning의 발전으로 대규모 사전학습 Model을 여러 Task에 재사용하는 Foundation Model이 중요해졌다.

```text
대규모 Data
 ↓
Pre-training
 ↓
Foundation Model
├─ Language Foundation Model
│   └─ LLM
├─ Vision Foundation Model
├─ Multimodal Foundation Model
└─ Domain Foundation Model
```

생성형 AI는 Text뿐 아니라 여러 Modality에서 새로운 결과를 생성한다.

```text
Generative AI
├─ Text  → LLM
├─ Image → GAN / Diffusion 등
├─ Audio / Video
└─ Multimodal
```

`Foundation Model`, `Generative AI`, `LLM`, `Transformer`, `GAN`, `Multimodal`은 모두 같은 계층의 용어가 아니다.

상세: `생성형-AI와-멀티모달.md`, `Foundation-Model과-AI-활용계층.md`

## 7. LLM은 생성형 AI 안의 큰 가지다

LLM 내부를 가장 크게 보면 다음 흐름만 먼저 잡는다.

```text
Text
 ↓
Tokenization
 ↓
Embedding
 ↓
Transformer / Attention
 ↓
다음 Token 후보
 ↓
Token 생성
 ↓
다시 Context에 추가
 └──────── 반복
```

그리고 LLM을 업무에 활용하는 방법은 크게 다음처럼 연결된다.

```text
                       LLM
                        │
        ┌───────────────┼───────────────┐
        ↓               ↓               ↓
      지시             외부 지식          행동
        │               │               │
 Prompt / Few-shot      RAG         Tool / Agent
                                        │
                                       MCP

Model 행동 자체 조정
→ Fine-tuning
```

- Prompt / Few-shot / RAG: 주로 Inference Context를 구성
- Fine-tuning: 추가 Training으로 학습 Parameter를 조정
- Agent: Tool 실행 결과를 관찰하며 판단·행동을 반복
- MCP: 외부 Tool·Resource를 Agent에 연결할 수 있는 Protocol
- Harness: Agent의 Rule·Context·Tool·Workflow·권한 등을 구성하는 운용 체계

상세: `LLM의-동작원리.md`, `임베딩-벡터검색-RAG.md`, `Fine-tuning과-PEFT-LoRA.md`, `에이전트와-MCP.md`, `Agent-Harness.md`

## 8. 응용은 Model과 별개의 문제 영역이다

AI 기술은 실제 문제 영역에 조합되어 사용된다.

```text
AI / ML / DL / Foundation Model
 ↓
응용 영역
├─ NLP · 음성
├─ 추천
├─ Pattern Recognition / Vision
├─ 보안
└─ 업무 자동화
```

예를 들어 Text2SQL은 LLM 자체가 아니라 **자연어를 SQL로 변환하는 Task**다.

```text
Text2SQL
├─ Rule / Template
├─ 전용 ML Model
└─ LLM 기반
    ├─ Schema Retrieval
    ├─ Schema Linking
    └─ SQL Generation
```

상세: `Text2SQL과-스키마-링킹.md`

## 9. 전체를 한 번에 다시 연결한다

```text
문제와 실패 비용
 ↓
어떤 정보로 해결할 것인가?
├─ 명시적 지식       → 규칙 / 전문가 시스템
├─ 정답 Data         → 지도학습
├─ 정답 없는 Data    → 비지도학습
├─ 행동 · 보상       → 강화학습
└─ 사전학습 Model    → Foundation Model 활용
 ↓
문제와 Data에 맞는 구체적인 방법 선택
├─ 고전 ML
├─ Neural Network / Deep Learning
└─ Foundation Model / LLM 활용
 ↓
Training · Evaluation
 ↓
배포 · Inference · Monitoring
 ↓
실제 응용

[항상 함께 보는 횡단 통제]
Data 품질 · 개인정보 · 공정성 · 보안 · XAI · 책임 · 감사
```

이 지도의 목적은 Algorithm을 모두 담는 것이 아니다.

> **새로운 AI 용어를 만나면 먼저 `학습 패러다임`, `Model/Architecture`, `Training·평가`, `Foundation Model 활용`, `응용`, `운영·통제` 중 어디에 위치하는지 찾는다. 그 다음 세부학습 문서로 내려간다.**
