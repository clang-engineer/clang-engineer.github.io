# 클라우드 인프라 구성과 관리

> [클라우드 전체 개념지도](00-전체.md) → Cloud Infrastructure  
> 범위: 성안당 Vol.10의 Compute·Network·Storage와 이를 서비스로 제공하는 기반 기술.

## 1. 큰 그림 — 기존 자원을 어떻게 클라우드 서비스로 제공하는가?

온프레미스에서도 서버·네트워크·스토리지를 사용한다. 클라우드는 이러한 자원을 **풀링·추상화·자동 할당하여 사용자가 서비스로 요청할 수 있게 한다**.

```text
[클라우드 사용자]
VM 생성 / VPC 구성 / Storage 할당 요청
                  │ API·Console
                  ▼
[클라우드 관리·자동화 계층]
인증·권한 / 자원 배치 / Provisioning
                  │ 구성 요청
          ┌───────┼────────┐
          ▼       ▼        ▼
       Compute  Network  Storage
       VM 실행  가상망 연결 Volume 할당
          └───────┼────────┘
                  ▼
           서비스 이용·운영
────────────────────────────────────
[사업자 기반] 물리 서버·네트워크 장비·저장장치
```

이 흐름은 대표적인 **VM 제공 개념 모델**이다. 모든 클라우드가 동일한 구현이나 OpenStack을 사용하는 것은 아니다.

## 2. 사용자가 제공받는 자원

```text
Cloud Infrastructure Service
├─ Compute — 어디서 실행?
│  ├─ Bare Metal : 전용 물리 서버
│  ├─ VM         : Hypervisor 기반 가상 서버
│  └─ Container  : Kernel 공유 실행환경
├─ Network — 어떻게 연결?
│  └─ VPC / Subnet / Routing / VPN
└─ Storage — 어떤 형태로 저장?
   ├─ Block  : 서버에 Volume 연결 (예: AWS EBS)
   ├─ File   : 공유 File System   (예: AWS EFS)
   └─ Object : API로 객체 저장    (예: AWS S3)
```

**클라우드 ≠ VM.** 클라우드는 자원 제공·관리 모델이고 VM은 실행환경 중 하나다. Container는 물리 서버 또는 VM 위에서 실행될 수 있다. Bare Metal은 물리 서버를 전용으로 사용하는 방식이며, IDC(서버를 수용하는 시설)와 다르다.

스토리지에서 **Block/File/Object는 사용자에게 제공하는 접근 방식**이다. 특정 서비스가 전통적인 DAS·NAS·SAN으로 구현된다는 뜻은 아니다.

## 3. 사업자가 서비스를 구현하는 기술

### Compute — 가상화와 자원 할당

```text
물리 서버 (CPU / RAM)
      │ 자원 추상화·할당
      ▼
Hypervisor → VM → Guest OS → Application

별도 실행 방식: Bare Metal 전용 제공
VM 또는 물리 서버 위: Container 실행 가능
```

가상화는 자원을 나누고 격리하는 **구현 기술**이다. 관리 플랫폼은 이 자원을 요청에 맞게 배치·할당한다.

### Network — SDN과 NFV

```text
[SDN: 네트워크 제어 구조]
Controller ──경로·정책 제어──> Switch / 전달 장치

[NFV: 네트워크 기능 실행 방식]
범용 서버 ──실행──> Virtual Firewall / Virtual Router
```

- **SDN(Software-Defined Networking):** 제어 평면과 패킷 전달 평면을 분리해 네트워크를 소프트웨어 중심으로 제어한다.
- **NFV(Network Functions Virtualization):** 방화벽·라우터 같은 네트워크 기능을 전용 장비 대신 범용 컴퓨팅 자원의 소프트웨어로 실행한다.

온프레미스의 **장비별 제어·설정**과 **전용 방화벽 장비**를 떠올리면 차이가 분명해진다. SDN은 *제어 구조*, NFV는 *기능의 실행 위치·방식*을 바꾼다. 둘은 함께 사용할 수 있지만, 모든 VPC나 VM 생성에 반드시 적용되는 기술은 아니다.

### Storage — Pooling과 Provisioning

```text
사업자의 저장 자원
       ↓ Pooling
논리적 Storage Pool
       ↓ Provisioning
사용자에게 Block / File / Object 서비스 제공
```

- **Pool:** 여러 저장 자원을 논리적으로 묶어 관리한다.
- **Provisioning:** 필요한 용량·Volume 등을 할당한다.
- **Tiering:** 데이터 특성에 따라 저장 계층을 선택·이동한다.
- **RAID:** 디스크를 조합해 성능·내결함성을 확보하는 전통적인 방식이다. 백업을 대신하지 않는다.

사업자는 전통적인 DAS·NAS·SAN 또는 분산 스토리지 등 여러 구조를 활용할 수 있다. **사용자가 받는 Storage 서비스 유형과 사업자 내부의 물리적 연결 구조는 다른 분류 축**이다.

### 통합·관리 — 인프라 구성과 서비스 제공 계층

```text
물리 Compute / Network / Storage
           │
           ├─ Converged / HCI : 인프라 통합 방식
           │
           ▼
클라우드 관리 플랫폼 (예: OpenStack)
           │
           └─ API / 자동 할당 / 서비스 관리
```

- **Converged Infrastructure:** 서버·스토리지·네트워크를 사전 통합한 인프라 구성.
- **HCI(Hyper-Converged Infrastructure):** 범용 서버와 가상화·소프트웨어 정의 스토리지 등을 결합한 통합 인프라.
- **OpenStack:** Compute(Nova), Network(Neutron), Block Storage(Cinder), Object Storage(Swift) 등의 자원을 API로 제공·관리하는 오픈소스 클라우드 플랫폼.

Converged·HCI는 **기반 인프라를 구성하는 접근**, OpenStack은 **클라우드 자원을 관리·제공하는 플랫폼**이다. HCI와 OpenStack은 필수적인 선후 단계도, 직접적인 대체재도 아니다.

## 4. 기존 온프레미스 기술의 위치

다음은 클라우드 고유의 서비스 모델이 아니라, 사업자 내부 또는 일반 데이터센터에서 활용할 수 있는 **기존 인프라 기술**이다.

| 기술 | 기존 역할 | 클라우드와의 연결 |
|---|---|---|
| VLAN | 하나의 물리망을 논리적 L2 영역으로 분리 | 네트워크 격리 구현에 활용 가능 |
| VPN | 떨어진 네트워크를 논리적으로 연결 | 온프레미스·클라우드 연결 등에 활용 |
| Bonding / Teaming | 여러 NIC를 논리적으로 묶음 | 호스트 링크 이중화·분산 |
| 3-Tier / Spine-Leaf | 스위치 연결 토폴로지 | 데이터센터 네트워크 구성 |
| DAS / NAS / SAN | 저장장치 연결·접근 구조 | 기반 스토리지 구현에 활용 가능 |

```text
Network 구성: VLAN(분리) / VPN(연결) / Bonding(NIC 결합)
Topology    : 3-Tier(Core·Distribution·Access)
              ↔ Spine-Leaf(Leaf마다 Spine 연결)
Storage 연결: DAS(직접) / NAS(파일 공유) / SAN(블록 망)
```

이 기술들을 모두 사용해야 클라우드가 되는 것은 아니다. **기존 인프라의 연결·구성 방법**과 **클라우드의 서비스화·자동화**를 구분해서 이해한다.

## 5. 기억·인출 장치

```text
기존 인프라 (Server / Network / Storage)
               ↓ 추상화·풀링
관리 플랫폼 (요청 / 배치 / 할당 / 자동화)
               ↓ 서비스 제공
Compute / Network / Storage

SDN  → 네트워크 제어 구조
NFV  → 네트워크 기능의 SW 실행
HCI  → 기반 자원 통합
OpenStack → 클라우드 자원 관리·제공
```
