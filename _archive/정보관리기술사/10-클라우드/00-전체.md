# 클라우드 전체 개념지도

> 클라우드는 **컴퓨팅 자원을 서비스로 사용하면서 배치 위치·관리 책임·실행환경을 선택하고, 탄력성·비용·가용성·보안의 Trade-off를 운영하는 방식**이다.

이 문서는 성안당 Vol.10의 문제군을 범위의 뼈대로 삼되, 교재 순서보다 **어디에 둘 것인가 / 어디까지 맡길 것인가 / 어떤 환경에서 실행할 것인가**라는 의사결정 구조로 재배치한다.

## 1. 클라우드 전체 좌표

```text
사업 목표 · Workload
+ 규제 · Data 주권 · SLA/SLO · 비용 · 복구 목표
                    ↓
            Shared Responsibility
                    ↓
┌────────────────────────────────────────────┐
│ 함께 결정할 세 가지 축                    │
│                                            │
│ 배치 위치        관리 범위        실행환경 │
│ Public           IaaS             Bare Metal
│ Private          PaaS             VM
│ Hybrid           SaaS             Container
│ Multi            XaaS             Serverless
│ Sovereign / Edge                           │
└────────────────────────────────────────────┘
                    ↓
      Compute · Network · Storage 구성
                    ↓
      Cloud Native · MSA · Kubernetes
                    ↓
     Migration / Deployment / Operation
                    ↓
 Observability → Auto Scaling → HA / DR
                    ↓
       Cost · Performance · Security KPI
                    ↺
```

보안·규제·SLA는 마지막에 붙이는 항목이 아니라 처음부터 모든 선택을 제약하는 횡단 축이다.

## 2. 어디를 파고들 것인가

### 배치 모델 · 서비스 모델

```text
[어디에 둘 것인가]
Public / Private / Hybrid / Multi / Sovereign

[어디까지 맡길 것인가]
IaaS / PaaS / SaaS
```

두 분류는 서로 다른 질문이다. 배치 모델은 **위치와 소유·통제 경계**, 서비스 모델은 **공급자와 사용자의 관리 책임 경계**를 결정한다.

→ [클라우드 배치와 서비스 유형](클라우드-배치와-서비스-유형.md)

### 가상화 · 실행환경

```text
Physical Resource
      ↓
Virtualization
├─ VM
│   └─ Guest OS 단위 격리
├─ Container
│   └─ OS Kernel 공유
└─ Serverless
    └─ 실행환경 운영을 더 많이 Provider에 위임
```

대표 비교·분류 축:
- Full ↔ Para Virtualization
- VM ↔ Container
- 직접 관리 ↔ Provider 관리 확대

→ [가상화 구조와 VM · Container](가상화-구조와-VM-컨테이너.md)

### Network · Storage

```text
Cloud Infrastructure
├─ Network
│   ├─ SDN ↔ NFV
│   ├─ 3-Tier ↔ Spine-Leaf
│   └─ VLAN / VPN
│
└─ Storage
    ├─ Block / File / Object
    ├─ DAS / NAS / SAN
    └─ Tiering / Provisioning / RAID
```

Compute만 확장해도 Network·Storage가 병목이면 전체 성능은 늘지 않는다. 세 자원은 하나의 Workload 경로로 함께 본다.

### Cloud Native · 자동화 · 운영

```text
Cloud Native
├─ MSA
├─ Container
└─ Kubernetes
      ↓
Deployment / Orchestration
      ↓
Observability
      ↓
Auto Scaling
      ↓
HA / DR / Recovery
```

Auto Scaling은 부하 변화에 대응하는 용량 조절이고, HA·DR·Backup을 대체하지 않는다.

### Desktop · End User Computing

```text
중앙화된 Desktop 제공
├─ VDI
├─ RDS / SBC
├─ CCI / DaaS
└─ Thin / Zero Client
```

→ [Desktop 가상화 · VDI · RDS · CCI · DaaS](데스크톱-가상화-VDI-RDS-CCI-DaaS.md)  
→ [VDI · Thin · Zero Client](VDI-Thin-Zero-Client.md)

### Security · Governance · SLA

```text
Multi-Tenancy / Shared Responsibility
        ↓
Identity · Isolation · Encryption
        ↓
Audit / Certification / CASB
        ↓
SLA / SLO · Compliance
```

클라우드 보안은 기존 보안 통제를 없애는 것이 아니라 **공급자와 사용자의 책임 경계가 바뀌는 환경에서 통제를 재배치하는 문제**로 본다.

## 3. 탐색 방식

```text
성안당 문제·학습등급표
        ↓
클라우드 전체 개념지도
"어떤 경계와 책임을 선택하는가"
        ↓
필요한 세부학습
"구조·비교·운영 Trade-off는 무엇인가"
```

제품별 기능이나 버전보다 **배치·서비스·실행환경·Network/Storage·운영·보안 책임의 경계**를 우선 인출한다.
