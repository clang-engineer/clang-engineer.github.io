# 클라우드 전체 개념지도

> **목적:** 클라우드 컴퓨팅의 핵심 구조·관계·선택 기준을 조망하고 복습할 때 인출하는 지도  
> 기술사 시험 대비 참고: [성안당 Vol.10 클라우드](../성안당/Vol.%2010%20클라우드.md) · 기출·학습등급표

## 1. 전체 조망

```text
Cloud Computing
자원 풀링 · On-Demand · 탄력성 · 사용량 측정
│
├─ 배치·활용 — 어디에 둘까?
│  ├─ Public / Private / Hybrid
│  └─ Multi-Cloud (복수 공급자 활용)
│
├─ 서비스·책임 — 어디까지 맡길까?
│  ├─ IaaS / PaaS / SaaS
│  └─ XaaS / Serverless
│
├─ 실행·인프라 — 자원을 어떻게 제공할까?
│  ├─ 기반 자원: Compute / Network / Storage
│  ├─ 추상화·격리: Virtualization → VM / Container
│  └─ 전용 물리 자원: Bare Metal
│
├─ 아키텍처·운영 — 어떻게 배포·운영할까?
│  ├─ Cloud Native / MSA / Kubernetes
│  └─ Auto Scaling / HA / DR
│
└─ 횡단 통제 — 무엇을 지켜야 할까?
   └─ Shared Responsibility / 보안 / SLA / 규제 / 비용

[확장·적용 관점] Edge(처리 위치) · Sovereign(주권·통제)
```

*위 가지는 순차적인 구축 단계가 아니라 서로 다른 선택·설계 관점이다. Serverless는 VM·Container와 같은 격리 방식이 아닌 운영 추상화 관점이다.*

## 2. 주요 분류·비교 좌표

### ① 배치·서비스 — 위치와 관리 책임

```text
배치 모델                       서비스 모델
Public / Private / Hybrid      IaaS → PaaS → SaaS
Multi-Cloud                    (공급자 관리 범위 확대)
              └───── 함께 선택 ─────┘
                         │
                 Shared Responsibility
```

→ [클라우드 배치와 서비스 유형](클라우드-배치와-서비스-유형.md) — 배치·서비스 모델의 차이

### ② 가상화·실행 — 자원 추상화와 활용

```text
Virtualization — 무엇을 추상화·격리하나?
├─ Compute
│  ├─ Server : Hypervisor / VM (Full ↔ Para)
│  └─ OS 수준: Container / Host Kernel 공유
├─ Network : 논리적 네트워크 자원
└─ Storage : 논리적 저장 자원

별도 제공 방식: Bare Metal (전용 물리 서버)
활용 사례: Desktop Virtualization / VDI
운영 추상화: 직접 관리 ─ 관리형 실행 ─ Serverless
```

가상화는 클라우드 전용 기술이 아니라 **물리 자원을 추상화·격리하는 기반 기술**이다. Desktop 가상화는 가상화의 활용 영역이며, Thin·Zero Client는 가상화 방식이 아닌 접속 단말이다. Serverless는 가상화 유형이 아니라 운영 책임의 추상화다.

→ [가상화 구조와 VM·Container](가상화-구조와-VM-컨테이너.md) — Compute 가상화와 실행환경 비교

### ③ 인프라 — 사용자 서비스와 사업자 구현

```text
Cloud Infrastructure
├─ 사용자 서비스
│  ├─ Compute : Bare Metal / VM / Container (예: AWS EC2)
│  ├─ Network : VPC / Subnet / Routing (예: AWS VPC)
│  └─ Storage : Block / File / Object (예: EBS / EFS / S3)
└─ 사업자 구현
   ├─ Compute : 가상화 / 물리 서버
   ├─ Network : SDN / NFV
   ├─ Storage : Tiering / RAID
   └─ 통합·관리
      ├─ CI / HCI : 인프라 통합
      ├─ OpenStack : 클라우드 관리 플랫폼
      ├─ Resource Pooling : 자원 논리적 통합·공유
      ├─ Provisioning : 자원 준비·구성·할당
      └─ Orchestration : 자원 구성 작업 조정
```

VLAN·Bonding·3-Tier/Spine-Leaf·DAS/NAS/SAN·RAID는 **기반 인프라의 구성 기술**로서 세부학습에서 관계를 확인한다. 서비스와 내부 구현은 일대일 대응이 아니다.

→ [클라우드 인프라 구성과 관리](클라우드-인프라-구성과-관리.md) — 서비스 제공 구조와 기반 기술

### ④ Cloud Native·운영 — 아키텍처와 신뢰성

```text
Cloud Native (지향점: 탄력성 · 복원력 · 자동화)
├─ 아키텍처 : MSA
├─ 실행     : Container
├─ 관리     : Kubernetes (예: AWS EKS)
└─ 운영     : Observability / Auto Scaling

Auto Scaling ≠ HA / DR / Backup
```

*MSA·Container·Kubernetes는 대표 수단이며 필수 구성요소는 아니다.*

### ⑤ Desktop — 중앙 업무환경 제공

```text
Desktop / Application 제공
├─ VDI
├─ RDS / SBC
├─ CCI / DaaS
└─ 접속 단말: Thin / Zero Client
```

→ [Desktop 가상화·VDI·RDS·CCI·DaaS](데스크톱-가상화-VDI-RDS-CCI-DaaS.md) — 제공 방식  
→ [VDI·Thin·Zero Client](VDI-Thin-Zero-Client.md) — 단말 비교

### ⑥ 보안·거버넌스 — 횡단 통제

```text
Shared Responsibility / Multi-Tenancy
├─ 접근·격리 : IAM / Encryption
├─ 서비스    : SECaaS / CASB
├─ 인증·감사 : CSAP / ISO 27017·27018
└─ 대응·책임 : Forensic / SLA / Compliance

[주권·통제 고려] Sovereign Cloud
```

## 3. 대표 인출 축

**배치 모델 ↔ 서비스 모델**, **VM ↔ Container**, **SDN ↔ NFV**, **Block/File/Object**, **CI ↔ HCI**, **Auto Scaling ↔ HA/DR**.
