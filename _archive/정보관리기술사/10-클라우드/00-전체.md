# 클라우드 전체 개념지도

> **목적:** 클라우드 컴퓨팅의 핵심 구조·관계·선택 기준을 조망하고 복습할 때 인출하는 지도  
> 기술사 시험 대비 참고: [성안당 Vol.10 클라우드](../성안당/Vol.%2010%20클라우드.md) · 기출·학습등급표

## 1. 전체 조망

```text
클라우드 — 자원을 서비스로 제공·활용·운영
│
├─ [1. 배치 · 활용]
│  └─ Public · Private · Hybrid · Multi-Cloud
├─ [2. 서비스 · 책임]
│  └─ IaaS · PaaS · SaaS · XaaS
├─ [3. 실행 · 인프라]
│  └─ Compute · Network · Storage · VM · VPC
├─ [4. 아키텍처 · 운영]
│  └─ MSA · Container · Kubernetes · Serverless · Observability · Scaling · HA/DR
└─ [5. 횡단 통제]
   └─ Shared Responsibility · 보안 · SLA · 비용 · 규제

[기반 기술] 가상화 · 물리 인프라 · Network · Storage
[적용 관점] Edge(처리 위치) · Sovereign(주권·통제)
```

*위 가지는 순차적인 구축 단계가 아니라 서로 다른 선택·설계 관점이다. Serverless는 VM·Container와 같은 격리 방식이 아닌 운영 추상화 관점이며, 서비스 모델과도 연결된다.*

## 빠른 복습 좌표

| 복습 축 | 핵심 관계·판단 단서 |
|---|---|
| 배치 | Public·Private·Hybrid·Multi-Cloud는 자원 배치·운영 선택 |
| 서비스 | IaaS → PaaS → SaaS는 공급자 관리 범위가 달라짐 |
| 실행 | VM은 Guest OS 격리, Container는 Kernel 공유, Serverless는 운영 추상화 |
| 운영 | Autoscaling(부하 대응), HA(가용성), DR(재해 복구), Observability(상태 파악) |
| 통제 | Shared Responsibility·SLA·보안·비용은 서비스·배치 선택과 함께 판단 |

**복습 방법:** 이 표에서 핵심 관계가 기억나지 않는 축만 아래 조망도와 연결된 하위 학습으로 내려간다. 상세 예제는 세부학습 본문에 남긴다.

## 2. 주요 분류·비교 좌표

### ① 배치·서비스 — 위치와 관리 책임

```text
배치 모델                       서비스 모델
Public / Private / Hybrid      IaaS → PaaS → SaaS
Multi-Cloud                    (공급자 관리 범위 확대)
              └───── 함께 선택 ─────┘
                         │
                 Shared Responsibility
```

→ [클라우드 배치와 서비스 유형](클라우드-배치와-서비스-유형.md) — 배치·서비스 모델의 차이

### ② 기반 기술과 연결 — 가상화의 활용

```text
기존 기반 기술: Virtualization
   ├─ VM / Hypervisor → 가상 서버 제공
   ├─ Container → 실행환경 격리
   └─ Desktop Virtualization → DaaS 등에 활용
                ↓
클라우드: 자원을 On-Demand로 제공·관리
```

가상화 자체의 구조·종류·VDI는 [가상화 전체 개념지도](../99-가상화/00-전체.md)에서 이해한다. **클라우드는 가상화를 활용할 수 있지만, 가상화와 동일한 개념은 아니다.**

### ③ 인프라 — 사용자 서비스와 사업자 구현

```text
Cloud Infrastructure
├─ 사용자 서비스
│  ├─ Compute : Bare Metal / VM / Container (예: AWS EC2)
│  ├─ Network : VPC / Subnet / Routing (예: AWS VPC)
│  └─ Storage : Block / File / Object (예: EBS / EFS / S3)
└─ 사업자 구현
   ├─ Compute : 가상화 / 물리 서버
   ├─ 자원 추상화 : VM / 가상 네트워크 / 저장 자원
   ├─ Resource Pooling : 자원 통합·공유
   ├─ Provisioning : 요청에 따른 자원 준비·할당
   └─ Orchestration : 자원 구성·운영 작업 조정
```

SDN·NFV·VLAN·3-Tier/Spine-Leaf·DAS/NAS/SAN·RAID·CI/HCI·OpenStack 등은 클라우드가 활용할 수 있는 **기반 인프라 기술·플랫폼**이다. 서비스와 내부 구현은 일대일 대응이 아니며, 이 지도에서는 **클라우드가 자원을 서비스로 제공하는 과정**을 중심으로 본다.

→ [클라우드 인프라 구성과 관리](클라우드-인프라-구성과-관리.md) — 서비스 제공 구조와 기반 기술

### ④ Cloud Native·운영 — 설계·실행과 신뢰성 구분

Cloud Native는 **클라우드의 탄력성·자동화·복원력을 활용하도록 애플리케이션을 설계·배포·운영하는 접근**이다. 아래 기술은 대표 수단이지 모두 필수인 구성요소는 아니다.

```text
Cloud Native — 클라우드를 활용해 어떻게 운영할까?
├─ 설계 — 서비스를 어떻게 나눌까?
│  └─ MSA
├─ 실행 — 어떻게 격리·배포할까?
│  └─ Container
├─ 관리 — 배포·확장을 어떻게 자동화할까?
│  └─ Kubernetes (예: AWS EKS)
└─ 운영 — 상태를 보고 부하에 대응하려면?
   ├─ Observability : Metrics / Logs / Traces
   └─ Auto Scaling : 부하에 따른 자원 확장·축소

[별도 신뢰성 관점]
HA     : 구성요소 장애에도 서비스 지속
DR     : 대규모 장애·재해 뒤 서비스 복구
Backup : 데이터 손실에 대비한 복구 사본
```

**Auto Scaling ≠ HA / DR / Backup.** 확장은 부하 변화에 대응하고, HA·DR·Backup은 서로 다른 장애·복구 문제를 다룬다. Auto Scaling만으로 고가용성이나 재해복구가 보장되지는 않는다.

### ⑤ 보안·거버넌스 — 횡단 통제

```text
Shared Responsibility / Multi-Tenancy
├─ 접근·격리 : IAM / Encryption
├─ 서비스    : SECaaS / CASB
├─ 인증·감사 : CSAP / ISO 27017·27018
└─ 대응·책임 : Forensic / SLA / Compliance

[주권·통제 고려] Sovereign Cloud
```

## 3. 대표 인출 축

**배치 모델 ↔ 서비스 모델**, **VM ↔ Container**, **SDN ↔ NFV**, **Block/File/Object**, **CI ↔ HCI**, **Auto Scaling ↔ HA/DR**.
