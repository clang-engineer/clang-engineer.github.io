## 1. 전체 조망

```text
                     Cloud Computing
        자원 풀링 · On-Demand · 탄력성 · 사용량 측정
                            │
           ┌────────────────┼────────────────┐
           ▼                ▼                ▼
       배치·활용          서비스·책임        실행·격리
       어디에?            어디까지?          어떻게?
       Public/Private     IaaS/PaaS/SaaS    VM/Container
       Hybrid             XaaS · CSB        Bare Metal
       Multi-Cloud                           Serverless*
       Sovereign / Edge*
           └────────────────┼────────────────┘
                            ▼
                      기반 인프라
                 Compute / Network / Storage
                 가상화 / HCI / OpenStack
                            │
              ┌─────────────┴─────────────┐
              ▼                           ▼
         아키텍처·배포                 운영·신뢰성
         Cloud Native                  Auto Scaling
         MSA / Kubernetes              HA / DR / Backup
              └─────────────┬─────────────┘
                            ▼
                     전환 · 운영 · 개선

[횡단 제약] Shared Responsibility · 보안 · 규제 · SLA/SLO · 비용
```

*배치·서비스·실행은 순차 단계가 아닌 **서로 다른 선택 축**이다. Multi-Cloud는 공급자 활용 전략, Sovereign은 주권·통제, Edge는 처리 위치 관점이다. Serverless는 VM·Container와 같은 격리 기술이 아닌 **운영 추상화** 관점이다.*

## 2. 주요 분류·비교 좌표

### ① 배치·서비스 — 위치와 관리 책임

```text
배치 모델                       서비스 모델
Public / Private / Hybrid      IaaS → PaaS → SaaS
Multi-Cloud / Sovereign        (공급자 관리 범위 확대)
              └───── 함께 선택 ─────┘
                         │
                 Shared Responsibility
```

→ [클라우드 배치와 서비스 유형](클라우드-배치와-서비스-유형.md) — 배치·서비스 모델의 차이

### ② 가상화·실행 — 격리와 운영 추상화

```text
실행·격리
├─ VM        : Hypervisor / Guest OS
│              Full ↔ Para Virtualization
└─ Container : Host Kernel 공유

운영 추상화
직접 관리 ── 관리형 실행 ── Serverless
```

→ [가상화 구조와 VM·Container](가상화-구조와-VM-컨테이너.md) — VM·Container 비교

### ③ 인프라 — 클라우드 서비스를 제공하는 기반

```text
Cloud Infrastructure
클라우드 서비스를 제공하는 기반 자원 + 구성·관리 기술
│
├─ 기반 자원 — 무엇을 제공하나?
│  ├─ Compute — 어디서 실행?
│  │  └─ Bare Metal / VM / Container
│  ├─ Network — 어떻게 연결·통신?
│  │  ├─ 논리망·연결: VLAN / VPN / Bonding
│  │  └─ 토폴로지: 3-Tier / Spine-Leaf
│  └─ Storage — 어떻게 저장·접근?
│     ├─ 데이터 제공: Block / File / Object
│     ├─ 연결 구조: DAS / NAS / SAN
│     └─ 관리·보호: Pool / Tiering / Provisioning / RAID
│
└─ 구성·관리 기술 — 자원을 어떻게 운영하나?
   ├─ 가상화: 자원 추상화·격리
   ├─ SDN / NFV: 네트워크 제어·기능 가상화
   ├─ Converged / HCI: 자원 통합
   └─ OpenStack: 클라우드 관리 플랫폼
```

→ [클라우드 인프라 구성과 관리](클라우드-인프라-구성과-관리.md) — 기반 자원과 구성·관리 기술의 관계

### ④ Cloud Native·운영 — 탄력성과 복원력

```text
Cloud Native (지향점: 탄력성 · 복원력 · 자동화)
├─ 아키텍처 : MSA
├─ 실행     : Container
├─ 관리     : Kubernetes
└─ 운영     : Observability / Auto Scaling

Auto Scaling ≠ HA / DR / Backup
```

*MSA·Container·Kubernetes는 대표 수단이며 필수 구성요소는 아니다.*
