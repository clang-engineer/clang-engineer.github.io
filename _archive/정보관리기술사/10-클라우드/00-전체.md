# 클라우드 전체 개념지도

> **클라우드 = 컴퓨팅 자원을 서비스로 이용하고, 배치·관리 책임·실행 방식과 운영 위험을 설계하는 방식.**
>
> 범위: [성안당 Vol.10 클라우드](../성안당/Vol.%2010%20클라우드.md)의 7개 PART·116개 문제군. 교재 순서가 아닌 **개념 관계와 선택 기준**으로 재구성한다.

## 1. 클라우드 전체 조망

클라우드의 출발점은 **자원을 소유·직접 운영하는 방식에서 필요한 만큼 서비스로 사용하는 방식으로의 전환**이다. 가상화·자원 풀링으로 공유 기반을 만들고, 온디맨드 제공·탄력적 확장·사용량 측정을 통해 서비스화한다.

```text
        사업 목표 · Workload · 기존 자산
        + 비용 · 규제 · 데이터 주권 · SLA/SLO
                         │ 설계 제약
                         ▼
                 Cloud Computing
         (자원 풀링 · 서비스화 · 탄력성)
                         │
        ┌────────────────┼────────────────┐
        ▼                ▼                ▼
   배치·활용 방식     서비스·관리 범위     실행·격리 방식
   어디에 둘까?      어디까지 맡길까?    어떻게 실행할까?
   Public/Private    IaaS/PaaS/SaaS     Bare Metal
   Hybrid            XaaS              VM/Container
   Multi-Cloud                          Serverless*
   Sovereign/Edge*
        └────────────────┼────────────────┘
                         ▼
               인프라와 플랫폼 구성
         Compute · Network · Storage
            가상화 · 관리 플랫폼
                         │
             ┌───────────┴───────────┐
             ▼                       ▼
       아키텍처·배포              운영·신뢰성
       Cloud Native               Auto Scaling
       MSA · Kubernetes           HA · DR · Backup
             └───────────┬───────────┘
                         ▼
                전환 · 운영 · 개선
                비용 · 성능 · 보안
                         ↺

[횡단 기준] Shared Responsibility · IAM · 격리 · 감사 · SLA · 규제
```

*세 가지 질문은 **함께 검토할 선택 축**이지 순차 단계가 아니다. Multi-Cloud는 복수 공급자 활용 전략, Sovereign은 주권·통제 요건, Edge는 처리 위치 관점이다. Serverless는 VM·Container와 같은 격리 기술이 아니라 **실행환경 관리의 추상화 수준**을 나타낸다.*

## 2. 핵심 관계와 학습 가지

### ① 배치·서비스 모델 — 위치와 책임의 차이

```text
배치·활용 관점                     서비스 제공 관점
Public / Private / Hybrid         IaaS → PaaS → SaaS
Multi-Cloud · Sovereign           공급자가 관리하는 범위 확대
          │                                │
          └───────── 함께 결정 ────────────┘
                    │
              Shared Responsibility
```

배치 모델과 서비스 모델은 서로 다른 분류다. **CSB(Cloud Service Broker)**는 서비스 선택·중개·통합을 돕는 역할이며, XaaS는 다양한 서비스형 제공 모델을 포괄한다.

→ [클라우드 배치와 서비스 유형](클라우드-배치와-서비스-유형.md) — 배치 모델·IaaS/PaaS/SaaS의 차이와 관리 책임

### ② 실행·격리 — 가상화 기술과 운영 추상화

```text
Physical Resource
├─ VM         : Hypervisor 기반 Guest OS 격리
└─ Container  : Host OS Kernel 공유 격리

운영 추상화 관점
직접 관리 ──> 관리형 실행환경 ──> Serverless
```

VM ↔ Container는 **실행·격리 구조**의 비교, 직접 관리 ↔ Serverless는 **운영 책임**의 비교다. 가상화에서는 Full ↔ Para Virtualization도 대표 비교 축이다.

→ [가상화 구조와 VM·Container](가상화-구조와-VM-컨테이너.md) — 격리 구조·Hypervisor·Container 비교

### ③ 인프라 — 연결·저장·통합 구조

```text
Cloud Infrastructure
├─ Compute : Bare Metal / VM / Container
├─ Network : SDN ↔ NFV, VLAN / VPN
│            3-Tier ↔ Spine-Leaf
├─ Storage : Block / File / Object
│            DAS / NAS / SAN
│            Pool / Tiering / Provisioning / RAID
└─ 구성·관리
   ├─ Converged / HCI : 인프라 자원 통합
   └─ OpenStack       : 클라우드 관리 플랫폼
```

Compute만 확장해도 Network·Storage가 병목이면 전체 성능은 늘지 않는다. HCI와 OpenStack은 같은 종류의 기술이 아니라 **인프라 통합 방식과 관리 플랫폼**이라는 차이가 있다.

### ④ Cloud Native — 아키텍처와 운영 수단

```text
Cloud Native 지향점
탄력성 · 복원력 · 자동화
├─ 아키텍처 접근 : MSA
├─ 패키징·실행   : Container
├─ 배포·관리     : Kubernetes
└─ 운영          : 관측성 · 자동 확장
```

MSA·Container·Kubernetes는 **Cloud Native를 구현하는 대표적인 접근과 수단**이지 모두 필수 조건은 아니다. Auto Scaling은 용량 조절이며 HA·DR·Backup을 대체하지 않는다.

### ⑤ Desktop — 중앙 실행과 사용자 단말

```text
중앙화된 Desktop / Application 제공
├─ VDI
├─ RDS / SBC
├─ CCI / DaaS
└─ 사용자 단말 : Thin / Zero Client
```

→ [Desktop 가상화·VDI·RDS·CCI·DaaS](데스크톱-가상화-VDI-RDS-CCI-DaaS.md) — 중앙 실행·서비스 제공 유형  
→ [VDI·Thin·Zero Client](VDI-Thin-Zero-Client.md) — 단말 구조와 차이

### ⑥ 보안·거버넌스 — 전 과정의 통제

```text
Shared Responsibility · Multi-Tenancy
          │
          ├─ 접근·격리 : IAM / Isolation / Encryption
          ├─ 서비스 보안 : SECaaS / CASB
          ├─ 인증·감사 : CSAP / ISO 27017·27018
          └─ 대응·책임 : Forensic / SLA / Compliance
```

클라우드 보안은 기존 통제를 없애는 것이 아니라 **공급자와 사용자 사이의 책임·통제 경계를 다시 배치하는 문제**다.

## 3. 복습·탐색 기준

```text
전체 지도에서 개념의 위치 확인
        ↓
분류·관계·선택 이유를 설명할 수 있는가?
        ├─ Yes → 다음 가지로
        └─ No  → 연결된 세부학습으로 Zoom-in
```

**복습 질문:** 배치와 서비스 모델은 왜 다른 축인가? VM·Container와 Serverless는 무엇이 다른가? Cloud Native의 목표와 Kubernetes의 역할은 어떻게 다른가? Auto Scaling은 왜 DR을 대신하지 못하는가?

이 지도는 성안당 문제를 모두 나열하는 목차가 아니라 **개념군의 위치·관계·핵심 비교 축을 복원하는 탐색 지도**다.
