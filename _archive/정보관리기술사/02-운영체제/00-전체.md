# 운영체제 전체 개념지도

이 문서는 `../학습등급표/02-운영체제.md`에서 정한 학습 범위를 **개념 관계로 재배치한 최상위 탐색 지도**다.

운영체제는 CPU·Memory·Storage·I/O 같은 물리 자원을 Application이 직접 다루지 않아도 되도록 추상화하고, 여러 실행 주체가 한정된 자원을 안전하고 효율적으로 공유하게 한다.

이 문서에서는 세부 Algorithm까지 펼치지 않되, 각 가지의 **대표 Mechanism과 핵심 관계를 보고 기존 지식을 복원할 수 있는 정도**까지 잡는다. 더 촘촘한 관계는 하위 개념지도에서, 동작 원리·예제·계산은 세부학습에서 다룬다.

## 1. 운영체제 전체 좌표

```text
운영체제
│
├─ 실행 모델과 CPU 배분
│   ├─ Process / Thread
│   ├─ System Call / Kernel
│   ├─ Scheduling
│   └─ Context Switch
│
├─ 동시성과 자원 공유
│   ├─ Race Condition → Synchronization
│   ├─ Resource Wait → Deadlock
│   └─ Process Cooperation → IPC
│
├─ Memory 관리
│   ├─ Paging / Segmentation
│   ├─ Virtual Memory
│   └─ Page Fault / Thrashing
│
├─ File과 I/O
│   ├─ File System
│   └─ Device I/O
│
└─ 가상화와 운영 품질
    ├─ Virtualization
    ├─ Performance / Capacity
    └─ HA / Checkpointing
```

운영체제의 중심 관점은 다음 다섯 축이다.

```text
추상화
자원 배분
격리
동시성
성능과 안전성의 Trade-off
```

## 2. 어디를 파고들 것인가

### 실행 모델과 CPU 배분

프로그램이 실행 단위가 되고, 여러 실행 주체가 한정된 CPU를 나누어 쓰는 관계를 본다.

```text
Program → Process / Thread
              ↓
        CPU 경쟁 발생
              ↓
          Scheduling
              ↓
        Context Switch
```

→ [실행 모델과 CPU 배분 개념지도](01-실행모델-CPU-배분.md)

### 동시성과 자원 공유

여러 실행 주체가 자원을 공유할 때 생기는 실행 순서·대기·협업 문제를 본다.

```text
공유 자원
  ↓
동시 접근
  ↓
Race Condition
  ↓
Synchronization
  ↓
Deadlock / IPC와 연결
```

→ [동시성과 자원 공유 개념지도](02-동시성-자원공유.md)

### Memory 관리

프로세스별 주소 공간을 만들고, 한정된 물리 Memory를 배치·보호·확장해서 사용하는 구조를 본다.

```text
주소 공간
  ↓
Paging / Segmentation
  ↓
Virtual Memory
  ↓
Page Fault / Thrashing
```

→ [Memory 관리 개념지도](03-메모리-관리.md)

### File과 I/O

Application이 보호된 Device와 Storage를 공통 Interface로 사용하는 구조를 본다.

```text
Application
  ↓ System Call
Kernel
  │
  ├─ File 추상화
  │   ├─ File / Directory
  │   ├─ File Descriptor
  │   └─ File System
  │
  └─ Device I/O
      ├─ Driver
      ├─ Interrupt
      └─ Buffer / Cache

→ Storage · Device의 차이를
  Application에 공통 Interface로 제공
```

### 가상화와 운영 품질

자원 추상화·격리를 더 큰 단위로 확장하고, 운영 중 성능·용량·가용성을 관리하는 축이다.

```text
자원 추상화 · 격리
      ↓
Virtualization
├─ VM → Hardware 수준 자원 가상화
└─ Container → OS 수준 격리·자원 제한

운영 Workload
      ↓
Performance / Capacity
      ↓
장애 대응 · HA / Checkpointing
```

## 3. 다른 영역과 만나는 지점

```text
컴퓨터 구조
MMU / TLB / Cache / Interrupt
        ↕
운영체제
Process / Scheduling / Virtual Memory / I/O
        ↕
Cloud · 분산 시스템
Virtualization / Resource Pooling / HA
```

Memory의 주소 변환 구조는 컴퓨터 구조와 직접 연결되고, Virtualization과 운영 품질은 Cloud·분산 시스템으로 확장되는 연결점이다.

## 4. 권장 탐색 흐름

처음 운영체제를 훑을 때는 **실행 주체 → 자원 공유 → Memory 관리**를 핵심 축으로 먼저 읽으면 운영체제가 자원을 관리하는 흐름을 연결하기 쉽다.

```text
01. 실행 모델과 CPU 배분
"Program은 어떤 실행 단위가 되고 CPU를 어떻게 나누어 쓰는가?"
        ↓
02. 동시성과 자원 공유
"여러 실행 주체가 자원을 공유하면 어떤 문제가 생기는가?"
        ↓
03. Memory 관리
"여러 Process에 한정된 Memory를 어떻게 배분·보호·운영하는가?"
```

그 뒤 `File·I/O`와 `가상화·운영 품질`은 위 세 가지의 다음 발전 단계가 아니라 **운영체제가 제공하는 다른 자원관리·확장 축**으로 본다.

```text
[별도 학습 가지]

File · I/O
→ Application이 File과 Device를 어떤 공통 Interface로 사용하는가?

가상화 · 운영 품질
→ 자원 추상화·격리를 어떻게 확장하고 운영 품질을 관리하는가?
```

현재 이 두 가지는 별도의 하위 개념지도를 만들지 않는다. 전체 지도에서 위치를 잡은 뒤 필요한 세부학습으로 바로 내려간다.

이 순서는 운영체제 기능의 구현 순서나 필수 의존관계를 뜻하지 않는다. 처음 학습할 때 `실행 → 공유 → 자원관리`라는 중심 구조를 잡기 위한 **권장 탐색 순서**다.

```text
학습등급표
"무엇을 얼마나 볼 것인가"
        ↓
운영체제 전체 개념지도
"어느 큰 가지를 팔 것인가"
        ↓
필요한 하위 개념지도
"관계와 비교를 더 촘촘히"
        ↓
세부학습
"왜 필요하고 어떻게 동작하는가"

하위 지도가 필요하지 않은 가지
00-전체 → 세부학습으로 직접
```

전체 지도에는 대표 Node뿐 아니라 **기존 지식을 복원하는 데 필요한 대표 Mechanism과 관계까지** 남긴다. 선점/비선점의 세부 비교, Scheduling Algorithm별 동작, Deadlock 대응 절차, Paging 세부 동작처럼 한 가지 내부를 더 촘촘히 봐야 하는 내용은 하위 지도나 세부학습으로 내려간다.
