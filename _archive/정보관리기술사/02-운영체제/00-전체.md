# 운영체제 전체 개념지도

운영체제는 CPU·Memory·Storage·I/O 같은 물리 자원을 Application이 직접 다루지 않아도 되도록 추상화하고, 여러 실행 주체가 한정된 자원을 안전하고 효율적으로 공유하게 한다.

## 빠른 복습 좌표

| 복습 축 | 핵심 관계·판단 단서 |
|---|---|
| 실행 | Process는 자원·주소 공간 단위, Thread는 실행 흐름; Scheduling이 CPU를 배분 |
| 동시성 | Race는 공유 상태 경쟁, Lock·Semaphore는 동기화, Deadlock은 자원 대기 순환 문제 |
| 메모리 | Virtual Page → Page Table → Frame; Page Fault와 Replacement는 필요 시 적재 |
| I/O·파일 | File System은 영속 데이터의 이름·구조, Device I/O는 장치 접근 추상화 |
| 격리·운영 | Namespace는 자원 뷰, cgroup은 사용량 제어; 성능·안전성은 횡단 관점 |

**복습 방법:** 이 표에서 핵심 관계가 기억나지 않는 축만 아래 조망도와 연결된 하위 학습으로 내려간다. 상세 예제는 세부학습 본문에 남긴다.

## 1. 운영체제 전체 좌표

```text
운영체제 — 실행 주체와 하드웨어 자원을 관리
│
├─ [1. 실행 · CPU 배분]
│  └─ Process · Thread · Scheduling · Context Switch
├─ [2. 동시성 · 협업]
│  └─ Race Condition · Synchronization · Deadlock · IPC
├─ [3. 메모리 관리]
│  └─ Paging · Virtual Memory · Page Fault
├─ [4. 파일 · I/O]
│  └─ File System · Device I/O
└─ [5. 격리 · 운영 품질]
   └─ Namespace · cgroup · Performance · HA

실행 주체의 자원 공유 → 동시성 문제
가상화·격리는 운영체제 자원 관리와 연결
```

운영체제의 중심 관점은 다음 다섯 축이다.

```text
추상화
자원 배분
격리
동시성
성능과 안전성의 Trade-off
```

## 2. 어디를 파고들 것인가

### 실행 모델과 CPU 배분

프로그램이 실행 단위가 되고, 여러 실행 주체가 한정된 CPU를 나누어 쓰는 관계를 본다.

```text
Program → Process / Thread
              ↓
        CPU 경쟁 발생
              ↓
          Scheduling
              ↓
        Context Switch
```

→ [실행 모델과 CPU 배분 개념지도](01-실행모델-CPU-배분.md)  
Process / Thread의 실행 단위 차이를 잡고, 선점·비선점 Scheduling과 Context Switch가 CPU 배분 과정에서 어떻게 연결되는지 본다.

### 동시성과 Process 협업

여러 실행 주체가 동시에 존재하면 **공유 자원 충돌, 자원 대기, Process 간 협업**이라는 서로 다른 문제가 생긴다.

```text
여러 실행 주체
│
├─ 공유 자원에 동시 접근
│      ↓
│  Race Condition
│      ↓
│  Synchronization
│
├─ 자원을 서로 기다림
│      ↓
│   Deadlock
│
└─ 서로 Data를 주고받고 협업
       ↓
      IPC
```

→ [동시성과 자원 공유 개념지도](02-동시성-자원공유.md)  
Race Condition·Synchronization·Deadlock·IPC를 하나의 직렬 흐름으로 보지 않고, 서로 다른 문제축과 대표 해결 방식으로 구분해 본다.

### Memory 관리

프로세스별 주소 공간을 만들고, 한정된 물리 Memory를 배치·보호·확장해서 사용하는 구조를 본다.

```text
주소 공간
  ↓
Paging / Segmentation
  ↓
Virtual Memory
  ↓
Page Fault / Thrashing
```

→ [Memory 관리 개념지도](03-메모리-관리.md)  
Paging·Segmentation의 배치 방식 차이에서 시작해 Virtual Memory, Page Fault, Thrashing으로 이어지는 Memory 관리 흐름을 본다.

### File과 I/O

Application이 보호된 Device와 Storage를 공통 Interface로 사용하는 구조를 본다.

```text
Application
  ↓ System Call
Kernel
  │
  ├─ File 추상화
  │   ├─ File / Directory
  │   ├─ File Descriptor
  │   └─ File System
  │
  └─ Device I/O
      ├─ Driver
      ├─ Interrupt
      └─ Buffer / Cache

→ Storage · Device의 차이를
  Application에 공통 Interface로 제공
```

### 실행환경 격리와 가상화의 연결

운영체제에서는 **프로세스 격리·커널 자원 관리**를 중심으로 이해한다. VM·Hypervisor의 전체 구조와 VDI 등 활용은 독립된 가상화 지도로 연결한다.

```text
자원 추상화 · 격리
      ↓
Virtualization
├─ VM
│   └─ Hardware 수준 자원 가상화
└─ Container
    └─ OS 수준 격리 · 자원 제한
```

VM은 Guest OS·Kernel을 갖는 가상 컴퓨터이고, Container는 Host Kernel의 Namespace·cgroup 등을 활용하는 실행환경이다. 둘의 전체 구조·비교는 [가상화 전체 개념지도](../99-가상화/00-전체.md)에서 다룬다.

### 운영 품질

운영 중에는 자원을 어떻게 격리하는가와 별개로 **성능·용량·가용성**을 지속적으로 관리해야 한다.

```text
운영 Workload
      │
      ├─ 성능·용량 → Performance / Capacity
      │                 └─ 병목 · 자원 한계 분석
      │
      └─ 가용성·복구 → HA / Checkpointing
                        └─ 장애 영향 축소 · 상태 복구
```

## 3. 다른 영역과 만나는 지점

```text
컴퓨터 구조
MMU / TLB / Cache / Interrupt
        ↕
운영체제
Process / Scheduling / Virtual Memory / I/O
        ↕
Cloud · 분산 시스템
Virtualization / Resource Pooling / HA
```

Memory의 주소 변환 구조는 컴퓨터 구조와 직접 연결되고, Virtualization과 운영 품질은 Cloud·분산 시스템으로 확장되는 연결점이다.

## 4. 핵심 자원관리 관계

```text
Program → Process / Thread
              │
       ┌──────┼────────┐
       ▼      ▼        ▼
   CPU 배분  공유 자원  Memory
   Scheduling 동기화    Paging / Virtual Memory
       │      │        │
       └──────┼────────┘
              ▼
      File / I/O · 격리 · 운영 품질
```
