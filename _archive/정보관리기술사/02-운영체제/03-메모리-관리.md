# 운영체제 메모리 관리 개념지도

이 지도는 [[00-전체|운영체제 전체 개념지도]]에서 **여러 Process에 Memory를 배분하고, Process별 주소 공간을 보호·격리하며, 한정된 Physical Memory를 Workload에 맞게 운영하는 관계**를 본다.

Paging·Virtual Memory·MMU·TLB는 컴퓨터 구조의 [[../01-컴퓨터-구조/02-메모리-계층-가상메모리|메모리 계층과 가상 메모리]]와 연결된다. 이 지도에서는 Hardware 주소 변환 구조를 반복하지 않고 **운영체제가 Memory 자원을 어떻게 관리하는가**에 초점을 둔다.

## 1. 운영체제에서 Memory를 보는 핵심 질문

```text
여러 Process가 실행됨
        ↓
한정된 Physical Memory를 나눠야 함
        ↓
운영체제 Memory 관리
│
├─ Process를 어디에 배치할까?
│   └─ Memory Allocation
│
├─ Process끼리 Memory를 침범하지 않게 하려면?
│   └─ 독립 주소 공간 / Protection / Isolation
│
└─ 필요한 Memory가 RAM보다 많거나 Workload가 커지면?
    └─ Demand Paging / Frame Allocation / Replacement
        └─ 과도한 Page Fault → Thrashing
```

운영체제 관점의 중심은 **주소 변환 Hardware 자체보다 Process에 Memory를 배분하고 보호하며 부족한 Frame을 운영하는 정책**이다.

## 2. 연속 배치는 Memory 활용에 제약을 만든다

처음에는 Process를 연속된 Physical Memory 공간에 배치할 수 있다.

```text
Physical Memory
┌──────────────┐
│ OS           │
├──────────────┤
│ Process A    │
├──────────────┤
│ Process B    │
├──────────────┤
│ Free         │
└──────────────┘
```

하지만 Process의 크기와 빈 공간의 모양에 따라 단편화와 배치 제약이 생긴다.

```text
연속 할당
├─ 고정 분할 → 내부 단편화 가능
└─ 가변 분할 → 외부 단편화 가능
```

이 문제 때문에 불연속 배치를 사용할 수 있고, Paging / Segmentation이 연결된다.

```text
연속 공간 제약
  ↓
불연속 배치
├─ Paging
└─ Segmentation
```

Paging과 Segmentation의 Hardware 주소 변환 구조와 상세 비교는 컴퓨터 구조 지도에서 다룬다. 여기서는 **운영체제가 Process를 연속된 Physical Memory에 묶어 두지 않고 배치할 수 있게 하는 기반**이라는 위치만 잡는다.

## 3. Process별 주소 공간은 보호와 격리의 경계다

여러 Process가 같은 Physical Memory를 사용하더라도 각 Process는 자신의 주소 공간을 기준으로 실행한다.

```text
Process A Address Space
Process B Address Space
Process C Address Space
        ↓
운영체제가 독립적인 실행 경계 제공
        ↓
Protection / Isolation
```

Virtual Memory는 이 주소 공간과 실제 Physical Memory 배치를 분리하는 기반이다.

```text
Process가 보는 주소 공간
        ↓
Virtual Memory
        ↓
Physical Memory의 실제 배치와 분리
```

MMU / Page Table / TLB가 주소 변환을 지원하지만, 그 Hardware 동작 자체는 [[../01-컴퓨터-구조/02-메모리-계층-가상메모리|컴퓨터 구조의 메모리 지도]]가 중심 소유한다.

운영체제에서는 그 기반 위에서 **Process마다 어떤 Memory를 사용할 수 있는지 관리하고 접근 경계를 통제한다**는 점을 본다.

## 4. 필요한 Page만 적재하면 Physical Memory를 더 유연하게 운영할 수 있다

모든 Process의 모든 Page를 항상 RAM에 유지할 필요는 없다.

```text
Process 실행
  ↓
필요한 Page만 RAM에 유지
  ↓
Demand Paging
  ↓
필요한 Page가 RAM에 없음
  ↓
Page Fault
  ↓
OS가 Page를 적재하고 실행 재개
```

Page Fault는 오류 그 자체라기보다 Demand Paging에서 발생할 수 있는 정상적인 사건이다. 다만 Storage I/O가 필요하므로 비용이 크다.

운영체제의 관심은 여기서부터 **어떤 Process와 Page에 한정된 Frame을 배분할 것인가**로 이어진다.

## 5. Frame이 부족하면 배분과 교체 정책이 필요하다

```text
Page Fault
  ↓
빈 Frame 있음?
├─ Yes → Page 적재
└─ No
    ↓
Page Replacement
    ↓
어떤 Page를 내보낼지 선택
```

Page Replacement는 단순 Algorithm 암기보다 **한정된 Frame을 경쟁하는 Page에 어떻게 배분할 것인가**라는 자원관리 문제로 본다.

```text
Physical Frame
= 한정 자원
        ↓
여러 Process / Page가 경쟁
        ↓
Frame Allocation + Page Replacement
```

Replacement Algorithm의 반복 손계산은 세부학습으로 내린다.

## 6. Workload에 비해 Frame이 부족하면 Thrashing이 생긴다

```text
동시에 실행하는 Process 증가
        ↓
각 Process가 사용할 수 있는 Frame 부족
        ↓
필요한 Page를 유지하기 어려움
        ↓
Page Fault / Page In·Out 증가
        ↓
실제 실행보다 Paging I/O에 많은 시간 소비
        ↓
Thrashing
```

Thrashing은 한 번의 Page Fault가 아니라 **Memory 압박 때문에 Page 교체가 과도하게 반복되어 시스템 처리량이 무너지는 상태**다.

운영체제는 다음과 같은 자원관리 관점으로 대응한다.

```text
Thrashing 완화
├─ Working Set 관찰
├─ Process별 Frame 조정
└─ Multiprogramming Degree 조절
    └─ 동시에 Memory를 경쟁하는 Workload 감소
```

이 부분이 Hardware 주소 변환과 구분되는 운영체제 Memory 관리의 핵심이다.

## 7. Cache는 연결점만 남긴다

Cache는 CPU와 RAM의 속도 격차를 줄이는 Hardware 성능 계층이므로 상세 구조의 중심은 컴퓨터 구조에 둔다.

```text
CPU-RAM 속도 격차
→ Cache / Locality
→ [[../01-컴퓨터-구조/02-메모리-계층-가상메모리|컴퓨터 구조의 메모리 지도]]
```

운영체제에서는 Cache 자체를 다시 설명하기보다 **Memory 성능이 Process 실행과 전체 System Performance에 영향을 준다**는 연결점으로만 본다.

Cache Mapping, Write Policy, MESI 등의 상세는 이 지도에서 반복하지 않는다.

## 8. 전체 관계를 다시 연결한다

```text
여러 Process 실행
        ↓
Physical Memory는 한정됨
        ↓
Memory Allocation
        ↓
불연속 배치 기반
        ↓
Process별 독립 주소 공간
        ↓
Protection / Isolation
        ↓
Demand Paging
        ↓
Page Fault
        ↓
Frame 부족
        ↓
Frame Allocation / Page Replacement
        ↓
Memory 압박 증가
        ↓
Thrashing
        ↓
Working Set / Frame / Workload 조절
```

Hardware 관점은 별도 연결한다.

```text
주소 변환 Hardware / Cache
→ MMU / TLB / Locality / Cache
→ 컴퓨터 구조 메모리 지도
```

## 9. 복습용 핵심 좌표

```text
[배치]
연속 할당
→ 단편화 / 연속 공간 제약
→ 불연속 배치 기반

[보호·격리]
Process별 Address Space
→ Virtual Memory 기반
→ Protection / Isolation

[자원 운영]
Demand Paging
→ Page Fault
→ Frame Allocation
→ Page Replacement
→ Thrashing
   ├─ Working Set
   ├─ Frame 조정
   └─ Multiprogramming Degree 조절

[컴퓨터 구조와 연결]
MMU / TLB / Cache
→ Hardware 동작은 컴퓨터 구조 지도에서 Zoom-in
```

이 Node를 보고 `운영체제가 왜 Process별 주소 공간을 제공하는가`, `Frame 부족이 왜 Replacement로 이어지는가`, `Thrashing을 왜 Workload와 Frame 배분 문제로 보는가`를 설명할 수 있으면 된다. 주소 변환 Hardware와 Cache 내부 동작은 컴퓨터 구조에서, Replacement 계산은 세부학습에서 파고든다.
