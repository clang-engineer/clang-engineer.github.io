# 운영체제 메모리 관리 개념지도

이 지도는 [운영체제 전체 개념지도](00-전체.md)에서 **여러 Process에 Memory를 배분하고, Process별 주소 공간을 보호·격리하며, 한정된 Physical Memory를 Workload에 맞게 운영하는 관계**를 본다.

여기서 `Workload`는 **현재 시스템에서 함께 실행되며 CPU·Memory 같은 자원을 요구하는 Process / Task의 집합과 그 부하**를 뜻한다.

Paging·Virtual Memory·MMU·TLB는 컴퓨터 구조의 메모리 계층과 가상 메모리와 연결된다. 이 지도에서는 Hardware 주소 변환 구조를 반복하지 않고 **운영체제가 Memory 자원을 어떻게 관리하는가**에 초점을 둔다.

## 1. 운영체제에서 Memory를 보는 핵심 질문

```text
여러 Process가 실행됨
        ↓
한정된 Physical Memory를 나눠야 함
        ↓
운영체제 Memory 관리
│
├─ Process를 어디에 배치할까?
│   └─ Memory Allocation
│
├─ Process끼리 Memory를 침범하지 않게 하려면?
│   └─ 독립 주소 공간 / Protection / Isolation
│
└─ 필요한 Memory가 RAM보다 많거나 Workload가 커지면?
    └─ Demand Paging / Frame Allocation / Replacement
        └─ 과도한 Page Fault → Thrashing
```

운영체제 관점의 중심은 **주소 변환 Hardware 자체보다 Process에 Memory를 배분하고 보호하며 부족한 Frame을 운영하는 정책**이다.

## 2. 연속 배치는 Memory 활용에 제약을 만든다

처음에는 Process를 연속된 Physical Memory 공간에 배치할 수 있다.

```text
Physical Memory
┌──────────────┐
│ OS           │
├──────────────┤
│ Process A    │
├──────────────┤
│ Process B    │
├──────────────┤
│ Free         │
└──────────────┘
```

하지만 Process의 크기와 빈 공간의 모양에 따라 단편화와 배치 제약이 생긴다.

```text
연속 할당
├─ 고정 분할 → 내부 단편화 가능
└─ 가변 분할 → 외부 단편화 가능
    ├─ First Fit
    ├─ Best Fit
    └─ Worst Fit
```

이 문제 때문에 불연속 배치를 사용할 수 있고, Paging / Segmentation이 연결된다.

```text
연속 공간 제약
  ↓
불연속 배치
├─ Paging
│   └─ 고정 크기 Page / Frame
└─ Segmentation
    └─ 논리 단위의 가변 크기 Segment
```

Paging과 Segmentation의 Hardware 주소 변환 구조와 상세 비교는 컴퓨터 구조 지도에서 다룬다. 여기서는 **연속/불연속 배치는 Physical Memory 배치 방식의 축**이라는 점을 잡는다.

중요한 점은 **연속/불연속 배치와 Virtual Memory가 같은 개념은 아니라는 것**이다.

```text
[Physical Memory 배치 방식]
연속 할당 ↔ 불연속 할당

[주소 공간 추상화]
Virtual Address Space
        ↕ Mapping
Physical Memory
```

Virtual Memory의 핵심은 `Virtual Address`와 `Physical Address`를 분리해 Mapping하는 것이다. 따라서 개념적으로는 연속된 Physical Memory에 Mapping할 수도 있다.

다만 현대 OS에서는 보통 **Paging 기반 Virtual Memory**를 사용하므로, Process에는 연속적인 Virtual Address Space를 제공하면서 실제 Page는 여러 Physical Frame에 불연속으로 배치되는 형태가 일반적이다.

```text
Virtual Address Space
        ↓ Paging / Mapping
Physical Frame
├─ Frame 8
├─ Frame 102
├─ Frame 21
└─ ...
```

즉 `Virtual Memory ≠ 불연속 배치`이지만, 현대 OS에서는 두 개념이 매우 강하게 함께 나타난다.

## 3. Process별 Virtual Address Space는 Physical Memory 배치와 별도 축이다

여러 Process가 같은 Physical Memory를 사용하더라도 각 Process는 자신의 Virtual Address Space를 기준으로 실행한다.

```text
Process A Virtual Address Space
Process B Virtual Address Space
Process C Virtual Address Space
        ↓
Address Translation / Mapping
        ↓
Physical Memory
```

이 구조를 통해 Process별 Protection / Isolation을 제공하고, Virtual Address와 실제 Physical Memory 배치를 분리할 수 있다.

```text
Virtual Address Space
        ↓
Address Translation / Mapping
        ↓
Physical Memory

배치 방식은 별도 축
├─ 연속 할당
└─ 불연속 할당
    ├─ Paging
    └─ Segmentation
```

즉 `Virtual Memory`는 **주소 공간 추상화와 Mapping의 개념**, 연속/불연속 배치는 **Physical Memory 배치 방식의 개념**이다. 실제 현대 OS에서는 Paging을 통해 Virtual Page를 불연속 Physical Frame에 Mapping하는 방식이 일반적이다.

MMU / Page Table / TLB가 주소 변환을 지원하지만, 그 Hardware 동작 자체는 컴퓨터 구조의 메모리 지도가 중심 소유한다.

운영체제에서는 그 기반 위에서 **Process마다 어떤 Memory를 사용할 수 있는지 관리하고 접근 경계를 통제한다**는 점을 본다.

## 4. Page와 Frame을 먼저 구분한다

```text
Virtual Address Space
└─ Page
    ↓ Mapping
Physical Memory(RAM)
└─ Frame
```

- `Page` = Virtual Address Space를 일정 크기로 나눈 단위
- `Frame` = 실제 Physical Memory(RAM)를 같은 크기로 나눈 물리 공간 단위

보통 Page와 Frame의 크기를 같게 두고 다음처럼 Mapping한다.

```text
Virtual Page 3
     ↓
Physical Frame 10
```

따라서 Physical Frame이 부족하면 어떤 Page를 내보낼지 결정하는 Page Replacement가 필요해진다.

## 5. Demand Paging은 필요한 Page만 실제 접근 시 적재하는 방식이다

모든 Process의 모든 Page를 항상 RAM에 유지할 필요는 없다. Demand Paging은 **Page를 미리 전부 적재하지 않고, 실제 접근할 때 필요한 Page만 Physical Frame에 적재하는 운영 방식**이다.

아래는 접근권한이 유효한 주소에서 **필요한 Page를 새로 준비·적재하는 경로**를 단순화한 것이다. 접근권한 위반 등 다른 Fault 원인은 제외한다.

```text
Demand Paging
= 필요한 Page만 실제 접근 시 RAM에 준비

Process가 Virtual Page 접근
        ↓
사용 가능한 Mapping이 있는가?
├─ Yes → 계속 실행
└─ No  → Page Fault
         ↓
       OS가 필요한 Page와 Frame을 준비
         ↓
       Mapping 갱신
         ↓
       중단됐던 접근을 다시 시도
```

Page Fault는 Demand Paging에서 정상적으로 발생할 수 있으며, **모든 Page Fault가 Storage I/O를 요구하는 것은 아니다.** Linux는 I/O 없이 처리한 Minor Fault와 I/O가 필요한 Major Fault를 구분한다. 이미 RAM에 있는 Page의 Mapping을 연결하거나 새 Page를 준비하는 경우와 Storage에서 읽어 와야 하는 경우의 비용을 같게 보지 않는다.

운영체제의 관심은 여기서부터 **어떤 Process와 Page에 한정된 Frame을 배분할 것인가**로 이어진다.

## 6. Frame이 부족하면 배분과 교체 정책이 필요하다

새 Frame이 필요한 경우에는 **공간 확보 → Page 준비·적재 → Mapping 갱신 → 접근 재시도** 순서로 본다. 먼저 적재한 다음 공간이 부족한지 확인하는 것이 아니다.

```text
새 Frame이 필요한 Page Fault
        ↓
Frame 확보
├─ 빈 Frame 있음 → 그 Frame 사용
└─ 빈 Frame 없음 → 희생 Page 선택·교체
                   → 그 Frame 재사용
        ↓ 두 경로 합류
확보한 Frame에 Page 준비·적재
        ↓
Page Table의 Mapping 갱신
        ↓
중단됐던 접근을 다시 시도
```

교체할 Page에 보존해야 할 변경 내용이 있으면 Frame을 재사용하기 전에 해당 내용을 기록해야 한다. 위 그림은 Frame 확보에 성공하는 경로를 보여주며, 확보 실패 처리는 별도다.

Page Replacement는 단순 Algorithm 암기보다 **한정된 Frame을 경쟁하는 Page에 어떻게 배분하고 어떤 Page를 내보낼 것인가**라는 자원관리 문제로 본다.

```text
Physical Frame
= 한정 자원
        ↓
여러 Process / Page가 경쟁
        ↓
Frame Allocation
├─ Global Replacement
└─ Local Replacement
        ↓
Page Replacement
├─ FIFO
├─ OPT
└─ LRU
```

대표 비교축은 `FIFO ↔ OPT ↔ LRU`, `Global ↔ Local Replacement`이다. 반복적인 Page Fault 손계산은 세부학습으로 내린다.

## 7. Workload에 비해 Frame이 부족하면 Thrashing이 생긴다

```text
Workload 증가
= 동시에 실행되며 Memory를 요구하는 Process / Task 증가
        ↓
각 Process가 사용할 수 있는 Frame 부족
        ↓
필요한 Page를 유지하기 어려움
        ↓
Page Fault / Page In·Out 증가
        ↓
실제 실행보다 Paging I/O에 많은 시간 소비
        ↓
Thrashing
```

Thrashing은 한 번의 Page Fault가 아니라 **Memory 압박 때문에 Page 교체가 과도하게 반복되어 시스템 처리량이 무너지는 상태**다.

운영체제는 다음과 같은 자원관리 관점으로 대응한다.

```text
Thrashing 완화
├─ Working Set
│   └─ Process가 최근 실제로 사용하는 Page 집합
├─ PFF(Page Fault Frequency)
│   └─ Page Fault 빈도로 Frame 부족 여부 판단
├─ Process별 Frame 조정
│   └─ 필요한 Process에 Physical Frame을 더 배분하거나 회수
└─ Multiprogramming Degree 조절
    └─ 동시에 Memory를 경쟁하는 Process 수를 줄여 Workload를 낮춤
```

관계는 다음처럼 기억한다.

```text
Working Set / PFF로 Memory 압박 파악
        ↓
Process별 Frame 조정
        ↓
그래도 전체 Frame이 부족하면
        ↓
Multiprogramming Degree 감소
        ↓
Memory 경쟁 완화 → Thrashing 완화
```

이 부분이 Hardware 주소 변환과 구분되는 운영체제 Memory 관리의 핵심이다.

## 8. Cache는 연결점만 남긴다

Cache는 CPU와 RAM의 속도 격차를 줄이는 Hardware 성능 계층이므로 상세 구조의 중심은 컴퓨터 구조에 둔다.

```text
CPU-RAM 속도 격차
→ Cache / Locality
→ 컴퓨터 구조의 메모리 지도
```

운영체제에서는 Cache 자체를 다시 설명하기보다 **Memory 성능이 Process 실행과 전체 System Performance에 영향을 준다**는 연결점으로만 본다.

Cache Mapping, Write Policy, MESI 등의 상세는 이 지도에서 반복하지 않는다.

## 9. Memory 관리의 전체 관계

~~~text
여러 Process 실행
        ↓
Physical Memory는 한정됨
        ↓
Allocation
├─ 연속 할당
│   ├─ 내부 / 외부 단편화
│   └─ First / Best / Worst Fit
│
└─ 불연속 배치
    ├─ Paging
    └─ Segmentation

Process별 Virtual Address Space
        ↓
Address Translation / Mapping
        ↓
Protection / Isolation

Demand Paging (정상 주소의 Page 준비 경로)
└─ Virtual Page 접근
   ├─ 사용 가능한 Mapping 있음 → 계속 실행
   └─ Page 준비 필요 → Page Fault
                      ↓
                  Frame 확보
                  ├─ 빈 Frame 사용
                  └─ 없으면 Page 교체 후 재사용
                      ↓ 두 경로 합류
                  Page 준비·적재
                      ↓
                  Mapping 갱신 → 접근 재시도

Memory 압박으로 필요한 Page를 유지하기 어려움
        ↓
Page Fault / Replacement가 과도하게 반복
        ↓
Paging I/O에 많은 시간 소비 → Thrashing
        ↓
Working Set / PFF / Frame / Workload 조절
~~~

대표 비교·분류축:

- 고정 분할 ↔ 가변 분할
- Paging ↔ Segmentation
- 연속/불연속 배치 ↔ Virtual Memory 사용 여부는 서로 다른 분류축
- Virtual Address Space ↔ Physical Memory
- 정상적인 Page Fault ↔ 과도한 Page Fault / Thrashing
- FIFO ↔ OPT ↔ LRU
- Global ↔ Local Replacement

Hardware 주소 변환은 별도 소유 영역으로 연결한다.

→ 컴퓨터 구조 · 메모리 계층과 가상 메모리  
MMU·TLB·Page Table·Cache의 Hardware 동작과 주소 변환 비용을 더 깊게 볼 때 내려간다.

## 10. 학습 경로

~~~text
1. 연속 Memory Allocation
   → 단편화와 배치 제약을 이해
        ↓
2. Paging ↔ Segmentation
   → 불연속 배치의 대표 방식 비교
        ↓
3. Virtual Address Space ↔ Physical Memory
   → 배치 방식과 별개인 주소 공간 추상화 · Mapping을 이해
   → Protection · Isolation의 기준선 이해
        ↓
4. Demand Paging
   → 필요한 Page만 실제 접근 시 준비·적재하는 정책
   └─ 필요한 Mapping이 없으면 Page Fault를 통해 처리
        ↓
5. Frame Allocation / Replacement
   → 빈 Frame이 없을 때 어떤 Frame/Page를 교체할지 결정
   → Global / Local 정책과 FIFO · OPT · LRU의 차이를 잡는다
        ↓
6. Thrashing
   → Frame 부족으로 Page Fault / Replacement가 과도하게 반복될 때 발생
   → Working Set · PFF로 Memory 압박을 감지·조절한다
~~~

이 지도에서는 OS가 Memory를 **배분·보호·회수·조절하는 정책**을 중심으로 본다. 주소 변환 Hardware와 Cache 내부 구조는 컴퓨터 구조에서, Replacement 반복 계산은 세부학습으로 내린다.
