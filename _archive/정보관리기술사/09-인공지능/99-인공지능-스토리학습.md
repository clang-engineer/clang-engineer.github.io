# 인공지능 스토리 학습 — 고객 문의를 처리하는 AI 서비스

> [인공지능 전체 개념지도](00-전체.md)의 문제 해결 방식·학습·모델 구조·생성형 AI·응용·평가를 고객 문의 서비스 사례로 이해한다. **학습 방법·아키텍처·모델 범용성·응용 목적은 서로 다른 분류축**이다.

위 그림은 **본문을 읽을 때 따라갈 학습 경로**다. 실제 인과관계가 없는 개념을 필수 선후 단계로 해석하지 않는다.

## 1. 규칙으로 답할까, 데이터에서 배울까 — AI와 ML

유통회사는 고객 문의에 자동 응답하려 한다. '배송 조회'라는 단어가 들어오면 정해진 안내문을 보내는 규칙을 만들었다. 그런데 표현이 다양해지자 규칙이 복잡해졌다.

표현이 다양해질수록 모든 규칙을 사람이 직접 작성하기는 어려워진다. AI에는 Rule/Expert System처럼 명시적 규칙을 사용하는 접근도 있고, 데이터에서 패턴을 학습하는 **ML(Machine Learning)**도 있다. 둘은 같은 개념이 아니다.

ML에서도 어떤 학습 신호를 사용하는지에 따라 접근이 달라진다. 지도학습은 정답 신호, 비지도학습은 데이터 구조, 강화학습은 보상 신호를 활용한다. 학습 신호의 분류이며 모델 구조와는 별도 관점이다.

## 2. 신경망은 무엇이 다를까 — DL과 모델 구조

문의 문장을 분류하는 모델을 만들고 싶다.

ML이 모두 Deep Learning인 것은 아니다. Classical ML과 Neural Network/DL은 모델 계열을 구분하는 관점이다. DL은 다층 신경망으로 표현을 학습한다. CNN은 공간적 패턴, RNN 계열은 순차 정보, Transformer는 Attention 기반 관계 처리를 대표하는 구조다.

Transformer 구조를 사용했다고 모든 모델이 LLM이 되는 것도 아니다. Transformer는 Architecture다. 모델이 어떤 목적과 데이터로 학습됐는지, 무엇을 수행하는지는 별도로 봐야 한다. [ML·DL 지도](01-ML-DL.md)에서 분류를 더 살펴본다.

## 3. 다양한 업무에 재사용하고 싶다 — Foundation Model과 생성형 AI

문의 분류뿐 아니라 답변 생성·요약·번역까지 필요해졌다.

여러 업무에 활용하려면 작업마다 모델을 처음부터 학습하는 것 외의 선택지가 있다. 여러 과제에 적응 가능한 **Foundation Model**을 활용할 수 있다. Foundation Model은 학습 알고리즘 자체가 아니라 모델의 범용성·활용 가능성을 강조한다.

Foundation Model·Generative AI·LLM은 서로 다른 기준으로 설명해야 한다. Foundation Model은 범용성, Generative AI는 새로운 콘텐츠 생성 목적, LLM은 대규모 언어 모델 계열을 가리킨다. Transformer는 그 모델에 활용될 수 있는 아키텍처다. 언어·비전·멀티모달 모델과 텍스트·이미지·음성·영상 생성은 서로 겹치지만 분류축이 다르다.

## 4. 우리 회사 정보를 모르는 모델 — Prompt·RAG·Fine-tuning

모델이 일반적인 배송 안내는 잘하지만 우리 회사의 실제 반품 규정은 모른다.

회사 내부 정보를 활용하려고 반드시 모델을 다시 학습할 필요는 없다. Prompt/Context로 정보를 제공하거나 **RAG(Retrieval-Augmented Generation)**로 관련 문서를 검색해 답변 맥락에 넣을 수 있다. **Fine-tuning**은 모델 파라미터를 추가 학습해 특정 행동·형식·업무에 적응시키는 접근이다.

Prompt·RAG·Fine-tuning도 반드시 순서대로 거치는 단계가 아니다. 문제의 성격과 비용·품질 요구에 따라 선택하거나 조합한다. RAG도 검색 결과의 품질이 낮으면 잘못된 답변을 낼 수 있다.

## 5. 답변을 넘어 주문을 처리한다 — Tool과 Agent

고객이 '주문을 취소해 줘'라고 요청한다.

답변을 생성하는 것과 실제 주문을 취소하는 것은 다른 작업이다. 실제 주문 취소는 권한 확인·상태 조회·업무 API 호출 등이 필요하다. Tool 사용은 외부 기능 호출, Agent는 목표 달성을 위해 모델·도구·상태·행동을 조합하는 실행 구조를 뜻한다. Agent가 항상 필요한 것도 아니다.

도구를 호출할 수 있어도 권한과 실행 결과를 검증해야 한다. 권한·검증·승인·오류 처리와 관측이 필요하다. [생성형 AI·LLM 지도](02-생성형AI-LLM.md)에서 내부 관계를 더 본다.

## 6. 정확한 답변인지 어떻게 알까 — 평가·운영·통제

AI가 고객에게 잘못된 환불 규정을 안내했다.

모델 정확도 하나만으로 실제 서비스의 성공을 평가할 수는 없다. 데이터 품질, 작업별 평가, 지연·비용, 편향·공정성, 설명 가능성(XAI), 개인정보·보안, 책임과 Governance를 함께 고려해야 한다. 모델은 배포 뒤에도 Monitoring과 피드백을 통해 개선해야 한다.

~~~text
문제 정의 → 데이터 → 모델·학습 → 평가 → 배포 → 모니터링
   ↑                                      │
   └────────────── 피드백·개선 ──────────────┘
[전 과정] 품질·Bias/Fairness·XAI·보안·Governance
~~~
