# 인공지능 전체 개념지도

AI(Artificial Intelligence, 인공지능) 전체의 위치를 먼저 잡고, ML(Machine Learning, 데이터에서 패턴을 학습하는 기계학습)·DL(Deep Learning, 다층 신경망 기반 학습)은 [ML·DL 개념지도](01-ML-DL.md), 생성형 AI·LLM(Large Language Model, 대규모 언어 모델)은 [생성형 AI·LLM 개념지도](02-생성형AI-LLM.md)로 내려가 관계를 더 촘촘히 본다. 세부 동작 원리·수식·Algorithm·예제는 필요한 세부학습 문서에서 다룬다.

## 빠른 복습 좌표

| 복습 축 | 핵심 관계·판단 단서 |
|---|---|
| 학습 | 지도(정답), 비지도(구조), 강화(보상) 학습은 학습 신호의 차이 |
| 구조 | Neural Network·CNN·RNN·Transformer는 모델 Architecture 관점 |
| 범용성 | Foundation Model은 여러 과제에 활용 가능한 모델의 성격 |
| 응용 | Generative AI는 생성 목적, LLM은 언어 모델 계열, Agent는 도구·행동 수행 구조 |
| 검증 | 데이터·성능 평가와 Bias·안전·보안·Governance는 전 과정 통제 |

**복습 방법:** 이 표에서 핵심 관계가 기억나지 않는 축만 아래 조망도와 연결된 하위 학습으로 내려간다. 상세 예제는 세부학습 본문에 남긴다.

## 1. AI 전체 좌표

AI 지식은 하나의 계층으로만 나뉘지 않는다. **문제 해결 방식, Model 구조, Model 범용성, 응용 목적, 통제 관점**처럼 서로 다른 분류축을 구분해서 본다.

```text
인공지능 — 문제 해결 방식에서 모델·응용·통제까지
│
├─ [1. 문제 해결 방식]
│  └─ Rule/Expert System · Machine Learning
├─ [2. 학습 모델 · Architecture]
│  └─ Classical ML · Neural Network/DL · Transformer
├─ [3. 범용 모델]
│  └─ Foundation Model → LLM · Vision · Multimodal
├─ [4. 응용]
│  └─ 예측 · 분류 · 추천 · NLP · 생성 · Agent
└─ [5. 평가 · 통제]
   └─ 품질 · Bias/Fairness · XAI · 보안 · Governance

학습 방식·모델 구조·범용성·응용 목적은 서로 다른 분류축
평가·통제는 모든 모델·응용에 적용
```

Foundation Model은 별개의 학습 알고리즘이라기보다 다양한 학습 방법으로 만들어져 여러 과제에 활용되는 모델의 성격·범용성을 가리킨다.

예를 들어 `Transformer`는 Architecture, `Foundation Model`은 범용성 관점의 Model 분류, `Generative AI`는 생성 목적, `LLM`은 Language Model 계열의 위치를 가진다. 서로 다른 분류축을 하나의 발전 순서처럼 연결하지 않는다.

## 2. 어디를 파고들 것인가

### ML · DL

Data에서 Pattern을 학습하는 방식과 Classical ML에서 Neural Network·DL로 확장되는 관계를 본다.

```text
ML
├─ Supervised
├─ Unsupervised
└─ Reinforcement Learning

Model 계열
├─ Classical ML
└─ Neural Network / DL
    ├─ CNN
    ├─ RNN 계열
    └─ Transformer
```

대표 Algorithm과 선택 기준, 신경망 구조, 평가·검증은 하위 지도에서 더 펼친다.

→ [ML·DL 개념지도](01-ML-DL.md)  
지도·비지도·강화의 차이와 Classical ML → Neural Network / DL의 관계를 더 촘촘히 보고, 대표 Algorithm의 선택 기준까지 내려간다.

### Foundation Model · 생성형 AI · LLM

이 영역은 하나의 발전 순서가 아니라 **서로 다른 질문의 축**을 먼저 나눠 본다.

```text
[범용 Model 계열]
Foundation Model
├─ Language Foundation Model → LLM
├─ Vision Foundation Model
└─ Multimodal Foundation Model

[생성 목적]
Generative AI
├─ Text
├─ Image
├─ Audio / Video
└─ Multimodal

[이미 만들어진 Model의 활용]
Prompt / Context
RAG
Fine-tuning
Tool / Agent
```

Transformer·Foundation Model·Generative AI·LLM은 같은 개념이 아니며, 각각 **Architecture·Model 범용성·생성 목적·언어 Model**이라는 서로 다른 위치를 가진다. Prompt·RAG·Fine-tuning·Agent 역시 서로의 필수 다음 단계가 아니라 목적에 따라 선택·조합하는 활용 기술이다.

→ [생성형 AI·LLM 개념지도](02-생성형AI-LLM.md)  
Transformer · Foundation Model · Generative AI · LLM의 위치를 구분한 뒤, LLM 내부 원리와 Prompt · RAG · Fine-tuning · Agent 활용 가지로 Zoom-in한다.

### 응용

Model 자체와 해결하려는 업무 문제는 구분한다.

```text
AI 기술
  ↓
응용 Task
├─ 추천
├─ NLP / 음성
├─ Vision
├─ 예측 · 분류
├─ Text2SQL
└─ 업무 자동화
```

같은 Task도 Rule, 전용 ML, Foundation Model 등 여러 방식으로 해결할 수 있다.

### 평가 · 운영 · 통제

평가와 통제는 특정 Model의 마지막 단계가 아니라 AI 전 영역을 가로지르는 축이다.

```text
문제 정의 → Data → Model / Training → Evaluation → Deployment → Monitoring
   ↑                                                        │
   └────────────────────── Feedback / 개선 ──────────────────┘

┌────────────────────── 전 과정 통제 ──────────────────────┐
│ Data 품질 · 개인정보 · Bias / Fairness · XAI · 보안     │
│ 책임 · Governance · 운영 Monitoring                      │
└───────────────────────────────────────────────────────────┘
```

평가·통제는 마지막 단계에 한 번 붙는 검사가 아니라 **Data를 준비하고 Model을 만들고 배포·운영하는 전 과정에 반복해서 적용되는 축**이다.
