# 보안 전체 개념지도

> 보안은 **업무와 정보자산을 위협으로부터 보호하기 위해 위험을 식별하고, 예방·탐지·대응·복구 통제를 계층적으로 적용하며 계속 개선하는 활동**이다.

## 1. 보안 전체 좌표

```text
보안 목표: CIA · 업무 연속성 · 개인정보 보호
                    │
                    ▼
              Risk Management
       자산 → 위협·취약점 → 위험 평가
                    │
                    ▼
                통제 선택
       ┌────────────┼─────────────┐
       ▼            ▼             ▼
    암호·신뢰    인증·접근통제   시스템·네트워크·앱
    Hash/PKI      IAM/AAA       Firewall/TLS/Secure Coding
       └────────────┼─────────────┘
                    ▼
        Monitoring · Incident Response
                    ▼
          Audit · Review · Improvement
                    └──→ Risk 재평가

[전 과정] Governance / ISMS / Privacy / Compliance
```

위 화살표는 **위험 평가와 대응·개선의 순환**이고, 아래 통제 가지는 순서가 아닌 **병렬적인 보호 수단**이다. 개인정보 보호와 거버넌스는 마지막 단계가 아니라 전 과정에 걸친다.

## 2. 어디를 파고들 것인가

### 위험 · 거버넌스

```text
Asset
  ↓
Threat + Vulnerability
  ↓
Likelihood × Impact
  ↓
Risk
  ↓
Avoid / Reduce / Transfer / Accept
  ↓
Residual Risk
```

CIA는 목표이고, Risk Management는 그 목표를 위협하는 상황에서 어떤 통제를 선택할지 결정하는 과정으로 본다.

### 암호 · 신뢰

```text
기밀성
├─ Symmetric Key
└─ Asymmetric Key

무결성
├─ Hash
└─ MAC

신원 · 부인방지
└─ Digital Signature / Certificate / PKI
```

대표 비교·분류 축:
- Symmetric ↔ Asymmetric
- Block ↔ Stream
- Hash ↔ MAC ↔ Digital Signature

→ [TLS · 보안 채널과 Handshake](TLS-보안채널과-Handshake.md)

### 인증 · 접근통제

```text
Who are you?
→ Authentication

What may you do?
→ Authorization

What did you do?
→ Accounting / Logging
```

인증과 인가는 같은 개념이 아니며, 최소권한·직무분리·추적성을 함께 본다.

### 공격 · Application 보안

```text
공격 표면
├─ Network / Protocol
├─ Account / Credential
├─ Application Input
└─ Configuration
      ↓
공격
├─ DDoS
├─ Sniffing / Spoofing
├─ Malware / APT
└─ Injection / XSS / CSRF
      ↓
예방 · 탐지 · 대응
```

→ [웹 애플리케이션 공격 · SQL Injection · XSS](웹-애플리케이션-공격-SQL-Injection-XSS.md)  
→ [SOP · CORS · 브라우저 동일출처 정책](SOP-CORS-브라우저-동일출처-정책.md)  
→ [HTTP 응답 정책 Header](HTTP-응답-정책-헤더-Cache-CSP-Permissions-Referrer.md)

### Network · System 심층방어

```text
Network Edge
├─ Firewall
├─ IDS / IPS
└─ VPN / IPSec

Secure Channel
├─ TLS
├─ SSH
└─ Tunnel

Execution Trust
├─ TEE
├─ TPM
└─ TrustZone
```

대표 비교·분류 축:
- Firewall ↔ IDS ↔ IPS
- VPN / IPSec ↔ TLS
- Detection ↔ Prevention

→ [VPN · Tunneling · 사설 Network](VPN-터널링과-사설-네트워크.md)  
→ [SSH Tunneling · Port Forwarding](SSH-Tunneling-Port-Forwarding.md)

### 관리체계 · 개인정보 · 사고대응

```text
Policy / Governance
      ↓
ISMS / ISO 27001
      ↓
운영 통제 · Audit
      ↓
Incident
      ↓
Response / Forensics
      ↓
개선 Feedback → Policy·운영 통제 재검토로 복귀

[별도 보호 목표]
Privacy / PIA
```

관리체계는 기술 통제를 반복 운영하는 구조이고, 개인정보 보호는 처리 목적·최소 수집·권리 보장이라는 별도 보호 목표를 가진다.
