# 보안 전체 개념지도

> 보안은 **업무와 정보자산을 위협으로부터 보호하기 위해 위험을 식별하고, 예방·탐지·대응·복구 통제를 계층적으로 적용하며 계속 개선하는 활동**이다.

## 1. 보안 전체 좌표

```text
업무 목표 · 정보자산
        ↓
위협 · 취약점 · 영향
        ↓
      Risk
        ↓
통제 선택
├─ 암호 · 신뢰
│   ├─ Symmetric ↔ Asymmetric
│   ├─ Block ↔ Stream
│   ├─ Hash / MAC
│   └─ Digital Signature / PKI
│
├─ 인증 · 접근통제
│   ├─ Identification / Authentication
│   ├─ Authorization
│   └─ Accounting / Log
│
├─ Network · System · Application
│   ├─ Firewall / IDS / IPS
│   ├─ VPN / IPSec / TLS
│   ├─ TEE / TPM / TrustZone
│   └─ Secure Coding / Web Security
│
└─ 관리 · 개인정보
    ├─ ISMS / ISO 27001
    ├─ Security Governance
    └─ Privacy / PIA
        ↓ 선택한 통제의 운영 결과 관찰
Monitoring · Incident Response · Forensics
        ↓
Audit · Review · Improvement
        ↓ 발견된 취약점 · 통제 효과 반영
Risk 재평가 → 통제 선택·개선으로 복귀
```

핵심은 공격명이나 보안 장비를 따로 외우는 것이 아니라 **어떤 위험을 어떤 통제로 줄이고, 남은 위험을 어떻게 탐지·대응·개선하는지** 연결하는 것이다. 마지막 Feedback은 막연히 처음으로 돌아가는 표시가 아니라 **발견된 취약점과 통제 효과를 Risk 평가와 통제 선택에 다시 반영하는 경로**다. Monitoring 이후의 흐름은 마지막 가지인 개인정보에만 붙는 것이 아니라 선택한 통제 전체에 적용된다.

## 2. 어디를 파고들 것인가

### 위험 · 거버넌스

```text
Asset
  ↓
Threat + Vulnerability
  ↓
Likelihood × Impact
  ↓
Risk
  ↓
Avoid / Reduce / Transfer / Accept
  ↓
Residual Risk
```

CIA는 목표이고, Risk Management는 그 목표를 위협하는 상황에서 어떤 통제를 선택할지 결정하는 과정으로 본다.

### 암호 · 신뢰

```text
기밀성
├─ Symmetric Key
└─ Asymmetric Key

무결성
├─ Hash
└─ MAC

신원 · 부인방지
└─ Digital Signature / Certificate / PKI
```

대표 비교·분류 축:
- Symmetric ↔ Asymmetric
- Block ↔ Stream
- Hash ↔ MAC ↔ Digital Signature

→ [TLS · 보안 채널과 Handshake](TLS-보안채널과-Handshake.md)

### 인증 · 접근통제

```text
Who are you?
→ Authentication

What may you do?
→ Authorization

What did you do?
→ Accounting / Logging
```

인증과 인가는 같은 개념이 아니며, 최소권한·직무분리·추적성을 함께 본다.

### 공격 · Application 보안

```text
공격 표면
├─ Network / Protocol
├─ Account / Credential
├─ Application Input
└─ Configuration
      ↓
공격
├─ DDoS
├─ Sniffing / Spoofing
├─ Malware / APT
└─ Injection / XSS / CSRF
      ↓
예방 · 탐지 · 대응
```

→ [웹 애플리케이션 공격 · SQL Injection · XSS](웹-애플리케이션-공격-SQL-Injection-XSS.md)  
→ [SOP · CORS · 브라우저 동일출처 정책](SOP-CORS-브라우저-동일출처-정책.md)  
→ [HTTP 응답 정책 Header](HTTP-응답-정책-헤더-Cache-CSP-Permissions-Referrer.md)

### Network · System 심층방어

```text
Network Edge
├─ Firewall
├─ IDS / IPS
└─ VPN / IPSec

Secure Channel
├─ TLS
├─ SSH
└─ Tunnel

Execution Trust
├─ TEE
├─ TPM
└─ TrustZone
```

대표 비교·분류 축:
- Firewall ↔ IDS ↔ IPS
- VPN / IPSec ↔ TLS
- Detection ↔ Prevention

→ [VPN · Tunneling · 사설 Network](VPN-터널링과-사설-네트워크.md)  
→ [SSH Tunneling · Port Forwarding](SSH-Tunneling-Port-Forwarding.md)

### 관리체계 · 개인정보 · 사고대응

```text
Policy / Governance
      ↓
ISMS / ISO 27001
      ↓
운영 통제 · Audit
      ↓
Incident
      ↓
Response / Forensics
      ↓
개선 Feedback → Policy·운영 통제 재검토로 복귀

[별도 보호 목표]
Privacy / PIA
```

관리체계는 기술 통제를 반복 운영하는 구조이고, 개인정보 보호는 처리 목적·최소 수집·권리 보장이라는 별도 보호 목표를 가진다.
