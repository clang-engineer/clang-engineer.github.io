# 다형성과 Dispatch — Subtype · Parametric · Static · Dynamic

> 학습 원칙: [`00-프로그래밍-언어-학습원칙.md`](00-프로그래밍-언어-학습원칙.md)
>
> 핵심 질문: **같은 인터페이스나 같은 코드로 여러 타입을 다룰 때, 실제로 어떤 동작을 실행할지 어떻게 정하는가?**

---

## 1. 큰 그림

다형성(Polymorphism)은 **하나의 형태로 여러 타입이나 동작을 다루는 개념**이다.

```text
다형성
├─ Subtype Polymorphism
│  → 공통 상위 타입/계약으로 여러 구체 타입을 다룸
│
├─ Parametric Polymorphism
│  → 타입 자체를 매개변수로 받아 같은 알고리즘을 여러 타입에 재사용
│
└─ Ad-hoc Polymorphism
   → Overloading처럼 같은 이름을 타입에 따라 다르게 해석
```

그리고 Dispatch는 **실제로 어떤 구현을 호출할지 정하는 과정**이다.

```text
Compile Time에 결정
→ Static Dispatch

Runtime에 결정
→ Dynamic Dispatch
```

따라서 `다형성 = virtual`이라고 외우면 다형성의 한 종류만 보게 된다.

---

## 2. C++ 기준점 — virtual로 보는 Runtime 다형성

```cpp
struct Animal {
    virtual void speak() = 0;
    virtual ~Animal() = default;
};

struct Dog : Animal {
    void speak() override {
        std::cout << "woof";
    }
};

struct Cat : Animal {
    void speak() override {
        std::cout << "meow";
    }
};

void run(Animal& a) {
    a.speak();
}
```

`run()`은 `Animal`이라는 공통 타입만 알지만, 실제 객체가 `Dog`인지 `Cat`인지에 따라 다른 함수가 실행된다.

```text
공통 Interface
      ↓
Animal&
      ↓
Runtime에 실제 객체에 맞는 구현 선택
      ↓
Dog::speak() 또는 Cat::speak()
```

이게 **Subtype Polymorphism + Dynamic Dispatch**를 C++에서 구현하는 대표적인 방식이다.

## 3. vtable은 다형성 그 자체가 아니라 구현 방법이다

C++ 구현은 보통 개념적으로 다음처럼 이해할 수 있다.

```text
객체
├─ Data
└─ vptr
    ↓
vtable
├─ speak → Dog::speak
└─ ...
```

호출:

```cpp
a.speak();
```

개념적으로는:

```text
객체가 가리키는 vtable 확인
  ↓
해당 함수 주소 선택
  ↓
간접 호출
```

핵심은 다음 경계다.

```text
다형성
→ 하나의 추상 형태로 여러 구현을 다루는 개념

virtual / vtable
→ C++에서 Runtime 다형성을 구현하는 대표적인 방법
```

## 4. Static Polymorphism — Template

C++ Template도 넓은 의미의 다형성이다.

```cpp
template <typename T>
void print(const T& value) {
    value.print();
}
```

사용:

```cpp
print(foo);
print(bar);
```

여기서는 Runtime에 호출 대상을 찾는 것이 아니라 Compile Time에 타입이 정해지고, 그 타입에 맞는 코드가 만들어질 수 있다.

```text
Template<T>
   ↓
T = Foo
→ Foo에 맞는 코드

T = Bar
→ Bar에 맞는 코드
```

따라서 C++에서는 다음처럼 구분하면 쉽다.

```text
virtual
→ Runtime Subtype Polymorphism

Template
→ Compile Time Parametric Polymorphism / Static Polymorphism
```

## 5. Parametric Polymorphism — 타입 자체를 매개변수로 받는다

C++ Template, Java Generic, Go Generic, Rust Generic은 문법은 다르지만 같은 문제를 해결한다.

```text
하나의 알고리즘
+
Type Parameter T
        ↓
여러 타입에 재사용
```

C++:

```cpp
template <typename T>
T max_value(T a, T b) {
    return a > b ? a : b;
}
```

Java:

```java
<T> T identity(T value) {
    return value;
}
```

Rust:

```rust
fn identity<T>(value: T) -> T {
    value
}
```

핵심은 `<T>`라는 문법이 아니라 **타입에 독립적인 코드를 어떤 조건과 비용으로 재사용하느냐**다. 구체적인 구현 전략은 [`제네릭과-타입-추상화.md`](제네릭과-타입-추상화.md)에서 더 자세히 본다.

## 6. 언어별 Interface는 비슷한 목적을 제공하지만 규칙은 다르다

### C++ / Java

```text
명시적인 상속 또는 구현 관계
→ 어떤 타입이 공통 계약을 따른다고 선언
```

### Go

```text
필요한 Method Set을 갖추면 Interface 만족
→ implements 같은 명시적 선언이 없어도 됨
```

### Rust

```text
Trait 구현을 명시
→ Generic Bound에서는 Static Dispatch 가능
→ dyn Trait에서는 Dynamic Dispatch 가능
```

따라서:

> `Go interface = 상속 없는 C++ virtual`

처럼 등치하지 않는다.

더 정확하게는:

> **Go Interface는 C++ Virtual Dispatch와 비슷하게 여러 구현을 하나의 계약으로 다룰 수 있게 한다. 다만 Go는 Method Set으로 Interface 만족 여부를 판단하고 명시적 상속 관계를 요구하지 않는다.**

## 7. Static Dispatch와 Dynamic Dispatch

### Static Dispatch

```text
Compile Time에 호출 대상 결정
```

대표:

- C++ Template
- Rust Generic + Trait Bound
- 일반 함수 Overload Resolution

장점:

- 간접 호출 비용을 줄일 수 있다.
- Inlining과 최적화에 유리할 수 있다.

Trade-off:

- 타입별 코드 생성으로 Binary Size가 커질 수 있다.
- Compile Time이 늘어날 수 있다.

### Dynamic Dispatch

```text
Runtime에 실제 객체나 Metadata를 보고 호출 대상 결정
```

대표:

- C++ virtual
- Java Interface/Virtual Method
- Rust `dyn Trait`

장점:

- Runtime에 서로 다른 구체 타입을 같은 Interface로 다루기 쉽다.
- 모든 구현을 Compile Time에 고정하지 않아도 된다.

Trade-off:

- 간접 호출 비용이 생길 수 있다.
- 일부 최적화가 제한될 수 있다.
- Runtime Metadata가 필요할 수 있다.

## 8. Overloading은 다른 종류의 다형성이다

```cpp
void print(int v);
void print(std::string v);
```

같은 함수 이름을 쓰지만 인자 타입에 따라 Compile Time에 어떤 함수를 호출할지 결정한다.

```text
Overloading
→ 같은 이름을 여러 Signature에 사용

Subtype Polymorphism
→ 공통 추상 타입 뒤에 여러 구체 구현을 둠

Parametric Polymorphism
→ 타입 자체를 매개변수로 받음
```

같은 "다형성"이라는 이름 아래에 있지만 해결하는 문제가 다르다.

## 9. Duck Typing과 구조적 타입도 같은 질문 위에서 비교한다

동적 언어에서는 명시적인 Interface 선언이 없어도 필요한 Method가 있으면 사용할 수 있다.

```python
def run(x):
    x.speak()
```

핵심 질문은 이것이다.

```text
"이 값으로 이 연산을 해도 되는가?"
→ 언제, 어떤 규칙으로 확인하는가?
```

```text
C++ virtual
→ 명시적 상속 관계 + Runtime Dispatch

C++ template
→ 필요한 표현이 Compile Time에 유효한지 확인

Go interface
→ Method Set으로 구조적으로 판단

Python Duck Typing
→ Runtime에 실제 연산이 가능한지 드러남
```

이렇게 같은 질문 위에서 보면 언어별 차이가 문법이 아니라 규칙의 차이로 보인다.

---

## 10. 다형성과 추상화는 같은 말이 아니다

```text
추상화
→ 중요하지 않은 세부를 감추고 필요한 계약만 드러냄

다형성
→ 하나의 추상 형태로 여러 구체 타입이나 동작을 다룸
```

추상화된 Interface가 다형성을 제공할 수 있지만 둘은 같은 개념이 아니다.

## 12. 기억·인출

```text
다형성
= 한 형태로 여러 타입/동작을 다룸

Subtype
= 공통 부모/계약 뒤에 여러 구현

Parametric
= 타입을 T로 받음

Static Dispatch
= Compile Time에 결정

Dynamic Dispatch
= Runtime에 결정

C++ virtual
= Runtime Subtype Polymorphism의 대표 구현

C++ template
= Parametric / Static Polymorphism의 대표 구현
```

핵심 문장:

> **다형성은 `virtual` 그 자체가 아니다. 여러 타입을 하나의 형태로 다루는 상위 개념이고, `virtual`, Template, Interface, Trait은 각 언어가 그 문제를 해결하는 서로 다른 장치다.**
