# 제네릭과 타입 추상화 — Template · Generic · Constraint · Type Erasure

> 학습 원칙: [`00-프로그래밍-언어-학습원칙.md`](00-프로그래밍-언어-학습원칙.md)
>
> 핵심 질문: **구체 타입에 묶이지 않는 코드를 만들면서, 그 타입이 어떤 연산을 지원해야 하는지 어떻게 표현하고 확인하는가?**

---

## 1. 큰 그림

Generic의 핵심은 `<T>`라는 문법이 아니다.

```text
하나의 Algorithm / Data Structure
        +
Type Parameter T
        ↓
여러 Type에 재사용
```

하지만 아무 타입이나 무조건 받을 수는 없다.

```text
T가 무엇을 할 수 있어야 하는가?
        ↓
Constraint / Bound / Concept / Interface
```

그리고 실제 Code를 만드는 방식도 나뉜다.

```text
Compile Time에 타입별 Code 생성
→ Monomorphization

구체 타입을 감추고 공통 형태로 다룸
→ Type Erasure / Dictionary / Metadata
```

---

## 2. C++ 기준점 — Template

```cpp
template <typename T>
T max_value(T a, T b) {
    return a > b ? a : b;
}
```

호출:

```cpp
max_value(1, 2);
max_value(1.5, 2.5);
```

C++에서는 다음처럼 이해하면 쉽다.

```text
Template Source
   ↓
T = int
→ int에 맞는 Code 생성

T = double
→ double에 맞는 Code 생성
```

즉 C++ Template는 **타입을 Compile Time 매개변수로 받고, 필요하면 타입별 Code를 만들어 내는 방식**을 잘 보여준다.

---

## 3. Parametric Polymorphism과 연결

Generic은 다형성의 한 종류인 Parametric Polymorphism과 연결된다.

```text
Subtype Polymorphism
→ 공통 상위 타입 뒤에 여러 구현

Parametric Polymorphism
→ 타입 자체를 매개변수로 받음
```

`vector<int>`와 `vector<string>`은 상속 관계가 아니라 같은 Generic 구조에서 `T`만 달라진 경우다.

---

## 4. Constraint — T가 무엇을 할 수 있어야 하는가

초기 C++ Template에서는 필요한 연산이 실제 Instantiation 과정에서 드러난다.

```cpp
template <typename T>
T add(T a, T b) {
    return a + b;
}
```

이 코드를 쓰려면 `T`가 `+` 연산을 지원해야 한다.

Modern C++에서는 Concept으로 이런 요구사항을 더 직접 적을 수 있다.

```cpp
template <typename T>
concept Addable = requires(T a, T b) {
    a + b;
};

template <Addable T>
T add(T a, T b) {
    return a + b;
}
```

핵심은 다음과 같다.

```text
Generic
→ 타입을 T로 받아 코드 재사용

Constraint
→ T가 어떤 연산이나 조건을 만족해야 하는지 명시
```

## 5. Java Generic — 문법은 비슷해도 구현은 다르다

```java
class Box<T> {
    T value;
}
```

겉모양은 C++ Template와 비슷하지만 실제 Code를 만드는 방식은 다를 수 있다.

Java Generic은 대표적으로 Type Erasure를 사용한다.

```text
Source에서는 T를 사용
      ↓
Compile Time에 타입 검사
      ↓
Runtime 표현에서는 일부 Generic 타입 정보가 사라짐
```

따라서 `Java Generic = C++ Template`이라고 볼 수는 없다.

공통점은 **타입을 매개변수로 받는다는 점**이고, 실제 구현 전략은 다르다.

---

## 6. Rust Generic과 Trait Bound

```rust
fn max_value<T: Ord>(a: T, b: T) -> T {
    if a > b { a } else { b }
}
```

여기서:

```text
T
→ 타입 매개변수

Ord
→ T가 만족해야 하는 Trait
```

Rust Generic은 흔히 Monomorphization으로 구현된다.

C++의 `Template + Concept`를 떠올리면 이해하기 쉽지만, Rust는 Trait 규칙과 Ownership이 언어 전체와 더 깊게 연결된다는 차이가 있다.

---

## 7. Go Generic과 Constraint

```go
func Max[T Ordered](a, b T) T {
    ...
}
```

Go도 같은 질문을 푼다.

```text
어떤 타입을 받을까?
→ T

T가 무엇을 지원해야 할까?
→ Constraint
```

언어별 문법보다 이 구조를 먼저 본다.

---

## 8. Type Erasure — 구체 타입은 숨기고 공통 인터페이스만 남긴다

C++에서는 `std::function`을 좋은 기준점으로 볼 수 있다.

```cpp
std::function<int(int)> f = [](int x) {
    return x + 1;
};
```

서로 다른 Callable을 하나의 공통 타입으로 다룰 수 있다.

```text
Lambda A ─┐
Functor B ├→ std::function<int(int)>
Function  ┘
```

호출자는 안쪽의 구체 Callable 타입을 몰라도 된다.

Type Erasure의 핵심은 다음과 같다.

> **구체 타입은 감추고, 호출자가 필요한 공통 연산만 남겨 Runtime에서 하나의 형태로 다룬다.**

---

## 9. Monomorphization과 Type Erasure의 Trade-off

### Monomorphization

```text
타입마다 Code 생성
```

장점:

- Static Dispatch가 가능하다.
- Inlining과 최적화에 유리할 수 있다.
- 구체 타입 정보를 그대로 활용할 수 있다.

Trade-off:

- Code Size가 커질 수 있다.
- Compile Time이 늘어날 수 있다.

### Type Erasure / 공통 Runtime 표현

```text
여러 구체 타입
→ 공통 형태로 감쌈
```

장점:

- 같은 Code를 여러 타입이 공유하기 쉬울 수 있다.
- Runtime에 서로 다른 타입을 같은 Container나 Interface로 다루기 쉽다.

Trade-off:

- 간접 호출, Boxing, Metadata 같은 비용이 생길 수 있다.
- 구체 타입 정보 일부를 직접 쓰기 어려워질 수 있다.

---

## 10. Generic과 Interface는 서로 대체하는 개념이 아니다

둘 다 추상화를 돕지만 질문이 다르다.

```text
Generic
→ 타입을 매개변수로 받아 같은 Code를 여러 타입에 재사용할 것인가?

Interface / Trait Object
→ 서로 다른 구체 구현을 하나의 공통 계약으로 Runtime에 다룰 것인가?
```

Rust는 같은 Trait을 두 방식으로 사용할 수 있어 차이를 잘 보여준다.

```text
T: Trait
→ Static Dispatch 중심

dyn Trait
→ Dynamic Dispatch 중심
```

## 11. Generic Data Structure와 Generic Algorithm

### Data Structure

```cpp
std::vector<T>
std::optional<T>
```

### Algorithm

```cpp
template <typename Iter>
void sort(Iter first, Iter last);
```

같은 Generic 원리가 자료구조와 Algorithm 양쪽에 적용된다.

| 표현력 | 연산·연관 타입·조건부 구현 등을 얼마나 표현할 수 있는가? |

## 13. 기억·인출

```text
Generic
= 타입을 T로 받는다

Constraint
= T가 해야 하는 일을 적는다

Monomorphization
= T마다 Code를 만든다

Type Erasure
= 구체 타입을 감추고 공통 껍데기로 다룬다
```

핵심 문장:

> **Generic은 타입을 매개변수로 받아 같은 Code를 여러 타입에 재사용하는 개념이다. Template·Generic·Trait Bound·Concept은 이를 표현하는 언어별 장치이고, 실제 Code를 만드는 방식은 Monomorphization과 Type Erasure 등으로 다시 나뉜다.**
