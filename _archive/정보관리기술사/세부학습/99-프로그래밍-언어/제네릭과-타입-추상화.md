# 제네릭과 타입 추상화 — Template · Generic · Constraint · Type Erasure

> 학습 원칙: [`00-프로그래밍-언어-학습원칙.md`](00-프로그래밍-언어-학습원칙.md)
>
> 핵심 질문: **구체 타입에 종속되지 않는 코드를 만들면서도, 그 타입이 어떤 연산을 지원해야 하는지 어떻게 표현하고 검증하는가?**

---

## 1. 큰 그림

제네릭(Generic)의 핵심은 문법 `<T>`가 아니다.

```text
하나의 Algorithm / Data Structure
        +
Type Parameter T
        ↓
여러 Type에 재사용
```

하지만 아무 타입이나 무조건 받을 수는 없다.

```text
T가 무엇을 할 수 있어야 하는가?
        ↓
Constraint / Bound / Concept / Interface
```

그리고 구현 전략도 갈린다.

```text
Compile Time에 타입별 코드 생성
→ Monomorphization

공통 표현으로 감싸 Runtime에 처리
→ Type Erasure / Dictionary / Metadata
```

---

## 2. C++ 기준점 — Template

```cpp
template <typename T>
T max_value(T a, T b) {
    return a > b ? a : b;
}
```

호출:

```cpp
max_value(1, 2);
max_value(1.5, 2.5);
```

핵심 직관:

```text
Template Source
   ↓
T = int
→ int용 코드

T = double
→ double용 코드
```

C++ Template는 **Compile Time 타입 매개변수화와 코드 생성**이라는 기준점을 잘 보여준다.

---

## 3. Parametric Polymorphism과 연결

제네릭은 다형성의 한 종류인 Parametric Polymorphism과 연결된다.

```text
Subtype Polymorphism
→ 공통 상위 타입 뒤에 여러 구현

Parametric Polymorphism
→ 타입 자체를 매개변수로 받음
```

`vector<int>`와 `vector<string>`은 상속 관계가 아니라 `T`가 달라진 동일한 Generic 구조다.

---

## 4. Constraint — T가 무엇을 할 수 있어야 하는가

초기 C++ Template에서는 필요한 연산이 실제 Instantiation 시점에 드러난다.

```cpp
template <typename T>
T add(T a, T b) {
    return a + b;
}
```

`T`가 `+`를 지원해야 한다.

Modern C++에서는 Concept으로 요구사항을 명시할 수 있다.

```cpp
template <typename T>
concept Addable = requires(T a, T b) {
    a + b;
};

template <Addable T>
T add(T a, T b) {
    return a + b;
}
```

핵심은:

```text
Generic
→ 타입을 추상화

Constraint
→ 그 타입이 만족해야 할 계약을 추상화
```

이다.

---

## 5. Java Generic — 문법은 비슷하지만 구현은 다를 수 있다

```java
class Box<T> {
    T value;
}
```

C++ Template와 겉모양은 비슷하지만 구현 전략과 Runtime 타입 정보는 다르다.

Java는 대표적으로 Type Erasure 기반 Generic을 사용한다.

```text
Source에서는 T 존재
      ↓
Compile Time 타입 검사
      ↓
일부 Generic 타입 정보가 Runtime 표현에서 지워짐
```

따라서:

> `Java Generic = C++ Template`

이라고 등치하면 안 된다.

공통점은 **타입을 매개변수화한다는 의미론**이고, 구현 전략은 다르다.

---

## 6. Rust Generic과 Trait Bound

```rust
fn max_value<T: Ord>(a: T, b: T) -> T {
    if a > b { a } else { b }
}
```

여기서:

```text
T
→ 타입 매개변수

Ord
→ T가 만족해야 하는 Trait 계약
```

Rust Generic은 흔히 Monomorphization으로 구현된다.

C++ 기준으로는:

```text
Template + Concept
```

을 떠올리면 이해하기 쉽지만, Rust Trait 시스템의 Coherence·Ownership·Trait Bound 의미론은 별도 차이가 있다.

---

## 7. Go Generic과 Constraint

```go
func Max[T Ordered](a, b T) T {
    ...
}
```

Go에서도 타입 매개변수와 Constraint를 사용한다.

핵심 질문은 동일하다.

```text
어떤 타입을 받을 것인가?
→ T

T가 무엇을 지원해야 하는가?
→ Constraint
```

언어별 문법보다 이 구조를 먼저 본다.

---

## 8. Type Erasure — 구체 타입을 숨기고 공통 Interface로 다룬다

C++에서는 `std::function`을 좋은 기준점으로 볼 수 있다.

```cpp
std::function<int(int)> f = [](int x) {
    return x + 1;
};
```

내부적으로 다양한 Callable 타입을 하나의 공통 타입으로 감싼다.

```text
Lambda A ─┐
Functor B ├→ std::function<int(int)>
Function  ┘
```

호출자는 구체 Callable 타입을 몰라도 된다.

Type Erasure의 핵심:

> **구체 타입 정보 일부를 감추고, 필요한 공통 연산만 남겨 하나의 Runtime 표현으로 다룬다.**

---

## 9. Monomorphization과 Type Erasure의 Trade-off

### Monomorphization

```text
타입별 코드 생성
```

장점:

- Static Dispatch
- Inlining/Optimization에 유리할 수 있음
- 구체 타입 정보 활용 가능

Trade-off:

- Code Size 증가 가능
- Compile Time 증가 가능

### Type Erasure / 공통 Runtime 표현

```text
여러 구체 타입
→ 공통 Representation
```

장점:

- Binary Code 중복 감소 가능
- Runtime에 서로 다른 타입을 동일 Container/Interface로 다루기 쉬움

Trade-off:

- 간접 호출/Boxing/Metadata 비용 가능
- 구체 타입 정보 일부 상실

---

## 10. Generic과 Interface는 대체 관계가 아니다

둘 다 추상화를 제공하지만 질문이 다르다.

```text
Generic
→ 타입을 Compile Time 매개변수로 받을 것인가?

Interface / Trait Object
→ Runtime에 여러 구체 구현을 공통 추상 타입으로 다룰 것인가?
```

Rust는 같은 Trait을:

```text
T: Trait
→ Static Dispatch 중심

dyn Trait
→ Dynamic Dispatch 중심
```

으로 활용할 수 있어 차이를 잘 보여준다.

---

## 11. Generic Data Structure와 Generic Algorithm

### Data Structure

```cpp
std::vector<T>
std::optional<T>
```

### Algorithm

```cpp
template <typename Iter>
void sort(Iter first, Iter last);
```

같은 Generic 원리가 타입 저장 구조와 Algorithm 재사용 양쪽에 적용된다.

---

## 13. 기억·인출

```text
Generic
= 타입을 T로 받는다

Constraint
= T가 할 수 있어야 하는 일을 적는다

Monomorphization
= T마다 코드를 찍는다

Type Erasure
= 구체 타입을 감추고 공통 껍데기로 다룬다
```

핵심 문장:

> **제네릭은 타입을 매개변수화하는 의미론이고, Template·Generic·Trait Bound·Concept은 이를 표현하는 언어별 장치이며, 실제 실행 코드를 만드는 전략은 Monomorphization과 Type Erasure 등으로 다시 나뉜다.**
