## 1. 프로그래밍 언어를 다섯 질문으로 본다

언어별 문법을 외우기 전에 다음 질문으로 나눈다.

```text
1. 값과 메모리
→ 값이 복사되는가, 공유되는가, 이동되는가?
→ 누가 Lifetime과 Ownership을 관리하는가?

2. 함수와 실행
→ 함수가 외부 상태를 어떻게 기억하는가?
→ 오래 걸리는 작업 뒤에 실행을 어떻게 이어가는가?

3. 타입과 다형성
→ 여러 타입을 하나의 코드로 어떻게 다루는가?
→ 실제 호출 대상은 언제 결정되는가?

4. 실패와 부재
→ 실패와 값 없음을 어떻게 표현하고 전달하는가?

5. 모듈과 의존관계
→ 코드를 어떻게 나누고 언제 실제 구현과 연결하는가?
```

이 다섯 축은 발전 단계가 아니라 서로 다른 관점이다.

## 3. C++를 기준점으로 사용하는 이유

이 학습 영역에서는 C++를 정답 언어가 아니라 **추상 개념을 실제 실행 요소로 풀어보는 기준점**으로 사용한다.

```text
Closure
→ Functor + Lambda + Capture로 실체화

다형성
→ virtual / vtable과 Template으로 구체화

Ownership
→ RAII / unique_ptr로 구체화

Callback
→ 함수 포인터 / std::function / Lambda

Future
→ std::future

Module / Linking
→ 선언·정의·Object File·Linker
```

그리고 각 언어가 이 기준점과 어디에서 달라지는지 확인한다.

```text
C++로 이해
   ↓
공통 의미론 확인
   ↓
언어별 차이 확인
   ↓
타입·Lifetime·Runtime·성능 차이까지 연결
```

## 9. 언어를 새로 볼 때의 순서

새 언어를 배울 때 문법 목록부터 만들지 않는다.

```text
새 언어
 ↓
1. 값은 복사/참조/이동 중 어떻게 동작하는가?
 ↓
2. Ownership과 Lifetime은 누가 관리하는가?
 ↓
3. 함수는 외부 상태를 어떻게 Capture하는가?
 ↓
4. 비동기 실행을 어떻게 표현하고 Scheduling하는가?
 ↓
5. 다형성과 Generic을 어떤 타입 시스템으로 제공하는가?
 ↓
6. 실패와 부재를 어떻게 계약에 표현하는가?
 ↓
7. Module과 Dependency를 언제 연결하는가?
```

이렇게 보면 새로운 문법이 기존 개념의 어디에 위치하는지 빠르게 판단할 수 있다.

## 10. 같은 단어가 나와도 의미론을 다시 확인한다

```text
move
C++ std::move ↔ Rust move

interface
Java ↔ Go

closure
C++ ↔ JavaScript ↔ Rust

async
JavaScript ↔ C++ ↔ Rust

generic
C++ Template ↔ Java Generic
```

이름이나 역할이 비슷하다고 같은 제도라고 단정하지 않는다.

다음 차이를 확인한다.

```text
타입 시스템의 강제 범위
Ownership / Lifetime
메모리 표현
Compile Time / Runtime 역할
Dispatch
Error 처리
Scheduling
```

## 11. 파일을 늘리는 기준

언어별 Keyword 하나당 파일 하나를 만들지 않는다.

현재 기본 학습 단위는 다음과 같다.

```text
함수 객체와 Closure
비동기 실행 모델
값·참조·이동과 Lifetime
다형성과 Dispatch
제네릭과 타입 추상화
실패와 부재 처리
모듈과 의존관계
```

새 개념을 만났을 때:

```text
기존 개념군과 함께 보면 이해가 좋아지는가?
├─ Yes → 기존 문서에 추가
└─ No
   ↓
독립적인 의미론/실행 모델인가?
├─ Yes → 새 문서 검토
└─ No → 별도 파일을 만들지 않음
```

## 12. 기술사 학습에서의 목표

이 영역의 목표는 특정 언어의 문법을 많이 기억하는 것이 아니다.

문제를 보았을 때 다음 흐름을 복원할 수 있으면 된다.

```text
언어 기능 이름
   ↓
어떤 공통 문제를 해결하는가?
   ↓
C++에서는 무엇으로 실체화되는가?
   ↓
다른 언어는 의미론을 어떻게 달리 선택했는가?
   ↓
그 차이가 성능·안전성·유연성·실행 모델에 어떤 Trade-off를 만드는가?
```

> **프로그래밍 언어 학습의 핵심은 문법 간 번역이 아니라, 같은 문제를 서로 다른 언어가 어떤 의미론과 Runtime 비용으로 해결하는지 비교할 수 있는 상태를 만드는 것이다.**
