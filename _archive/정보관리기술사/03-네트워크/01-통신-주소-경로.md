# 통신·주소·경로 개념지도

이 지도는 **데이터를 같은 망 안에서 보내고, 다른 망까지 찾아가게 만드는 데 필요한 주소와 경로 개념**을 함께 본다.

처음에는 `L2`, `L3`, `Prefix` 같은 용어보다 다음 질문부터 잡는다.

```text
같은 망 안에서는 누구에게 보내지?
  ↓
MAC / Switch

다른 망에 있는 상대는 어떻게 구분하지?
  ↓
IP / Subnet / Gateway

멀리 있는 목적지까지 어느 길로 가지?
  ↓
Routing
```

이 세 질문을 따라가면서 정식 용어와 세부 관계를 단계적으로 붙인다.

## 빠른 복습 단서

| 질문 | 핵심 판단 |
|---|---|
| 같은 Subnet인가? | 목적지 MAC을 알아내 같은 Link에서 직접 전달 |
| 다른 Subnet인가? | Default Gateway MAC으로 Frame 전달, Router가 IP 경로 선택 |
| MAC / IP | 링크 내 전달 주소 / 네트워크 간 목적지 주소 |
| VLAN / Subnet | L2 Broadcast Domain 구분 / L3 주소 범위 구분 |
| Routing | 목적지 Prefix에 맞는 다음 홉·출력 경로 선택 |

기억나지 않는 항목만 아래 구조와 세부 설명으로 내려간다. 전체 과목 지도와 같은 설명을 반복하지 않고 **이 주제 내부의 비교·선택 기준**을 복원한다.

## 1. 계층화와 데이터 전달

계층화는 통신 기능을 역할별로 분리해 **표준화·상호운용성·변경 용이성**을 높인다. 대신 계층별 헤더와 처리에 따른 **Overhead**가 발생할 수 있다. OSI는 통신 기능을 구분하는 **참조 모델**이며, 실제 인터넷의 TCP/IP 프로토콜 체계와 계층 구성이 다르다.

```text
OSI 7계층                         TCP/IP 4계층
7 응용       — 네트워크 서비스 ┐
6 표현       — 형식·변환       ├── 응용
5 세션       — 대화 관리       ┘
4 전송       — 종단 간 통신    ─── 전송
3 네트워크   — IP·경로         ─── 인터넷
2 데이터링크 — 인접 노드 전달 ┐
1 물리       — 비트·신호       ┴── 네트워크 액세스
```

**송신은 캡슐화, 수신은 역캡슐화**한다. 각 계층은 아래 계층의 서비스를 이용하며, 대응 계층끼리는 프로토콜에 따라 논리적으로 통신한다.

```text
송신 측 (위 → 아래)
응용 데이터     Data            (7~5계층)
   ↓ 전송 Header
전송 단위       Segment(TCP) / Datagram(UDP) (4계층)
   ↓ IP Header
네트워크 단위   Packet          (3계층)
   ↓ Link Header·Trailer
링크 단위       Frame           (2계층)
   ↓ 신호로 전송
물리 단위       Bit             (1계층)
```

```text
Protocol  — 서로 다른 장치의 대응 계층 사이 통신 규칙 (수평)
Interface — 같은 장치의 인접 계층 사이 이용 경계 (수직)
Service   — 하위 계층이 상위 계층에 제공하는 기능

Port (L4) — 호스트 안의 통신 종단
IP   (L3) — 네트워크 간 목적지
MAC  (L2) — 현재 링크의 다음 전달 대상
```

IP 목적지는 여러 링크를 거쳐 유지되는 것이 일반적이지만, **MAC 주소는 링크를 지날 때 달라질 수 있다**. Port → IP → MAC은 송신 측의 계층 처리 순서이지, 목적지를 순차적으로 검색한다는 뜻은 아니다.

## 2. 같은 Network와 다른 Network

송신 Host 입장에서는 먼저 **목적지가 나와 같은 Subnet인가?**를 판단한다.

```text
송신 Host
  ↓
목적지 IP와 Subnet Mask 비교
  ↓
같은 Subnet인가?
  ├─ Yes → 목적지 MAC 확인 → 같은 망에서 직접 전달
  └─ No  → Default Gateway MAC 확인
               ↓
             Router
               ↓
          다른 Network로 전달
```

같은 Link의 IP를 MAC으로 해석하는 대표 Protocol이 ARP다. 다른 Network로 갈 때 Host가 찾는 MAC은 최종 목적지의 MAC이 아니라 **Default Gateway의 MAC**이다.

## 3. L2 Network 분리와 L3 Network 분리

여기서 `VLAN`과 `Subnet`의 경계를 잡는다.

```text
L2 영역
├─ Switch
├─ MAC Address
├─ Broadcast Domain
└─ VLAN
    └─ 하나의 물리 Switch 환경을 여러 논리 L2 영역으로 분리

L3 영역
├─ IP Address
├─ Prefix / Subnet Mask
└─ Subnet
    └─ IP Prefix 기준으로 Network 범위 분리
```

VLAN과 Subnet은 실제 설계에서 함께 쓰이는 경우가 많지만 같은 개념은 아니다.

→ [VLAN-서브넷-브로드캐스트-도메인](VLAN-서브넷-브로드캐스트-도메인.md)

## 4. IP 주소와 주소 공간 설계

```text
IP Address
├─ IPv4
│   └─ 주소 부족
│       ├─ 사설 주소
│       └─ NAT / PAT
└─ IPv6
    └─ 더 큰 주소 공간

주소 범위 표현·분할
├─ Prefix Length
├─ Subnetting
├─ VLSM
└─ CIDR
```

역할을 구분한다.

```text
Subnetting
= Network를 여러 Subnet으로 나누는 행위

VLSM
= Subnet마다 필요한 크기를 다르게 설계

CIDR
= Class 없이 Prefix로 주소 범위를 표현·할당·집약

DHCP
= Host에 IP·Mask·Gateway·DNS 등의 설정을 자동 제공

NAT / PAT
= Network 경계에서 주소 또는 주소·Port 대응을 변환
```

→ [IP-주소-NAT-DHCP-CIDR-VLSM](IP-주소-NAT-DHCP-CIDR-VLSM.md)

## 5. Routing의 위치

다른 Network로 가야 한다면 Router는 **어느 방향으로 보낼지** 결정해야 한다.

```text
다른 Network로 전달 필요
  ↓
Routing Table
  ↓
목적지 Prefix와 비교
  ↓
Longest Prefix Match
  ↓
Next Hop / Interface 선택
  ↓
Packet Forwarding
```

Routing과 Forwarding을 같은 것으로 보지 않는다.

```text
Routing
= 경로 정보를 학습하고 좋은 경로를 결정

Forwarding
= 만들어진 Table을 이용해 실제 Packet을 다음 Hop으로 전달
```

## 6. Routing Protocol의 분류축

```text
Routing
├─ Static Routing
│   └─ 관리자가 경로 지정
└─ Dynamic Routing
    ├─ AS 내부
    │   ├─ Distance Vector
    │   │   └─ RIP
    │   └─ Link State
    │       └─ OSPF
    └─ AS 간
        └─ BGP
            └─ Path Vector / Policy
```

`RIP → OSPF → BGP`를 단순 발전 순서로 외우지 않는다. RIP와 OSPF는 AS 내부 Routing 문제를 서로 다른 방식으로 풀고, BGP는 **관리 주체가 다른 AS 사이**에서 정책을 포함해 경로를 선택한다.

→ [라우팅-원리와-RIP-OSPF-BGP](라우팅-원리와-RIP-OSPF-BGP.md)

## 7. 망 구성 — 기본 토폴로지와 네트워크 아키텍처

**기본 토폴로지는 장비의 연결 모양**, **네트워크 아키텍처는 연결 구조와 장비의 역할을 함께 설계**하는 관점이다.

```text
[기본 토폴로지: 연결 형태]
Star             Ring
    A            A ─── B
    │            │     │
B ─ SW ─ C       D ─── C
    │
    D

[3-Tier: 역할을 계층으로 분리]
             Core
            /    \
         Dist A  Dist B
          /  \    /  \
        Acc  Acc Acc  Acc
         │    │   │    │
       Host Host Host Host

[Spine-Leaf: Leaf마다 모든 Spine에 연결]
       Spine A     Spine B
        / | \       / | \
       /  |  \     /  |  \
    Leaf A  Leaf B  Leaf C
       │       │       │
     Host    Host    Host
```

| 구분 | 무엇을 설명하는가? | 대표 특징 |
|---|---|---|
| Star / Ring / Mesh | 장비 사이의 기본 연결 형태 | 중심·고리·다중 연결 |
| 3-Tier | Core·Distribution·Access의 계층적 역할 | 전통적 기업망·데이터센터 구성 |
| Spine-Leaf | Spine·Leaf 스위치의 연결 구조 | 서버 간(East-West) 통신·수평 확장에 유리 |

**3-Tier ↔ Spine-Leaf**는 데이터센터 네트워크를 어떻게 설계할지 비교하는 축이다. Spine-Leaf는 서로 다른 Leaf의 서버가 보통 `Leaf → Spine → Leaf`로 통신하며, 기본 Mesh와 일부 연결 특성이 비슷해도 완전 Mesh와 동일하지 않다.

이 구조는 클라우드 전용 기술이 아니라 **네트워크 토폴로지·아키텍처**이고, 클라우드 사업자의 데이터센터에서도 활용할 수 있다.

## 8. 학습 이동 경로

```text
같은 망 안에서는 누구에게 보내는가?
  ↓
다른 망에 있는 상대는 어떻게 구분하는가?
  ↓
VLAN과 Subnet은 각각 어떤 경계를 나누는가?
  ↓
IP 주소 범위는 어떻게 표현하고 나누는가?
  ↓
Host는 Network 설정을 어떻게 얻는가?
  ↓
다른 Network로 갈 때 Gateway와 Router는 무엇을 하는가?
  ↓
Router들은 경로 정보를 어떻게 만들고 공유하는가?
```

Header 세부 필드, ARP 메시지 형식, Routing Algorithm의 계산 단계와 Timer는 세부학습으로 내려간다.
