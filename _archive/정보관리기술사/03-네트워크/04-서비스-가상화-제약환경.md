# 서비스·가상화·제약환경 개념지도

**핵심 질문: 기본 네트워크 전달 위에서 서비스·보안·제어·단말 환경의 요구가 달라지면 무엇을 추가하는가?**

## 1. 한눈에 보는 구조

```text
기본 네트워크 위의 확장 요구
│
├─ ① 서비스 전달 — 어떤 응용 요구를 해결하는가?
│  ├─ Web 요청·응답 → HTTP
│  ├─ 실시간 음성·영상 → RTP / RTCP
│  └─ 콘텐츠 분산 제공 → CDN
│
├─ ② 사설 연결 — 공용망에서 어떻게 격리하는가?
│  └─ VPN
│
├─ ③ 제어·기능 구현 — 망 운영을 어떻게 유연하게 하는가?
│  ├─ SDN — 제어를 소프트웨어 중심으로 구성
│  └─ NFV — 네트워크 기능을 소프트웨어로 실행
│
└─ ④ 제약 환경 — 자원이 부족한 단말은 어떻게 연결하는가?
   └─ Sensor Network / IoT
```

**이 네 가지는 발전 순서가 아니다.** 서로 다른 문제 축이며 필요에 따라 함께 사용한다.

## 2. 서비스 — HTTP·RTP·CDN은 무엇이 다른가?

- **HTTP(Hypertext Transfer Protocol):** 응용 계층의 웹 요청·응답 의미를 정한다. Persistent Connection/Keep-Alive, Connection Pool은 연결 재사용을 위한 상위 계층의 접근이다.
- **RTP(Real-time Transport Protocol):** 실시간 미디어 전달. **RTCP(RTP Control Protocol):** 전달 품질·상태 피드백. 실시간 서비스는 Delay·Jitter·Loss에 민감하며 QoS(Quality of Service)와 QoE(Quality of Experience)를 함께 고려한다.
- **CDN(Content Delivery Network):** 콘텐츠를 여러 지점에 배치해 사용자 가까이서 제공한다. **Multicast**는 네트워크가 하나의 트래픽을 여러 수신자에게 복제·전달하는 방식이므로 CDN과 문제 해결 계층이 다르다.

```text
HTTP     → 요청·응답 의미
RTP/RTCP → 실시간 미디어 전달·피드백
CDN      → 콘텐츠 배치·제공 위치 최적화
```

## 3. 사설 연결 — VPN은 단순 암호화인가?

**VPN(Virtual Private Network)**은 공용 네트워크 위에 논리적 사설 연결을 만드는 개념이다. 암호화는 구현에 따라 함께 사용할 수 있지만 VPN을 암호화 하나와 동일시하지 않는다. 세부 터널·보안 프로토콜은 [보안 전체 개념지도](../04-보안/00-전체.md)에서 연결한다.

## 4. 제어와 기능 — SDN과 NFV는 왜 다른가?

```text
네트워크 운영 유연화
├─ SDN(Software-Defined Networking)
│  └─ Control Plane(정책·경로 결정)과
│     Data Plane(패킷 전달)의 분리·소프트웨어 중심 제어
└─ NFV(Network Functions Virtualization)
   └─ Firewall / Router / Load Balancer 등의
      네트워크 기능을 범용 컴퓨팅 자원에서 SW로 실행
```

SDN은 **제어 방식**, NFV는 **기능 구현 방식**에 초점이 있다. 둘은 조합할 수 있지만 동일 개념은 아니다. → [가상화 전체 개념지도](../99-가상화/00-전체.md)

## 5. 제약 환경 — IoT가 추가로 고려할 것

**IoT(Internet of Things)** 및 Sensor Network에서는 기존 네트워크 원리 위에 **전력·CPU(Central Processing Unit)·메모리·불안정한 링크·대규모 단말 관리·보안** 제약이 강해진다.

**복습 기준:** HTTP/RTP/CDN은 서비스 요구, VPN은 사설 연결, SDN/NFV는 제어·구현, IoT는 제약 환경이라는 서로 다른 축을 설명한다. 헤더·터널·인터페이스·개별 IoT 규격은 필요할 때 세부학습으로 내려간다.
