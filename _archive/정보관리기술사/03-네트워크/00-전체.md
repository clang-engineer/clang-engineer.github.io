# 네트워크 전체 개념지도

네트워크는 **떨어진 시스템의 응용 프로그램 사이에 데이터를 전달**하기 위한 구조다. 비트를 전송하고, 링크와 네트워크를 연결하고, 목적지 프로세스까지 전달한다. 그 과정에서 **신뢰성·품질·보안·운영** 문제를 해결한다.

> **학습 기준:** 컴퓨터공학의 큰 구조·원리·관계를 먼저 인출한다. [성안당 Vol.3 학습등급표](../학습등급표/03-네트워크.md)는 범위 점검과 기술사 복습 깊이 조절에 사용하며, 교재 목차나 A/B/C 등급으로 지도의 뼈대를 결정하지 않는다.

## 1. 전체 조망

```text
네트워크 — 분산된 응용 프로그램 사이의 데이터 전달
│
├─ [통신 기반] 비트를 신호로 전송하고 자원을 공유
│   └─ 매체 · 변조/부호화 · 다중화 · 교환 방식
│
├─ [계층과 연결] 통신 역할 분리 · 같은 링크의 전달
│   └─ OSI/TCP-IP · 캡슐화 · Ethernet · Switch · VLAN
│
├─ [주소와 경로] 다른 네트워크까지 목적지 탐색
│   └─ MAC/ARP · IP/Subnet · Gateway · Routing
│
└─ [종단 통신과 응용] 목적지 프로세스와 서비스 통신
    └─ Port · TCP/UDP · Socket · DNS/HTTP · 실시간 미디어

[전달 전 과정의 횡단 문제]
├─ 신뢰성·품질·운영 → 오류/흐름/혼잡 제어 · QoS/QoE · NMS/SNMP
└─ 보안·환경·확장   → VPN · 무선/이동 · SDN/NFV · IoT
```

위 네 가지 중심 가지는 **통신 범위를 넓혀 이해하는 학습 흐름**이다. 무선·보안·가상화·IoT는 마지막 단계가 아니라 여러 계층에 걸치는 별도 문제 축이다.

## 2. 계층별 전달 역할

```text
Application ─ 서비스의 요청·응답 의미      HTTP 등
     ↓
Transport   ─ 종단 간 전달 특성·Port      TCP / UDP
     ↓
Network     ─ IP 목적지·다음 경로         IP / Routing
     ↓
Link        ─ 현재 링크의 Frame 전달      MAC / Ethernet / WLAN
     ↓
Physical    ─ 비트를 물리 신호로 전달     전기 / 광 / 무선
```

송신 측은 계층별 제어 정보를 붙여 **캡슐화**, 수신 측은 **역캡슐화**한다. 계층 모델은 역할과 인터페이스를 구분하는 좌표다.

## 3. 핵심 개념군과 비교 축

### 통신 기반 — 전송 자원의 이용

```text
교환 방식
├─ 회선 교환 — 통신 전 채널 자원 확보
├─ 메시지 교환 — 메시지 전체를 저장·전달 [보충]
└─ 패킷 교환 — 패킷 단위로 자원 공유
   ├─ 가상회선 — 논리적 전달 경로 사전 설정
   └─ 데이터그램 — 패킷별 독립 전달
```

**인출 기준:** 회선 교환은 자원 확보, 패킷 교환은 자원 공유. 가상회선의 **경로 설정**은 대역폭 **예약**과 같지 않다. 전통적 전화망과 IP 인터넷을 대표 사례로 연결한다. 변조·다중화·채널 용량은 물리 전송의 한계와 효율을 설명하는 별도 축이다.

### 연결·주소·경로 — 링크에서 네트워크로

```text
같은 L2 영역 → Switch / MAC / ARP / VLAN
                     ↓ 다른 Subnet이면 Gateway
다른 네트워크 → IP / Prefix / Routing / Forwarding
                     └─ 주소 운영 → DHCP / NAT / IPv6
```

**인출 기준:** VLAN은 L2 브로드캐스트 영역, Subnet은 L3 주소 범위. Routing은 경로 학습·선택, Forwarding은 패킷의 실제 전달이다.

→ [통신·주소·경로 개념지도](01-통신-주소-경로.md): L2/L3 경계와 주소·라우팅을 함께 복원한다.

### 종단 통신·응용 — 호스트에서 프로세스로

```text
IP 목적지 Host
    ↓
Port / TCP·UDP — 종단 간 전달 특성
    ↓
Socket API — 응용과 OS의 접점
    ↓
HTTP / RTP·RTCP — 서비스별 통신
CDN — 콘텐츠 배치·전달 최적화 [별도 축]
```

**인출 기준:** TCP의 종단 간 연결은 네트워크 내부의 가상회선 설정이 아니다. Socket은 응용과 네트워크 스택의 경계다.

→ [전송·품질·운영 개념지도](02-전송-품질-운영.md): TCP/UDP와 제어·품질의 관계를 복원한다.  
→ [서비스·가상화·제약환경 개념지도](04-서비스-가상화-제약환경.md): 서비스 전달과 확장 기술을 구분한다.  
→ [Socket·Server I/O 보충학습](_보충학습/Socket-서버-IO.md): OS·응용 구현 경계가 필요할 때만 내려간다.

### 신뢰성·품질·운영 — 전달 과정의 제어

```text
오류·손실 대응 → 오류 제어
수신자 처리 한계 → 흐름 제어
망의 수용 한계 → 혼잡 제어
서비스별 품질 요구 → QoS / QoE
장비 상태 관측·관리 → NMS / SNMP
```

**인출 기준:** 흐름 제어는 수신자, 혼잡 제어는 네트워크를 보호한다. QoS는 네트워크 품질 정책, QoE는 사용자 체감 품질이다.

→ [전송·품질·운영 개념지도](02-전송-품질-운영.md): 제어 방식·품질·관측의 비교 기준을 복원한다.

### 무선·이동 — 공유 매체와 이동성

```text
무선 채널 공유 → 간섭·매체 접근 → WLAN / CSMA/CA
전송 효율 향상 → MIMO 등
접속점 변경 → Roaming / Handover / 이동통신
```

WLAN과 이동통신은 같은 발전 단계가 아니라 무선 자원·보안·이동성 문제를 서로 다른 환경에서 다룬다.

→ [무선·이동 개념지도](03-무선-이동.md): 공유 매체, 무선 접속, 이동 중 연결 유지로 확대한다.

### 보안·제어·가상화·제약 환경 — 병렬 확장 축

```text
통신 보호·격리 → 인증·암호화 / VPN
제어·정책 자동화 → SDN (Control / Data Plane)
네트워크 기능 SW화 → NFV
제약 단말 연결 → Sensor Network / IoT
```

VPN은 논리적 사설 연결, SDN은 제어 구조, NFV는 네트워크 기능 구현을 다룬다. 서로 동의어이거나 하나의 순차 발전 과정이 아니다.

→ [서비스·가상화·제약환경 개념지도](04-서비스-가상화-제약환경.md): 서로 다른 확장 요구와 Trade-off를 구분한다.  
→ [보안 전체 개념지도](../04-보안/00-전체.md): 인증·암호화·통제의 일반 원리.  
→ [가상화 전체 개념지도](../99-가상화/00-전체.md): 논리망 구성과 SDN/NFV의 차이.

## 4. 빠른 복습 좌표

| 큰 질문 | 떠올릴 핵심 관계 |
|---|---|
| 통신 자원을 어떻게 이용하는가? | 회선 교환 ↔ 패킷 교환 / 가상회선 ↔ 데이터그램 |
| 역할을 왜 나누는가? | 계층화 · 인터페이스 · 캡슐화 |
| 같은 망과 다른 망은 어떻게 연결되는가? | MAC·VLAN ↔ IP·Subnet·Routing |
| 어느 프로그램까지 전달하는가? | Port · TCP/UDP · Socket |
| 통신을 어떻게 안정적으로 유지하는가? | 오류 ↔ 흐름 ↔ 혼잡 / QoS·QoE / NMS |
| 다른 환경으로 어떻게 확장되는가? | 무선·이동 / 보안·VPN / SDN·NFV / IoT |

**복습 경로:** 전체 지도로 위치·관계를 떠올린 뒤 [성안당 Vol.3 학습등급표](../학습등급표/03-네트워크.md)의 A급 중심으로 책순 회독한다. 막히는 개념만 해당 하위 지도와 세부학습으로 내려간다. **전체 지도는 거시적 인출, 하위 지도는 내부 관계·비교, 세부학습은 필요한 동작·예제**를 맡는다.
