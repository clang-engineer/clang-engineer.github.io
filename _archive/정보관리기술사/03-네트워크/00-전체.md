# 네트워크 전체 개념지도

네트워크는 **서로 떨어진 컴퓨터의 응용 프로그램이 데이터를 교환하도록 만드는 시스템**이다. 핵심은 특정 프로토콜의 목록이 아니라, **신호 전달 → 장치 연결 → 목적지 식별·경로 선택 → 종단 통신**을 가능하게 하고, 그 전 과정의 품질·보안·운영 문제를 해결하는 구조다.

> **지도 설계 원칙:** 컴퓨터공학의 문제·원리·관계를 먼저 세운다. [성안당 Vol.3 학습등급표](../학습등급표/03-네트워크.md)는 누락 점검과 복습 깊이 조절에 활용하지만, 책의 Part 구분이나 A/B/C 등급으로 지도의 뼈대를 결정하지 않는다.

## 1. 전체 조망 — 네트워크는 어떤 문제를 해결하는가?

```text
[목표] 떨어진 두 응용 프로그램 사이의 통신
  │
  ├─ ① 통신의 기반: 비트는 어떻게 신호가 되어 이동하는가?
  │      매체 · 부호화/변조 · 다중화 · 교환 방식
  │
  ├─ ② 연결과 계층: 여러 장치를 어떻게 연결하고 역할을 나누는가?
  │      OSI/TCP-IP · 캡슐화 · Ethernet/WLAN · Switch · VLAN
  │
  ├─ ③ 주소와 경로: 상대를 어떻게 식별하고 찾아가는가?
  │      MAC · IP · Subnet · Gateway · Routing
  │
  └─ ④ 종단 통신과 응용: 목적지 프로그램이 어떻게 주고받는가?
         Port · TCP/UDP · Socket · DNS/HTTP · 실시간 미디어

[전 과정에 걸치는 문제]
  ├─ ⑤ 신뢰성·성능·품질·운영
  │      오류/흐름/혼잡 제어 · QoS/QoE · NMS/SNMP
  └─ ⑥ 보안·다양한 환경·망의 진화
         인증/암호화/VPN · 무선/이동 · SDN/NFV · IoT
```

①~④는 **설명을 위한 전달 흐름**이고, ⑤~⑥은 특정 마지막 단계가 아니라 여러 계층과 환경에 걸친 **횡단 관점**이다. 무선, 보안, SDN, IoT도 하나의 기술 발전 순서가 아니다.

## 2. 데이터 하나가 전달되는 흐름

```text
Application: 무엇을 요청하고 응답하는가?     HTTP 등
       ↓
Transport: 어느 통신 종단에, 어떤 특성으로?  Port · TCP/UDP
       ↓
Network: 다른 망의 어느 목적지로?           IP · Routing
       ↓
Link: 지금 이 링크에서 누구에게?            MAC · Ethernet/WLAN
       ↓
Physical: 비트를 어떤 신호로 실어 보낼까?    전기 · 광 · 무선
```

송신 측은 계층별 정보를 덧붙여 캡슐화하고 수신 측은 역캡슐화한다. 실제 패킷은 링크를 지날 때마다 L2 전달 정보가 바뀔 수 있지만, 최종 목적지 IP는 일반적인 라우팅 중 유지된다(NAT 등 예외는 별도).

계층 모델은 **역할을 나누는 설명 도구**이지 모든 프로토콜이 정확히 한 계층에만 들어맞는다는 뜻은 아니다.

## 3. 큰 학습 가지

### ① 통신 기반과 계층 — 데이터를 전송 가능하게 만들기

```text
정보/비트 → 신호와 매체 → 전송 자원 공유(다중화)
                         → 교환 방식(회선/패킷)
                         → 계층별 역할·인터페이스
```

변조·부호화·Shannon 용량·다중화·오류 검출은 **전송이 가능한 이유와 한계**를 이해하는 좌표다. 수식과 개별 규격은 필요할 때 내려간다. 패킷 교환과 OSI/TCP-IP는 실제 전달 구조를 이해하는 연결 고리다.

### ② 연결·주소·경로 — 한 링크에서 여러 네트워크로

```text
Ethernet / Switch / VLAN
            ↓ 같은 링크의 전달
MAC · ARP ──┬── 같은 Subnet: 직접 전달
            └── 다른 Subnet: Gateway
                              ↓
                       IP · Routing
```

주소 체계, VLAN과 Subnet의 차이, IPv4/IPv6, NAT, 경로 학습과 실제 포워딩을 연결한다.

### ③ 종단 통신과 응용 — 호스트를 넘어 프로세스까지

```text
IP로 목적지 Host에 도착
        ↓
Port / TCP·UDP로 통신 종단 구분
        ↓
Socket API를 통한 Application 통신
        ↓
HTTP · RTP/RTCP · CDN 등 서비스별 요구
```

TCP/UDP는 전달 특성을, Socket은 OS와 응용의 인터페이스를, HTTP는 응용 메시지의 의미를 다룬다. CDN은 콘텐츠 배치·전달 최적화로, Transport 프로토콜과 같은 종류가 아니다.

### ④ 신뢰성·성능·품질·운영 — 통신을 지속 가능하게

```text
손실/오류 → 검출·재전송 등 오류 제어
수신자 한계 → 흐름 제어
네트워크 혼잡 → 혼잡 제어
서비스별 요구 → QoS / 사용자 체감 QoE
운영 상태 파악 → NMS / SNMP / 관측
```

오류 제어, 흐름 제어, 혼잡 제어는 **보호 대상이 서로 다르다**. TCP 송신자의 혼잡 대응과 네트워크 장비의 QoS 정책도 구분한다.

### ⑤ 무선과 이동성 — 공유 매체와 움직이는 단말

```text
무선 채널 공유 → 간섭·매체 접근 → WLAN
제한된 주파수 자원 → 다중화·MIMO 등 효율 개선
이동 중 접속점 변경 → Roaming / Handover / 이동통신
```

WLAN과 이동통신은 같은 계보의 단계가 아니라 공통 무선 문제를 서로 다른 규모·구조로 푸는 시스템이다.

→ [무선·이동 개념지도](03-무선-이동.md)

### ⑥ 보안·제어·가상화·제약 환경 — 기본 통신을 다른 요구에 맞추기

```text
신뢰할 수 없는 통신 경로 → 인증·암호화·격리 / VPN
장비별 제어의 복잡성     → SDN(제어 구조)
전용 네트워크 장비 의존  → NFV(기능의 SW 구현)
전력·자원 제약 단말     → Sensor Network / IoT
```

이들은 **병렬적인 문제 축**이다. VPN은 사설 연결을, SDN은 제어 구조를, NFV는 기능 구현을 다룬다. 네트워크 가상화와 SDN/NFV도 동의어가 아니다. 보안의 일반 원리는 [보안 영역](../04-보안/00-전체.md)과 교차한다.

→ [서비스·가상화·제약환경 개념지도](04-서비스-가상화-제약환경.md)

## 4. 복습 좌표 — 먼저 관계를 인출한다

| 질문 | 최소한 떠올릴 관계 |
|---|---|
| 데이터는 왜 계층으로 나누는가? | 역할 분리·인터페이스·캡슐화 |
| 같은 망과 다른 망의 전달 차이는? | MAC/ARP/Switch ↔ IP/Gateway/Routing |
| Host와 Process의 구분은? | IP ↔ Port/Transport/Socket |
| 통신 품질 문제는 어떻게 나뉘는가? | 오류 ↔ 흐름 ↔ 혼잡 ↔ QoS/QoE |
| 무선이 유선과 다른 이유는? | 공유 채널·간섭·이동성 |
| 네트워크를 운영·확장하는 방법은? | 관측(NMS)·정책(SDN)·기능(NFV)·보안 |

**학습 순서:** 이 지도로 전체 구조를 떠올린 뒤 [Vol.3 학습등급표](../학습등급표/03-네트워크.md)를 따라 성안당 책순으로 토픽을 훑는다. A/B/C는 **복습의 깊이**를 조절할 뿐 지도의 구성 원칙이 아니다. 이해가 막힌 지점만 하위 지도와 세부학습으로 내려간다.

## 백지 복습 사례 — 브라우저 요청 한 번

```text
이름 해석(DNS) → 목적지 IP 파악
→ 라우팅 판단·다음 홉 결정
→ 현재 링크의 MAC 전달
→ 목적지의 Transport 종단·Socket
→ Application의 요청 처리
```

이는 개념적 관계를 보여 주는 단순화된 예시다. 실제 요청에는 DNS 조회 생략(캐시), TCP 또는 QUIC 연결, TLS, 프록시/CDN 등의 변형이 있을 수 있다. TCP의 전송 신뢰성은 응용 수준의 중복 처리 방지를 대신하지 않는다.
