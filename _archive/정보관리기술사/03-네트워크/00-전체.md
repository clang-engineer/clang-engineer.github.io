# 네트워크 전체 개념지도

네트워크는 **서로 떨어진 시스템이 데이터를 주고받을 수 있게 연결하고, 그 과정에서 생기는 주소·경로·전송·혼잡·운영 문제를 해결하는 구조**로 본다.

## 빠른 복습 좌표

| 복습 축 | 핵심 관계·판단 단서 |
|---|---|
| Link | MAC·Switch·VLAN: 같은 L2 영역 안의 전달·분리 |
| Network | IP·Subnet·Routing: 서로 다른 네트워크 간 경로 선택 |
| Transport | Port·TCP/UDP: 프로세스 식별, 신뢰성·순서·연결 특성 구분 |
| 품질 | 오류 제어(손실 복구) ≠ 흐름 제어(수신자 보호) ≠ 혼잡 제어(망 보호) |
| 운영·확장 | SNMP/NMS는 관측, SDN/NFV는 제어·기능 구현의 분리·유연화 |

**복습 방법:** 이 표에서 핵심 관계가 기억나지 않는 축만 아래 조망도와 연결된 하위 학습으로 내려간다. 상세 예제는 세부학습 본문에 남긴다.

## 1. 가장 먼저 잡을 큰 그림

```text
네트워크 — 데이터를 다른 컴퓨터의 응용까지 전달
│
├─ [1. 통신 기반 · 계층]
│  └─ 신호 · 매체 · 변조 · 다중화 · OSI/TCP-IP
├─ [2. 주소 · 경로]
│  └─ MAC · Switch · VLAN · IP · Subnet · Routing
├─ [3. 종단 간 전달 · 응용]
│  └─ Port · TCP/UDP · Socket · Application
├─ [4. 전송 품질 · 제어]
│  └─ 오류 · 흐름 · 혼잡 제어 · QoS/QoE
└─ [5. 운영 · 확장 환경]
   └─ NMS/SNMP · 무선·이동 · VPN/SDN/NFV · IoT

통신 기반 → 주소·경로 → 종단 전달 : 전달 경로
품질·운영 : 전달 전 과정에 적용되는 횡단 관점
```

여기서 중요한 것은 이름보다 **문제의 위치**다.

```text
같은 망 안의 전달
→ 다른 망까지의 전달
→ 종단 Process까지의 전달
→ Application과 Network의 경계
→ 품질과 혼잡
→ 운영과 관측
```

이 흐름은 기술의 역사적 발전 순서가 아니라, 통신 범위를 넓혀가며 어떤 문제가 추가되는지 보는 학습 흐름이다.

## 2. 계층은 역할을 나누는 좌표다

```text
Application
    ↓
Transport
TCP / UDP
    ↓
Network
IP / Routing
    ↓
Link
Ethernet / WLAN
    ↓
Physical
물리 매체
```

계층 번호와 Header를 먼저 외우기보다 다음 역할을 구분한다.

```text
Link
= 같은 L2 영역 안에서 전달

Network
= 다른 Network까지 목적지를 찾아 전달

Transport
= 종단 Process 사이의 전달 특성 제공

Application
= Network 위에서 실제 Service 의미를 구성
```

OSI 7 Layer와 TCP/IP Model, Encapsulation의 상세는 필요한 하위 지도와 세부학습에서 확인한다.

## 3. 큰 학습 가지

### 통신 · 주소 · 경로

같은 망 안의 전달에서 시작해 다른 Network까지 목적지를 찾는 구조를 본다.

```text
MAC / Switch / VLAN
        ↓
IP / Subnet / Gateway
        ↓
Routing
```

→ [통신·주소·경로 개념지도](01-통신-주소-경로.md)

### 전송 · 품질 · 운영

목적지 Host에 도착한 뒤 Process까지 전달하고, 신뢰성·혼잡·품질·운영 문제를 본다.

```text
Port / TCP / UDP
        ↓
오류 · 흐름 · 혼잡 제어
        ↓
QoS / QoE
        ↓
NMS / SNMP
```

→ [전송·품질·운영 개념지도](02-전송-품질-운영.md)

### 무선 · 이동

공유 무선 매체를 사용할 때 생기는 접근·전송·이동성 문제를 본다.

```text
공유 무선 매체
  ↓
CSMA/CA
  ↓
WLAN
  ↓
Roaming / Handover
```

→ [무선·이동 개념지도](03-무선-이동.md)

### 응용 서비스 · 네트워크 제어 · 제약환경

기본 전달 위에 추가되는 **서로 다른 세 가지 문제**를 한 하위 지도에서 병렬로 확인한다. 응용 서비스, 네트워크 제어·기능 구현, 자원 제약은 한 단계의 발전 순서가 아니다.

```text
응용 서비스·전달 → HTTP / RTP·RTCP / CDN
논리적 사설 연결  → VPN
제어 구조         → SDN
기능 가상화       → NFV
제약 환경         → Sensor Network / IoT
```

→ [서비스·가상화·제약환경 개념지도](04-서비스-가상화-제약환경.md)

네트워크 가상화는 논리망 구성에 관한 개념이며 SDN·NFV와 동의어가 아니다. → [가상화 전체 개념지도](../99-가상화/00-전체.md)

### Network와 OS · Application의 경계

Socket과 Server I/O는 시험 대분류를 추가한 것이 아니라 Network가 실제 Application 실행과 만나는 경계를 이해하기 위한 횡단·보강 축이다.

```text
Application
  ↓
Socket API
  ↓
Kernel Network Stack
  ↓
TCP / UDP
```

→ [Socket·Server I/O 개념지도](_보충학습/Socket-서버-IO.md)

## 4. 보충학습으로 구현 계층까지 내려가기

본문은 정보관리기술사 Topic 자체의 원리와 관계를 이해하는 데 집중한다. OS · Runtime · Framework 수준의 구현 세부가 필요하면 `_보충학습/`으로 내려간다.

```text
Network 개념
  ↓
File Descriptor / Socket
  ↓
I/O Multiplexing
  ↓
Event Loop / Reactor
  ↓
Java NIO / Netty / WebFlux
```

보충학습은 별개의 지식 모음이 아니라 **본문 개념을 정확히 이해하기 위해 필요한 구현 계층으로 잠시 내려가는 Zoom-in 경로**다.

## 5. 통신 범위의 확장

```text
같은 망 전달 (MAC / Switch)
        ↓
다른 망 전달 (IP / Routing)
        ↓
종단 Process (Port / TCP·UDP)
        ↓
Application 경계 (Socket)
        ├─ 품질·혼잡 (QoS / Congestion)
        └─ 운영·관측 (NMS / SNMP)

[병렬 학습] 무선·이동 / 서비스·가상화 / 제약환경
```

위 화살표는 기술의 발전 순서가 아니라 **통신 범위를 넓혀 이해하는 학습 경로**다.
