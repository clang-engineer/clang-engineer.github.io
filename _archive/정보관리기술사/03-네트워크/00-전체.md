# 네트워크 전체 개념지도

네트워크는 **서로 떨어진 시스템이 데이터를 주고받을 수 있게 연결하고, 그 과정에서 생기는 주소·경로·전송·혼잡·운영 문제를 해결하는 구조**로 본다.

이 문서는 Protocol 이름을 외우기 위한 목차가 아니다. 먼저 **컴퓨터끼리 통신하려면 어떤 문제가 생기는지** 큰 그림을 잡고, 필요한 가지에서 더 자세히 내려간다.

## 1. 가장 먼저 잡을 큰 그림

```text
컴퓨터끼리 데이터를 주고받고 싶다
│
├─ 데이터를 어떤 역할로 나눠 전달하지?
│   └─ 계층 모델
│
├─ 같은 망 안에서는 누구에게 보내지?
│   └─ MAC · Switch · VLAN
│
├─ 다른 망까지는 어떻게 찾아가지?
│   └─ IP · Subnet · Gateway · Routing
│
├─ 도착한 데이터를 어느 프로그램에 넘기지?
│   └─ Port · TCP / UDP
│
├─ Application은 Network 기능을 실제로 어떻게 사용하지?
│   └─ Socket API
│
├─ 손실되거나 너무 많이 보내면 어떻게 하지?
│   └─ 오류 제어 · 흐름 제어 · 혼잡 제어
│
├─ 여러 Traffic이 몰리면 품질을 어떻게 관리하지?
│   └─ QoS / QoE
│
└─ 망이 정상인지 어떻게 계속 확인하지?
    └─ NMS / SNMP
```

여기서 중요한 것은 이름보다 **문제의 위치**다.

```text
같은 망 안의 전달
→ 다른 망까지의 전달
→ 종단 Process까지의 전달
→ Application과 Network의 경계
→ 품질과 혼잡
→ 운영과 관측
```

이 흐름은 기술의 역사적 발전 순서가 아니라, 통신 범위를 넓혀가며 어떤 문제가 추가되는지 보는 학습 흐름이다.

## 2. 계층은 역할을 나누는 좌표다

```text
Application
    ↓
Transport
TCP / UDP
    ↓
Network
IP / Routing
    ↓
Link
Ethernet / WLAN
    ↓
Physical
물리 매체
```

계층 번호와 Header를 먼저 외우기보다 다음 역할을 구분한다.

```text
Link
= 같은 L2 영역 안에서 전달

Network
= 다른 Network까지 목적지를 찾아 전달

Transport
= 종단 Process 사이의 전달 특성 제공

Application
= Network 위에서 실제 Service 의미를 구성
```

OSI 7 Layer와 TCP/IP Model, Encapsulation의 상세는 필요한 하위 지도와 세부학습에서 확인한다.

## 3. 큰 학습 가지

### 통신 · 주소 · 경로

같은 망 안의 전달에서 시작해 다른 Network까지 목적지를 찾는 구조를 본다.

```text
MAC / Switch / VLAN
        ↓
IP / Subnet / Gateway
        ↓
Routing
```

→ [통신·주소·경로 개념지도](01-통신-주소-경로.md)

### 전송 · 품질 · 운영

목적지 Host에 도착한 뒤 Process까지 전달하고, 신뢰성·혼잡·품질·운영 문제를 본다.

```text
Port / TCP / UDP
        ↓
오류 · 흐름 · 혼잡 제어
        ↓
QoS / QoE
        ↓
NMS / SNMP
```

→ [전송·품질·운영 개념지도](02-전송-품질-운영.md)

### 무선 · 이동

공유 무선 매체를 사용할 때 생기는 접근·전송·이동성 문제를 본다.

```text
공유 무선 매체
  ↓
CSMA/CA
  ↓
WLAN
  ↓
Roaming / Handover
```

→ [무선·이동 개념지도](03-무선-이동.md)

### 서비스 · 가상화 · 제약환경

기본 Network 위에서 Service 요구, 운영 자동화, 기능 가상화, 자원 제약이 추가될 때의 별도 문제 축을 본다.

```text
Service 전달      → HTTP / RTP · RTCP / CDN / VPN
운영 자동화       → SDN
Network 기능 SW화 → NFV
제약 환경         → Sensor Network / IoT
```

→ [서비스·가상화·제약환경 개념지도](04-서비스-가상화-제약환경.md)

### Network와 OS · Application의 경계

Socket과 Server I/O는 시험 대분류를 추가한 것이 아니라 Network가 실제 Application 실행과 만나는 경계를 이해하기 위한 횡단·보강 축이다.

```text
Application
  ↓
Socket API
  ↓
Kernel Network Stack
  ↓
TCP / UDP
```

→ [Socket·Server I/O 개념지도](_보충학습/Socket-서버-IO.md)

## 4. 권장 탐색 흐름

처음에는 **같은 망 → 다른 망 → 종단 전송**이라는 핵심 전달 축을 먼저 잡고, 이후 품질·운영·무선·서비스 같은 별도 질문으로 분기하는 것이 자연스럽다.

```text
01. 통신 · 주소 · 경로
같은 망의 전달
  ↓
주소와 Network 경계
  ↓
다른 Network까지의 Routing
        ↓
02. 전송 · 품질 · 운영
종단 Process 전달과 TCP / UDP
        ↓
        ├─ 품질 · 혼잡
        └─ 운영 · 관측

[별도 축]
03. 무선 · 이동
04. 서비스 · 가상화 · 제약환경
99. Network ↔ OS ↔ Application 경계
```

`01 → 02`는 핵심 전달 구조를 따라가기 위한 권장 흐름이다. `03`, `04`, `99`는 그 뒤의 발전 단계가 아니라 **환경·서비스·구현 경계가 달라질 때 선택하는 별도 Zoom 가지**다.

구체적인 VLAN, IP, Routing, TCP, QoS, NMS 등의 세부학습 파일은 이 전체 지도에서 다시 나열하지 않는다. 해당 `01~04` 하위 지도에서 관계를 확인한 뒤 필요한 세부학습으로 내려간다.

## 5. 보충학습으로 구현 계층까지 내려가기

본문은 정보관리기술사 Topic 자체의 원리와 관계를 이해하는 데 집중한다. OS · Runtime · Framework 수준의 구현 세부가 필요하면 `_보충학습/`으로 내려간다.

```text
Network 개념
  ↓
File Descriptor / Socket
  ↓
I/O Multiplexing
  ↓
Event Loop / Reactor
  ↓
Java NIO / Netty / WebFlux
```

보충학습은 별개의 지식 모음이 아니라 **본문 개념을 정확히 이해하기 위해 필요한 구현 계층으로 잠시 내려가는 Zoom-in 경로**다.

## 6. 탐색 방식

```text
학습등급표
"무엇을 얼마나 볼 것인가"
        ↓
네트워크 전체 개념지도
"어느 통신 문제를 볼 것인가"
        ↓
01 ~ 04 하위 개념지도
"선택한 가지의 관계와 경계를 어떻게 볼 것인가"
        ↓
세부학습
"왜 필요하고 어떻게 동작하는가"

필요할 때
→ 99 횡단·보강 지도
→ _보충학습 구현 계층
```

전체 지도에서 모든 Protocol·Algorithm·Header·Timer를 펼치지는 않는다. **대표 Protocol·Mechanism이 어디에 있고 어떤 문제를 해결하며 서로 어떻게 연결되는지 보고 기존 지식을 복원할 수 있으면 충분하다.**
