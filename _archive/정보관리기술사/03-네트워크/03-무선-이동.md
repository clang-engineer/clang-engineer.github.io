# 무선·이동 개념지도

**핵심 질문: 여러 단말이 무선 채널을 공유할 때 어떻게 접속·전송하고, 이동 중 연결을 이어가는가?**

## 0. 전체 구조

```text
무선 통신
│
├─ ① 공유 매체 접근 — 충돌을 어떻게 피하는가?
│  └─ CSMA/CA → Carrier Sense / IFS / Backoff / ACK
│     └─ Hidden Node → RTS/CTS
│
├─ ② 무선 접속 — Wi-Fi 연결은 어떤 단계를 거치는가?
│  └─ AP 탐색 → 인증 → Association → 보안 협상 → IP 설정
│
├─ ③ 무선 효율 — 한정된 주파수를 어떻게 활용하는가?
│  └─ MIMO 등 다중 안테나 기술
│
└─ ④ 이동성 — 접속 지점이 바뀌면 어떻게 유지하는가?
   └─ Roaming / Handover → AP 또는 Cell 변경
```

WLAN과 이동통신은 동일한 발전 단계가 아니라 **무선 자원·접속·이동성 문제를 공유하는 별도 환경**이다.

## 1. 공유 매체 접근 — 충돌을 어떻게 피하는가?

```text
CSMA(Carrier Sense Multiple Access) — 전송 전 매체 확인
├─ CD(Collision Detection) — 충돌 감지
│  └─ 과거 공유형 반이중 Ethernet
└─ CA(Collision Avoidance) — 충돌 회피
   └─ WLAN(Wireless Local Area Network)
      Carrier Sense → IFS → Random Backoff → 전송 → ACK
```

- **Carrier Sense:** 동시에 채널이 비어 있다고 판단하면 충돌할 수 있다.
- **CSMA/CD:** 송신 전 감지하고, 충돌 시 중단·임의 대기·재시도한다.
- **CSMA/CA:** 무선에서 송신 중 충돌 검출이 어려워 IFS·Random Backoff로 충돌 가능성을 줄인다. ACK가 없으면 재전송을 시도할 수 있다. 충돌을 완전히 방지하지는 않는다.

전이중 스위치 기반 유선 Ethernet에서는 충돌이 없어 CSMA/CD가 필요 없다.

- **IFS(Interframe Space):** 프레임 사이 대기 간격
- **ACK(Acknowledgment):** 수신 확인
- **RTS/CTS(Request to Send / Clear to Send):** 숨은 단말(Hidden Node) 상황에서 충돌 가능성을 줄이는 송신 요청·허가 절차. 제어 프레임 비용이 추가된다.

→ [무선 매체 접근과 WLAN](무선-매체접근과-WLAN.md)

## 2. 무선 접속 — Wi-Fi 연결은 어떤 단계를 거치는가?

```text
AP(Access Point) 탐색 — Beacon / Probe
  ↓
Authentication → Association → 보안 Key 협상
  ↓
DHCP(Dynamic Host Configuration Protocol) — IP·Gateway·DNS 설정
  ↓
ARP / Neighbor Discovery → 네트워크 통신
```

AP 발견 ≠ 인증 성공 ≠ 연결(Association) 성공 ≠ IP 설정 획득 ≠ 인터넷 통신 성공. **매체 접근·보안·IP 설정은 서로 다른 문제**다.

## 3. 무선 효율 — 한정된 주파수를 어떻게 활용하는가?

- **MIMO(Multiple-Input Multiple-Output):** 다중 송수신 안테나를 활용해 무선 전송 효율·용량을 높이는 기술 축.
## 4. 이동성 — 접속 지점이 바뀌면 어떻게 유지하는가?

- **Roaming / Handover:** 단말이 AP 또는 Cell을 바꿀 때 통신 연속성을 유지하는 문제. 새 신호를 찾는 것만으로 끝나지 않는다.
- **WLAN vs 이동통신:** 근거리 AP 중심 접속 vs 광역 Cell 기반 접속. 둘 다 간섭·보안·전송 효율·이동성을 다룬다.

**복습 기준:** CSMA/CD와 CSMA/CA의 차이 → Wi-Fi 접속 단계 → MIMO → 이동성 문제를 복원한다. 802.11 세대별 규격·타이머·보안 Handshake 상세는 세부학습으로 내려간다.
