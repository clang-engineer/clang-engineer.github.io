# 네트워크 전달 구조 개념지도

**핵심 질문: 데이터는 계층을 거쳐 현재 링크를 지나 다른 네트워크의 목적지 응용까지 어떻게 도달하는가?**

## 0. 한눈에 보는 구조

```text
네트워크 전달
│
├─ ① 계층화 — 역할 분리
│  └─ OSI / TCP-IP · 캡슐화 · SAP/SDU/PDU
│
├─ ② 링크 계층 — 현재 링크에서 전달
│  ├─ Ethernet / NIC / MAC / ARP / L2 Switch
│  ├─ 오류 검출 → CRC / FCS
│  ├─ 공유 매체 접근 → CSMA/CD · CSMA/CA
│  └─ 망 분리 → VLAN / Access·Trunk
│
├─ ③ 네트워크 계층 — 주소와 경로
│  ├─ 주소 관리 → Subnet / CIDR / VLSM / DHCP
│  │  └─ IPv4 부족 → 사설 IP / NAT·PAT / IPv6
│  └─ 경로 선택 → Routing / Forwarding
│     ├─ Unicast → Static / RIP / OSPF / BGP
│     └─ Multicast → Group / IGMP·MLD / PIM·RPF
│
└─ ④ 종단·응용 통신
   ├─ 전송 → TCP / UDP / Port · 연결 관리
   └─ 응용과 접점 → Socket / HTTP · 연결 재사용
```

ARP는 링크 전달을 위한 주소 해석, DHCP는 IP 설정, Socket은 응용과 OS의 통신 접점으로 관련 기능에 배치한다. 엄밀한 프로토콜 계층 분류와는 구분한다.

망 구성·설계는 [전체 지도](00-전체.md)의 별도 관점이며, 전송 제어는 [제어·품질·운영](02-전송-품질-운영.md)에서 다룬다.

## 1. 계층화 — 계층별 역할

```text
Application Data
  ↓ TCP(Transmission Control Protocol)/UDP(User Datagram Protocol) Header
Segment / Datagram (L4) — Port: 종단 통신
  ↓ IP Header
Packet (L3)            — IP: 목적지·경로
  ↓ Link Header/Trailer
Frame (L2)             — MAC: 현재 링크 전달
  ↓
Bit / Signal (L1)
```

OSI(Open Systems Interconnection)는 7계층 참조 모델, TCP/IP는 인터넷 프로토콜 체계다. IP(Internet Protocol)는 네트워크 계층의 주소 지정·전달을 담당한다. **상위 PDU가 하위 계층의 SDU**가 되고, 하위 계층이 제어 정보를 추가한다.

- **SAP(Service Access Point):** 상위 계층이 하위 계층 서비스를 이용하는 접점
- **SDU(Service Data Unit):** 하위 계층에 넘긴 데이터
- **PCI(Protocol Control Information):** 해당 계층이 추가한 제어 정보
- **PDU(Protocol Data Unit):** 계층이 다루는 데이터 단위(개념적으로 SDU + PCI)

예를 들어 TCP Segment는 IP 계층의 SDU가 되고 IP Header가 붙어 Packet이 된다. 수신 측에서는 역순으로 Header를 해석한다. **IP는 종단 목적지, MAC은 현재 링크의 전달 대상, Port는 호스트 내부의 통신 종단**을 구분한다.

**계층별 장비 — 무엇을 보고 전달하는가?**

- **L1 Hub/Repeater:** 신호
- **L2 Switch:** MAC 주소
- **L3 Router/L3 Switch:** IP 주소
- **L4 Load Balancer:** IP·Port 기반 분산
- **L7 Proxy/Load Balancer/WAF(Web Application Firewall):** URL·Host 등 응용 정보

L4·L7 Switch는 실무에서 Load Balancer/ADC(Application Delivery Controller)를 가리키기도 한다. 계층 이름보다 어떤 정보를 보고 결정하는지가 중요하다.

## 2. 링크 계층 — 현재 링크에서 전달

```text
목적지 IP와 Prefix 확인
├─ 직접 전달 가능 → 목적지 MAC 확인(ARP) → Frame 전송
└─ 다른 Subnet    → Gateway MAC 확인(ARP) → Router → 다음 망
```

- **ARP(Address Resolution Protocol):** IPv4 주소에 대응하는 MAC(Media Access Control) 주소를 확인한다. IPv6에서는 Neighbor Discovery를 사용한다.
- **직접 전달:** 같은 Subnet의 목적지 MAC을 확인한다. 실제 L2 도달 가능성이 전제된다.
- **간접 전달:** 다른 Subnet이면 Gateway의 MAC으로 Frame을 보내고, Router가 다음 홉을 선택해 새 Frame을 만든다.
- **L2 Switch:** 학습한 MAC·Port 정보로 같은 VLAN 안에서 Frame을 전달한다.

**핵심 관계:** 일반적인 라우팅에서는 목적지 IP가 유지되지만 링크마다 MAC은 바뀔 수 있다(NAT는 예외).

**Ethernet 프레임·매체 접근과 관련 오류 복구**

```text
Ethernet (IEEE 802.3)
├─ NIC(Network Interface Card) / Switch Port
├─ 오류 검출 → CRC(Cyclic Redundancy Check) 계산
│             └─ FCS(Frame Check Sequence) 필드에 검사값 저장
└─ 공유 매체 접근 → CSMA/CD(Carrier Sense Multiple Access with Collision Detection) — 충돌 감지, 과거 공유형 반이중 Ethernet

관련 기술 (Ethernet의 필수 기능·처리 순서가 아님)
├─ 무선 매체 접근 → CSMA/CA(Carrier Sense Multiple Access with Collision Avoidance) — 충돌 회피, WLAN
└─ 오류 복구
   ├─ ARQ(Automatic Repeat reQuest) — 재전송
   │  ├─ Stop-and-Wait
   │  ├─ Go-Back-N
   │  └─ Selective Repeat
   └─ FEC(Forward Error Correction) — 수신 측 정정
```

**오류 검출·복구**

- **CRC/FCS:** CRC로 오류 검사값을 계산하고 FCS 필드에 저장한다.
- **ARQ:** ACK와 재전송으로 복구한다. Stop-and-Wait·Go-Back-N·Selective Repeat는 미확인 데이터와 재전송 범위가 다르다.
- **FEC:** 중복 정보를 이용해 수신 측에서 오류를 정정한다.

일반적인 유선 Ethernet 스위치는 오류 Frame을 폐기하며 L2 ARQ를 수행하지 않는다. 오류 복구의 상세 원리는 [제어·품질·운영](02-전송-품질-운영.md)에서 다룬다.

**공유 매체 접근**

- **CSMA:** 송신 전 매체 사용 여부를 감지한다. 동시에 비어 있다고 판단하면 충돌할 수 있다.
- **CSMA/CD:** 송신 중 충돌을 감지하면 중단·대기·재시도한다. 전이중 스위치 링크에는 필요 없다.
- **CSMA/CA:** 무선에서는 송신 중 충돌 검출이 어려워 Backoff 등으로 충돌 가능성을 줄인다. 충돌을 완전히 제거하는 것은 아니다.

### VLAN과 Subnet — L2 경계와 L3 경계

```text
VLAN(Virtual Local Area Network) — L2 프레임 전달 영역 분리
├─ Access Port — 보통 한 VLAN
└─ Trunk Port  — 여러 VLAN을 802.1Q Tag로 구분

Subnet — IP Prefix 기준 L3 주소 범위
└─ 서로 다른 Subnet의 일반적인 IP 통신에는 Routing 필요
```

- **VLAN:** L2 Frame·Broadcast 전달 범위를 분리한다.
- **Subnet:** IP Prefix 기준 L3 주소 범위를 나눈다.
- **Access/Trunk:** Access는 보통 한 VLAN의 단말을 연결하고, Trunk는 여러 VLAN을 한 링크로 운반한다.

**핵심 관계:** VLAN과 Subnet은 자주 대응시키지만 동일하지 않다. Trunk는 VLAN 간 Routing을 수행하지 않으며, VLAN 간 통신에는 Router 또는 L3 Switch가 필요하다.

→ [VLAN·서브넷·브로드캐스트 도메인](VLAN-서브넷-브로드캐스트-도메인.md)

## 3. 네트워크 계층 — 주소와 경로

### 주소의 설계·설정·변환

```text
IP 주소 관리
├─ 범위 설계
│  ├─ Subnetting — 주소 범위 분할
│  ├─ CIDR — Classless Inter-Domain Routing
│  │         Class 고정 경계 없이 Prefix로 표현·할당·집약
│  └─ VLSM — Variable Length Subnet Mask
│            Subnet마다 필요한 크기로 분할
├─ 설정 → DHCP(Dynamic Host Configuration Protocol)
│         IP·Mask·Gateway·DNS 등 자동 제공
└─ IPv4(32bit) 주소 부족 대응
   ├─ 주소 재사용 → 사설 IP
   ├─ 주소 변환 → NAT(Network Address Translation)
   │             └─ PAT(Port Address Translation) / NAPT
   │                (Network Address and Port Translation)
   │                IP와 Port 변환으로 공인 IP 공유
   ├─ 효율적 할당 → CIDR
   └─ 주소 공간 확대 → IPv6(128bit)
      ├─ 전달 대상 → Unicast / Multicast / Anycast
      ├─ 사용 범위 → Global / Link-Local / Unique Local
      └─ IPv4 공존 → Dual Stack / Tunneling / Translation
```

**범위 설계**

- **CIDR:** 클래스에 묶이지 않는 Prefix 기반 주소 표현·할당·집약.
- **VLSM:** Subnet마다 필요한 크기로 주소 범위를 분할.

**주소 설정**

- **DHCP:** IP·Mask·Gateway·DNS 등을 자동 제공하고 주소를 임대(Lease)한다.
- **DORA:** Discover → Offer → Request → ACK(Acknowledgment).
- **Relay:** 다른 Subnet의 DHCP 서버로 요청을 전달한다.

**IPv4 주소 부족 대응**

- **사설 IP:** 내부망에서 주소를 재사용한다.
- **NAT/PAT:** NAT는 IP 주소, PAT는 Port까지 변환하여 여러 내부 연결이 공인 IP를 공유하도록 한다. 변환 정보로 응답을 올바른 내부 연결에 돌려준다.
- **IPv6:** 주소 공간을 128bit로 확대한다. IPv4와 패킷 형식이 달라 Dual Stack·Tunneling·Translation 등 공존 기술이 필요하다.

**IPv6의 두 분류축**

- 전달 대상: Unicast(하나), Multicast(그룹), Anycast(라우팅상 가까운 하나). Broadcast는 없다.
- 사용 범위: Global Unicast(인터넷 라우팅), Link-Local(같은 링크), Unique Local(내부망).

DHCP는 주소 설정, NAT/PAT는 패킷 주소·Port 변환이라는 차이를 기억한다.

→ [IP 주소·NAT·DHCP·CIDR·VLSM](IP-주소-NAT-DHCP-CIDR-VLSM.md): Prefix 분할·DHCP DORA·PAT 변환 테이블 등 예시.

### 경로 선택 — Routing과 Forwarding

```text
Control Plane — 경로 학습·선택(Routing)
├─ Static — 관리자 설정
└─ Dynamic — 경로 정보 교환
   ├─ AS 내부: RIP(Routing Information Protocol) — Distance Vector
   │           OSPF(Open Shortest Path First) — Link State
   └─ AS 간:   BGP(Border Gateway Protocol) — Path Vector / 정책
         ↓
Routing Table → 전달 정보
         ↓
Data Plane — Forwarding
목적지 IP → Longest Prefix Match → 다음 홉·출력 인터페이스
```

- **Control Plane / Routing:** 경로 정보를 학습하고 선택한다.
- **Data Plane / Forwarding:** 목적지 IP에 Longest Prefix Match를 적용해 다음 홉과 출력 인터페이스를 결정한다.

**동적 라우팅 프로토콜**

- **RIP:** 이웃의 거리·방향 정보를 이용하는 Distance Vector.
- **OSPF:** 링크 상태를 공유하고 최단 경로를 계산하는 Link State.
- **BGP:** AS(Autonomous System, 자율 시스템) 사이의 경로와 정책을 다루는 Path Vector.

RIP·OSPF는 주로 AS 내부, BGP는 AS 간 경로 교환에 사용한다. 단순한 발전 순서가 아니다.

#### 멀티캐스트 — 하나의 패킷을 여러 수신자에게 전달

```text
Multicast — 그룹 기반 전달
├─ 전달 대상 → Unicast(1:1) / Broadcast(영역 전체) / Multicast(그룹)
├─ 그룹 식별 → IPv4 224.0.0.0/4 / IPv6 ff00::/8
├─ 그룹 멤버십 → IGMP(IPv4) / MLD(IPv6)
└─ 그룹별 전달 경로 → PIM
   ├─ Dense Mode  → Flood 후 Prune(불필요한 방향 제외)
   ├─ Sparse Mode → Join한 방향만 전달
   └─ RPF → 송신자 쪽 정상 입력 경로인지 검사
```

**전달 원리:** Unicast는 수신자별 흐름을 만들지만 Multicast는 그룹 주소를 사용하고 공통 구간에서 한 번 전달한 뒤 분기점에서 복제한다.

- **IGMP(Internet Group Management Protocol) / MLD(Multicast Listener Discovery):** 인접 라우터가 IPv4/IPv6 그룹 수신자의 존재를 파악하도록 돕는다.
- **PIM(Protocol Independent Multicast):** 기존 경로 정보를 활용해 라우터 간 전달 트리를 구성한다. 그룹별 또는 송신자·그룹별 입력·출력 인터페이스를 관리한다.
  - **Dense Mode:** 넓게 전달한 뒤 불필요한 방향을 Prune한다.
  - **Sparse Mode:** 필요한 방향에서 Join하며 RP(Rendezvous Point)를 중심으로 공유 트리를 구성할 수도 있다.
- **RPF(Reverse Path Forwarding):** 송신자 방향의 예상 입력 인터페이스로 패킷이 들어왔는지 검사한다. 실제 회신하는 기능이 아니며 잘못된 방향의 패킷을 폐기해 루프·중복 전달을 방지한다.

**핵심 관계:** 그룹 관리(IGMP·MLD), 트리 구성(PIM), 입력 경로 검사(RPF)는 서로 다른 역할이다.

## 4. 종단·응용 통신 — Host에서 프로세스까지

```text
송신 Application
      │ Socket API(Application Programming Interface)
      ▼
TCP / UDP — Port로 통신 종단 구분
      │
      ▼
IP — 목적지 Host까지 전달
      │
      ▼
수신 Host → Port → 수신 Application
```

| 비교축 | TCP | UDP |
|---|---|---|
| 전달 형태 | 연결지향 바이트 스트림 | 비연결 데이터그램 |
| 순서·손실 복구 | 순서 보장, ACK·재전송 | 기본 제공하지 않음 |
| 흐름·혼잡 제어 | 기본 제공 | 기본 제공하지 않음 |
| 오류 검출 | Checksum | Checksum |
| 대표 선택 | 파일 전송 등 순서·신뢰성 중시 | 실시간 미디어 등 응용별 제어 중시 |

**종단 통신**

- **Port:** 호스트 안의 통신 종단을 구분한다.
- **Socket API:** 응용과 OS 네트워크 스택을 연결한다.
- **TCP:** 3-Way Handshake로 연결을 수립하고 FIN 기반으로 정상 종료한다.
- **UDP:** 비연결 데이터그램 방식이며 항상 더 빠른 것은 아니다. QUIC처럼 UDP 위에서 신뢰성·혼잡 제어를 구현할 수도 있다.

**HTTP와 연결 관리**

- **HTTP Keep-Alive:** 여러 요청에 연결을 재사용해 연결 비용을 줄인다.
- **TCP Keepalive:** 유휴 TCP 연결의 생존 여부를 확인한다.
- **Connection Pool:** 응용이 재사용할 연결을 관리한다.

HTTP(Hypertext Transfer Protocol)/1.1은 지속 연결이 기본이고, HTTP/2는 스트림 다중화, HTTP/3는 QUIC/UDP를 사용한다. QUIC은 현재 별도의 공식 약어 풀이 없이 쓰이는 프로토콜 이름이다.

→ [TCP 연결·종료·흐름·혼잡 제어](TCP-연결-종료-흐름-혼잡제어.md): 연결 상태·윈도우·혼잡 알고리즘 · [Socket·Server I/O](_보충학습/Socket-서버-IO.md): 응용과 OS의 접점

→ [제어·품질·운영](02-전송-품질-운영.md): 오류·흐름·혼잡 제어

**복습 기준:** MAC·IP·Port의 역할 → VLAN/Subnet 경계 → 주소 설계·변환 → Routing/Forwarding → TCP·UDP·Socket·HTTP의 관계를 설명한다. 세부 헤더·타이머·계산은 필요할 때만 내려간다.
