# 네트워크 전달 구조 개념지도

이 지도는 **계층별 역할 → 현재 링크에서 전달 → 다른 네트워크로 전달 → 경로 선택**의 관계를 복원한다. 망의 물리·논리적 연결 구조는 이 전달을 뒷받침하는 별도 설계 관점이다.

## 1. 전체 구조 — 데이터는 어떻게 목적지에 도달하는가?

```text
[통신 기능 분리] OSI / TCP-IP · 캡슐화 · PDU
         │
         ▼
[현재 링크 전달] MAC · ARP · Switch
         │
         ├─ 같은 Subnet → 직접 전달 (동일 L2 도달 가능 전제)
         └─ 다른 Subnet → Default Gateway로 전달
                               │
                               ▼
[네트워크 간 전달] IP · Prefix · Router
         ├─ 주소·범위 관리 → IPv4/IPv6 · Subnetting/CIDR · DHCP/NAT
         ├─ 망 분리의 경계 → VLAN(L2) ↔ Subnet(L3)
         └─ 경로 정보 → Routing(RIP/OSPF/BGP)
                               ↓
                         Forwarding(다음 홉)

[별도 설계 관점] 망 연결 형태(Star/Ring/Mesh) · 장비 역할(3-Tier/Spine-Leaf)
```

위의 화살표는 **이해를 위한 전달 관계**이며, 모든 장치가 반드시 같은 절차를 순서대로 수행한다는 뜻은 아니다. 아래에서는 헷갈리기 쉬운 구분을 중심으로 확대한다.

## 2. 계층화 — 역할과 데이터 단위

**연결 복습 범위:** Topic 04 OSI 7 Layer(A) · 05 TCP/IP Model(A) · 06 SAP·SDU·PDU(B) · 07 L3·L4·L7 Switch(B). 교재 번호는 누락 확인용이며 개념 관계의 분류 기준은 아니다.

계층화는 통신 기능을 분리해 **표준화·상호운용성·변경 용이성**을 높인다. 반면 계층별 헤더·처리에는 **Overhead**가 따른다. OSI는 기능을 구분하는 **참조 모델**이며, TCP/IP는 실제 인터넷의 프로토콜 체계에 기반한 모델이다.

```text
OSI 7계층                         TCP/IP 4계층
7 응용       — 서비스         ┐
6 표현       — 형식·변환      ├── 응용
5 세션       — 대화 관리      ┘
4 전송       — 종단 간 통신   ─── 전송
3 네트워크   — 주소·경로      ─── 인터넷
2 데이터링크 — 링크 전달     ┐
1 물리       — 비트·신호      ┴── 네트워크 액세스
```

```text
송신: 캡슐화 (위 → 아래)          수신: 역캡슐화 (아래 → 위)

7~5  Data
  ↓ 전송 Header
4    Segment(TCP) / Datagram(UDP)
  ↓ IP Header
3    Packet
  ↓ Link Header·Trailer
2    Frame
  ↓ 신호로 전송
1    Bit
```

```text
Protocol  — 대응 계층 간 통신 규칙 (수평)
Interface — 같은 장치의 인접 계층 간 이용 경계 (수직)
Service   — 하위 계층이 상위 계층에 제공하는 기능

SAP — 상위 계층이 하위 계층 서비스를 이용하는 접점
SDU — 상위 계층이 하위 계층에 넘긴 데이터
PCI — 해당 계층이 붙이는 제어 정보 (Header 등)
PDU — 해당 계층에서 취급하는 프로토콜 데이터 단위
      = SDU + PCI (개념적 표현)

Port (L4) — 호스트 내 통신 종단
IP   (L3) — 네트워크 간 목적지
MAC  (L2) — 현재 링크의 전달 대상
```

캡슐화에서는 **상위 계층 PDU가 하위 계층의 SDU로 취급**되고, 하위 계층이 PCI를 추가해 자신의 PDU를 만든다. 예를 들어 TCP Segment(L4 PDU)는 IP 계층에서 SDU가 되고 IP Header를 붙이면 IP Packet(L3 PDU)이 된다. 실제 PDU에는 계층에 따라 Trailer도 포함될 수 있다.

### 장비는 어느 계층 정보를 보고 전달하는가?

```text
신호 전달         L1 Repeater / Hub — 비트·신호
주소 기반 전달    L2 Switch — MAC / Frame
                  L3 Router·L3 Switch — IP / Packet
서비스 기반 분산  L4 Load Balancer — IP·Port
                  L7 Proxy·Load Balancer·WAF — HTTP 등 응용 정보
```

L3 Switch와 Router는 모두 IP 기반 전달이 가능하며, 장비별 실제 기능은 겹친다. L4·L7 '스위치'는 실무에서 주로 로드밸런서를 뜻한다. 계층 번호보다 **어떤 정보를 보고 어떤 전달·분산·보안 결정을 내리는지**를 구분한다.

**Port → IP → MAC**은 송신 측 캡슐화의 계층 순서이지 목적지를 순차 검색하는 과정이 아니다. IP 목적지는 일반적인 라우팅에서 유지되지만 NAT 등의 예외가 있고, 링크별 MAC 주소는 달라질 수 있다.

## 3. 링크 전달 — 같은 망과 다른 망

일반적인 IPv4 Ethernet 환경에서 송신 Host는 **목적지에 직접 전달할지, Gateway를 거칠지** 결정한다.

```text
목적지 IP + Prefix/Mask → 직접 전달할 대상인가?
  ├─ Yes → 목적지 IP의 MAC 확인(ARP) → Frame 전달
  └─ No  → Default Gateway의 MAC 확인(ARP)
                                  ↓
                               Router
                                  ↓
                           다른 Network로 전달
```

같은 Subnet이라도 **실제로 같은 L2 영역에서 도달 가능해야** 직접 전달할 수 있다. ARP는 IPv4 주소를 링크의 MAC 주소로 해석하는 대표 방식이다. IPv6는 ARP 대신 Neighbor Discovery를 사용한다.

### 링크의 매체 접근과 프레임 검사

**연결 복습 범위:** Topic 17 CRC(B) · 18 ARP·RARP(B) · 19 IEEE 802.3 Ethernet(B) · 21 CSMA/CD·CSMA/CA(B). Topic 20 CSMA(C)는 공통 원리로 연결한다.

```text
Ethernet — 링크의 Frame 형식·전달 규칙
├─ 송수신 Interface — NIC / Switch Port
├─ 주소·전달 — MAC / L2 Switch (IP→MAC 해석은 ARP)
├─ 오류 검출 — CRC 계산값을 Frame의 FCS 필드에 담음
└─ 매체 접근 — 공유 매체에서 누가 언제 송신할까?
   └─ CSMA — 송신 전 매체 사용 여부 감지
      ├─ CSMA/CD — 충돌 감지·중단·재시도 (공유형 반이중 Ethernet)
      └─ CSMA/CA — 충돌 가능성 회피 (WLAN)
```

**CRC는 계산 기법, FCS는 검사값을 담는 필드**다. 송신 인터페이스가 검사값을 붙이고 수신 인터페이스가 검사한다. 일반적인 Store-and-Forward 스위치는 오류 프레임을 폐기하고 정상 프레임을 MAC 주소에 따라 전달한다. Cut-Through는 검사가 끝나기 전에 전달을 시작할 수 있다. **일반적인 유선 Ethernet은 L2 ARQ 재전송을 수행하지 않는다.**

매체 공유 여부가 핵심이다. Hub는 여러 포트가 하나의 충돌 영역을 공유하지만, Switch의 **전이중 링크는 충돌이 없어 CSMA/CD가 불필요**하다. WLAN은 같은 무선 채널을 공유하며 송신 중 충돌 감지가 어려워 CSMA/CA를 사용한다. CSMA/CD도 **송신 전에 매체를 확인**하며, 확인 후에도 동시 송신으로 충돌할 수 있어 CD가 필요하다.

오류 검출(CRC), 오류 복구(ARQ·FEC), 매체 접근(CSMA)은 해결 문제가 다르다. ARQ·FEC가 반드시 Ethernet L2에서 실행되는 것은 아니다. → [전송·품질·운영 개념지도](02-전송-품질-운영.md)

## 4. 네트워크 분리 — VLAN과 Subnet

```text
L2 분리 — VLAN
├─ Port 기반 소속 지정 → VLAN ID별 Frame 전달 범위 구분
├─ Broadcast Domain 분리 → ARP 등 Broadcast 확산 제한
└─ 여러 Switch로 확장 → Access(보통 1 VLAN) / Trunk(여러 VLAN) · 802.1Q Tag

L3 분리 — Subnet
└─ IP Prefix 기준으로 주소 범위 구분
```

VLAN과 Subnet은 설계에서 흔히 함께 대응시키지만 **동일한 개념은 아니다**. VLAN 간 통신에는 L3 Routing이 필요하다.

→ [VLAN·서브넷·브로드캐스트 도메인](VLAN-서브넷-브로드캐스트-도메인.md): L2/L3 분리 경계와 실제 전달을 비교한다.

## 5. IP 주소 체계 — 범위·할당·변환

```text
IP 주소 체계
├─ 주소 공간 → IPv4 / IPv6
├─ 범위 표현·설계 → Prefix / Subnetting / VLSM / CIDR
├─ 설정 자동화 → DHCP
└─ 주소 변환 → NAT / PAT

IPv4 주소 부족 대응
├─ 주소 재사용 → 사설 주소 + NAT/PAT
├─ 주소 효율화 → CIDR 등
└─ 주소 공간 확대 → IPv6
```

- **Subnetting:** Network를 여러 Subnet으로 분할
- **VLSM:** Subnet마다 서로 다른 Prefix 길이 사용
- **CIDR:** Class에 묶이지 않고 Prefix로 주소 범위를 표현·할당·집약
- **DHCP:** Host의 주소·Mask·Gateway·DNS 등 설정 자동 제공
- **NAT/PAT:** 경계 장치에서 IP 주소 또는 주소·Port 대응 변환

→ [IP 주소·NAT·DHCP·CIDR·VLSM](IP-주소-NAT-DHCP-CIDR-VLSM.md): 주소 부족 대응과 주소 설계·운영의 차이를 복원한다.

## 6. 경로 선택과 실제 전달 — Routing vs Forwarding

```text
[경로 정보 생성·선택: Control Plane]
정적 경로 / Routing Protocol
          ↓
      Routing Table
          ↓ 경로 정보 반영
[패킷 전달: Data Plane]
목적지 IP → Longest Prefix Match
          ↓
다음 홉·출력 Interface 결정
          ↓
Packet Forwarding
```

**Routing**은 경로를 학습·선택하는 과정, **Forwarding**은 결정된 전달 정보를 이용해 패킷을 다음 홉으로 보내는 과정이다. Longest Prefix Match는 목적지 IP에 가장 구체적으로 일치하는 Prefix를 선택한다.

### 경로 정보를 어떻게 만드는가?

```text
[설정 방식]
├─ Static — 관리자가 경로 지정
└─ Dynamic — Routing Protocol로 경로 정보 교환

[적용 범위]
├─ AS 내부 (IGP)
│  ├─ RIP  — Distance Vector
│  └─ OSPF — Link State
└─ AS 간 (EGP)
   └─ BGP  — Path Vector / Policy
```

설정 방식·적용 범위·알고리즘은 **서로 다른 분류축**이다. RIP와 OSPF는 AS 내부 경로 선택을 서로 다른 원리로 수행하며, BGP는 AS 사이에서 정책을 반영해 경로를 교환한다. 세 프로토콜을 단순한 발전 순서로 외우지 않는다.

→ [라우팅 원리와 RIP·OSPF·BGP](라우팅-원리와-RIP-OSPF-BGP.md): 경로 계산·교환 원리와 선택 기준을 더 살펴본다.

## 7. 망 구성 — 전달 경로를 뒷받침하는 설계

**Topology**는 장치 간 연결 형태이고, **Network Architecture**는 장비 역할과 트래픽 경로를 포함한 설계다. 주소 체계나 Routing Protocol과 동일한 분류축이 아니다.

```text
[기본 연결 형태] Star / Ring / Mesh

[역할 중심의 계층적 구성: 3-Tier]
Core
 └─ Distribution
      └─ Access → Host

[서버 간 통신·확장 중심: Spine-Leaf]
Spine A ─┬─ Leaf A ─ Host
         └─ Leaf B ─ Host
Spine B ─┬─ Leaf A
         └─ Leaf B
```

3-Tier는 Core·Distribution·Access로 역할을 분리한다. Spine-Leaf는 각 Leaf가 모든 Spine과 연결되는 구조로, 서로 다른 Leaf 간 트래픽이 일반적으로 **Leaf → Spine → Leaf**를 거친다. 이는 완전 Mesh와 동일하지 않다.

---

**복습 기준:** 계층별 전달 역할 → MAC/IP/Port의 범위 → VLAN/Subnet의 경계 → 주소 설계·변환 → Routing/Forwarding의 차이를 스스로 설명할 수 있는지 확인한다. 세부 Header 필드, ARP 메시지 형식, Routing Algorithm의 계산 단계·Timer는 필요한 경우에만 세부학습으로 내려간다.
