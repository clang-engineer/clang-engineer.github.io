# 트랜잭션 · 동시성 · 회복 개념지도

> 여러 사용자가 동시에 데이터를 바꾸고 장애까지 발생할 수 있는 환경에서 **하나의 논리적 작업과 데이터의 정확성을 어떻게 지키는가**를 보는 지도다.

```text
논리적 작업 단위
      ↓
Transaction
└─ ACID
   ├─ Atomicity
   ├─ Consistency
   ├─ Isolation
   └─ Durability
      ↓
      ├─ 여러 Transaction이 동시에 실행됨
      │        ↓
      │     동시성 문제
      │        ↓
      │     동시성 제어
      │     ├─ Serializability
      │     ├─ Lock / 2PL
      │     ├─ Isolation Level
      │     ├─ MVCC
      │     └─ Deadlock
      │
      └─ 처리 도중 장애 발생
               ↓
             회복
             ├─ Log
             ├─ Undo / Redo
             └─ Checkpoint
```

## ACID와 실제 제어 Mechanism의 연결

ACID는 구현 기법의 목록이 아니라 **Transaction이 제공하려는 보장**이다. 실제 DBMS에서는 동시성 제어와 회복 Mechanism, 데이터 무결성 규칙이 함께 유효한 상태를 유지한다.

```text
                    Transaction
                         │
       ┌─────────────────┼─────────────────┐
       ▼                 ▼                 ▼
  동시 실행 문제       장애 문제          무결성 규칙
       │                 │                 │
       ▼                 ▼                 │
   동시성 제어            회복               │
 Lock / MVCC       Log / Undo / Redo       │
       │                 │                 │
       ▼                 ▼                 │
   Isolation      Atomicity / Durability   │
       │                 │                 │
       └─────────────────┼─────────────────┘
                         ▼
                 유효한 상태 유지
                    Consistency
```

여기서 `Consistency`를 특정 하나의 Mechanism이 직접 구현한다고 보지 않는다. **Transaction 전후에 정의된 무결성 규칙을 만족하는 상태가 유지되는 성질**이며, 동시성 제어와 회복은 이를 깨뜨릴 수 있는 간섭과 장애를 통제한다.

```text
Isolation
= 동시에 실행되는 Transaction의 간섭 통제

Atomicity
= 중간까지만 반영된 Transaction을 남기지 않음

Durability
= Commit된 결과가 장애 뒤에도 유지되도록 함

Consistency
= Transaction 전후에 정의된 무결성 규칙을 만족하는 상태 유지
```
## 핵심 경계

```text
Transaction
= 보장하려는 논리적 작업 단위

동시성 제어
= 여러 Transaction 사이의 간섭을 통제

회복
= 장애로 불완전해진 상태를 정상 상태로 복원

Backup
= 별도 보존본을 이용한 데이터 복원
```

동시성 제어와 회복은 모두 Transaction의 신뢰성을 지키지만 해결하는 문제가 다르다.
