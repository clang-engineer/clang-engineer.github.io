# 데이터베이스 개념지도

> 데이터베이스는 **업무 데이터를 공통 구조로 관리하고, 정확성·동시성·장애·성능·확장 문제를 해결하면서 안전하게 활용하는 체계**다.

이 문서는 데이터베이스 영역의 큰 학습 가지와 연결점을 잡는 전체 지도다. 내부 관계를 더 촘촘히 볼 필요가 있는 부분만 하위 개념지도로 내려간다.

## 1. 데이터베이스 전체 좌표

```text
현실의 업무
  ↓
데이터 모델링
  ↓
Schema · Key · 무결성
  ↓
정규화 / 반정규화
  ↓
관계형 모델 · SQL
  ↓
  ├────────────────┬────────────────┐
  ▼                ▼                ▼
신뢰성             성능             확장
Transaction        Optimizer        Replication
동시성 · 회복      Index            Sharding
                   Partition        분산 DB

[별도 활용 축]
OLTP ↔ DW / OLAP / BI

[전 영역 관리 축]
보안 · 품질 · 표준 · Metadata · Governance
```

처음에는 **업무를 데이터 구조로 옮기는 기반**을 잡고, 그 위에서 `신뢰성 · 성능 · 확장`이라는 서로 다른 시스템 문제를 본다. 세 가지는 발전 단계가 아니라 같은 데이터 시스템을 보는 서로 다른 문제 축이다.

`분석 활용`은 운영 DB의 다음 단계가 아니라 목적이 다른 활용 축이고, `보안 · 품질 · 표준 · Metadata · Governance`는 구조화부터 활용까지 전체를 가로지른다.

## 2. 어디를 파고들 것인가

### 데이터 구조화 · 관계형 모델

```text
현실의 업무
   ↓
데이터 모델링
   ↓
논리 구조
├─ Entity / Relation
├─ Attribute
├─ Key
└─ 관계 · 무결성
   ↓
Schema
   │
   ├─ 함수 종속 · 중복 · 갱신 이상
   │        ↓
   │      정규화
   │        → 중복과 이상 현상 감소
   │
   └─ 성능 · 운영 요구
            ↓
         반정규화

관계형 DB
→ Relation을 SQL로 정의 · 조회 · 변경
```

핵심은 현실의 업무 의미를 관계형 구조로 옮기고, `Key · 무결성 · 정규화`로 데이터의 일관성과 변경 비용을 통제하는 것이다. 반정규화는 정규화의 반대 이론이라기보다 성능·운영 요구에 따라 구조를 의도적으로 조정하는 선택으로 본다.


### Transaction · 동시성 · 회복

```text
Transaction
│
├─ 동시 실행 문제
│   └─ 동시성 제어
│       ├─ Isolation Level
│       ├─ Lock / 2PL
│       └─ MVCC
│
└─ 장애 문제
    └─ Recovery
        ├─ Log 기반 회복
        │   ├─ 미완료 변경 → Undo → Atomicity
        │   ├─ 완료 변경   → Redo → Durability
        │   └─ Checkpoint  → 복구 범위 축소
        │
        ├─ Shadow Paging
        │   ├─ Shadow Page Table
        │   ├─ Current Page Table
        │   └─ Commit 시 Page Table 전환
        │
        └─ Backup / Restore
            └─ Media 장애 대응
```

동시성은 `어떤 병행 실행을 허용하고 어떻게 제어할 것인가`, 회복은 `장애 뒤에 Transaction의 원자성과 지속성을 어떻게 복원할 것인가`라는 서로 다른 신뢰성 문제다.

동시 실행과 격리의 내부 원리는 이해가 더 필요한 부분이므로 세부학습으로 내려간다.

→ [Transaction · 동시성 · 격리수준 · Lock · MVCC](트랜잭션-동시성-격리수준-Lock-MVCC.md)

회복은 현재 이 지도에서 대표 방법과 관계까지 복원하는 수준으로 학습한다. `Log 기반 회복`은 변경 이력을 기록한 뒤 Undo / Redo로 복구하고, `Shadow Paging`은 기존 Page를 유지한 채 변경 Page를 별도로 작성한 뒤 Commit 시 Page Table을 전환하는 방식으로 구분한다. 더 깊게 들어가면 `LSN`, WAL 세부 규칙, `Steal / No-Steal`, `Force / No-Force`, `ARIES` 같은 영역이 이어지지만 현재 기술사 학습범위에서는 위치만 인지하고 상세 학습하지 않는다.

### Index · 질의최적화

```text
SQL
 ↓
Query Processing
├─ Parsing
├─ Rewrite
├─ Optimization
│   ├─ Rule Based / Cost Based
│   ├─ Statistics
│   │   ├─ Selectivity
│   │   └─ Cardinality
│   ├─ Access Path
│   │   ├─ Table Scan
│   │   └─ Index
│   ├─ Join Order
│   └─ Join Algorithm
│       ├─ Nested Loop
│       ├─ Sort Merge
│       └─ Hash Join
└─ Execution
      ↓
Execution Plan
      ↓
Estimated ↔ Actual
      ↓
Tuning
```

질의최적화는 SQL을 바로 실행하는 것이 아니라 `Parsing → Rewrite → Optimization → Execution` 흐름으로 본다. Optimizer는 규칙 또는 Cost를 기준으로 후보 실행전략을 비교하며, 통계·Selectivity·Cardinality는 Cost 추정의 근거가 된다.

```text
Index
├─ B-Tree / B+Tree
├─ Clustered / Nonclustered
├─ Hash Index
└─ Bitmap Index

Partition
└─ Partition Pruning
```

Index는 **Optimizer가 선택할 수 있는 Access Path를 제공하는 구조**이고, Partition은 큰 Table을 분할하여 조건에 맞는 영역만 접근하도록 해 탐색 범위를 줄인다.

- [질의최적화 · JOIN 실행전략](질의최적화와-JOIN-실행전략.md)
- [탐색 Tree · DB Index](탐색트리와-DB인덱스-BTree-BPlusTree-BStarTree-TTree.md)

### 분산 · 확장

```text
단일 DB의 용량 · 처리량 · 가용성 한계
              │
       ┌──────┴──────┐
       ▼             ▼
같은 Data 복제     Data 분할
       ↓             ↓
Replication       Sharding
       ↓             ↓
가용성 · 읽기      용량 · 처리량
확장               확장
       └──────┬──────┘
              ↓
      여러 Node에 Data 존재
              ↓
          분산 문제
      ├─ Consistency
      ├─ Availability
      ├─ Network Partition
      │    └─ CAP / PACELC
      ├─ 분산 Transaction
      └─ Consensus
```

`Replication`은 같은 데이터를 여러 곳에 두는 방법, `Sharding`은 데이터 자체를 나누는 방법이다. 둘은 함께 사용할 수 있으며, 분산되면서 얻는 확장성과 함께 일관성·장애·조정 문제가 커진다.

- [분산 DB · CAP · PACELC · NoSQL](분산-데이터베이스-CAP-PACELC-NoSQL.md)
- [Sharding · 분산 Transaction · 합의](샤딩-분산트랜잭션-합의.md)


### 분석 활용 · 전 영역 관리

운영과 분석은 같은 Data를 사용하더라도 목적과 Workload가 다르다.

```text
[운영]
OLTP
├─ 현재 업무 상태 처리
├─ 빈번한 Insert / Update
└─ 짧은 Transaction

[분석]
Operational Data
      ↓
   ETL / ELT
      ↓
      DW
주제 중심 · 통합 · 시계열 Data
      ↓
     OLAP
다차원 · 집계 분석
      ↓
      BI
의사결정 지원
```

Data를 저장하고 활용하는 전 과정에는 별도의 관리 관점이 가로지른다.

```text
Data 관리
├─ 품질       → 정확성 · 완전성 · 일관성
├─ Metadata   → Data의 의미 · 구조 · 위치
├─ 표준       → 공통 명칭 · 형식 · 정의
├─ 보안       → 접근 통제 · 보호
└─ Governance → 정책 · 책임 · 통제
```

이 축들은 특정 한 단계의 후속 작업이 아니라 모델링·저장·운영·분석 전반에 적용된다.


## 3. 탐색 원칙

```text
학습등급표
"무엇을 얼마나 볼 것인가"
        ↓
데이터베이스 전체 개념지도
"지금 어떤 문제 축을 보는가"
        ↓
필요한 세부학습
"원리·기법·Trade-off는 무엇인가"
```

현재 데이터베이스 영역은 별도의 하위 개념지도를 두지 않는다. `00-전체`에서 위치와 관계를 잡은 뒤 필요한 세부학습으로 바로 내려간다.
