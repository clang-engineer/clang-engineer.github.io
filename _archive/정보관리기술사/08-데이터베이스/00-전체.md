# 데이터베이스 개념지도

> 데이터베이스는 **업무 데이터를 공통 구조로 관리하고, 정확성·동시성·장애·성능·확장 문제를 해결하면서 안전하게 활용하는 체계**다.

이 문서는 데이터베이스 영역의 큰 학습 가지와 연결점을 잡는 전체 지도다. Transaction 내부의 동시성·회복, Index·질의최적화, 분산·확장처럼 관계를 더 촘촘히 볼 필요가 있는 부분은 하위 개념지도로 내려간다.

## 1. 데이터베이스 전체 좌표

```text
데이터베이스
│
├─ 데이터 구조화
│   ├─ 데이터 모델링
│   ├─ Schema / Key / 무결성
│   └─ 정규화 / 반정규화
│
├─ 관계형 데이터 활용
│   ├─ 관계형 모델
│   ├─ SQL
│   └─ View
│
├─ Transaction 신뢰성
│   ├─ ACID
│   ├─ 동시성 제어
│   └─ 회복
│
├─ 성능
│   ├─ 질의 최적화
│   ├─ Index
│   └─ Partition / Tuning
│
├─ 분산·확장
│   ├─ Replication
│   ├─ Sharding
│   └─ 분산 DB
│
├─ 분석 활용
│   └─ DW / OLAP / BI
│
└─ 전 영역 관리
    └─ 보안 / 품질 / 표준 / Metadata / Governance
```

## 2. 어디를 파고들 것인가

### 데이터 구조화와 관계형 모델

업무의 의미를 데이터 구조로 옮기고, 중복·무결성·변경 비용을 조절하는 축이다.

```text
현실의 업무
  ↓
데이터 모델링
  ↓
Schema / Key / 무결성
  ↓
정규화 ↔ 반정규화
  ↓
관계형 모델 / SQL
```

이 영역은 큰 위치와 경계가 잡히면 필요한 Topic을 세부학습으로 바로 내려간다.

### Transaction · 동시성 · 회복

여러 사용자의 동시 변경과 장애 속에서도 데이터의 일관성을 지키는 축이다.

```text
Transaction
├─ 동시 실행 문제 → 동시성 제어
└─ 장애 문제     → 회복
```

→ [[01-트랜잭션-동시성-회복|Transaction·동시성·회복 개념지도]]

### Index · 질의최적화

데이터가 커졌을 때 원하는 결과를 더 적은 비용으로 찾는 구조와 실행 계획을 본다.

```text
Query
  ↓
Optimizer
  ↓
Access Path
├─ Index
├─ Partition
└─ Scan / Join 등 실행 선택
```

→ [[02-인덱스-질의최적화|Index·질의최적화 개념지도]]

### 분산 · 확장

단일 DB의 용량·처리량·가용성 한계를 넘으면서 새로 생기는 일관성·장애·운영 문제를 본다.

```text
단일 DB 한계
  ↓
Replication / Sharding
  ↓
분산 DB
  ↓
일관성 · 가용성 · 운영 복잡성 Trade-off
```

→ [[03-분산-확장|분산·확장 개념지도]]

### 분석 활용과 전 영역 관리

운영 Transaction 처리와 분석 활용은 목적이 다른 별도 축이고, 보안·품질·표준·Metadata·Governance는 저장부터 활용까지 전체를 가로지른다.

```text
운영 활용 → OLTP
분석 활용 → DW / OLAP / BI

[전체]
보안 · 품질 · 표준 · Metadata · Governance
```

## 3. 기억할 큰 경계

```text
구조
모델링 / Schema / 정규화

정확성
Transaction / 동시성 / 회복

성능
Optimizer / Index / Partition

확장
Replication / Sharding / 분산 DB

활용·관리
OLTP / 분석 / Governance
```

`동시성 제어 ↔ 회복`, `Optimizer ↔ Index`, `Replication ↔ Sharding`, `OLTP ↔ OLAP`처럼 내부 비교가 필요한 내용은 하위 지도나 세부학습에서 더 펼친다.

## 4. 권장 탐색 흐름

처음에는 **업무 데이터를 어떻게 구조화하는지**를 기반으로 잡고, 그 위에서 DBMS가 해결해야 하는 `신뢰성 · 성능 · 확장` 문제를 서로 다른 가지로 보는 것이 자연스럽다.

```text
[기반]
현실의 업무
  ↓
모델링 · Schema · Key · 무결성
  ↓
정규화 / 반정규화
  ↓
관계형 모델 · SQL
  ↓
  ├────────────────┬────────────────┐
  ▼                ▼                ▼
신뢰성             성능             확장
Transaction        Optimizer        Replication
동시성 · 회복      Index            Sharding
                   Partition        분산 DB
```

세 가지는 `Transaction → Index → 분산 DB`처럼 발전하는 단계가 아니다. **같은 데이터 시스템에서 정확성, 처리 비용, 규모·가용성이라는 서로 다른 문제를 보는 축**이다.

```text
정확성과 장애 대응을 더 보고 싶다
→ [[01-트랜잭션-동시성-회복|Transaction · 동시성 · 회복]]

Query 실행과 성능을 더 보고 싶다
→ [[02-인덱스-질의최적화|Index · 질의최적화]]

단일 DB의 한계를 넘어서는 구조를 더 보고 싶다
→ [[03-분산-확장|분산 · 확장]]
```

`분석 활용`은 운영 DB의 다음 발전 단계가 아니라 목적이 다른 활용 축이고, `보안 · 품질 · 표준 · Metadata · Governance`는 데이터의 구조화부터 활용까지 전체를 가로지르는 관리 축으로 본다.

```text
[별도 활용 축]
OLTP ↔ DW / OLAP / BI

[전 영역 관리 축]
보안 · 품질 · 표준 · Metadata · Governance
```

`데이터 구조화·관계형 모델`, `분석 활용`, `전 영역 관리`는 현재 별도의 하위 개념지도를 만들지 않는다. 전체 지도에서 위치를 잡은 뒤 필요한 세부학습으로 바로 내려간다.

```text
학습등급표
"무엇을 얼마나 볼 것인가"
        ↓
데이터베이스 전체 개념지도
"데이터 시스템에서 지금 어떤 문제를 보는가"
        ↓
필요한 하위 개념지도
"신뢰성 · 성능 · 확장의 내부 관계를 더 촘촘히"
        ↓
세부학습
"구체적인 원리·기법·Trade-off는 무엇인가"

하위 지도가 필요하지 않은 가지
00-전체 → 세부학습으로 직접
```

전체 지도에서는 대표 Node와 학습 경로까지만 남기고, Lock·격리수준·MVCC, B-Tree 계열, CAP 같은 **한 가지 내부의 세부 관계와 대표 기법은 하위 지도 또는 세부학습으로 내린다.**
