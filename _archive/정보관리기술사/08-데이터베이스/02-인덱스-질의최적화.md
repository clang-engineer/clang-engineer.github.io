# 인덱스 · 질의최적화 개념지도

> 데이터가 많아졌을 때 **DBMS가 어떤 실행 방법을 선택하고, Index가 그 선택에 어떤 접근 경로를 제공하는가**를 보는 지도다.

## 전체 흐름

```text
SQL
 ↓
Query Optimizer
 │
 ├─ 통계
 │    ↓
 │  Selectivity / Cardinality 추정
 │
 └─ 실행 후보 생성
      ├─ Access Path
      │   ├─ Table Scan
      │   └─ Index Scan / Seek
      ├─ Join Order
      └─ Join Algorithm
            ↓
        Cost 비교
            ↓
      Execution Plan
            ↓
         실제 실행
            ↓
   Estimated ↔ Actual 비교
            ↓
          Tuning
      ├─ Index
      ├─ Partition
      ├─ SQL / Schema
      └─ 통계 · DB 설정
            ↓
          재측정
```

핵심 관계는 다음처럼 잡는다.

```text
통계 / Cardinality
= 후보 실행 방법의 Cost를 추정할 근거

Index
= Optimizer가 선택할 수 있는 Access Path 제공

Execution Plan
= Optimizer가 선택한 물리 실행 전략

Tuning
= 실제 실행 결과를 보고 접근 경로와 추정 정확도를 개선
```

## Index를 볼 때 분류축을 섞지 않는다

```text
[탐색 구조]
B-Tree 계열
└─ B+Tree

[데이터 배치·Locator 관계]
Clustered Index
↔ Nonclustered Index
```

`B+Tree`와 `Clustered Index`는 같은 축의 대안이 아니다. 전자는 탐색 자료구조이고 후자는 Index Entry와 실제 데이터의 배치·Locator 관계를 설명한다.
