# 분산 · 확장 개념지도

> 단일 DB의 용량·처리량·가용성 한계를 넘을 때 **데이터를 복제하거나 나누면서 새로 생기는 일관성·장애·운영 문제**를 보는 지도다.

## 문제에서 분산 구조로

```text
단일 DB
  ↓
용량 · 처리량 · 가용성 한계
  ↓
어떤 문제를 풀려는가?
  │
  ├─ 같은 Data를 여러 곳에 둔다
  │        ↓
  │   Replication
  │        ↓
  │   가용성 · 읽기 확장
  │        ↓
  │   복제본 일관성 · 장애 처리 문제
  │
  └─ Data 자체를 나눈다
           ↓
       Sharding
           ↓
       저장 용량 · 처리 부하 분산
           ↓
       분산 Query · Transaction 문제

Replication + Sharding
→ 함께 사용할 수도 있음
        ↓
여러 Node를 하나의 데이터 시스템으로 운영
        ↓
분산 DB
        ↓
Network Partition · Node Failure
        ↓
일관성 · 가용성 · 운영 복잡성 Trade-off
```

`Replication`과 `Sharding`은 둘 다 분산에 사용되지만 해결하려는 중심 문제가 다르다.

```text
Replication
= 같은 데이터를 복제
→ 가용성 · 읽기 확장

Sharding
= 데이터를 분할
→ 저장 용량 · 처리량 확장
```

## 분산에서 새로 커지는 문제

```text
분산
├─ 확장성 ↑
├─ 가용성 ↑ 가능
└─ 운영 복잡성 ↑
      ↓
Network Partition과 장애를 고려해야 함
      ↓
Consistency · Availability 관계
      ↓
CAP
```

CAP은 `Replication`이나 `Sharding`의 종류를 분류하는 개념이 아니라, **분산 환경에서 Network Partition이 발생할 수 있을 때 일관성과 가용성 사이의 선택을 이해하는 관계**로 본다.
