# IT 경영 전체 개념지도

> IT 경영은 **사업 목표를 IT 투자·구축·운영·성과로 연결하고, 그 과정의 책임·위험·비용·품질을 통제하는 체계**다.

이 지도는 **전략 → 과제 선택 → 실행 → 운영 → 성과 확인**이라는 대표 경영 흐름과, 전 과정을 가로지르는 관리 관점을 구분한다. EA·ISP·BPR 등은 필요에 따라 병행·반복되며, 아래 화살표가 모든 조직의 필수 수행 순서를 뜻하지는 않는다. 교재는 학습 보완에 활용한다.

## 1. IT 경영 전체 좌표

```text
IT 경영 — 사업 목표를 IT 투자·실행·성과로 연결
│
├─ [1. 전략 · 계획]
│  └─ 사업·IT 전략 정렬(Alignment) · Capability · EA · ISP
│              ↓ 우선순위·가치 판단
├─ [2. 투자 · 포트폴리오]
│  └─ ROI · TCO · Business Case · PPM
│              ↓ 과제 실행
├─ [3. 변화 실행 · 시스템 구축]
│  ├─ 실행 관리·조달: PM · RFP/SOW
│  ├─ 업무 혁신: BPR/PI/BPM
│  ├─ 업무 시스템: ERP/SCM/CRM
│  └─ 시스템 연계: EAI/API
│              ↓ 서비스 전환
├─ [4. 서비스 운영]
│  └─ ITSM/ITIL · SLA/SLM · Outsourcing(선택)
│              ↓ 성과 확인
└─ [5. 성과 · 개선]
   └─ KPI/BSC · 성과 분석 · 지속 개선
                └─ 전략·투자 재검토

[전 과정] IT Governance · Risk/BCP/DR · Compliance · 품질 관리 · Data Governance · 감리/감사
```

중심은 기술 도입 자체가 아니라 **왜 투자하고, 무엇을 우선하며, 누가 책임지고, 어떤 성과를 확인할 것인가**다. 성과 확인은 마지막에 보고서를 내고 끝내는 단계가 아니라, **결과를 전략과 다음 투자·자원 배분 판단으로 되돌리는 Feedback**이다.

## 2. 어디를 파고들 것인가

### 전략 · EA · ISP

사업 목표와 IT 투자·역량을 정렬하는 것이 출발점이다. EA와 ISP는 이를 구조와 실행계획으로 구체화하는 수단이다.

```text
사업 전략 ↔ IT 전략 정렬(Alignment)
  ↓ 구조·과제 구체화
EA
├─ As-Is
├─ To-Be
└─ Architecture Principle
  ↓
ISP
├─ 정보화 과제
├─ 우선순위
└─ 실행 Roadmap
```

EA는 전사 구조와 원칙을 정리하고, ISP는 사업 목표를 정보화 과제와 실행계획으로 구체화한다. PPM은 여러 투자 과제의 조합과 자원 배분을 관리한다. **EA → ISP는 가능한 연계 예시이지 항상 고정된 선후 단계는 아니다.**

### 투자 · Portfolio

```text
후보 과제
  ↓
비용 · 기대효과 · Risk
  ↓
ROI / TCO / Business Case
  ↓
PPM
  ↓
예산 · 인력 · 우선순위 배분
```

모든 과제를 수행할 수 없으므로 개별 투자타당성과 Portfolio 수준의 우선순위를 구분한다. ROI는 투자 수익성, TCO는 도입부터 운영까지의 총비용을 보는 관점이다. 수익성이 높아도 전략 적합성·위험·의존관계에 따라 우선순위는 달라진다.

### 변화 실행 · 업무 개선 · 구축 · 연계

```text
프로젝트 수행·조달
├─ PM
└─ RFP / SOW

업무 자체 개선
├─ BPR
├─ PI
└─ BPM

정보 System 구축
├─ ERP
├─ SCM
└─ CRM

System 간 연결
├─ EAI
└─ API / Platform
```

PM은 개별 프로젝트 수행 관리, RFP·SOW는 조달·범위 정의에 쓰인다. BPR·PI·BPM은 업무 프로세스 혁신·관리의 관점이고, ERP·SCM·CRM은 서로 다른 업무 영역을 지원하는 시스템 유형이다. **BPR과 시스템 도입은 필수 선후관계가 아니다.** EAI는 애플리케이션 통합 접근, API는 연계에 활용할 수 있는 인터페이스다. **단계적 구축은 반드시 시스템 분리를 뜻하지 않으며**, 분리 구축 시에는 연계 비용과 장기 TCO도 함께 판단한다.

### 조달 · Outsourcing · Service Management

```text
필요한 외부 수행 범위 정의
      ↓
RFP / SOW
      ↓
계약 · Outsourcing
      ↓
SLA
      ↓
SLM / ITSM
      ↓
지속 개선
```

위 흐름은 외부 위탁 시 가능한 예시이지 필수 절차가 아니다. 아웃소싱은 수행 주체에 관한 선택이고 ITSM은 서비스 관리 활동이다. SLA는 합의된 서비스 수준, SLM은 그 수준을 관리하는 활동이다. 외부 위탁해도 서비스에 대한 기업의 관리 책임은 남는다.

### 업무연속성 · DR

```text
중단 Risk
├─ Risk Assessment
└─ BIA
    ↓
복구 우선순위
├─ RTO
└─ RPO
    ↓
BCP / DR / HA / Backup
    ↓
훈련 · Test · 개선
```

대표 비교·분류 축:
- Risk Assessment ↔ BIA
- RTO ↔ RPO
- BCP ↔ DR
- HA ↔ Backup / Recovery

### Governance · 성과 · 독립 검증

```text
의사결정과 책임
→ IT Governance

법 · 규정 · 계약 준수
→ Compliance

성과 측정
→ KPI / BSC

독립적 적정성 확인
→ 감리 / 감사

Data 책임
→ Data Governance
```

거버넌스·위험·준법·품질 관리와 감리·감사는 성과 측정 이후의 필수 순서가 아니라 전략·투자·구축·운영에 걸쳐 적용·수행될 수 있는 관점이다. IT Governance는 의사결정 권한과 책임·감독, IT Management는 계획·실행·운영에 초점을 둔다. KPI는 목표 달성 지표, BSC는 전략을 여러 관점의 목표·지표로 연결하는 체계다. **지표 미달은 원인 분석의 출발점이지 IT 시스템 결함의 증거는 아니다.**
