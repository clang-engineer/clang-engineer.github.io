# IT 경영 전체 개념지도

> IT 경영은 **사업 목표를 IT 투자·구축·운영·성과로 연결하고, 그 과정의 책임·위험·비용·품질을 통제하는 체계**다.

이 지도는 **전략 → 투자 → 실행 → 운영 → 성과**의 대표 흐름과 횡단 관리 관점을 구분한다. 화살표는 모든 개념의 필수 선후관계를 뜻하지 않는다.

## 1. IT 경영 전체 좌표

```text
IT 경영 — 사업 목표를 IT 투자·실행·성과로 연결
│
├─ [1. 전략 · 계획]
│  └─ 사업·IT 전략 정렬(Alignment) · Capability · EA · ISP
│              ↓ 우선순위·가치 판단
├─ [2. 투자 · 포트폴리오]
│  └─ ROI · TCO · Business Case · PPM
│              ↓ 과제 실행
├─ [3. 변화 실행 · 시스템 구축]
│  ├─ 실행 관리·조달: PM · RFP/SOW
│  ├─ 업무 혁신: BPR/PI/BPM
│  ├─ 업무 시스템: ERP/SCM/CRM
│  └─ 시스템 연계: EAI/API
│              ↓ 서비스 전환
├─ [4. 서비스 운영]
│  └─ ITSM/ITIL · SLA/SLM · Outsourcing(선택)
│              ↓ 성과 확인
└─ [5. 성과 · 개선]
   └─ KPI/BSC · 성과 분석 · 지속 개선
                └─ 전략·투자 재검토

[전 과정] IT Governance · Risk/BCP/DR · Compliance · 품질 관리 · Data Governance · 감리/감사
```

**성과는 전략·투자 판단으로 환류(Feedback)**한다.

처음 학습하거나 흐름이 기억나지 않을 때는 [IT 경영 스토리 학습](99-IT경영-스토리학습.md) — 가상 기업의 문제를 따라 전략부터 횡단 관리까지 이해한다.

## 2. 어디를 파고들 것인가

### 전략 · EA · ISP

**핵심 질문:** 사업 목표를 IT 구조와 실행 과제로 어떻게 바꿀까?

```text
사업 전략 ↔ IT 전략 정렬(Alignment)
  ↓ 구조·과제 구체화
EA — 전사 업무·IT의 구조와 관계
├─ 아키텍처 관점: BA · DA · AA · TA
├─ As-Is / To-Be · Architecture Principle
├─ 프레임워크: EA를 수립·관리하는 체계 (예: TOGAF)
└─ 참조모델: 공통 분류·비교·표준화 기준
   └─ BRM(업무) · DRM(데이터) · SRM(서비스) · TRM(기술) · PRM(성과)
  ↓
ISP
├─ 정보화 과제
├─ 우선순위
└─ 실행 Roadmap
```

**EA = 구조·원칙 / ISP = 과제·로드맵.** 병행·반복 가능. **EA 프레임워크**는 수립·관리의 체계, **참조모델**은 업무·데이터·서비스·기술·성과를 공통 기준으로 분류·비교하는 도구다. 참조모델은 기업의 실제 EA 자체가 아니며, 위 다섯 모델은 대표적인 참조모델 체계의 예시다.

### 투자 · Portfolio

**핵심 질문:** 모든 과제를 할 수 없다면 어떤 기준으로 투자할까?

```text
후보 과제
  ↓
비용 · 기대효과 · Risk
  ↓
ROI / TCO / Business Case
  ↓
PPM
  ↓
예산 · 인력 · 우선순위 배분
```

**ROI = 수익성 / TCO = 총비용 / PPM = 과제 간 우선순위·자원 배분.**

### 변화 실행 · 업무 개선 · 구축 · 연계

**핵심 질문:** 결정한 IT 투자를 어떻게 실행하고, 업무 혁신·시스템 구축·연계를 구분할까?


```text
프로젝트 수행·조달
├─ PM
└─ RFP / SOW

업무 자체 개선
├─ BPR
├─ PI
└─ BPM

정보 System 구축
├─ ERP
├─ SCM
└─ CRM

System 간 연결
├─ EAI
└─ API / Platform
```

**PM = 수행 관리 / BPR·PI·BPM = 업무 혁신·관리 / ERP·SCM·CRM = 업무 시스템 / EAI = 통합 접근 / API = 인터페이스.** 서로 필수 선후관계가 아니다. 단계적 구축은 시스템 분리와 다르며, 초기 투자·장기 TCO·위험을 함께 고려한다.

→ [업무 혁신·시스템 구축: 관계와 선택 기준](01-업무혁신·시스템구축.md) — 업무 방식, 시스템, 연계가 왜 다른 관점인지 복원

### 조달 · Outsourcing · Service Management

**핵심 질문:** 구축한 IT를 누가, 어떤 서비스 수준으로 지속 제공할까?

```text
필요한 외부 수행 범위 정의
      ↓
RFP / SOW
      ↓
계약 · Outsourcing
      ↓
SLA
      ↓
SLM / ITSM
      ↓
지속 개선
```

**Outsourcing = 수행 주체 선택 / SLA = 합의 기준 / SLM = 수준 관리 / ITSM = 서비스 관리.** 위 흐름은 외부 위탁의 예시일 뿐 필수 순서가 아니다.

### 업무연속성 · DR

**핵심 질문:** 업무가 중단되면 무엇을 언제까지 복구해야 할까?

```text
중단 Risk
├─ Risk Assessment
└─ BIA
    ↓
복구 우선순위
├─ RTO
└─ RPO
    ↓
BCP / DR / HA / Backup
    ↓
훈련 · Test · 개선
```

**인출 축:** Risk Assessment/BIA · RTO/RPO · BCP/DR · HA/Backup.

→ [업무연속성·재해복구: 중단 영향에서 복구 전략까지](02-업무연속성·재해복구.md) — 목표·수단·검증의 차이를 복원

### Governance · 성과 · 독립 검증

**핵심 질문:** 누가 책임지고, 성과와 준수 여부를 어떻게 확인할까?

```text
의사결정과 책임
→ IT Governance

법 · 규정 · 계약 준수
→ Compliance

성과 측정
→ KPI / BSC

독립적 적정성 확인
→ 감리 / 감사

Data 책임
→ Data Governance
```

**Governance = 권한·책임·감독 / KPI = 핵심 지표 / BSC = 전략·성과 연결.** 횡단 관리·검증은 5단계 이후의 순차 단계가 아니다.
