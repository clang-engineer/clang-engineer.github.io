# 업무연속성·재해복구 개념지도

> **중단되면 무엇이 중요한가 → 얼마나 빨리·어디까지 복구할 것인가 → 어떤 대비책을 선택하고 검증할 것인가**를 연결하는 지도다.

[IT 경영 전체 지도](00-전체.md)의 전 과정 위험 관리 중 업무연속성과 복구 영역을 확대한다. 실제 분석·계획 활동은 병행·반복될 수 있다.

## 1. 전체 좌표

```text
업무 중단 가능성
│
├─ 무엇이 위험한가?
│   ├─ Risk Assessment: 위협·취약점·영향·가능성
│   └─ BIA: 업무 중단이 사업에 미치는 영향·우선순위
│
├─ 어느 수준으로 복구해야 하는가?
│   ├─ RTO: 허용 가능한 복구 소요시간 목표
│   └─ RPO: 허용 가능한 데이터 손실 시점 목표
│
├─ 무엇으로 대비하는가?
│   ├─ BCP: 핵심 업무 지속·재개를 위한 전체 계획
│   └─ DR: IT 시스템·데이터 복구 대책
│       ├─ FT: 구성요소 결함에도 기능 지속(결함허용)
│       ├─ HA: 서비스 중단 최소화·가용성 확보
│       └─ Backup / Recovery: 데이터 보존·복원
│
└─ 실제로 작동하는가?
    └─ 훈련 · 복구 시험 · 결과 분석 · 계획 개선
```

## 2. 중요한 경계

### 위험 평가 ↔ 업무 영향 분석

- **Risk Assessment**는 어떤 위험이 얼마나 심각한지 판단한다.
- **BIA(Business Impact Analysis)**는 업무가 중단되면 사업에 어떤 영향이 생기는지, 어떤 업무부터 복구해야 하는지 판단한다.

### RTO ↔ RPO

```text
장애 발생 ─────────── 서비스 복구
         ← RTO: 복구 시간 목표 →

마지막 복구 가능 데이터 시점 ─── 장애 발생
                  ← RPO: 데이터 손실 허용 목표 →
```

RTO와 RPO는 실제 복구 결과가 아니라 **계획 수립 시 설정하는 목표**다. 업무 중요도와 비용 제약에 따라 다르게 정한다.

### BCP ↔ DR / FT ↔ HA ↔ Backup

- **BCP**는 인력·업무·대체 절차까지 포함하는 업무연속성 계획이다.
- **DR**은 그중 IT 복구에 초점을 둔다.
- **FT(Fault Tolerance)**는 구성요소 결함이 발생해도 기능을 지속할 수 있도록 설계하는 특성이다.
- **HA(High Availability)**는 서비스 중단을 최소화해 높은 가용성을 확보하는 목표·설계 관점이다. 장애 감지와 Failover 등으로 구현할 수 있으며 전환 중 짧은 중단이 발생할 수도 있다.
- **FT는 HA를 달성하는 수단이 될 수 있지만 동일한 개념은 아니다.** 단순 이중화만으로 무중단 FT가 보장되지 않는다.
- **Backup**은 데이터 보존·복원 수단이다. FT·HA·DR·Backup은 서로 완전히 대체하지 못한다.

## 3. 복구 전략의 판단

```text
업무 중요도·중단 영향(BIA)
         +
복구 목표(RTO / RPO)
         +
비용·기술 제약
         ↓
복구 전략 선택(FT·HA·DR·Backup 등) → 훈련·검증 → 보완
```

복구 목표를 짧게 잡을수록 일반적으로 더 높은 수준의 대비와 비용이 요구된다. 특정 기술을 도입했다고 목표 달성이 자동으로 보장되지는 않는다.

## 4. 복습 인출 질문

- 위험 평가와 BIA는 무엇을 다르게 묻는가?
- RTO와 RPO는 각각 시간과 데이터 손실 중 무엇을 다루는가?
- BCP와 DR의 범위는 어떻게 다른가?
- FT와 HA는 무엇을 각각 목표로 하며 어떻게 연결되는가?
- HA만 있으면 백업이 필요 없는가?
- 복구 전략이 실제로 작동하는지는 어떻게 확인하는가?
