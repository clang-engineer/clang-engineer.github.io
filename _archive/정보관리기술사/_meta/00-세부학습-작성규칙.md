# 정보관리기술사 세부학습 작성 규칙

## 0. 작성 전 확인

세부학습 문서를 작성하거나 수정하기 전에 다음을 확인한다.

1. [정보관리기술사 문서작성 공통 원칙](00-문서작성-공통원칙.md)
2. [저장소 공통 지식 구성 원칙](../../../docs/KNOWLEDGE_ORGANIZATION.md)
3. [저장소 공통 문체·표기 원칙](../../../docs/WRITING_STYLE.md)
4. 이 문서

세부학습의 목적은 **시험 직전 암기용 요약본이 아니라, 학습 과정에서 이해한 내용을 나중에 다시 읽었을 때 그 이해가 복원되는 문서**를 만드는 것이다.

공통적인 묶음·Story·비교·문서 유형 원칙은 상위 문서를 따르고 여기서는 기술사 세부학습에만 필요한 깊이·인출·보충학습 규칙을 추가한다.

## 1. 상위 학습 자료와 역할을 나눈다

자료별 역할, Node와 File의 관계, 세부학습 생성·보강 판단은 [기술사 공통 원칙](00-문서작성-공통원칙.md)을 따른다. 내용 이동·통합·분리 시 설명 보존 기준은 [지식 구성 원칙](../../../docs/KNOWLEDGE_ORGANIZATION.md)을 따른다.

## 2. 기술사에 필요한 깊이까지만 내려간다

기본 범위:

```text
정의
→ 왜 필요한가
→ 핵심 구조·동작
→ 주요 구성요소
→ 대표 비교·경계
→ 장단점·Trade-off
→ 적용·운영 고려사항
```

새 세부 내용을 넣기 전에 묻는다.

```text
이 내용을 빼면 핵심 개념을 잘못 이해하는가?
기술사 답안을 구성하는 데 실질적으로 필요한가?
```

둘 다 아니라면 기본 범위에서는 상세 학습하지 않는다.

지도만으로 충분한지, 정한 범위 안에서 더 깊이 볼 필요가 있는지는 기술사 공통 원칙에 따라 판단한다.

예를 들어 대표 Mechanism까지는 현재 범위지만 그 내부 구현이 지나치게 지엽적이라면 다음처럼 경계만 남길 수 있다.

```text
Recovery
├─ Log / Undo / Redo / Checkpoint  → 현재 학습범위
└─ 더 깊게 들어가면
   LSN · WAL 세부 규칙 · Steal/No-Steal · ARIES
   → 위치만 인지, 현재는 상세 학습하지 않음
```

구현체 내부 구조, 제품 옵션, 버전별 차이, 논문 수준 수식, 지나친 최적화 세부는 핵심 이해에 필요할 때만 포함한다. 문서가 길다는 이유만으로 이해에 필요한 설명을 삭제하지는 않는다.

## 3. 이해가 됐던 설명과 인출 장치를 보존한다

대화나 학습 중 특정 설명·비유·예제로 이해가 됐다면 그 부분을 우선 보존한다.

기술사 시험에서 즉시 비교·열거·서술해야 하는 핵심은 **기억·인출 장치**를 함께 둔다.

- 인과관계와 단계 흐름
- 핵심 질문
- 비교·대칭
- 용어의 의미·어원
- 작은 예제
- Text/ASCII Diagram
- 필요한 경우에만 연상법

외우기 쉬운 표현보다 **왜 그런지 다시 도출할 수 있는 방식**을 우선한다.

## 4. `_보충학습/`은 이해의 빈틈을 메울 때만 사용한다

직접 출제 Topic은 아니지만 모르면 핵심 관계·동작을 잘못 이해하는 기반·실무 개념은 해당 영역의 `_보충학습/`에 둘 수 있다.

```text
본 학습에서 이해의 빈틈 발견
        ↓
직접 출제 Topic은 아니지만 이해에 필요
        ↓
_보충학습에서 필요한 만큼만 Zoom-in
        ↓
본 학습으로 복귀
```

- 범위 밖 지식 모음으로 사용하지 않는다.
- 흥미만으로 계속 확장하지 않는다.
- 별도 `기반학습/`, `보조학습/` 최상위 분류를 만들지 않는다.
- 디렉터리 자체가 성격을 나타내므로 파일명에 별도 `99-` Prefix를 붙이지 않는다.
- 큰 그림을 방해하는 구현 동작·호출 순서·예외 경계는 여기로 내릴 수 있다.

## 5. 가지 주제는 중앙 TODO로 보낸다

현재 이해에 당장 필요하지 않지만 **나중에 실제로 학습할 가치가 있다고 판단한 주제**는 현재 문서를 확장하지 않고 `_meta/00-학습-TODO.md`에 등록한다.

단순히 범위 밖 전문 개념의 이름과 위치를 기록한 것은 TODO가 아니다.

```text
범위 밖 연결
= 이런 전문 영역이 이어진다는 위치 정보
= 현재 학습 계획 없음

TODO
= 나중에 실제로 학습할 의도가 있는 주제
```

TODO에는 최소한 다음을 남긴다.

```text
무엇을 볼 것인가
왜 이 주제가 나왔는가
어느 주제와 연결되는가
```

현재 개념을 정확히 이해하는 데 반드시 필요한 내용은 TODO로 미루지 않는다.

## 6. 문서는 이해를 복원할 수 있어야 한다

다시 읽었을 때 다음 질문에 답할 수 있어야 한다.

```text
이 개념은 전체에서 어디에 있는가?
왜 필요한가?
무엇을 해결하는가?
어떻게 동작하는가?
무엇과 헷갈리기 쉬운가?
실제 시스템에서는 어디에 위치하는가?
```

권장 기본 흐름은 다음이지만 같은 Template을 강제하지 않는다.

```text
큰 그림 / 현재 위치
        ↓
왜 필요한가
        ↓
핵심 구조·동작
        ↓
비교·경계
        ↓
적용·Trade-off
        ↓
기억 흐름
```

실제 인과가 있으면 `왜 → 어떻게 → 그래서`를 살리고, 인과가 없으면 비교·계층·경계·조합 관계를 사용한다.

### 세부학습 재구성 사례 — 가상화 방식

[가상화 구조와 VM·컨테이너](../99-가상화/가상화-구조와-VM-컨테이너.md)는 설명의 중심을 **서버·컴퓨팅 가상화 방식**으로 정한 뒤, 학습 중 실제로 이해가 이어졌던 순서로 재구성한 사례다.

```text
가상화의 목적·전체 분류
  ↓
VM 기반 가상화
  ├─ Hypervisor 역할
  ├─ Type 1 / Type 2 (실행 위치)
  └─ 전가상화 / 반가상화 (Guest OS 상호작용)
  ↓
컨테이너 기반 가상화
  └─ Host Kernel 공유 · Namespace · cgroup
  ↓
VM과 컨테이너의 구조·Trade-off·적용 비교
  ↓
핵심 질문으로 이해 복원
```

이 사례의 핵심은 다섯 단계 자체가 아니라 **목적에 맞는 내용 선별, 선행 개념부터 설명, Section별 역할 분리, 중복 제거, 이해에 결정적인 인과관계 보존**이다. 예를 들어 반가상화는 단순히 'Guest OS 수정'으로 끝내지 않고 **왜 Hypervisor와 협력해야 하는지**까지 연결한다.

이는 **고정 Template이 아니다.** 다른 주제에서는 실제 분류축·처리 흐름·비교 관계에 맞게 설명 순서를 바꾼다. 인출 질문은 본문을 다시 요약하기보다 스스로 핵심 관계를 설명하는 데 사용한다.

### 공통 구조 원칙을 적용하는 예

상위 구조로 복귀·보정하는 기준과 처리 과정·비교축의 설계, 기존 문서 보강·분리 판단은 [지식 구성 원칙](../../../docs/KNOWLEDGE_ORGANIZATION.md)을 따른다. 한 문서 안에서 반복적으로 멀리 왕복해야 한다면 설명 순서·구조와 분리 필요성을 함께 점검한다.

다음은 서로 다른 분류축을 발전 순서로 만들지 않고 구분하는 사례다.

```text
Fine-tuning
├─ 학습 신호 관점 → SFT
└─ Parameter 효율 관점
    ├─ Full Fine-tuning
    └─ PEFT → LoRA
```

학습 중 실제로 생긴 질문과 헷갈린 지점은 FAQ로 쌓기보다 자연스러운 Section과 설명 흐름에 녹인다.

### 세부학습 상단의 주제 개념지도

세부학습 문서는 **해당 주제를 이해하기 위한 거시적 설명 구조**를 최상단의 기본 구성으로 둔다. 이 상단 지도는 문서가 **무엇을, 어떤 관점에서, 어떤 논리적 흐름으로, 어디까지 설명하는지** 보여주는 학습 설계도다. 영역 전체를 조망하는 `00-전체.md`와 달리, 현재 주제 내부의 핵심 개념 관계를 중심으로 **본문에서 원리·경계·적용으로 이해를 확장하는 경로**를 드러낸다.

- 단순 목차·Keyword 목록이나 기술 분류표를 그대로 그리지 않는다. **문서의 중심 설명 관점과 핵심 관계**가 드러나도록 실제 인과·계층·비교·조합 관계 중 주제에 맞는 형태를 선택한다.
- 본문의 모든 절을 지도에 넣지 않는다. 이해에 필요한 출발점, 주요 전개, 개념 경계와 학습 범위만 선별한다.
- `왜 필요한가 → 무엇을 보장하는가 → 어떻게 구현하는가`처럼 서로 다른 질문과 분류축을 구분한다. 실제 선후관계가 없는 개념을 단계처럼 연결하지 않는다.
- 핵심 Node와 관계만 지도에 두고, 정의·예제·예외·Trade-off는 본문에서 설명한다.
- 본문에 이미 설명된 관계를 반복하는 별도 그림은 만들지 않는다. 매우 짧거나 단일 개념으로 충분한 문서는 한두 문장 또는 간단한 구조로 대체할 수 있다.
- 세부학습 중 관계가 바뀌면 상단 지도와 영역 개념지도(`00-전체.md`)의 정합성을 함께 확인한다.

세부학습 상단 지도에서도 관점을 표시할 때는 [개념지도 공통 원칙의 간결한 관점 표기](00-개념지도-공통원칙.md)를 참고한다. **짧은 관점명 → 대표 기술**로 큰 구조를 먼저 보여주고, 질문·동작·예외는 본문에서 좁혀간다. 질문형 트리나 고정 Template을 강제하지 않는다.

**복습 깊이:** 영역 전체 지도는 과목 전체를, 세부학습 상단 지도는 해당 주제를 빠르게 복습하도록 역할을 나눈다. 세부 지도는 조망도와 필요한 경우 짧은 비교표·인출 단서를 두어 핵심 역할·원리·선택 조건을 떠올리게 한다. 세부 예제와 구현별 예외는 본문에 남긴다. 전체 지도와 같은 표를 반복하지 않으며, 1~2분은 강제 분량이 아닌 복습 목표다.

이 원칙의 목적은 형식 통일이 아니라 **복습할 때 지도를 보고 본문의 논리를 스스로 다시 도출하는 것**이다. 문서마다 동일한 Diagram Template이나 Node 수를 강제하지 않는다.

## 7. 선택적 챕터 스토리 학습 문서

전체 개념지도만으로 챕터의 큰 흐름과 개념의 필요성이 직관적으로 이해되지 않을 때, **챕터 전체를 관통하는 스토리 학습 문서**를 선택적으로 작성할 수 있다. 모든 챕터에 의무적으로 만들거나 새로운 필수 학습 계층으로 취급하지 않는다.

- **역할:** 개념지도는 빠른 구조 복습·인출, 스토리 문서는 첫 이해와 재학습을 담당한다. 하위 개념지도나 개별 세부학습을 대체하지 않는다.
- **작성 시점:** 실제 학습에서 흐름이 막혔거나 사례·질문으로 이해가 개선된 경우에 우선 작성한다. 작성 자체를 위해 인위적인 이야기를 만들지 않는다.
- **구성:** 가능하면 일관된 사례를 사용해 문제 상황 → 왜 필요한가 → 개념의 역할 → 다른 개념과의 관계·경계를 설명한다. 해당 챕터의 주요 영역을 빠뜨리지 않되 모든 세부 Topic을 나열하지 않는다.
- **정확성:** 실제 선후·인과가 없는 개념을 스토리에 맞추려고 순서대로 연결하지 않는다. 병렬·포함·비교 관계와 전 과정에 적용되는 관점을 명시한다.
- **이해 보존:** 학습 중 결정적으로 도움이 된 질문, 비유, 잘못 이해했던 관계의 수정, 실제 판단의 Trade-off를 본문 흐름에 자연스럽게 반영한다.
- **중복 관리:** 지도 내용을 문장으로 그대로 복제하지 않는다. 지도에는 위치·관계·인출 단서를 남기고 스토리 문서에는 이해에 필요한 맥락·사례를 남긴다. 챕터 전체 스토리 학습은 `99-<주제>-스토리학습.md`처럼 보강 자료로 구분하며, 정규 하위 개념지도로 취급하지 않는다.
- **완성 기준:** 스토리 문서만 읽어도 챕터의 큰 질문과 주요 개념의 필요성·경계를 이해할 수 있고, 읽은 뒤 전체 지도로 돌아가 흐름을 복원할 수 있어야 한다.

참고 사례: [IT 경영 스토리 학습](../07-IT-경영/99-IT경영-스토리학습.md).

## 8. Diagram은 이해 복원에 사용한다

Diagram의 사용 판단, 대표 Mental Model, Zoom-in 원칙은 [저장소 공통 지식 구성 원칙](../../../docs/KNOWLEDGE_ORGANIZATION.md)을 따른다.

세부학습에서는 **나중에 다시 봤을 때 동작·분기·경계를 빠르게 복원해야 하는 지점**에 Diagram을 우선 사용한다. 그림 뒤에는 오해하기 쉬운 관계만 짧게 해석한다.

## 9. 수식·특수기호는 Viewer 독립성을 우선한다

모바일 GitHub, Obsidian, Terminal 등에서 읽을 수 있도록 LaTeX보다 **Unicode + 일반 Text**를 우선한다.

```text
H₀: μ = 70
H₁: μ ≠ 70
α = 0.05
p-value ≥ 0.05

t = (x̄ - μ₀) / (s / √n)
```

복잡한 수식이 핵심이 아니라면 기호만 남기지 말고 자연어 설명을 함께 적는다.

우선순위:

```text
1. 여러 Viewer에서 깨지지 않는가?
2. 의미가 바로 보이는가?
```

## 10. 작성 후 확인

```text
[ ] 나중에 읽었을 때 당시 이해가 복원되는가?

```

## 11. 한 문장 원칙

> **세부학습은 기술사에 필요한 깊이까지 개념의 위치·필요성·동작·경계를 이해하고, 나중에 다시 읽었을 때 그 이해와 답안 구성 능력을 복원할 수 있게 기록한다.**
