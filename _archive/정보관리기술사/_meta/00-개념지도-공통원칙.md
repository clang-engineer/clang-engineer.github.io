# 정보관리기술사 개념지도 공통 원칙

## 0. 작성 전 확인

개념지도를 작성하거나 수정하기 전에 다음을 확인한다.

1. [정보관리기술사 문서작성 공통 원칙](00-문서작성-공통원칙.md)
2. [저장소 공통 지식 구성 원칙](../../../docs/KNOWLEDGE_ORGANIZATION.md)
3. [저장소 공통 문체·표기 원칙](../../../docs/WRITING_STYLE.md)
4. 이 문서

개념지도는 **학습할 개념의 위치·관계·학습 경로를 보여주고, 복습할 때 핵심 Node에서 세부 이해를 다시 꺼내는 탐색 지도**다.

학습 우선순위와 깊이는 `../학습등급표/`에서 정하고, 상세 원리·동작·예제는 세부학습 문서에서 다룬다.

저장소 공통 원칙에 이미 있는 묶음·관계·Story 기준은 여기서 반복하지 않는다.

## 1. 자료별 역할

```text
교재 · 기출 · 공식 출제기준
        ↓
학습등급표
= 무엇을 얼마나 우선해서 공부할 것인가
        ↓
개념지도
= 어디에 있고 무엇과 연결되는가
  + 어디로 더 파고들 것인가
        ↓
세부학습
= 왜 필요하고 어떻게 동작하는가
```

개념지도는 교재 목차나 세부학습 요약본이 아니다.

## 2. Node와 File을 구분한다

개념지도 Node와 세부학습 File은 1:1일 필요가 없다.

> **Node = 파고들 개념 꼭지 + 복습 인출 단서**  
> **File = 함께 이해할 때 좋은 학습 단위**

Node는 상위·하위·인접·비교·의존 관계를 우선해서 연결한다. 교재 번호나 이름이 비슷하다는 이유만으로 연결하지 않는다.

## 3. 전체 지도 → 필요한 Zoom → 세부학습

개념지도는 목차보다 깊고 세부학습보다 얕다.

```text
영역 전체 지도
= 큰 개념군의 위치·관계·학습 진입점
        ↓ 필요한 곳만
하위 개념지도
= 한 개념군 내부의 관계·경계 Zoom-in
        ↓
세부학습
= 원리·동작·비교·예제
```

전체 지도에는 큰 개념군의 위치·관계, 주요 경계, 다음 학습 가지를 고르는 이유, 대표 인출 Node를 우선 남긴다.

다음은 하위 지도 또는 세부학습으로 내리는 것을 우선한다.

- 상위 Node만으로 충분히 복원되는 반복적 하위 분류
- 관계 없이 이름만 늘어놓는 세부 기법·대표 예시
- 수식·Algorithm 상세 단계
- Parameter, 구현 Code, 제품별 설정
- 긴 설명 자체

단, **대표 기법·분류가 기술사 답안의 핵심 인출 좌표가 되거나, 상위 Node만으로는 중요한 비교·선택 구조가 복원되지 않는다면 전체 지도에 한 단계 더 펼쳐 둘 수 있다.**

```text
상위 개념
├─ 대표 분류 A
├─ 대표 분류 B
└─ 대표 분류 C
```

이때 목적은 세부 내용을 설명하는 것이 아니라 **이름을 보고 원리·비교·Trade-off를 다시 떠올릴 수 있게 하는 것**이다. 따라서 대표 항목의 이름과 관계까지만 남기고, 동작 원리·장단점·예제는 세부학습으로 내린다.

Node를 남길지 애매하면 다음만 확인한다.

```text
이 Node가 없으면 큰 그림이나 주요 경로가 끊기는가?
이 Node가 있어야 중요한 경계가 보이는가?
복습할 때 대표 인출 좌표가 되는가?
```

아니라면 아래로 내리는 것을 우선한다.

반대로 다음 중 하나에 해당하면 한 단계 더 펼치는 것을 허용한다.

- 대표 기법 이름 자체가 시험 답안의 기본 분류 축이 되는가?
- 상위 Node만 두면 서로 다른 접근 방식의 경계가 사라지는가?
- 복습할 때 하위 핵심 Keyword를 직접 보고 인출하는 편이 학습 효율이 높은가?
- 3~5개 안팎의 대표 항목으로 압축해도 Diagram의 구조가 흐트러지지 않는가?

여기서도 **대표 항목까지만 펼치고, 대표 항목 아래의 세부 단계까지 연쇄적으로 확장하지 않는다.**

## 4. 하위 지도는 필요한 곳에만 만든다

```text
전체 지도
  ↓
한 번 더 묶어 보면 관계가 더 잘 보이는가?
  ├─ Yes → 하위 개념지도 → 세부학습
  └─ No  → 세부학습으로 직접
```

파일 길이, Keyword 수, 교재 Chapter 수만으로 하위 지도를 만들지 않는다.

```text
00-*   = 영역 전체 지도
01-* ~ = 정규 학습 가지
99-*   = 정규 가지는 아니지만 큰 그림을 잇는 횡단·보강 지도
```

`99-*`는 기타 지식 모음이 아니다. 정규 지도만으로 중요한 연결이나 경계가 끊길 때만 만든다.

## 5. 쉬운 진입과 정확한 용어를 함께 유지한다

```text
쉬운 큰 질문
  ↓
정확한 핵심 개념명과 관계
  ↓
대표 인출 Node
  ↓
필요한 Zoom
```

낯선 약어·공식 용어는 지도를 읽는 데 필요한 최소 의미만 처음 한 번 붙인다.

## 6. 여러 영역에 걸친 개념은 설명 소유권을 나눈다

같은 Concept은 여러 지도에 Node로 등장할 수 있다. 대신 같은 정의·동작·세부 분류를 복사하지 않는다.

```text
같은 Concept
├─ 영역 A → A 관점에서 왜 필요한지
└─ 영역 B → B 관점에서 왜 필요한지

상세 설명
→ 가장 자연스러운 한 영역이 중심 소유
```

예:

```text
컴퓨터 구조
→ Memory Hierarchy / Cache / MMU / TLB

운영체제
→ Address Space / Protection / Frame / Replacement / Thrashing
```

현재 영역에서 필요한 연결 이유만 설명하고, 다른 영역이 중심 소유하는 내부 동작은 짧게 언급한 뒤 링크한다.

## 7. Diagram은 개념지도의 탐색 좌표로 사용한다

Diagram의 사용 판단과 대표 Mental Model / Zoom-in 원칙은 [저장소 공통 지식 구성 원칙](../../../docs/KNOWLEDGE_ORGANIZATION.md)을 따른다.

개념지도에서는 특히 다음 역할만 추가로 기억한다.

```text
영역 전체 지도 → 큰 가지와 대표 인출 Node를 잇는 Mental Model
하위 개념지도 → 선택한 가지 내부의 관계·경계 Zoom-in
```

Diagram을 세부 Keyword 목록으로 비대하게 만들지 않는다.
## 8. 학습등급표는 출발점이지 지도 복사본이 아니다

A/B/C는 Topic별 학습 우선순위와 깊이를 정하는 기준이지 개념지도 포함 등급이 아니다.

- B/C Topic이 직접 보이지 않는다고 누락으로 판단하지 않는다.
- 등급이 낮아도 큰 그림 연결에 필요하면 Node로 넣을 수 있다.
- 기출 여부나 교재 Chapter 자체를 개념지도 구조로 복사하지 않는다.
- 누락 여부는 개별 Topic 수보다 **큰 개념군과 관계가 빠졌는가**로 판단한다.

## 9. 세부학습과 왕복하며 보정한다

```text
개념지도에서 위치·관계 파악
        ↓
세부학습에서 원리·동작 이해
        ↓
새 관계·경계·의존성 발견
        ↓
개념지도 보정
```

세부학습에서 새 관계를 발견해도 전체 지도에는 관계 복원에 필요한 최소 Node만 올린다.

Obsidian 내부 링크도 실제 학습 경로에만 둔다. 존재하지 않는 파일을 가정하거나 단순 관련성만으로 모든 Node에 링크하지 않는다.

대표 Node를 펼쳤고 해당 내용을 다루는 **기존 세부학습 문서가 있다면, 실제로 더 파고들 수 있도록 가까운 위치에 링크를 둔다.** 링크는 Node마다 기계적으로 붙이지 않고, 한 문서가 여러 Node를 함께 다룬다면 묶어서 연결한다.

```text
개념지도 Node
├─ 대표 분류 / 핵심 Keyword
└─ → 관련 세부학습 문서
       = 원리 · 비교 · Trade-off · 예제
```

즉, 개념지도는 **인출 좌표만 보여주고 끝나는 문서가 아니라 실제 세부학습으로 진입할 수 있는 탐색 지도**가 되어야 한다. 다만 세부학습 문서가 아직 없다면 빈 링크나 예정 링크를 만들지 않는다.

## 10. 작성 후 확인

```text
[ ] 첫 화면에서 큰 가지와 관계가 보이는가?
[ ] 전체 지도에 세부 Keyword를 과도하게 펼치지 않았는가?
[ ] 반대로 핵심 인출 좌표가 되는 대표 기법·분류를 지나치게 숨기지는 않았는가?
[ ] 대표 기법을 펼쳤다면 이름·관계까지만 두고 원리·장단점·예제는 아래로 내렸는가?
[ ] 필요한 곳만 하위 지도로 Zoom-in했는가?
[ ] 교재 목차보다 실제 관계 중심으로 재배치했는가?
[ ] 다른 영역과 공유하는 Concept의 설명 소유권이 분명한가?
[ ] 핵심 Node만 보고 세부 이해를 다시 떠올릴 수 있는가?
[ ] 펼친 핵심 Node에 대응하는 기존 세부학습 문서가 있다면 실제 학습 경로로 링크했는가?
[ ] ASCII Diagram이 실제 관계·분기·경계를 더 잘 보여주는가?
[ ] 같은 관계를 여러 Diagram으로 반복하지 않았는가?
[ ] 세부학습을 요약한 문서처럼 변하지 않았는가?
```
