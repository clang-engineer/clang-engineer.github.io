# 정보관리기술사 개념지도 공통 원칙

> **빠른 판단 기준:** 거시적 ASCII 구조도로 핵심 개념의 위치·관계를 먼저 보여주고, 복습 시 원리·비교·Trade-off를 연상할 수 있는 대표 Keyword를 남긴다. Diagram만으로 부족한 이유·조건·경계는 적절한 본문 설명으로 보완한다. 지도만으로 필요한 이해가 충족되는 개념은 세부학습을 강제하지 않고, 더 깊은 원리·동작이 필요한 경우에만 Zoom-in한다. 교재·기출은 구조의 원본이 아니라 시험 대비 점검 자료로 사용한다.

이 요약은 아래 세부 원칙과 저장소 공통 규칙을 대체하지 않는다.

## 0. 작성 전 확인

개념지도를 작성하거나 수정하기 전에 다음을 확인한다.

1. [정보관리기술사 문서작성 공통 원칙](00-문서작성-공통원칙.md)
2. [저장소 공통 지식 구성 원칙](../../../docs/KNOWLEDGE_ORGANIZATION.md)
3. [저장소 공통 문체·표기 원칙](../../../docs/WRITING_STYLE.md)
4. 이 문서

개념지도는 **컴퓨터공학의 핵심 지식 체계를 조망하고, 정보관리기술사 학습·합격에 필요한 개념의 위치·관계·인출 경로를 보여주는 뼈대**다.

기술사 시험 대비 우선순위와 깊이는 `../학습등급표/`를 참고하고, 상세 원리·동작·예제는 필요할 때 세부학습에서 다룬다. **교재의 항목 수와 지도의 Node 수는 일치할 필요가 없다.**

저장소 공통 원칙에 이미 있는 묶음·관계·Story 기준은 여기서 반복하지 않는다.

## 1. 개념지도의 역할과 Node

자료별 역할, Node와 File의 관계, 필요한 곳만 세부학습으로 내려가는 기준은 [기술사 공통 원칙](00-문서작성-공통원칙.md)을 따른다. 개념지도는 교재 목차나 세부학습의 축약 복제본이 아니다. 다만 **영역 전체를 빠르게 복습할 수 있는 압축된 인출 자료**로 기능해야 한다.

개념지도에서 Node는 **파고들 개념 꼭지이자 복습 인출 단서**다. 상위·하위·인접·비교·의존 관계를 우선해서 연결하며, 교재 번호나 이름이 비슷하다는 이유만으로 연결하지 않는다.

## 2. 전체 지도 → 필요한 Zoom → 세부학습

개념지도는 목차보다 깊고 세부학습보다 얕다.

```text
영역 전체 지도
= 큰 개념군의 위치·관계·학습 진입점
        ↓ 필요한 곳만
하위 개념지도
= 한 개념군 내부의 관계·경계 Zoom-in
        ↓
세부학습
= 원리·동작·비교·예제
```

전체 지도에는 큰 개념군의 위치·관계, 주요 경계, 다음 학습 가지를 고르는 이유, 대표 인출 Node를 우선 남긴다.

### 복습을 위한 3단계 깊이

```text
영역 전체 개념지도 → 과목 전체 5~10분 복습 목표
        ↓ 기억이 흐릿한 주제만
세부학습 상단 개념지도 → 주제별 1~2분 복습 목표
        ↓ 원리·예제가 기억나지 않을 때만
세부학습 본문 → 깊은 이해 복원
```

시간은 **분량을 강제하는 제한이 아닌 설계 목표**다. 전체 지도에는 주요 영역의 대표 역할·관계·핵심 구분을 한 줄 단서로 남기고, 세부 지도의 비교표나 예제를 그대로 복사하지 않는다. 세부 지도는 동작 원리·선택 조건·비용·Trade-off를 간결하게 복원할 수 있게 보완한다. 중복은 허용하되 **전체 지도는 과목 간 연결, 세부 지도는 주제 내부 판단**이라는 서로 다른 설명 책임을 유지한다.


다음은 하위 지도 또는 세부학습으로 내리는 것을 우선한다.

- 상위 Node만으로 충분히 복원되는 반복적 하위 분류
- 관계 없이 이름만 늘어놓는 세부 기법·대표 예시
- 수식·Algorithm 상세 단계
- Parameter, 구현 Code, 제품별 설정
- 긴 설명 자체

단, **대표 기법·분류가 기술사 답안의 핵심 인출 좌표가 되거나, 상위 Node만으로는 중요한 비교·선택 구조가 복원되지 않는다면 전체 지도에 한 단계 더 펼쳐 둘 수 있다.**

```text
상위 개념
├─ 대표 분류 A
├─ 대표 분류 B
└─ 대표 분류 C
```

이때 목적은 세부 내용을 설명하는 것이 아니라 **이름을 보고 원리·비교·Trade-off를 다시 떠올릴 수 있게 하는 것**이다. 따라서 대표 항목의 이름·관계와 **구분에 꼭 필요한 짧은 역할 또는 판단 단서**까지만 남기고, 상세 동작·장단점·예제는 세부학습으로 내린다.

Node를 남길지 애매하면 다음만 확인한다.

```text
이 Node가 없으면 큰 그림이나 주요 경로가 끊기는가?
이 Node가 있어야 중요한 경계가 보이는가?
복습할 때 대표 인출 좌표가 되는가?
```

아니라면 아래로 내리는 것을 우선한다.

반대로 다음 중 하나에 해당하면 한 단계 더 펼치는 것을 허용한다.

- 대표 기법 이름 자체가 시험 답안의 기본 분류 축이 되는가?
- 기술사 문제에서 반복적으로 비교·분류·선택 기준이 되는 **대표 비교·분류 축**인가?
- 상위 Node만 두면 서로 다른 접근 방식의 경계가 사라지는가?
- 복습할 때 하위 핵심 Keyword를 직접 보고 인출하는 편이 학습 효율이 높은가?
- 3~5개 안팎의 대표 항목으로 압축해도 Diagram의 구조가 흐트러지지 않는가?

대표 비교·분류 축은 가능한 한 개념지도에 직접 드러낸다.

```text
Recovery
├─ Log 기반 회복
└─ Shadow Paging

Scale Out
├─ Replication
└─ Sharding

Optimizer
├─ Rule Based
└─ Cost Based
```

이런 축은 단순 Keyword 나열이 아니라 **서로 다른 접근 방식을 구분하고, 비교 기준과 선택 논리를 떠올리게 하는 인출 좌표**다.

여기서도 **대표 항목까지만 펼치고, 대표 항목 아래의 세부 단계까지 연쇄적으로 확장하지 않는다.**

## 3. 하위 지도는 필요한 곳에만 만든다

```text
전체 지도
  ↓
한 번 더 묶어 보면 관계가 더 잘 보이는가?
  ├─ Yes → 하위 개념지도 → 세부학습
  └─ No  → 세부학습으로 직접
```

파일 길이, Keyword 수, 교재 Chapter 수만으로 하위 지도를 만들지 않는다.

```text
00-*   = 영역 전체 지도
01-* ~ = 정규 학습 가지
99-*   = 정규 가지는 아니지만 큰 그림을 잇는 횡단·보강 지도
```

`99-*`는 기타 지식 모음이 아니다. 정규 지도만으로 중요한 연결이나 경계가 끊길 때만 만든다.

## 4. 쉬운 진입과 정확한 용어를 함께 유지한다

```text
쉬운 큰 질문
  ↓
정확한 핵심 개념명과 관계
  ↓
대표 인출 Node
  ↓
필요한 Zoom
```

낯선 약어·공식 용어는 지도를 읽는 데 필요한 최소 의미만 처음 한 번 붙인다.

## 5. 여러 영역에 걸친 개념은 설명 소유권을 나눈다

같은 Concept은 여러 지도에 Node로 등장할 수 있다. 대신 같은 정의·동작·세부 분류를 복사하지 않는다.

```text
같은 Concept
├─ 영역 A → A 관점에서 왜 필요한지
└─ 영역 B → B 관점에서 왜 필요한지

상세 설명
→ 가장 자연스러운 한 영역이 중심 소유
```

예:

```text
컴퓨터 구조
→ Memory Hierarchy / Cache / MMU / TLB

운영체제
→ Address Space / Protection / Frame / Replacement / Thrashing
```

현재 영역에서 필요한 연결 이유만 설명하고, 다른 영역이 중심 소유하는 내부 동작은 짧게 언급한다. 링크 경로는 아래 학습 링크 기준을 따른다.

## 6. Diagram은 개념지도의 탐색 좌표로 사용한다

Diagram의 사용 판단과 대표 Mental Model / Zoom-in 원칙은 [저장소 공통 지식 구성 원칙](../../../docs/KNOWLEDGE_ORGANIZATION.md)을 따른다.

개념지도에서는 특히 다음 역할만 추가로 기억한다.

```text
영역 전체 지도 → 큰 가지와 대표 인출 Node를 잇는 Mental Model
하위 개념지도 → 선택한 가지 내부의 관계·경계 Zoom-in
```

개념지도에서는 **무엇을 가장 먼저 인출하게 할 것인지**를 정한 뒤 공통 배치 기준을 적용한다. Diagram을 세부 Keyword 목록으로 비대하게 만들지 않는다.

## 7. 지도의 뼈대는 컴퓨터공학 핵심 구조로 잡는다

**개념지도의 일차 목적은 컴퓨터공학의 큰 구조·원리·관계를 이해하고 인출하는 것**이다. 정보관리기술사 출제기준·기출과 성안당 등 교재는 학습 우선순위와 시험 대비 보완에 활용한다.

```text
컴퓨터공학 핵심 지식 체계
       ↓ 큰 개념군·관계 선정
개념학습지도 (전체 뼈대)
       ↕ 시험 대비 점검
출제기준 · 기출 · 학습등급표 · 성안당 등 교재
       ↓ 이해가 부족한 곳만
세부학습
```

- **최상위 Node:** 해당 영역을 설명하는 핵심 개념군과 주요 관계를 우선한다.
- **하위 Node:** 대표 분류·비교·인출 단서가 필요한 만큼만 펼친다.
- **세부·주변 개념:** 교재에 등장해도 큰 그림을 형성하지 않으면 하위 문서나 교재 복습에 맡긴다.
- **교재 밖 핵심 개념:** 컴퓨터공학의 중요한 구조·관계를 설명한다면 포함할 수 있다.
- **누락 판단:** 교재 항목별 일치 여부가 아니라 큰 개념군·핵심 관계·기술사 답안의 주요 축이 빠졌는지 확인한다.

기출·교재의 문제군에서 반복되는 비교·분류·선택 기준을 확인하되, **문제 목록 자체를 지도 구조로 복사하지 않는다.** 지도에 없는 개별 문제는 교재에서 복습하거나 필요할 때 세부학습으로 내려간다.

A/B/C는 Topic별 학습 우선순위와 깊이이지 개념지도 포함 등급이 아니다. B/C Topic이 직접 보이지 않는다고 누락으로 판단하지 않으며, 등급이 낮아도 큰 그림 연결에 필요하면 Node로 넣을 수 있다.

## 8. 목록보다 실제 관계를 드러낸다

개념지도는 단순한 Keyword 목록보다 **포함·병렬·인과·비교·의존 중 실제 관계**가 보이도록 구성한다. 관련 기술이어도 서비스 모델·구현 기술·운영 제약처럼 분류축이 다르면 역할과 계층을 구분한다.

실제 인과가 있을 때는 다음 형태를 검토한다.

```text
문제
  ↓
대응 기술
  ↓
얻는 효과
  ↓
새로 생기는 Trade-off / 제약
```

예:

```text
단일 DB 확장 한계
   ↓
Replication / Sharding
   ↓
Scale Out
   ↓
Consistency / Distributed Transaction / Coordination 문제
```

### 큰 꼭지 우선, 인과관계는 연결선, Keyword는 인출 단서

영역 전체 지도의 **최우선 목적은 큰 꼭지를 보고 해당 분야의 전체 지식 구조가 머릿속에서 자연스럽게 흘러가도록 하는 것**이다. 큰 개념군을 먼저 식별하고, 포함·병렬·인과·비교·의존 중 실제 관계를 따라 전체 그림을 복원하며, 대표 Keyword로 학습한 세부 내용을 다시 떠올린다. 인과관계가 없는 개념을 억지로 순차 연결하지 않는다.

```text
[큰 꼭지 A] ── 왜 B가 필요한가? ──> [큰 꼭지 B]
  └─ 대표 Keyword                    └─ 대표 Keyword

우선순위: 큰 꼭지 인식 → 전체 구조·관계 복원 → 세부 지식 인출
```

- 큰 꼭지는 번호·박스·분기 등으로 구분하되, 장식보다 한눈에 식별되는 구조를 우선한다.
- 화살표는 실제 인과·순서가 있을 때 **문제·필요·효과**를 표현한다. 병렬은 분기, 포함은 하위 가지, 비교는 대칭으로 표현한다.
- 하위 Keyword는 3~5개 안팎의 대표 인출 단서로 제한하고 세부 원리·예제는 아래로 내린다.
- 실제 포함관계와 인과관계를 혼동하지 않는다. 예를 들어 정규화는 모델링의 일부이고 신뢰성·성능·확장은 병렬 운영 축이다.
- 지도는 필수 실행 순서가 아니라 **학습 내용을 복원하기 위한 개념적 연결**일 수 있음을 필요하면 명시한다.
- **복습 검증:** 지도를 10초간 훑은 뒤 큰 꼭지를 말할 수 있는가? 꼭지 사이의 실제 관계를 설명할 수 있는가? 각 꼭지에서 핵심 세부 개념을 스스로 떠올릴 수 있는가? 세 질문 중 하나라도 막히면 키워드 추가보다 구조·배치를 먼저 보정한다.

## 9. 지도 수정 시 역점검한다

새 Node를 추가하거나 구조를 바꾼 뒤에는 최소한 다음을 확인한다.

```text
[ ] 컴퓨터공학의 핵심 개념군·관계를 형성하는가?
[ ] 교재 포함 여부와 별개로 상위 Node에 둘 대표성이 있는가?
[ ] 기존 Node와 어떤 관계로 연결되는가?
[ ] 형제 Node와 추상 수준이 맞는가?
[ ] 별도 세부학습이 필요한가, 기존 문서로 연결 가능한가?
[ ] Diagram 형태가 순서·분류·비교·인과 중 강조하려는 목적에 맞는가?
```

## 10. 세부학습으로 이어지는 학습 링크를 둔다

기술사 공통 원칙에 따라 세부학습 결과로 지도를 보정하되, 전체 지도에는 관계 복원에 필요한 최소 Node만 올린다.

Obsidian 내부 링크도 실제 학습 경로에만 둔다. 존재하지 않는 파일을 가정하거나 단순 관련성만으로 모든 Node에 링크하지 않는다.

대표 Node를 펼쳤고 해당 내용을 다루는 **기존 세부학습 문서가 있다면, 실제로 더 파고들 수 있도록 가까운 위치에 링크를 둔다.** 링크는 Node마다 기계적으로 붙이지 않고, 한 문서가 여러 Node를 함께 다룬다면 묶어서 연결한다.

### 하위 개념지도끼리는 직접 학습 링크를 만들지 않는다

학습 경로는 원칙적으로 다음처럼 한 방향으로 유지한다.

```text
00 전체지도
   ↓
01 / 02 / 03 ... 하위 개념지도
   ↓
세부학습 문서
```

하위 개념지도에서 다른 하위 개념지도의 영역과 만나는 경우에는 **개념 경계나 연결 사실만 짧게 언급**하고, 서로를 다음 학습 단계처럼 직접 링크하지 않는다.

```text
하위지도 A
→ "이 지점은 동시성 영역과 만난다" 정도로 경계만 표시
→ 실제 Zoom-in은 세부학습 문서로 내려감
```

예외적으로 `00-전체`로 돌아가는 상위 탐색 링크는 허용한다. 다른 영역의 하위지도와 Concept 소유권이 겹치더라도, 하위지도끼리 링크망을 만들기보다 각 지도에서 필요한 관점만 남기고 세부학습의 중심 소유 문서로 내려간다.

세부학습 링크는 단순한 참고문헌 목록이 아니라 **학습 경로 안내**로 작성한다. 각 링크에는 가능한 한 다음 세 가지를 짧게 드러낸다.

- 왜 이 문서를 보는가
- 이 문서에서 무엇을 이해해야 하는가
- 앞·뒤 어떤 학습과 이어지는가

선후관계가 있는 경우에는 읽는 순서를 명시하고, 서로 독립적인 경우에는 병렬 학습 가지라고 표시한다.

```text
개념지도 Node
   ↓
1. 먼저 보는 세부학습
   = 다음 단계의 판단 근거를 이해
   ↓
2. 그다음 보는 세부학습
   = 실제 실행 방식·비교 기준을 이해
   ↓
3. 필요할 때 선택하는 세부학습
   = 특정 구조·기법으로 Zoom-in
```

즉, 개념지도는 **인출 좌표만 보여주고 끝나는 문서가 아니라 실제 세부학습으로 진입할 수 있는 탐색 지도**가 되어야 한다. 다만 세부학습 문서가 아직 없다면 빈 링크나 예정 링크를 만들지 않는다.
