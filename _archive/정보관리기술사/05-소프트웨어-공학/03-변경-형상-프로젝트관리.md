# 변경 · 형상 · 프로젝트 관리 개념지도

> 소프트웨어와 산출물의 **변경 자체를 통제하는 문제**와 제한된 자원 안에서 **프로젝트를 계획·통제하는 문제**의 경계를 보는 지도다.

```text
개발 전 과정에서 계속 변화
├─ 요구
├─ 설계
├─ Code
├─ Test
└─ 배포 산출물
      ↓
형상·변경관리
├─ Configuration Item
├─ Version
├─ Baseline
└─ 변경 통제

동시에 Project에는 제약이 존재
├─ 범위
├─ 일정
├─ 비용
├─ 위험
├─ 품질
└─ 이해관계자
      ↓
Project 관리
```

## 규모와 계획의 연결

```text
요구 · 범위
   ↓
Software 규모 추정
├─ LOC
└─ FP(Function Point)
   ↓
공수 · 기간 · 비용 추정
└─ COCOMO 등
   ↓
Project 계획 · 통제
```

```text
형상·변경관리
= 무엇이 바뀌었고 어느 Version이 기준인지 통제

Project 관리
= 무엇을 언제 얼마의 자원으로 완료할지 통제
```

둘 다 생명주기 전체에 적용되지만 통제 대상이 다르다. CPM·EVM·PMO 등 세부 기법과 조직 구조는 세부학습에서 확장한다.
