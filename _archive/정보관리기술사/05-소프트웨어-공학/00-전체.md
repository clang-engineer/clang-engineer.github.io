# 소프트웨어 공학 개념지도

> 소프트웨어 공학은 **불확실한 요구를 운영 가능한 소프트웨어로 바꾸고, 변경·품질·일정·비용의 위험을 생명주기 전체에서 통제하는 방법**을 다룬다.

이 문서는 소프트웨어 공학의 큰 흐름과 학습 가지를 잡는 전체 지도다. 개발 방식·전달·운영, 검증·시험·품질, 변경·형상·프로젝트 관리처럼 관계를 더 촘촘히 볼 필요가 있는 부분은 하위 개념지도로 내려간다.

## 1. 소프트웨어 공학 전체 좌표

```text
문제와 사용자 요구
        ↓
요구공학
        ↓
Architecture · 설계
        ↓
구현 · 통합
        ↓
검증 · Test
        ↓
Release · Deployment
        ↓
운영 · 유지보수
        ↓
Feedback ─────────→ 앞 단계로 환류

[전 과정 통제]
개발 방식 · 형상/변경 · 품질
규모/공수 · Project 관리 · 외부 제약
```

핵심은 개발 생명주기가 한 번의 직선 흐름으로 끝나는 것이 아니라, **Feedback과 변경 통제가 전 과정을 계속 연결한다는 것**이다.

## 2. 어디를 파고들 것인가

### 요구 · Architecture · 설계

무엇을 만들지 명확히 하고, 변경에 견딜 구조로 구체화하는 축이다.

```text
사용자 · 이해관계자 필요
  ↓
요구공학
  ↓ Traceability
Architecture
  ↓
상세 설계
  ↓
구현
```

요구 ↔ 설계 ↔ 구현 ↔ 시험의 추적성은 전체 생명주기를 연결하는 대표 좌표다.

### 개발 방식 · 전달 · 운영

개발을 어떤 Feedback 주기와 전달 방식으로 운영할지 본다.

```text
개발 방식
  ↓
반복 · 통합 · 자동화
  ↓
Release / Deployment
  ↓
운영 Feedback
```

Waterfall·Iterative·Agile·DevOps 같은 내부 비교는 하위 지도에서 더 펼친다.

→ [[01-개발방식-전달-운영|개발 방식·전달·운영 개념지도]]

### 검증 · 시험 · 품질

제대로 만들었는지, 실제 목적에 맞는지, 어떤 품질 수준인지 확인하는 축이다.

```text
품질 요구
  ↓
Review / V&V / Test
  ↓
결함 · Coverage · 품질 지표
  ↓
개선 Feedback
```

Verification·Validation·시험 수준·시험 기법·품질 특성의 세부 경계는 하위 지도에서 본다.

→ [[02-검증-시험-품질|검증·시험·품질 개념지도]]

### 변경 · 형상 · Project 관리

소프트웨어와 산출물의 변경을 통제하고, 범위·일정·비용·위험을 관리하는 횡단 축이다.

```text
변경 발생
  ↓
형상·변경관리
  ↓
Version / Baseline / 변경 통제

[동시에]
범위 · 일정 · 비용 · 위험 · 이해관계자 관리
```

규모·공수 추정과 Project 관리 기법, 외부 표준·OSS License·IP 같은 제약도 이 축과 연결된다.

→ [[03-변경-형상-프로젝트관리|변경·형상·Project 관리 개념지도]]

## 3. 기억할 큰 경계

```text
제품을 만드는 흐름
요구 → 설계 → 구현 → 검증 → 배포 → 운영

흐름을 개선하는 방식
개발 방법 / Feedback / 자동화 / DevOps

결과를 확인하는 축
Review / V&V / Test / 품질

전체를 통제하는 축
형상·변경 / 규모·공수 / Project 관리 / 외부 제약
```

SDLC와 생명주기 모델, Architecture와 UML, Verification과 Validation, Release와 Deployment처럼 **같은 가지 내부에서 구분해야 하는 개념은 하위 지도나 세부학습에서 더 펼친다.**

## 4. 탐색 방식

```text
학습등급표
"무엇을 얼마나 볼 것인가"
        ↓
소프트웨어 공학 전체 개념지도
"어느 큰 가지를 팔 것인가"
        ↓
┌──────────────────────────┐
│ 요구·Architecture·설계   │
│ 개발 방식·전달·운영      │
│ 검증·시험·품질           │
│ 변경·형상·Project 관리   │
└────────────┬─────────────┘
             ↓
      필요한 하위 지도
"관계와 비교를 더 촘촘히"
             ↓
          세부학습
"왜 필요하고 어떻게 동작하는가"
```

전체 지도에서는 큰 흐름과 대표적인 횡단 관점까지만 남긴다. 개별 방법론·시험 기법·품질 모델·추정식·프로젝트 관리 기법은 하위 지도 또는 세부학습으로 내린다.
