# 파레토 법칙과 파레토 분석

파레토(Pareto) 법칙은 **전체 결과의 상당 부분이 소수의 핵심 원인에 집중되는 현상**을 설명하는 경험 법칙이다. 흔히 `80:20 법칙`으로 표현하지만, 80과 20이라는 수치 자체가 법칙의 본질은 아니다.

정보관리기술사에서는 소프트웨어 결함, 운영 장애, 품질 개선, 데이터 항목 선정처럼 **무엇부터 집중해서 볼 것인가**를 설명할 때 연결할 수 있다.

---

## 1. 핵심 개념

```text
많은 원인
   ↓
영향도·빈도 측정
   ↓
큰 순서로 정렬
   ↓
누적 기여도 계산
   ↓
결과 대부분을 설명하는 소수 핵심 원인 식별
   ↓
개선·분석 우선순위 결정
```

파레토 법칙과 파레토 분석을 구분한다.

```text
파레토 법칙
= 결과가 소수 핵심 원인에 집중되는 경향

파레토 분석
= 항목을 영향도·빈도 등의 기준으로 정렬하고
  누적 기여도를 이용해 우선순위를 찾는 분석 방법

파레토 차트
= 파레토 분석 결과를 막대와 누적 비율로 표현하는 도구
```

---

## 2. 80:20은 고정된 임계값이 아니다

`80%의 결과는 20%의 원인에서 발생한다`는 표현은 파레토 법칙을 기억하기 위한 대표적인 형태다.

실제 데이터가 반드시 정확히 `80:20`으로 나뉘어야 하는 것은 아니다.

```text
핵심
X  상위 20%를 무조건 선택한다.
O  영향이 큰 소수 항목을 데이터에서 찾아 집중한다.
```

따라서 파레토 분석을 적용했다고 말하려면 단순히 항목 수를 줄였다는 사실보다 **무슨 기준으로 정렬했고 누적 기여도를 어떻게 판단했는지**가 중요하다.

---

## 3. 파레토 분석 절차

```text
1. 분석 대상 정의
2. 영향도·빈도 등 측정 기준 결정
3. 항목별 값을 집계
4. 큰 값부터 내림차순 정렬
5. 누적 비율 계산
6. 핵심 항목 식별
7. 개선·분석 우선순위 결정
```

예를 들어 장애 원인을 발생 건수로 분석한다면 다음과 같다.

```text
DB 오류       45건
API 오류      25건
Network 오류  15건
기타          15건

        ↓ 내림차순 정렬·누적

DB + API = 전체 장애의 70%

        ↓

DB와 API를 우선 개선 대상으로 선정
```

## 4. 소프트웨어 공학과 운영에서의 활용

### 결함 관리

많은 결함이 특정 Module이나 원인 유형에 집중되어 있다면 해당 부분을 우선 점검한다.

```text
결함 발생 위치 집계
 ↓
Module별 결함 수 정렬
 ↓
결함이 집중된 Module 식별
 ↓
Review · Refactoring · Test 강화
```

### 장애·운영 관리

장애 원인별 발생 빈도나 손실 규모를 분석하여 개선 효과가 큰 원인부터 대응한다.

### 품질 개선

품질 문제를 원인별로 분류한 뒤 발생 빈도 또는 영향도를 기준으로 핵심 원인을 선정한다. 파레토 차트는 이러한 우선순위를 시각화할 때 사용할 수 있다.

---

## 5. 데이터 항목 선정에 적용하는 경우

검사 항목이 매우 많지만 실제 사용량이 일부 항목에 집중되어 있다고 가정한다.

```text
전체 검사 항목
 ↓
검사별 수행 빈도 집계
 ↓
빈도 내림차순 정렬
 ↓
누적 수행 비율 계산
 ↓
대부분의 검사 수행량을 설명하는 핵심 검사 항목 선정
```

이 경우 다음 표현은 의미가 명확하다.

> 검사 수행 빈도에 대한 파레토 분석을 통해 핵심 검사 컬럼을 선정했다.

반면 `파레토 기반 148개 컬럼 선정`처럼 기준을 생략하면 **검사 빈도인지, 활용도인지, 비용인지, 중요도인지 알 수 없으므로** 분석 근거가 불명확하다.

---

## 6. 헷갈리기 쉬운 경계

### 파레토 분석 = 통계적 가설검정?

아니다.

파레토 분석은 주로 **집중 현상을 파악하고 우선순위를 정하는 분석**이다. 모집단에 대한 가설의 유의성을 검정하는 t-test, ANOVA 등의 통계적 가설검정과 목적이 다르다.

### 파레토 분석 = 상위 20% 선택?

아니다.

20%는 대표적인 경험적 표현이다. 실제 분석에서는 데이터의 누적 기여도와 업무 목적을 보고 핵심 범위를 정한다.

### 파레토 차트 = 파레토 분석?

같지 않다.

파레토 분석은 우선순위를 찾는 분석 과정이고, 파레토 차트는 그 결과를 보여주는 대표적인 시각화 방법이다.

---

## 7. 기억·인출

```text
파레토 = "다 보지 말고, 결과를 크게 만드는 핵심부터 찾는다."

법칙 → 집중 현상
분석 → 핵심 원인 선정
차트 → 빈도 + 누적 비율 시각화
```

시험에서는 `80:20` 숫자만 쓰기보다 **소수 핵심 원인에 대한 자원 집중과 우선순위 결정**이라는 의미까지 연결한다.
