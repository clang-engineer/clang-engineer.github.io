# 데이터베이스 개념지도

> 데이터베이스는 **업무 데이터를 공통 구조로 관리하고, 정확성·동시성·장애·성능·확장 문제를 해결하면서 안전하게 활용하는 체계**다.

## 1. 가장 먼저 잡을 큰 그림

```text
Application마다 File을 따로 관리
        ↓
중복 · 불일치 · 공유·통제 어려움
        ↓
DBMS
= 데이터를 공통으로 관리
        ↓
무엇을 어떤 구조로 저장할까?
        ↓
데이터 모델링 · Schema · Key · 무결성
        ↓
중복과 이상현상을 어떻게 줄일까?
        ↓
정규화 ↔ 반정규화
        ↓
구조화한 데이터를 어떻게 다룰까?
        ↓
관계형 모델 · SQL · View
        ↓
여러 사용자가 동시에 바꾸거나 장애가 나면?
        ↓
Transaction · ACID
├─ 동시 실행 문제 → 동시성 제어
└─ 장애 문제     → 회복
        ↓
데이터가 많아져 느려지면?
        ↓
질의 최적화 · Index · Partition · Tuning
        ↓
한 서버의 한계를 넘으면?
        ↓
Replication · Sharding · 분산 DB
```

이 흐름에 모든 DB 개념을 억지로 넣지는 않는다. `보안·품질·표준·Metadata·거버넌스`는 **전체를 가로지르는 관리 관점**, `DW·OLAP·BI`는 **분석 활용 가지**로 본다.

## 2. 데이터를 왜 DBMS로 공동 관리할까?

```text
File 중심 관리
├─ 데이터 중복·불일치
├─ 공유와 동시 접근 통제 어려움
└─ 저장 구조 변경이 Application에 직접 영향
        ↓
DBMS
├─ 공통 구조와 규칙 관리
├─ 여러 사용자의 접근·변경 통제
└─ 데이터 독립성으로 변경 영향 감소
```

`ANSI/SPARC 3-Schema`는 외부·개념·내부 Schema를 분리해 **논리적·물리적 데이터 독립성**을 설명하는 대표 좌표다.

## 3. 업무를 어떤 데이터 구조로 만들까?

```text
현실의 업무
  ↓ 추상화
데이터 모델링
├─ 개념 모델
├─ 논리 모델
└─ 물리 모델
```

논리 모델에서는 `Entity · Attribute · Relationship`, `Relation`, `Key`, `무결성`이 데이터의 의미와 관계를 구조화한다.

같은 사실을 반복 저장하면 중복과 삽입·수정·삭제 이상이 생기므로 정규화를 검토한다.

```text
중복·이상현상
      ↓
정규화
      ↕ Trade-off
반정규화
```

`정규화 ↔ 반정규화`는 **무결성·변경 비용 ↔ 조회 성능·단순성**의 선택 문제다.

## 4. 구조화한 데이터를 어떻게 사용하고 지킬까?

관계형 DB에서는 관계 연산을 SQL로 표현해 데이터를 정의·조회·변경한다.

```text
관계형 모델
   ↓
SQL · View
   ↓
Transaction
└─ ACID
   ├─ 동시성 제어
   └─ 회복
```

`동시성 제어`와 `회복`은 모두 Transaction 신뢰성을 지키지만 해결하는 문제가 다르다.

- 동시성 제어: 여러 Transaction이 겹칠 때 잘못된 결과를 막는다.
- 회복: 처리 중 장애가 나도 일관된 상태로 되돌린다.
- Backup: 별도 보존본에서 복원하므로 Transaction 회복과 목적·시간 범위가 다르다.

- [[트랜잭션-동시성-격리수준-Lock-MVCC]]

## 5. 데이터가 많아지면 어떻게 빠르게 처리할까?

```text
느린 질의
  ↓
실행계획 · I/O · 대기시간 확인
  ↓
질의 최적화
├─ Index
├─ Partition
├─ SQL / Schema 개선
└─ DB 설정 Tuning
  ↓
재측정
```

`Query Optimizer`는 실행 방법을 선택하고, `Index`는 원하는 Record에 빠르게 접근하기 위한 구조다.

Index에서는 분류축을 섞지 않는다.

```text
탐색 구조 관점
B-Tree 계열 · Hash

데이터 배치·Locator 관점
Clustered ↔ Nonclustered
```

- [[탐색트리와-DB인덱스-BTree-BPlusTree-BStarTree-TTree]]
- [[BTree-클러스터드-넌클러스터드-인덱스]]

## 6. 한 서버의 한계를 넘으면 어떻게 확장할까?

```text
단일 DB 한계
  ↓
분산 검토
├─ Replication : 복제
├─ Sharding    : 분할
└─ 분산 DB
```

분산은 확장성과 가용성을 높일 수 있지만, 일관성·분산 Transaction·장애 처리·운영 복잡성의 비용이 생긴다. `CAP`는 이 Trade-off를 이해하는 대표 좌표다.

## 7. 전체를 가로지르는 관리 관점

```text
DBMS → 모델링 → SQL → Transaction → 성능 → 분산
  │       │       │         │          │       │
  └───────┴───────┴─────────┴──────────┴───────┘
                       ↑
             보안 · 품질 · 표준
             Metadata · 거버넌스
```

이들은 특정 단계의 다음 기술이 아니라 설계·저장·변경·활용 전체에 적용된다.

## 8. 저장한 데이터를 어떻게 활용할까?

```text
데이터 활용
├─ OLTP
└─ 분석
    ├─ DW
    ├─ OLAP
    └─ BI · 데이터 마이닝
```

`OLTP → DW → OLAP`을 DB 자체의 발전 단계로 보지 않는다. 운영 처리와 분석 활용이라는 목적 차이를 먼저 구분한다.

## 9. 기억할 핵심 경계

| 헷갈리기 쉬운 개념 | 핵심 경계 |
|---|---|
| Schema ↔ Instance | 구조 정의 ↔ 특정 시점의 실제 데이터 |
| 정규화 ↔ 반정규화 | 중복·이상 감소 ↔ 성능 등을 위해 중복 일부 허용 |
| Transaction ↔ 동시성 제어 | 논리적 작업 단위 ↔ 여러 Transaction의 간섭 통제 |
| 동시성 제어 ↔ 회복 | 동시 실행 문제 ↔ 장애 문제 |
| Recovery ↔ Backup | Transaction 상태 복원 ↔ 별도 보존본에서 복원 |
| Query Optimizer ↔ Index | 실행 방법 선택 ↔ 빠른 접근을 위한 구조 |
| Replication ↔ Sharding | 데이터 복제 ↔ 데이터 분할 |
| OLTP ↔ OLAP | 운영 Transaction 처리 ↔ 분석 질의 처리 |

## 10. 한 번에 다시 떠올리기

```text
File 관리의 한계
   ↓
DBMS · 데이터 독립성
   ↓
모델링 · Schema · Key · 무결성
   ↓
정규화 ↔ 반정규화
   ↓
관계형 모델 · SQL
   ↓
Transaction
├─ 동시성 제어
└─ 회복
   ↓
질의 최적화 · Index · Partition
   ↓
Replication · Sharding · 분산 DB

[전체 관리]
보안 · 품질 · 표준 · Metadata · 거버넌스

[분석 활용]
DW · OLAP · BI
```

> **DBMS로 데이터를 공동 관리하고 → 업무를 구조화하고 → Transaction으로 정확성을 지키며 → 질의와 저장 구조를 최적화하고 → 필요하면 분산한다. 보안·품질·거버넌스는 이 전체를 가로지른다.**
