# 인덱스 · 질의최적화 개념지도

> 데이터가 많아졌을 때 **DBMS가 어떤 실행 방법을 선택하고, Index가 그 선택에 어떤 접근 경로를 제공하는가**를 보는 지도다.

```text
SQL
 ↓
Query Optimizer
├─ 통계 정보
├─ 가능한 실행 방법
└─ 예상 Cost
 ↓
Execution Plan
 ↓
실제 실행
├─ Table Scan
├─ Index Scan / Seek
└─ Join 방식 등
 ↓
I/O · CPU · 대기시간 측정
 ↓
병목에 맞게 개선
├─ Index
├─ Partition
├─ SQL / Schema
└─ DB 설정
 ↓
재측정
```

## Index를 볼 때 분류축을 섞지 않는다

```text
[탐색 구조]
B-Tree 계열
└─ B+Tree

[데이터 배치·Locator 관계]
Clustered Index
↔ Nonclustered Index
```

`B+Tree`와 `Clustered Index`는 같은 축의 대안이 아니다. 전자는 탐색 자료구조이고 후자는 Index Entry와 실제 데이터의 배치·Locator 관계를 설명한다.
