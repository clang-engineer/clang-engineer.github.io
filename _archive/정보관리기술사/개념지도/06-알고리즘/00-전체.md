# 알고리즘 전체 개념지도

알고리즘은 **문제를 계산 가능한 절차로 표현하고, 그 과정에서 사용할 데이터 구조와 처리 비용을 함께 판단하는 영역**으로 본다.

이 문서는 정렬·탐색 Algorithm의 이름이나 구현 Code를 외우기 위한 목차가 아니다. 먼저 **문제를 풀기 위해 데이터를 어떻게 표현하고, 어떤 절차로 처리하며, 그 절차의 효율을 어떻게 판단하는지** 큰 그림을 잡고 필요한 가지에서 더 자세히 내려간다.

## 1. 가장 먼저 잡을 큰 그림

```text
문제를 계산으로 해결하고 싶다
│
├─ 데이터를 어떤 형태로 표현하고 저장하지?
│   └─ 자료구조
│
├─ 해결 절차가 얼마나 효율적인지 어떻게 판단하지?
│   └─ 알고리즘 분석
│      └─ Time Complexity · Space Complexity · Big-O
│
├─ 같은 구조의 문제를 자기 자신으로 다시 표현할 수 있을까?
│   └─ Recursion
│
├─ 데이터를 원하는 순서로 만들려면?
│   └─ Sorting
│
├─ 원하는 데이터를 어떻게 찾지?
│   └─ Search · Hashing
│
├─ 계층 관계를 어떻게 표현하고 탐색하지?
│   └─ Tree
│
└─ 임의의 연결 관계를 어떻게 표현하고 탐색하지?
    └─ Graph
```

여기서 중요한 것은 개별 Algorithm 이름보다 **문제 표현 → 처리 절차 → 비용 판단**의 관계다.

```text
문제
  ↓
데이터를 어떤 구조로 표현할 것인가?
  ↓
자료구조
  ↓
그 구조에서 어떤 절차로 처리할 것인가?
  ↓
알고리즘
  ↓
그 처리에는 시간과 공간이 얼마나 필요한가?
  ↓
복잡도 분석
```

자료구조와 알고리즘은 별개의 암기 영역이 아니다. 같은 문제라도 데이터를 어떤 구조로 표현하는지에 따라 사용할 수 있는 연산과 비용이 달라진다.

## 2. 자료구조는 Algorithm이 다룰 데이터의 형태를 정한다

자료구조는 데이터를 저장하는 모양만 뜻하지 않는다. **어떤 관계로 데이터를 표현하고 어떤 연산을 효율적으로 수행할 것인지**를 함께 결정한다.

전체 지도에서는 먼저 다음 두 방향만 잡는다.

```text
자료구조
├─ 순서와 연결을 중심으로 표현
│   └─ Array · Linked List · Stack · Queue
│
└─ 계층이나 임의의 관계를 표현
    └─ Tree · Graph
```

Array와 Linked List는 데이터 배치와 삽입·삭제 특성이 다르고, Stack과 Queue는 데이터가 들어오고 나가는 순서를 제한한다.

이 구조들은 뒤의 Algorithm과 다시 연결된다.

```text
Stack
  └─ 후위식 계산 · Tree/Graph 탐색 등에 활용

Queue
  └─ Graph의 BFS 등에 활용

Tree
  └─ 계층 표현 · Traversal · Search

Graph
  └─ 임의의 관계 표현 · Traversal · 최소 연결 구조 탐색
```

세부 구조와 연산은 자료구조 Zoom 지도에서 본다.

→ [[01-자료구조]]

## 3. Algorithm은 결과뿐 아니라 비용도 평가해야 한다

같은 결과를 만드는 절차가 여러 개라면 어떤 절차가 더 적절한지 판단해야 한다.

```text
Algorithm
  ↓
입력 크기가 증가
  ↓
필요한 연산과 Memory도 증가
  ↓
증가 정도를 분석
```

대표적인 두 자원은 다음과 같다.

```text
Time Complexity
= 입력 크기에 따라 실행에 필요한 연산량이 어떻게 증가하는가

Space Complexity
= 입력 크기에 따라 필요한 Memory가 어떻게 증가하는가
```

Big-O는 입력 크기가 커질 때 Algorithm 비용의 증가 정도를 표현하는 대표적인 표기다.

전체 지도에서는 개별 수식 계산보다 다음 관계를 잡는다.

```text
문제를 해결할 수 있는가?
        ↓
Correctness
        ↓
얼마나 많은 자원이 필요한가?
        ↓
Time / Space Complexity
        ↓
입력 증가에 따른 비용의 증가 정도
        ↓
Big-O
```

→ [[02-알고리즘-분석]]

## 4. Recursion은 문제를 같은 형태의 더 작은 문제로 표현한다

어떤 문제는 자기 자신과 같은 구조의 더 작은 문제로 정의할 수 있다.

```text
큰 문제
  ↓
같은 형태의 작은 문제
  ↓
더 작은 문제
  ↓
종료 조건
```

Factorial, Fibonacci, Tower of Hanoi는 이런 구조를 이해하기 위한 대표적인 예다.

Recursion은 단순한 반복문 대체 문법이 아니다. 문제 자체를 재귀적으로 정의할 수 있다는 점과 호출이 Stack에 쌓인다는 실행 특성을 함께 이해해야 한다.

전체 지도에서는 Recursion을 독립된 큰 자료구조로 만들지 않고, **문제를 표현하는 Algorithm 구조와 Stack 실행 모델을 연결하는 Node**로 둔다.

## 5. Sorting과 Search는 자료를 다루는 대표적인 Algorithm 문제다

데이터를 다룰 때 반복해서 등장하는 두 질문이 있다.

```text
원하는 순서로 만들고 싶다
→ Sorting

원하는 값을 찾고 싶다
→ Search
```

Sorting에는 여러 방법이 존재하고 각 방법은 비교·교환 방식, 추가 공간, 입력 상태 등에 따라 비용 특성이 달라진다.

Search 역시 데이터가 어떤 상태와 구조로 저장되어 있는지에 따라 방법이 달라진다.

```text
Search
├─ 순차적으로 확인
├─ 정렬된 범위를 줄이며 탐색
├─ Tree 구조를 따라 탐색
└─ Hash 함수를 이용해 저장 위치를 찾음
```

따라서 Sorting과 Search는 Algorithm 이름을 따로 암기하기보다 다음 관계로 본다.

```text
데이터의 현재 구조와 상태
        ↓
가능한 Algorithm 선택
        ↓
비교 · 이동 · 접근 방식이 달라짐
        ↓
Time / Space 비용이 달라짐
```

→ [[03-정렬-탐색]]

## 6. Tree는 계층 관계를 표현하고 탐색한다

선형 구조만으로 표현하기 어려운 계층 관계에는 Tree가 사용된다.

```text
Tree
├─ Node 사이의 부모·자식 관계
├─ Traversal
├─ Heap
└─ Search를 위한 Tree 구조
```

Tree Traversal은 같은 Tree라도 어떤 순서로 Node를 방문할 것인지에 대한 Algorithm이다.

```text
Tree라는 Data Structure
        ↓
어떤 순서로 방문할 것인가?
        ↓
Traversal Algorithm
```

Heap이나 Search Tree 계열은 Tree 구조에 추가 조건을 두어 특정 연산을 효율적으로 수행하도록 만든다.

전체 지도에서는 개별 Tree 종류를 모두 펼치지 않고 **계층 표현 → Traversal → 특정 연산을 위한 구조화**라는 위치만 잡는다.

→ [[04-트리-그래프]]

## 7. Graph는 일반적인 연결 관계를 표현하고 탐색한다

Tree보다 일반적인 연결 관계는 Graph로 표현할 수 있다.

```text
Graph
= Vertex + Edge
```

Graph를 사용하려면 먼저 관계를 표현해야 하고, 그다음 연결된 Vertex를 어떤 순서로 방문할지 결정해야 한다.

```text
관계를 Graph로 표현
        ↓
인접 행렬 / 인접 리스트
        ↓
Graph Traversal
├─ DFS
└─ BFS
```

DFS와 BFS는 자료구조와도 직접 연결된다.

```text
DFS
↔ Stack

BFS
↔ Queue
```

모든 Vertex를 방문하는 것과 별도로, 전체 Vertex를 최소 비용으로 연결하는 문제에서는 Minimum Spanning Tree(MST)를 다룬다.

```text
Graph
  ↓
모든 Vertex를 연결하되 비용을 최소화
  ↓
MST
├─ Kruskal
└─ Prim
```

Tree와 Graph는 별개의 Keyword 목록이 아니라 **관계 표현을 위한 Data Structure와 그 위에서 수행하는 Traversal/Search Algorithm이 만나는 지점**으로 본다.

→ [[04-트리-그래프]]

```text
│

│   └─ Algorithm의 시간·공간 비용을 어떻게 판단할 것인가
│

│   └─ 데이터를 어떤 순서로 만들고 원하는 값을 어떻게 찾을 것인가
│

    └─ 계층·연결 관계를 어떻게 표현하고 탐색할 것인가
```

Recursion은 별도 Zoom 지도를 전제로 하지 않는다. 전체 지도에서 문제 분해 방식과 Stack 실행 특성의 연결 위치를 잡고, 필요하면 세부학습으로 직접 내려간다.

교재의 `기타 알고리즘`처럼 서로 다른 목적의 Topic을 하나의 개념군으로 억지로 묶지 않는다. 전체 지도에서는 큰 관계를 만드는 데 필요한 Node만 남긴다.

## 9. 이 지도를 보는 순서

```text
문제와 데이터를 어떻게 표현할지 확인
  ↓
자료구조와 Algorithm의 관계 이해
  ↓
Time / Space 비용을 판단하는 기준 확인
  ↓
Sorting · Search에서 구조와 비용의 관계 확인
  ↓
Tree · Graph에서 관계 표현과 Traversal 연결
  ↓
필요한 Zoom 지도와 세부학습으로 이동
```

전체 지도에서 모든 자료구조의 연산, 정렬 과정, Search 단계, Tree 종류와 Graph Algorithm을 이해하려 하지 않는다. **여기서는 어떤 문제에 어떤 개념군이 연결되고, 자료구조·Algorithm·복잡도가 어떻게 맞물리는지만 잡으면 된다.**
