# 정보관리기술사 개념지도 공통 원칙

## 0. 작성 전 필수 확인

개념지도를 새로 작성하거나 수정하기 전에 다음 문서를 반드시 먼저 확인한다.

1. [`../00-문서작성-공통원칙.md`](../00-문서작성-공통원칙.md)
2. [`docs/KNOWLEDGE_ORGANIZATION.md`](../../../docs/KNOWLEDGE_ORGANIZATION.md)
3. [`docs/WRITING_STYLE.md`](../../../docs/WRITING_STYLE.md)
4. 이 문서(`00-개념지도-공통원칙.md`)

상위 문서를 확인하지 않은 상태에서 개념지도 작성을 시작하지 않는다.

개념지도는 **학습할 개념의 위치와 관계를 연결해, 큰 그림에서 필요한 개념으로 파고들고 나중에는 핵심 Node를 보고 세부 이해를 다시 떠올릴 수 있게 만드는 탐색·복습 지도**다.

학습 대상과 A/B/C 우선순위는 `../학습등급표/`에서 정하고, 상세한 동작 원리와 이해 기록은 `../세부학습/`에서 다룬다.

### 상위 공통 원칙은 반복하지 않는다

개념을 어떤 단위로 묶을지, 실제 관계를 어떻게 표현할지, 인과가 없는 대상을 억지 스토리로 만들지 않는 기준은 저장소 공통 원칙을 그대로 따른다. 이 문서에서는 **개념지도에만 필요한 깊이·인출·학습 경로 규칙**만 추가한다.

## 1. 자료별 역할

```text
교재 · 기출 · 공식 출제기준
        ↓
학습등급표
= 무엇을 얼마나 우선해서 공부할 것인가
        ↓
개념지도
= 개념이 어디에 있고 무엇과 연결되는가
  + 복습할 때 무엇을 떠올려야 하는가
        ↓
세부학습
= 선택한 개념을 왜 필요한지부터 깊게 이해
```

개념지도는 교재 목차를 다시 나열하거나 세부학습을 압축한 요약본이 아니다.

## 3. 상위·하위·인접 관계를 우선한다

개념은 이름이 비슷하거나 교재 번호가 가깝다는 이유로 연결하지 않는다.

```text
상위 개념
  ↓
현재 개념
├─ 하위 개념 A
├─ 하위 개념 B
└─ 하위 개념 C

인접 개념
↔ 목적·방법·적용 조건 비교
```

## 6. 개념지도 Node와 세부학습 File은 1:1이 아니다

각 Node는 파고들 개념 꼭지지만, 세부학습에서는 하나의 이해 흐름이면 여러 Node를 한 문서에서 함께 다룰 수 있다.

> **개념지도 Node = 파고들 개념 꼭지 + 복습할 때 세부 이해를 꺼내는 인출 단서**
>
> **세부학습 File = 함께 이해할 때 좋은 학습 단위**

## 7. 적정 깊이

개념지도는 목차보다 깊고 세부학습보다 얕다.

적극적으로 남긴다.

- 학습할 가치가 있는 핵심 용어
- 큰 개념군 사이의 위치·관계·경계
- 직접 의존 관계
- 다음 학습 가지를 선택하는 데 필요한 짧은 이유·조건
- 복습할 때 세부 이해를 다시 꺼내는 대표적인 인출 Node

세부학습 또는 하위 지도로 내린다.

- 상위 Node만으로 자연스럽게 떠올릴 수 있는 하위 분류
- 세부 기법·대표 예시의 나열
- 수식 전개와 내부 Algorithm 상세 단계
- Parameter별 동작, 긴 예제, 구현 Code, 제품별 설정
- 핵심 Node를 보고 연상할 수 있는 상세 설명 자체

## 8. 전체 개념지도에 모든 것을 펼치지 않는다

영역 전체 개념지도는 **그 영역의 모든 핵심 Keyword를 한 문서에서 설명하는 문서가 아니다.** 하위 개념을 계속 펼치면 큰 관계보다 세부 목록이 먼저 보이고 개념지도와 요약노트의 경계가 흐려진다.

```text
영역 전체 지도
= 큰 개념군의 위치·관계·학습 진입점
        ↓ 필요한 곳만
하위 개념지도
= 한 개념군 내부의 관계를 한 단계 더 펼침
        ↓
세부학습
= 원리·동작·세부 비교·예제
```

전체 지도에서 Node를 남길 때는 다음을 우선 확인한다.

- 이 Node가 없으면 영역의 큰 그림이나 주요 경로가 끊기는가?
- 이 Node가 있어야 서로 다른 큰 개념군의 경계가 보이는가?
- 이 Node 자체가 세부 내용을 떠올리는 대표적인 인출 좌표인가?

위 질문에 해당하지 않고 **상위 Node를 보면 자연스럽게 떠올릴 수 있는 하위 분류·세부 기법·대표 예시**라면 전체 지도에서 펼치지 않는 것을 우선한다.

```text
전체 지도
Transaction
├─ 동시성 제어
└─ 회복

필요한 Zoom
동시성 제어
├─ Lock
├─ 격리수준
└─ MVCC
```

> **큰 그림을 이해하면서 세부를 채우는 것이 목적이지, 큰 그림 문서 안에 세부를 모두 채우는 것이 목적은 아니다.**

## 9. 하위 개념지도는 고정 단계가 아니라 필요한 Zoom 단위다

전체 지도 아래에 하위 지도를 기계적으로 만들지 않는다.

```text
전체 지도
  ↓
연관 개념을 한 번 더 함께 보면 이해가 좋아지는가?
  ├─ Yes → 하위 개념지도
  │          ↓
  │        세부학습
  └─ No  → 세부학습으로 직접
```

몇 개의 개념이라도 함께 보았을 때 위치·차이·경계가 더 잘 이해된다면 하나의 Zoom 단위가 될 수 있다. 반대로 파일 길이, Keyword 수, 교재 Chapter 구분만으로 하위 지도를 만들지 않는다.

> **파일 수를 늘리는 것이 목적이 아니라 필요한 곳에서만 탐색 밀도를 높이는 것이 목적이다.**

## 10. 영역 전체 지도와 하위 지도의 역할을 구분한다

```text
영역 전체 개념지도
= 어느 학습 가지로 들어갈지 선택
  + 큰 가지의 대표적인 핵심 좌표로 세부 내용을 연상
        ↓
필요한 하위 개념지도
= 연관 개념을 함께 보며 관계를 더 촘촘히 탐색
        ↓
세부학습
= 원리·동작·차이·Trade-off를 깊게 이해
```

영역 전체 지도는 가능한 많은 하위 개념을 담는 문서가 아니다. **큰 가지의 위치와 관계가 한눈에 보이는 것을 우선하고 대표적인 인출 좌표만 남긴다.**

## 11. 쉬운 큰 그림과 복습용 핵심 Node를 함께 유지한다

진입 난도를 낮추는 것과 핵심 용어를 제거하는 것은 다르다.

```text
쉬운 큰 질문
  ↓
정확한 핵심 개념명과 관계
  ↓
대표적인 인출 Node
  ↓
필요한 하위 지도에서 관계를 더 촘촘히 Zoom-in
  ↓
세부학습의 원리·동작·예제
```

> **Zoom-in은 전체 지도에 하위 Node를 계속 추가하는 과정이 아니라, 필요한 부분을 별도 밀도로 펼치는 과정이다.**

## 12. 처음 보는 핵심 용어 때문에 탐색이 끊기지 않게 한다

정확한 용어는 유지하되, 처음 보는 학습자가 다음 Node로 이동할 수 있을 정도의 짧은 설명을 제공한다.

- 핵심 약어는 필요할 때 처음 한 번 원어와 역할을 설명한다.
- 낯선 공식 용어는 지도를 읽는 데 필요한 최소한의 의미를 붙인다.
- 이미 충분히 익숙한 용어를 기계적으로 풀어 쓰지 않는다.

## 13. Text/ASCII Diagram을 기본으로 한다

모바일 GitHub, Obsidian, Terminal 등 어디서든 읽을 수 있도록 Text/ASCII Diagram을 기본으로 한다. 분기·합류가 복잡해 Mermaid가 명확한 이점을 줄 때만 선택적으로 사용한다.

## 14. 학습등급표에서 출발하되 그대로 복사하지 않는다

학습등급표의 A/B/C는 **정보관리기술사 학습에서 개별 Topic에 투입할 깊이와 우선순위**를 정하는 기준이다. 개념지도 포함 여부를 정하는 등급이 아니다.

- B/C Topic이 지도에 직접 나타나지 않는다는 이유만으로 누락으로 판단하지 않는다.
- 등급이 낮거나 학습등급표에 없는 개념이라도 큰 그림을 연결하는 데 필요하면 Node로 포함할 수 있다.
- 누락 여부는 개별 Topic 커버리지보다 **정보관리기술사 관점에서 필요한 큰 개념군과 관계가 빠졌는가**를 우선한다.
- 겸용 교재의 Chapter·Part 자체를 개념지도의 필수 범위로 간주하지 않는다.
- 기출됐다는 이유만으로 지엽적인 Topic을 지도에 올리지 않는다.

## 15. 파일 번호로 정규 학습 가지와 횡단·보강 지도를 구분한다

```text
00-*   = 영역 전체 지도
01-* ~ = 정보관리기술사 관점의 정규 학습 가지
99-*   = 정규 학습 가지는 아니지만 큰 그림 이해에 필요한 횡단·보강 지도
```

`99-*`는 시험 범위를 임의로 확장하는 기타 분류가 아니다. 정규 지도만으로 핵심 개념 사이의 연결이 끊기거나 다른 영역과의 경계·기반 구조를 이해하기 어려울 때만 만든다.

## 16. 세부학습과 왕복하며 지도를 보정한다

```text
개념지도에서 위치·관계 파악
        ↓
세부학습에서 원리·동작 이해
        ↓
새로운 관계·경계·의존성 발견
        ↓
개념지도 보정
```

세부학습에서 발견한 관계가 전체 지도에 필요하더라도 그 아래 세부 Node까지 함께 올릴 필요는 없다. **전체 지도에는 관계를 복원하는 데 필요한 최소한의 대표 Node만 반영한다.**

## 17. Obsidian 내부 링크는 실제 학습 경로에만 둔다

개념지도에서 실제로 세부학습으로 이동할 가치가 있는 지점에만 `[[...]]` 링크를 둔다.

- 존재하지 않는 세부학습 파일을 가정해 링크하지 않는다.
- 단순 관련성만으로 모든 Node에 링크를 붙이지 않는다.

## 18. 작성 후 확인

```text
[ ] 첫 화면에서 영역의 큰 가지와 관계가 먼저 보이는가?
[ ] 한 문서에서 모든 핵심 Keyword를 펼치려 하고 있지는 않은가?
[ ] 상위 Node만으로 떠올릴 수 있는 하위 분류·기법을 불필요하게 펼치지 않았는가?
[ ] 더 자세히 볼 필요가 있는 부분은 하위 지도 또는 세부학습으로 내렸는가?
[ ] 교재 목차를 그대로 옮긴 것은 아닌가?
[ ] B/C Topic이 없다는 이유만으로 기계적으로 추가하지 않았는가?
[ ] 정보관리기술사 관점에서 필요한 큰 개념군이나 관계가 빠지지는 않았는가?
[ ] 서로 다른 분류축을 한 흐름처럼 섞지 않았는가?
[ ] 실제 인과가 없는 곳에 스토리를 억지로 만들지 않았는가?
```

## 19. 한 문장 원칙

> **개념지도는 모든 세부를 한 문서에 펼치는 요약본이 아니라, 큰 개념군의 위치와 관계를 먼저 보여주고 필요한 부분만 단계적으로 Zoom-in하여 세부학습으로 연결하는 탐색·복습 지도다.**
