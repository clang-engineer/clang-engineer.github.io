# 정보관리기술사 전체 개념지도

이 문서는 열 권의 기술영역이 정보시스템 전체에서 **어디에 위치하고 어떻게 연결되는지** 잡는 최상위 개념지도다.

개별 Topic의 중요도와 학습 우선순위는 `../학습등급표/`에서 정하고, 영역별 세부 개념망은 각 개념지도 문서에서 확장한다.

## 1. 정보시스템 전체에서의 위치

```text
기업·사회가 해결하려는 문제
        ↓
IT 전략 · Governance · 투자 · 성과                    [IT 경영]
        ↓
요구사항 → 설계 → 구현 → 시험 → 배포 · 유지보수      [소프트웨어 공학]
        ↓
애플리케이션이 다루는 Data의 구조 · 품질 · 활용       [데이터베이스]
        ↓
컴퓨팅 자원의 추상화 · 실행 · 통신                     [운영체제 · 네트워크]
        ↓
CPU · Memory · I/O라는 물리적 기반                     [컴퓨터 구조]

보안
= 위 모든 계층의 위험과 통제를 횡단

Cloud
= SW · Data · Infra를 서비스 형태로 통합 · 운영

AI
= Data와 Model을 이용해 예측 · 생성 · 자동화

Algorithm
= 여러 영역의 문제 해결에 필요한 계산 원리
```

이 그림은 교재 순서를 뜻하지 않는다. 개별 Topic을 공부할 때 **현재 개념이 정보시스템 전체의 어느 층에 있고 어느 영역과 연결되는지 찾는 좌표**다.

## 2. 영역별 중심 질문

```text
컴퓨터 구조
→ CPU · Memory · I/O의 물리적 제약은 무엇인가?

운영체제
→ 한정된 실행 자원을 어떻게 안전하고 효율적으로 공유하는가?

네트워크
→ Data를 시스템 사이에서 어떻게 전달하는가?

보안
→ 자산과 전 과정의 위험을 어떻게 통제하는가?

소프트웨어 공학
→ 요구를 품질 있는 Software로 어떻게 전환하고 변화시키는가?

알고리즘
→ 문제를 정확하고 효율적인 계산 절차로 어떻게 표현하는가?

IT 경영
→ IT가 조직의 목표 · 투자 · 성과와 어떻게 연결되는가?

데이터베이스
→ Data를 구조화하고 정합성 · 성능 · 품질을 어떻게 유지하는가?

인공지능
→ Data · 지식 · Feedback으로 어떻게 예측 · 생성 · 의사결정하는가?

클라우드
→ Computing 자원을 서비스화해 확장성 · 탄력성 · 회복력을 어떻게 얻는가?
```

현재 영역별 개념지도가 존재하는 인공지능은 [[09-인공지능/00-전체|인공지능 전체 개념지도]]에서 이어서 탐색한다.

## 3. 아래에서 위로 보는 기술 계층

```text
컴퓨터 구조
CPU · Memory · Storage · I/O
        ↓
운영체제
Process · Thread · Memory · File · I/O 자원 관리
        ↓
네트워크
Host와 Service 사이의 통신
        ↓
데이터베이스
Application Data의 저장 · 조회 · Transaction
        ↓
소프트웨어 공학
이 기술들을 조합해 Service를 구축 · 변경
        ↓
IT 경영
Service와 투자를 조직 목표 · Governance와 연결
```

실제 시스템에서는 이 층들이 독립적으로 존재하지 않는다. 예를 들어 DB 성능 문제를 파면 Storage · Memory · OS · Network까지 내려갈 수 있고, Cloud는 이 여러 계층을 가상화·자동화해 서비스로 제공한다.

## 4. 횡단하는 영역

### 보안

```text
기획
 ↓
설계
 ↓
개발
 ↓
Data
 ↓
Infra / Network
 ↓
운영

[전 과정]
기밀성 · 무결성 · 가용성
인증 · 권한 · 감사
위협 · 취약점 · Risk
```

보안은 특정 한 층이라기보다 전 영역에 반복해서 붙는 횡단 개념이다.

### 알고리즘

```text
Algorithm
├─ DB       → Tree · Hash · 정렬 · 탐색
├─ Network  → Routing · Graph
├─ AI       → 탐색 · 최적화 · 학습
└─ SW       → 문제 해결과 효율성
```

알고리즘도 하나의 Application 영역이라기보다 여러 기술의 내부 원리를 설명하는 기반으로 연결된다.

## 5. 현대 시스템에서 다시 만나는 영역

### Cloud

```text
컴퓨터 구조의 물리 자원
        +
운영체제의 가상화 · 자원관리
        +
네트워크의 연결 · 격리
        +
보안의 공유책임 · 통제
        +
운영 자동화
        ↓
Cloud Service
```

### AI

```text
Data 확보 · 품질                    [DB]
        ↓
학습 · 추론 Algorithm               [AI · Algorithm]
        ↓
Compute · GPU · Memory              [컴퓨터 구조]
        ↓
배포 · 자원관리                      [OS · Cloud]
        ↓
API · 분산 통신                      [Network]
        ↓
보안 · 개인정보 · 책임               [Security · Governance]
```

AI와 Cloud는 기존 기본영역과 별개의 섬이라기보다 여러 기반기술이 다시 합쳐지는 지점이다.

## 6. 대표적인 권간 연결

```text
가상 Memory
운영체제 ↔ 컴퓨터 구조(MMU · TLB) ↔ Cloud 가상화

Cache · Locality
컴퓨터 구조 ↔ 운영체제 ↔ DB 성능

SDN · NFV
네트워크 ↔ Cloud

BCP · DR · RTO · RPO
IT 경영 ↔ 보안 ↔ Cloud

Data 품질 · Metadata · Governance
데이터베이스 ↔ AI ↔ IT 경영

보안 통제
보안 ↔ 모든 영역
```

같은 개념이 여러 권에 나타나면 어느 한 권만 정답이라고 보기보다 **각 영역이 그 개념을 어떤 관점으로 보는지** 구분한다.

## 7. 개념지도를 사용하는 법

예를 들어 `가상 Memory`를 잡았다면:

```text
상위
운영체제의 Memory 관리
 ↓
가상 Memory

아래로 파기
Paging · Page Table · Page Fault · Replacement

옆으로 연결
Segmentation · Cache

Hardware 쪽 연결
MMU · TLB

현대 응용 연결
Virtualization · Cloud
```

즉 전체 개념지도는 모든 Topic을 설명하는 문서가 아니다.

> **개념 하나를 잡았을 때 어느 영역으로 위·아래·옆으로 이동할 수 있는지 보여주는 최상위 좌표다.**

영역별 세부 개념지도는 이 구조 아래에서 필요한 만큼 확장한다.
