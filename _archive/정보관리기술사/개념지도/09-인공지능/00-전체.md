# 인공지능 전체 개념지도

이 문서는 `../../학습등급표/09-인공지능.md`에서 정한 학습 범위를 **개념 관계로 재배치한 최상위 탐색 지도**다.

AI(Artificial Intelligence, 인공지능) 전체의 위치를 먼저 잡고, ML(Machine Learning, 데이터에서 패턴을 학습하는 기계학습)·DL(Deep Learning, 다층 신경망 기반 학습)은 [[01-ML-DL|ML·DL 개념지도]], 생성형 AI·LLM(Large Language Model, 대규모 언어 모델)은 [[02-생성형AI-LLM|생성형 AI·LLM 개념지도]]로 내려가 관계를 더 촘촘히 본다. 세부 동작 원리·수식·Algorithm·예제는 `../../세부학습/09-인공지능/`에서 다룬다.

## 1. AI 전체 좌표

```text
AI
│
├─ 지식·규칙 기반
│   └─ Rule / 전문가 시스템
│
├─ Data에서 Pattern 학습
│   └─ ML
│       ├─ 고전 ML
│       └─ Neural Network / DL
│            └─ Transformer
│
├─ 사전학습된 범용 Model 활용
│   └─ Foundation Model
│       ├─ LLM
│       ├─ Vision
│       └─ Multimodal
│
├─ 응용
│   ├─ 예측 · 분류 · 군집
│   ├─ 추천
│   ├─ NLP(Natural Language Processing, 자연어 처리) / 음성 / Vision
│   └─ 생성형 AI / Agent
│
└─ 전 영역 통제
    ├─ 평가 · 검증
    ├─ Data 품질 · 개인정보
    ├─ Bias / Fairness / XAI(Explainable AI, 설명가능 AI)
    ├─ 보안
    └─ 윤리 · 책임 · Governance
```

핵심은 `AI = LLM`이 아니라는 것이다. LLM·RAG(Retrieval-Augmented Generation, 검색한 외부 지식을 LLM에 함께 제공하는 방식)·Agent는 AI 전체 중 Foundation Model과 생성형 AI 활용 영역에 위치한다.

## 2. 어디를 파고들 것인가

### ML · DL

Data에서 Pattern을 학습하는 방식과 Neural Network·DL로 확장되는 관계를 본다.

```text
ML
├─ 지도 / 비지도 / 강화
├─ 고전 ML
└─ Neural Network / DL
       ↓
   Transformer
```

Algorithm별 선택 기준, 신경망 구조, 평가·검증은 하위 지도에서 더 펼친다.

→ [[01-ML-DL|ML·DL 개념지도]]

### Foundation Model · 생성형 AI · LLM

이 영역은 하나의 발전 순서가 아니라 **서로 다른 질문의 축**을 먼저 나눠 본다.

```text
[범용 Model 계열]
Foundation Model
├─ Language Foundation Model → LLM
├─ Vision Foundation Model
└─ Multimodal Foundation Model

[생성 목적]
Generative AI
├─ Text
├─ Image
├─ Audio / Video
└─ Multimodal

[이미 만들어진 Model의 활용]
Prompt / Context
RAG
Fine-tuning
Tool / Agent
```

Transformer·Foundation Model·Generative AI·LLM은 같은 개념이 아니며, 각각 **Architecture·Model 범용성·생성 목적·언어 Model**이라는 서로 다른 위치를 가진다. Prompt·RAG·Fine-tuning·Agent 역시 서로의 필수 다음 단계가 아니라 목적에 따라 선택·조합하는 활용 기술이다.

→ [[02-생성형AI-LLM|생성형 AI·LLM 개념지도]]

### 응용

Model 자체와 해결하려는 업무 문제는 구분한다.

```text
AI 기술
  ↓
응용 Task
├─ 추천
├─ NLP / 음성
├─ Vision
├─ 예측 · 분류
├─ Text2SQL
└─ 업무 자동화
```

같은 Task도 Rule, 전용 ML, Foundation Model 등 여러 방식으로 해결할 수 있다.

### 평가 · 운영 · 통제

평가와 통제는 특정 Model의 마지막 단계가 아니라 AI 전 영역을 가로지르는 축이다.

```text
문제 정의 → Data → Model → Evaluation → Deployment → Monitoring
   └──────────────────────────────────────────────┘
      품질 · 개인정보 · Bias · XAI · 보안 · Governance
```

## 3. 기억할 큰 경계

```text
[문제 해결 방식]
Rule / ML / Foundation Model 활용

[Model · Architecture]
고전 ML / Neural Network / Transformer / Foundation Model

[응용]
추천 / Vision / NLP / 생성 / 자동화

[통제]
평가 / Data / 공정성 / 설명가능성 / 보안 / Governance
```

서로 다른 분류축을 한 발전 순서처럼 연결하지 않는다.

## 4. 탐색 방식

```text
학습등급표
"무엇을 얼마나 볼 것인가"
        ↓
인공지능 전체 개념지도
"어느 큰 가지에 있는가"
        ↓
┌──────────────────────────┐
│ ML·DL                    │
│ 생성형 AI·LLM            │
│ 응용                     │
│ 평가·운영·통제           │
└────────────┬─────────────┘
             ↓
          하위 지도
"관계와 비교를 더 촘촘히"
             ↓
          세부학습
"왜 필요하고 어떻게 동작하는가"
```

위 화살표는 실제 Runtime 호출 순서가 아니라 **학습·탐색을 위해 큰 그림에서 세부로 내려가는 Zoom-in 관계**를 나타낸다.

전체 지도에서는 대표 좌표까지만 남긴다. 개별 ML Algorithm, CNN·RNN·LSTM 같은 Architecture 상세, Prompt·RAG·Fine-tuning·Agent 내부 관계처럼 **한 가지 내부를 더 펼쳐야 하는 내용은 하위 지도에서 다룬다.**
