# 운영체제 전체 개념지도

이 문서는 `../../학습등급표/02-운영체제.md`에서 정한 학습 범위를 **개념 관계로 재배치한 최상위 탐색 지도**다.

운영체제는 CPU·Memory·Storage·I/O 같은 물리 자원을 Application이 직접 다루지 않아도 되도록 추상화하고, 여러 실행 주체가 한정된 자원을 안전하고 효율적으로 공유하게 한다.

이 문서에서는 세부 Algorithm과 비교를 펼치지 않고 **어느 큰 학습 가지로 내려갈지와 각 가지가 어떻게 연결되는지**만 잡는다. 세부 관계는 하위 개념지도에서, 동작 원리·예제·계산은 세부학습에서 다룬다.

## 1. 운영체제 전체 좌표

```text
운영체제
│
├─ 실행 모델과 CPU 배분
│   ├─ Process / Thread
│   ├─ System Call / Kernel
│   ├─ Scheduling
│   └─ Context Switch
│
├─ 동시성과 자원 공유
│   ├─ Race Condition
│   ├─ Synchronization
│   ├─ Deadlock
│   └─ IPC
│
├─ Memory 관리
│   ├─ Paging / Segmentation
│   ├─ Virtual Memory
│   └─ Page Fault / Thrashing
│
├─ File과 I/O
│   ├─ File System
│   └─ Device I/O
│
└─ 가상화와 운영 품질
    ├─ Virtualization
    ├─ Performance / Capacity
    └─ HA / Checkpointing
```

운영체제의 중심 관점은 다음 다섯 축이다.

```text
추상화
자원 배분
격리
동시성
성능과 안전성의 Trade-off
```

## 2. 어디를 파고들 것인가

### 실행 모델과 CPU 배분

프로그램이 실행 단위가 되고, 여러 실행 주체가 한정된 CPU를 나누어 쓰는 관계를 본다.

```text
Program → Process / Thread
              ↓
        CPU 경쟁 발생
              ↓
          Scheduling
              ↓
        Context Switch
```

→ [[01-실행모델-CPU-배분|실행 모델과 CPU 배분 개념지도]]

### 동시성과 자원 공유

여러 실행 주체가 자원을 공유할 때 생기는 실행 순서·대기·협업 문제를 본다.

```text
공유 자원
  ↓
동시 접근
  ↓
Race Condition
  ↓
Synchronization
  ↓
Deadlock / IPC와 연결
```

→ [[02-동시성-자원공유|동시성과 자원 공유 개념지도]]

### Memory 관리

프로세스별 주소 공간을 만들고, 한정된 물리 Memory를 배치·보호·확장해서 사용하는 구조를 본다.

```text
주소 공간
  ↓
Paging / Segmentation
  ↓
Virtual Memory
  ↓
Page Fault / Thrashing
```

→ [[03-메모리-관리|Memory 관리 개념지도]]

### File과 I/O

Application이 보호된 Device와 Storage를 공통 Interface로 사용하는 구조를 본다.

```text
Application
  ↓
System Call
  ↓
Kernel
  ↓
File System / Device I/O
```

### 가상화와 운영 품질

자원 추상화·격리를 더 큰 단위로 확장하고, 운영 중 성능·용량·가용성을 관리하는 축이다.

```text
자원 추상화·격리
  ↓
Virtualization

운영 Workload
  ↓
Performance / Capacity / HA
```

## 3. 다른 영역과 만나는 지점

```text
컴퓨터 구조
MMU / TLB / Cache / Interrupt
        ↕
운영체제
Process / Scheduling / Virtual Memory / I/O
        ↕
Cloud · 분산 시스템
Virtualization / Resource Pooling / HA
```

Memory의 주소 변환 구조는 컴퓨터 구조와 직접 연결되고, Virtualization과 운영 품질은 Cloud·분산 시스템으로 확장되는 연결점이다.

## 4. 탐색 방식

```text
학습등급표
"무엇을 얼마나 볼 것인가"
        ↓
운영체제 전체 개념지도
"어느 큰 가지를 팔 것인가"
        ↓
┌──────────────────────────┐
│ 실행 모델·CPU 배분       │
│ 동시성·자원 공유         │
│ Memory 관리              │
│ File·I/O                  │
│ 가상화·운영 품질         │
└────────────┬─────────────┘
             ↓
          하위 지도
"관계와 비교를 더 촘촘히"
             ↓
          세부학습
"왜 필요하고 어떻게 동작하는가"
```

전체 지도에서는 대표 Node까지만 남긴다. 선점/비선점, Scheduling Algorithm별 차이, Deadlock 대응 방식, Paging 세부 동작처럼 **한 가지 내부에서 더 촘촘히 봐야 하는 내용은 하위 지도나 세부학습으로 내려간다.**
