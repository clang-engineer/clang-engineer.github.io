# 동시성과 자원 공유 개념지도

이 지도는 [[00-전체|운영체제 전체 개념지도]]에서 **Process·Thread가 자원을 공유할 때 왜 실행 순서가 문제가 되고, 이를 어떻게 통제하며, 통제 자체가 어떤 대기 문제를 만드는지** 함께 본다.

핵심 흐름은 `공유 → Race Condition → Critical Section → Synchronization → 대기 비용 → Deadlock`이다. IPC는 격리된 Process가 협업하기 위한 별도 축으로 이 흐름과 연결한다.

## 1. 먼저 큰 흐름을 잡는다

```text
여러 Process / Thread가 동시에 실행
        ↓
Data / Resource 공유
        ↓
실행 순서에 따라 결과가 달라질 수 있음
        ↓
Race Condition
        ↓
Critical Section 식별
        ↓
Mutual Exclusion / Synchronization
        ↓
안전한 공유 가능
        +
Waiting / Contention 발생
        ↓
잘못된 자원 대기 관계
        ↓
Deadlock 가능
```

동기화는 문제를 없애는 무료 Mechanism이 아니다. **안전성을 얻는 대신 대기·경합·교착 가능성이라는 비용**이 생긴다.

## 2. 동시성과 병렬성은 같은 말이 아니다

```text
Concurrency
= 여러 작업의 진행 구간이 겹치며 함께 진행되는 구조

Parallelism
= 여러 작업이 실제로 같은 시점에 여러 실행 자원에서 수행되는 상태
```

단일 CPU에서도 Scheduling으로 여러 Task가 번갈아 진행되면 동시성 문제는 발생할 수 있다. 따라서 Race Condition은 Multi-core에서만 생기는 문제가 아니다.

## 3. 공유 자원에 동시에 접근하면 Race Condition이 생긴다

```text
공유 Data
  ↓
Task A와 Task B가 동시에 읽고 수정
  ↓
실행 순서가 매번 달라질 수 있음
  ↓
결과가 Timing에 의존
  ↓
Race Condition
```

Race Condition이 문제가 되는 Code 영역을 Critical Section으로 본다.

```text
Critical Section
= 공유 자원에 접근해 동시에 실행되면 일관성이 깨질 수 있는 구간
```

따라서 모든 Code를 막는 것이 아니라 **보호가 필요한 Critical Section의 동시 진입을 통제**한다.

## 4. Mutual Exclusion과 Synchronization의 관계

```text
Synchronization
= 여러 실행 흐름의 순서·진행 조건을 조정하는 큰 개념

Mutual Exclusion
= Critical Section에 한 번에 하나만 들어가게 하는 동기화 목적
```

```text
Synchronization
├─ Mutual Exclusion
│   └─ 동시에 들어가지 못하게 함
└─ Ordering / Coordination
    └─ 특정 사건이나 조건 뒤에 실행되게 함
```

둘을 완전히 같은 말로 놓지 않는다. 상호배제는 동기화가 해결하는 중요한 문제 중 하나다.

## 5. Semaphore는 상호배제와 실행 순서 조정에 사용된다

```text
Semaphore
├─ 공유 자원의 사용 가능 상태를 표현
├─ Mutual Exclusion에 활용
└─ Task 사이 실행 순서 Synchronization에 활용
```

이 지도에서는 Semaphore 연산 구현이나 Code보다 역할을 잡는다.

```text
Task가 자원 사용을 요청
  ↓
사용 가능?
├─ Yes → 진입 / 사용
└─ No  → 대기
        ↓
다른 Task가 자원 반환
        ↓
대기 Task 진행 가능
```

동기화 Mechanism을 잘못 사용하면 불필요한 직렬화, 긴 대기, Deadlock을 만들 수 있다.

## 6. 동기화에는 Contention과 Priority Inversion 비용이 붙는다

```text
Critical Section 보호
  ↓
동시에 진입하지 못함
  ↓
Waiting / Contention
```

우선순위 Scheduling과 공유 자원이 만나면 Priority Inversion이 생길 수 있다.

```text
낮은 Priority Task가 Lock 보유
        ↓
높은 Priority Task가 그 Lock을 기다림
        ↓
높은 Priority Task가 낮은 Task 때문에 진행하지 못함
        ↓
Priority Inversion
```

대표적인 완화 원리는 다음과 같이 위치만 잡는다.

```text
Priority Inversion
├─ Priority Inheritance
└─ Priority Ceiling
```

이 문제는 [[01-실행모델-CPU-배분|실행 모델과 CPU 배분]]의 Priority Scheduling과 이 지도의 Synchronization이 만나는 경계다.

## 7. 여러 자원을 점유하고 기다리면 Deadlock이 가능하다

Deadlock은 단순히 오래 기다리는 상태와 구분한다.

```text
Task A: Resource 1 보유 → Resource 2 대기
Task B: Resource 2 보유 → Resource 1 대기
        ↓
서로 상대가 가진 자원을 기다림
        ↓
진행 불가
        ↓
Deadlock
```

Deadlock의 네 조건은 발생 가능성을 판단하는 핵심 Node다.

```text
Deadlock 조건
├─ Mutual Exclusion
├─ Hold and Wait
├─ No Preemption
└─ Circular Wait
```

네 조건이 모두 성립할 수 있는 구조에서 Deadlock이 가능해진다.

## 8. Deadlock 대응은 서로 다른 전략으로 구분한다

```text
Deadlock 대응
│
├─ Prevention
│   └─ 발생 조건 중 하나가 성립하지 않게 설계
│
├─ Avoidance
│   └─ 자원 할당 전에 안전 상태를 유지할 수 있는지 판단
│       └─ Banker's Algorithm
│
└─ Detection / Recovery
    ├─ 발생을 허용하고 탐지
    └─ 발생 후 자원 회수·Task 종료 등으로 복구
```

`Prevention → Avoidance → Detection`은 발전 단계가 아니다. 시스템 특성과 비용에 따라 선택하는 대응 전략이다.

Banker's Algorithm은 Deadlock 전체의 해결책이 아니라 **Avoidance의 대표 예**라는 위치를 기억한다.

## 9. IPC는 격리된 Process가 협업하는 방법이다

Process는 서로 주소 공간이 격리되어 있으므로 협업하려면 통신 Mechanism이 필요하다.

```text
Process A        Process B
    │                │
    └──── IPC ───────┘
```

대표적인 큰 경계는 다음이다.

```text
IPC
├─ Shared Memory
│   ├─ 같은 Memory 영역을 공유
│   ├─ Data 전달 비용을 줄이기 유리
│   └─ 공유 Data Synchronization 필요
│
└─ Message Passing
    ├─ Message를 주고받아 협업
    └─ 격리 경계를 유지하기 쉬우나 전달 비용 존재
```

IPC와 Synchronization은 같은 개념은 아니지만 Shared Memory IPC에서는 둘이 강하게 연결된다.

## 10. 전체 관계를 다시 연결한다

```text
Process / Thread
        ↓
공유와 협업 필요
│
├─ 같은 자원에 동시 접근
│   ↓
│  Race Condition
│   ↓
│  Critical Section
│   ↓
│  Synchronization
│   ├─ Mutual Exclusion
│   └─ Semaphore 등
│       ↓
│   Waiting / Contention
│       ↓
│   Priority Inversion / Deadlock 가능
│
└─ 격리된 Process 사이 Data 교환
    ↓
   IPC
    ├─ Shared Memory ──→ Synchronization 필요
    └─ Message Passing
```

## 11. 복습용 핵심 좌표

```text
Concurrency ↔ Parallelism

공유 자원
→ Race Condition
→ Critical Section
→ Synchronization
   ├─ Mutual Exclusion
   └─ Semaphore
→ Waiting / Contention
   ├─ Priority Inversion
   │   ├─ Priority Inheritance
   │   └─ Priority Ceiling
   └─ Deadlock
       ├─ 4 Conditions
       ├─ Prevention
       ├─ Avoidance → Banker's Algorithm
       └─ Detection / Recovery

IPC
├─ Shared Memory → Synchronization과 연결
└─ Message Passing
```

이 Node를 보고 `왜 동기화가 필요한가`, `동기화가 어떤 새 비용을 만드는가`, `Deadlock 대응 전략은 무엇이 다른가`, `IPC와 Synchronization은 어디서 만나는가`를 떠올릴 수 있으면 된다. Semaphore 구현 Code와 Banker's Algorithm 계산은 세부학습으로 내려간다.
