# 통신·주소·경로 개념지도

이 지도는 **데이터를 같은 망 안에서 보내고, 다른 망까지 찾아가게 만드는 데 필요한 주소와 경로 개념**을 함께 본다.

처음에는 `L2`, `L3`, `Prefix` 같은 용어보다 다음 질문부터 잡는다.

```text
같은 망 안에서는 누구에게 보내지?
  ↓
MAC / Switch

다른 망에 있는 상대는 어떻게 구분하지?
  ↓
IP / Subnet / Gateway

멀리 있는 목적지까지 어느 길로 가지?
  ↓
Routing
```

이 세 질문을 따라가면서 정식 용어와 세부 관계를 단계적으로 붙인다.

## 1. 데이터는 여러 역할을 거쳐 전달된다

```text
응용 데이터
  ↓ 어떤 프로그램끼리 주고받는가
Transport
  ↓ 어느 Host까지 갈 것인가
IP
  ↓ 같은 Link에서 실제로 누구에게 전달할 것인가
Ethernet / WLAN
  ↓
물리 매체
```

목적지에서는 이 과정을 역순으로 풀어낸다(Decapsulation).

계층은 번호를 외우기보다 역할의 좌표로 본다.

```text
Link
= 같은 L2 영역에서 Frame 전달

Network
= IP 주소로 다른 Network까지 Packet 전달

Transport
= 종단 Process 사이의 전달 특성 제공
```

## 2. 같은 Network와 다른 Network

송신 Host 입장에서는 먼저 **목적지가 나와 같은 Subnet인가?**를 판단한다.

```text
송신 Host
  ↓
목적지 IP와 Subnet Mask 비교
  ↓
같은 Subnet인가?
  ├─ Yes → 목적지 MAC 확인 → 같은 망에서 직접 전달
  └─ No  → Default Gateway MAC 확인
               ↓
             Router
               ↓
          다른 Network로 전달
```

같은 Link의 IP를 MAC으로 해석하는 대표 Protocol이 ARP다. 다른 Network로 갈 때 Host가 찾는 MAC은 최종 목적지의 MAC이 아니라 **Default Gateway의 MAC**이다.

## 3. L2 Network 분리와 L3 Network 분리

여기서 `VLAN`과 `Subnet`의 경계를 잡는다.

```text
L2 영역
├─ Switch
├─ MAC Address
├─ Broadcast Domain
└─ VLAN
    └─ 하나의 물리 Switch 환경을 여러 논리 L2 영역으로 분리

L3 영역
├─ IP Address
├─ Prefix / Subnet Mask
└─ Subnet
    └─ IP Prefix 기준으로 Network 범위 분리
```

VLAN과 Subnet은 실제 설계에서 함께 쓰이는 경우가 많지만 같은 개념은 아니다.

→ [[VLAN-서브넷-브로드캐스트-도메인]]

## 4. IP 주소와 주소 공간 설계

```text
IP Address
├─ IPv4
│   └─ 주소 부족
│       ├─ 사설 주소
│       └─ NAT / PAT
└─ IPv6
    └─ 더 큰 주소 공간

주소 범위 표현·분할
├─ Prefix Length
├─ Subnetting
├─ VLSM
└─ CIDR
```

역할을 구분한다.

```text
Subnetting
= Network를 여러 Subnet으로 나누는 행위

VLSM
= Subnet마다 필요한 크기를 다르게 설계

CIDR
= Class 없이 Prefix로 주소 범위를 표현·할당·집약

DHCP
= Host에 IP·Mask·Gateway·DNS 등의 설정을 자동 제공

NAT / PAT
= Network 경계에서 주소 또는 주소·Port 대응을 변환
```

→ [[IP-주소-NAT-DHCP-CIDR-VLSM]]

## 5. Routing의 위치

다른 Network로 가야 한다면 Router는 **어느 방향으로 보낼지** 결정해야 한다.

```text
다른 Network로 전달 필요
  ↓
Routing Table
  ↓
목적지 Prefix와 비교
  ↓
Longest Prefix Match
  ↓
Next Hop / Interface 선택
  ↓
Packet Forwarding
```

Routing과 Forwarding을 같은 것으로 보지 않는다.

```text
Routing
= 경로 정보를 학습하고 좋은 경로를 결정

Forwarding
= 만들어진 Table을 이용해 실제 Packet을 다음 Hop으로 전달
```

## 6. Routing Protocol의 분류축

```text
Routing
├─ Static Routing
│   └─ 관리자가 경로 지정
└─ Dynamic Routing
    ├─ AS 내부
    │   ├─ Distance Vector
    │   │   └─ RIP
    │   └─ Link State
    │       └─ OSPF
    └─ AS 간
        └─ BGP
            └─ Path Vector / Policy
```

`RIP → OSPF → BGP`를 단순 발전 순서로 외우지 않는다. RIP와 OSPF는 AS 내부 Routing 문제를 서로 다른 방식으로 풀고, BGP는 **관리 주체가 다른 AS 사이**에서 정책을 포함해 경로를 선택한다.

→ [[라우팅-원리와-RIP-OSPF-BGP]]

## 7. 학습 이동 경로

```text
같은 망 안에서는 누구에게 보내는가?
  ↓
다른 망에 있는 상대는 어떻게 구분하는가?
  ↓
VLAN과 Subnet은 각각 어떤 경계를 나누는가?
  ↓
IP 주소 범위는 어떻게 표현하고 나누는가?
  ↓
Host는 Network 설정을 어떻게 얻는가?
  ↓
다른 Network로 갈 때 Gateway와 Router는 무엇을 하는가?
  ↓
Router들은 경로 정보를 어떻게 만들고 공유하는가?
```

Header 세부 필드, ARP 메시지 형식, Routing Algorithm의 계산 단계와 Timer는 세부학습으로 내려간다.
