# 명령 실행과 CPU 병렬성 개념지도

이 문서는 [컴퓨터 구조 전체 개념지도](00-전체.md)에서 **명령 실행과 CPU 병렬성** 가지를 선택했을 때, `명령 실행 → 처리량 확대 → 병렬성의 한계`를 하나의 학습 흐름으로 파고들기 위한 지도다.

## 1. 전체 좌표 — CPU 명령 실행과 병렬성

```text
CPU — 명령 실행
│
├─ 명령 체계 → ISA / Fetch·Decode·Execute
├─ 실행 효율 → Pipeline / Hazard
├─ 명령 수준 병렬성 → Superscalar / VLIW
├─ Core·Thread 병렬성 → Multicore / SMT
└─ 개선 한계 → Amdahl 법칙
```

Pipeline은 **명령의 실행 단계를 중첩**하고, Superscalar·VLIW는 **명령 수준 병렬성**을 활용하며, Multicore·SMT는 **Core·Thread 자원**을 활용한다. 서로 조합될 수 있으며 순차적인 교체 단계가 아니다.

### 핵심 용어

- **ISA:** 소프트웨어와 CPU가 약속한 명령 인터페이스
- **Hazard:** Data·Control·Structural 제약
- **ILP:** 명령 수준 병렬성
- **Superscalar / VLIW:** 하드웨어 동적 발행 / 컴파일러 중심 정적 병렬 구성
- **SMT:** 한 Core의 실행 자원을 여러 Thread가 활용

## 2. 명령 실행의 기반

```text
저장 프로그램 방식
  ↓
메모리에 명령과 데이터 저장
  ↓
CPU가 명령을 가져옴(Fetch)
  ↓
해석(Decode)
  ↓
실행(Execute)
```

ISA는 소프트웨어와 CPU 사이의 인터페이스다.

폰노이만 구조에서는 명령과 데이터가 같은 저장장치와 경로를 공유하므로 병목이 생길 수 있다. 이후 캐시·버스 개선과 파이프라이닝은 이 실행 흐름의 병목을 줄이는 방향으로 연결된다.

## 3. 파이프라이닝과 해저드

파이프라이닝은 여러 명령의 실행 단계를 겹쳐 처리해 처리량을 높인다.

```text
명령 1: Fetch → Decode → Execute
명령 2:         Fetch → Decode → Execute
명령 3:                 Fetch → Decode → Execute
```

단계를 겹치면 서로 독립적이지 않은 명령이나 공유 자원 때문에 문제가 생긴다.

```text
파이프라이닝
  ↓
동시에 여러 명령이 진행
  ↓
해저드
├─ 데이터 해저드   → 명령 사이 데이터 의존
├─ 제어 해저드     → 분기 결과를 아직 모름
└─ 구조 해저드     → 같은 하드웨어 자원을 동시에 요구
```

기술사 관점에서는 각 해저드의 세부 회로보다 **왜 생기고 어떤 방식으로 완화하며, 그 대가가 무엇인지**를 중심으로 본다.

## 4. 명령 수준 병렬성 확대

파이프라이닝이 실행 단계를 겹치는 구조라면 Superscalar와 VLIW는 한 시점에 더 많은 명령을 병렬 실행하려는 대표 구조다.

```text
명령 수준 병렬성(ILP)
├─ Superscalar
│   └─ 하드웨어가 실행 가능한 명령을 동적으로 찾아 병렬 실행
│
└─ VLIW
    └─ 컴파일러가 병렬 실행할 명령 묶음을 미리 구성
```

둘은 같은 문제를 다른 위치에서 해결한다.

```text
Superscalar
→ 하드웨어 복잡도 증가

VLIW
→ 컴파일러 책임과 코드 스케줄링 부담 증가
```

## 5. Core·Thread 수준 병렬성

```text
명령 하나의 실행 흐름을 개선
        ↓
명령 수준 병렬성
        ↓
더 큰 처리량이 필요
        ↓
실행 주체 자체를 늘림
├─ Multicore → 여러 Core
└─ SMT       → 한 Core의 실행 자원을 여러 Thread가 활용
```

Multicore와 SMT는 파이프라이닝의 단순 하위 단계가 아니다. 병렬성을 확보하는 수준이 다르다.

## 6. Amdahl 법칙으로 한계를 본다

병렬화 가능한 부분만 빨라지므로 전체 프로그램의 성능 향상에는 상한이 있다.

```text
전체 작업
├─ 병렬화 가능한 부분
└─ 순차 실행이 필요한 부분
        ↓
병렬 자원을 계속 늘려도
순차 부분은 그대로 남음
        ↓
전체 성능 향상에 상한
        ↓
Amdahl 법칙
```

따라서 CPU 병렬성은 `병렬화 기술 → 처리량 증가`만 보는 것이 아니라 **병렬화되지 않는 구간과 복잡도·전력 비용까지 함께** 본다.

## 7. 이해 복원

1. ISA와 명령어 실행 사이클은 어떤 관계인가?
2. Pipeline은 무엇을 중첩하며 Hazard는 왜 생기는가?
3. Superscalar와 VLIW는 병렬 실행을 누가 결정하는가?
4. Multicore와 SMT는 실행 자원을 어떻게 다르게 활용하는가?
5. Amdahl 법칙은 병렬화의 어떤 한계를 설명하는가?

**복원 단서:** 명령 체계 → 실행 효율 → 병렬성 수준 → 개선 한계. 이 순서는 기술 도입의 필수 단계가 아니다.
