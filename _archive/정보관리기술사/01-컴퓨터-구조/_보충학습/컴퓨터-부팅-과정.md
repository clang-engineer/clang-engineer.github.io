# 컴퓨터 부팅 과정 — BIOS · UEFI · Bootloader

> [컴퓨터 구조 전체 개념지도](../00-전체.md) · [I/O와 저장장치 개념지도](../03-IO-저장장치.md)에서 연결되는 **보충학습**이다. 저장공간을 나누는 기술이 아니라 **전원을 켠 뒤 OS를 실행하는 과정**을 이해한다.

## 1. 전체 구조 — 누가 무엇을 실행하는가?

```text
Power ON
   ↓
Firmware (BIOS 또는 UEFI)
   ├─ CPU·Memory·장치 초기화
   └─ 부팅 대상·경로 결정
   ↓
Bootloader 또는 EFI Boot Manager / EFI Application
   ↓
OS Kernel 로드·실행
   ↓
OS 초기화 → 사용자 환경
```

Firmware는 OS가 실행되기 전 동작하는 소프트웨어다. Bootloader는 OS Kernel을 적재하고 실행으로 넘기는 역할을 한다. UEFI 환경에서는 EFI 실행 파일이 Bootloader 역할을 하거나 Kernel을 직접 실행하는 등 구성에 따라 단계가 달라질 수 있다.

## 2. Legacy BIOS와 UEFI는 무엇이 다른가?

| 관점 | Legacy BIOS | UEFI |
|---|---|---|
| 부팅 방식 | 선택된 디스크의 부트 코드 실행(전통적 MBR 부팅) | EFI 실행 파일을 찾아 실행 |
| 대표 디스크 구성 | MBR Partition Table | GPT + EFI System Partition(ESP) |
| 부팅 프로그램 | MBR 부트 코드 → 후속 Bootloader | ESP 등의 EFI 프로그램 |
| 확장 기능 | 전통적인 펌웨어 인터페이스 | Boot Manager, Secure Boot 등 지원 |

**BIOS = MBR, UEFI = GPT라는 등식은 절대 규칙이 아니다.** 펌웨어 부팅 모드와 파티션 테이블 형식은 서로 다른 축이며, 위 표는 흔한 조합을 나타낸다.

## 3. GPT·MBR·ESP는 같은 개념인가?

```text
Disk
├─ Partition Table (영역의 위치·유형 기록)
│  ├─ MBR
│  └─ GPT
└─ Partition (실제 논리 영역)
   ├─ EFI System Partition (ESP) → EFI 부팅 파일
   └─ OS / Data Partition → File System 또는 LVM 등
```

- **MBR / GPT:** 파티션 정보를 기록하는 형식. MBR은 전통적인 부트 코드 영역도 포함한다.
- **Partition:** 디스크 주소 범위를 나눈 영역.
- **ESP:** UEFI 부팅 프로그램을 저장하는 특별한 Partition으로, 일반적으로 FAT 계열 파일시스템을 사용한다.
- **LVM:** 저장 자원을 PV·VG·LV로 관리하는 체계로, 부팅 펌웨어나 ESP와는 목적이 다르다.

ESP는 모든 디스크에 필요한 것이 아니라 **일반적인 UEFI OS 부팅 구성에 필요한 부팅 영역**이다. Windows에서는 시스템 파티션으로, Linux에서는 `/boot/efi` 등에 마운트된 형태로 볼 수 있다. 단, 마운트 위치는 배포판·설치 방식에 따라 다르다.

## 4. 대표 부팅 경로 비교

```text
[Legacy BIOS + MBR의 전통적 예]
Power ON → BIOS → MBR Boot Code → 후속 Bootloader
         → Kernel → OS 초기화

[UEFI + GPT의 일반적 예]
Power ON → UEFI Firmware → EFI Boot Manager
         → ESP의 .efi 프로그램 → Kernel → OS 초기화
```

UEFI에서는 Firmware가 NVRAM에 저장된 Boot Entry 등을 사용해 부팅 대상을 선택할 수 있다. Bootloader가 항상 독립된 프로그램으로 존재해야 하는 것은 아니다.

### Linux 설치 시에는 왜 EFI Partition이 보일까?

```text
SSD
├─ ESP (UEFI 부팅 파일)
├─ /boot (선택: Kernel·Bootloader 관련 파일)
└─ Linux 데이터 영역
   ├─ Partition → File System → /
   └─ 또는 PV → VG → LV → File System → /
```

ESP와 `/boot`는 같은 개념이 아니다. `/boot`를 별도 Partition으로 두는 것은 선택 사항이며, 배포판·암호화·부팅 구성에 따라 달라진다. **UEFI 부팅 여부와 LVM 사용 여부도 독립적**이다.

## 5. Secure Boot의 위치

Secure Boot는 UEFI 환경에서 부팅에 사용하는 코드의 서명·신뢰 관계를 검증하는 기능이다. **디스크 암호화나 RAID의 장애 보호 기능이 아니며**, 부팅 체인의 신뢰성을 높이는 메커니즘이다. 구체적인 신뢰 체인과 키 관리는 별도 심화 주제다.

3. ESP는 무엇을 저장하며 일반 데이터 Partition과 어떻게 다른가?
4. `/boot`와 ESP는 왜 항상 같은 영역이 아닌가?
5. Partition·LVM을 어떻게 구성하든 부팅 과정과 저장공간 관리를 구분해야 하는 이유는 무엇인가?

**인출 단서:** Firmware = 부팅 환경·초기화 / Bootloader = Kernel 실행 연결 / GPT·MBR = Partition 정보 / ESP = UEFI 부팅 파일 / LVM = 저장공간 관리.
