# 저장공간 관리 — Partition · RAID · LVM

> [I/O와 저장장치 개념지도](../03-IO-저장장치.md)의 보충학습. **디스크를 어떻게 나누고, 보호하고, 확장할 것인가**를 실제 구성에 연결한다. 부팅 과정은 [컴퓨터 부팅 과정](컴퓨터-부팅-과정.md)에서 다룬다.

## 1. 전체 좌표 — 서로 다른 문제

```text
저장공간을 사용한다
│
├─ 디스크 영역을 어떻게 기록·분할하나?
│  └─ GPT / MBR → Partition
│
├─ 여러 Disk에 데이터를 어떻게 배치·보호하나?
│  └─ RAID → Striping / Mirroring / Parity
│
└─ 저장공간을 어떻게 모으고 유연하게 할당하나?
   └─ LVM → PV(관리 자원) → VG(공간 Pool) → LV(사용할 논리 장치)
```

RAID·Partition·LVM은 서로 다른 문제를 해결하므로 **독립적으로 사용하거나 조합**할 수 있다. RAID는 장애 보호를 반드시 제공하는 것이 아니며(RAID 0 등), LVM도 기본적인 선형 LV만으로 장애 보호를 보장하지 않는다.

## 2. 디스크 초기화·Partition·File System

```text
Disk 또는 RAID 논리 Block Device
       ↓
Partition Table (GPT / MBR)
       ↓
Partition (주소 범위)
       ↓
File System 생성 (ext4 / NTFS 등)
       ↓
Mount (/data, C: 등)
```

GPT·MBR은 **Partition 정보를 기록하는 형식**, Partition은 **디스크 주소 공간을 나눈 영역**, 포맷은 **File System을 생성하는 과정**이다. 일상에서 '포맷'이라 부르더라도 이 단계는 구분한다. Partition 없이 장치 전체에 File System을 만들 수도 있다.

ESP(EFI System Partition)는 UEFI 부팅에 쓰이는 특별한 Partition이다. **UEFI는 부팅 체계, GPT·MBR은 파티션 테이블 형식**으로 서로 다른 분류축이다. 상세 부팅 흐름은 [컴퓨터 부팅 과정](컴퓨터-부팅-과정.md)을 참고한다.

## 3. Partition과 LV는 무엇이 같은가?

둘 다 File System을 생성하고 Mount해서 사용하는 **논리적 Block Device** 역할을 할 수 있다. 다만 공간의 출처가 다르다.

```text
[Partition 방식]
Disk (1TB)
├─ Partition A (300GB) → File System → /home
└─ Partition B (700GB) → File System → /data

[LVM 방식]
Disk A (1TB) → PV A ─┐
                     ├─ VG (약 2TB)
Disk B (1TB) → PV B ─┘
                         ├─ LV A (300GB) → File System → /home
                         └─ LV B (일부)  → File System → /data
```

| 구분 | Partition | LV |
|---|---|---|
| 공간의 출처 | 개별 Disk의 주소 범위 | VG의 저장공간 Pool |
| 파일 사용 | File System 생성·Mount | File System 생성·Mount |
| 여러 Disk에 걸친 공간 | Partition 자체로는 불가 | 여러 PV에 걸칠 수 있음 |
| 용량 변경 | 가능하지만 Disk 배치 제약 | VG 여유 공간에서 상대적으로 유연 |

**Partition = 특정 디스크에서 나눈 영역 / LV = 풀에서 할당한 논리 장치**라고 기억한다.

## 4. PV·VG·LV는 왜 세 단계인가?

```text
Disk 전체 / Partition / RAID 논리 장치
                    ↓
PV (Physical Volume) : LVM이 관리하도록 초기화한 Block Device
                    ↓
VG (Volume Group)    : 하나 이상의 PV를 묶은 Pool
                    ↓
LV (Logical Volume)  : VG에서 할당한 논리 Block Device
                    ↓
File System → Mount
```

- **PV:** Physical이라는 이름과 달리 실제 물리 Disk 자체만 뜻하지 않는다. Partition이나 RAID 장치도 PV로 사용할 수 있다.
- **VG:** 공간을 **모아 관리**한다. 아직 할당하지 않은 여유 공간도 VG에 남을 수 있다.
- **LV:** VG에서 공간을 **나눠 실제 사용**한다. 하나의 LV가 여러 PV에 걸칠 수도 있다.

예를 들어 VG가 600GB라면 LV 300GB와 200GB를 만들고 나머지를 향후 할당·확장용으로 남길 수 있다(실제 가용 용량은 메타데이터 등에 따라 차이).

**VG가 있는데 왜 LV가 필요한가?** VG는 공간 Pool, LV는 그 Pool에서 생성하는 사용 단위이기 때문이다.

Partition은 LVM의 필수 선행 단계가 아니다. Disk 전체나 RAID 장치를 직접 PV로 초기화할 수 있다.

## 5. RAID·Partition·LVM은 어떻게 조합되는가?

```text
[구성 A: 단순 Partition]
Disk → Partition → File System

[구성 B: LVM]
Disk → PV → VG → LV → File System

[구성 C: RAID + Partition + LVM]
여러 Disk → RAID 논리 장치 → Partition(선택)
          → PV → VG → LV → File System
```

또한 여러 디스크의 Partition을 Software RAID의 구성원으로 사용할 수도 있다. 따라서 위 순서는 **가능한 예시이지 필수 계층**이 아니다.

- **RAID:** 여러 디스크에 데이터를 배치하고 Level에 따라 중복·복구 기능 제공
- **Partition:** 디스크의 주소 범위 분할
- **LVM:** 여러 저장 자원을 풀로 모으고 논리 공간 할당

RAID의 Level별 동작은 [RAID 세부학습](../RAID-스트라이핑-미러링-패리티.md)에서 다룬다.

## 6. Linux에서 언제 LVM을 선택할까?

단순한 개인 PC나 고정 용량 디스크에서는 Partition만으로도 충분할 수 있다. 반면 운영 중 볼륨을 확장하거나 여러 저장 자원을 하나의 Pool로 관리할 때 LVM이 유용하다.

```text
[Partition만 사용]
SSD → Partition → ext4 → /data

[LVM 사용]
SSD → PV → VG
             ├─ LV(root) → ext4 → /
             ├─ LV(data) → ext4 → /data
             └─ 여유 공간 → 이후 확장에 사용
```

LVM을 사용한다고 반드시 여러 Disk를 묶어야 하는 것은 아니다. Partition도 확장 가능하지만, LVM은 저장공간 재할당과 확장에서 더 유연한 경우가 많다. LV를 확장한 뒤에는 File System도 별도로 확장해야 할 수 있다. 여러 PV에 걸친 일반 LV는 한 Disk 장애로 영향을 받을 수 있으므로 LVM을 백업·RAID의 대체재로 보지 않는다.

### 현재 Linux의 구성 확인

```bash
lsblk            # Disk / Partition / LVM Block Device의 계층
sudo pvs         # PV 목록
sudo vgs         # VG 목록
sudo lvs         # LV 목록
findmnt          # 실제 Mount 지점
```

읽기·조회 명령으로 현재 구성을 파악한 뒤 변경 작업을 검토한다.
