# 컴퓨터 구조 전체 개념지도

컴퓨터 구조는 **명령 실행과 데이터 이동·저장**을 담당하는 컴퓨터 시스템을, **대상 → 해결할 문제(관점) → 대표 구조·기술** 순서로 이해한다.


## 0. 전체 좌표 — 대상 · 관점 · 기술

```text
컴퓨터 구조
│
├─ ① CPU — 명령 실행
│  ├─ 구성 → CU / ALU / Register
│  ├─ 실행 → Fetch / Decode / Execute
│  └─ 성능 개선 → Pipeline / Multicore
│
├─ ② Memory — 데이터 제공
│  ├─ 접근 속도 → Memory Hierarchy / Cache
│  ├─ 배치 → Paging / Segmentation
│  └─ 주소 변환 → Virtual Memory / MMU / TLB
│
├─ ③ I/O · Storage — 데이터 이동·저장
│  ├─ 장치 사용 → 요청 / 전송 / 완료 확인
│  │  └─ Controller / DMA / Interrupt
│  └─ 지속 저장 → 매체 / 보호 / 공간 / 연결
│     └─ HDD·SSD / RAID / LVM / DAS·NAS·SAN
│
└─ ④ 성능·신뢰성 — 시스템 전체의 횡단 평가
   ├─ 성능 → Throughput / Latency / CPI / Amdahl
   └─ 신뢰성·가용성 → MTBF / MTTR / Watchdog
```

**대상 → 관점 → 대표 기술** 순서로 읽는다. 서로 다른 관점의 기술은 함께 사용될 수 있으며, 성능·신뢰성은 독립된 하드웨어 자원이 아닌 시스템 전체의 평가축이다.

**구성과 실행을 연결하는 출발점**

컴퓨터의 **5대 구성요소**는 입력장치·출력장치·기억장치·연산장치·제어장치다. 연산장치(ALU)와 제어장치(CU)는 CPU의 핵심 부분이며, CPU 내부 레지스터는 연산 데이터와 실행 상태를 임시 보관한다.

```text
컴퓨터의 구성 (무엇으로 이루어지는가?)
├─ 입력·출력장치 → 외부와 정보 교환
├─ 기억장치      → 명령어·데이터 저장
└─ CPU          → 명령 실행
   ├─ CU        → 명령 해독·제어신호
   ├─ ALU       → 산술·논리연산
   └─ Register  → 값·실행 상태 임시 저장

구조 (명령어·데이터에 어떻게 접근하는가?)
├─ 폰노이만 → 메모리·접근 경로 공유
└─ 하버드   → 명령어·데이터 메모리·경로 분리

동작 (CPU는 어떻게 처리하는가?)
└─ Fetch → Decode → Execute → 필요시 결과 기록

성능 (무엇이 병목인가?)
└─ CPU–메모리 속도·대역폭 격차
   → Cache 계층·Locality로 접근 지연 완화
```

**구성·구조·동작·성능은 서로 다른 질문**이다. 폰노이만/하버드는 CPU 사이클의 종류가 아니라 명령어·데이터의 저장 및 접근 방식에 관한 구분이다. 세부 원리는 [CPU 구조와 명령 실행](01-CPU-구조-명령실행.md), [메모리 계층과 가상 메모리](02-메모리-계층-가상메모리.md)에서 이어진다.

 **시스템의 실제 관계 — 구성요소가 협업하는 흐름**

위 지도는 **분류**이고, 아래 그림은 한 작업을 처리할 때 구성요소가 **상호작용하는 모습**이다. 둘을 같은 순서도로 읽지 않는다.

```text
           CPU (명령 실행)
            ↕       ↕
    Memory (명령·데이터)
            ↕
      I/O Controller
            ↕
      External Device
       └─ Storage 등

전체에 걸친 평가 → 성능 · 신뢰성 · 가용성
```

이 그림은 **개념적 상호작용**을 단순화한 것이다. 실제 시스템에서 CPU·Memory·I/O의 연결과 데이터 이동은 버스·인터커넥트·컨트롤러 구조에 따라 달라진다. 특히 DMA에서는 장치와 Memory 사이 데이터 전송에 CPU가 매번 개입하지 않아도 된다.
