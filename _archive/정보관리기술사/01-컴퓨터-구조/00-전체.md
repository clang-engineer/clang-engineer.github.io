# 컴퓨터 구조 전체 개념지도

컴퓨터 구조는 **명령 실행과 데이터 이동·저장**을 담당하는 컴퓨터 시스템을, **대상 → 해결할 문제(관점) → 대표 구조·기술** 순서로 이해한다.

처음부터 동작 흐름을 따라가려면 [컴퓨터구조 스토리 학습](99-컴퓨터구조-스토리학습.md)을 참고한다.

## 1. 전체 좌표 — 대상 · 관점 · 기술

```text
컴퓨터 구조
│
├─ CPU — 명령 실행
│  ├─ 명령 체계 → ISA / CISC / RISC
│  ├─ 실행 효율 → Pipeline / Hazard
│  └─ 병렬성 → Superscalar / VLIW / Multicore / SMT
│
├─ Memory — 데이터 제공
│  ├─ 접근 속도 → Memory Hierarchy / Cache
│  ├─ 배치 → Paging / Segmentation
│  └─ 주소 변환 → Virtual Memory / MMU / TLB
│
├─ I/O · Storage — 데이터 이동·저장
│  ├─ 장치 접근 → MMIO / Isolated I/O
│  ├─ 상태 확인 → Polling / Interrupt
│  ├─ 데이터 전송 → Programmed I/O / DMA
│  ├─ 처리 위임 → I/O Channel
│  ├─ 매체·주소 관리 → HDD / SSD / FTL
│  ├─ 데이터 배치·보호 → RAID
│  ├─ 공간 관리 → Partition / LVM
│  └─ 연결·공유 → DAS / NAS / SAN
│
└─ [횡단 평가] 시스템 전체
   ├─ 성능 → Throughput / Latency / CPI / Amdahl
   └─ 신뢰성·가용성 → MTBF / MTTR / Watchdog
```

**대상 → 관점 → 대표 기술** 순서로 읽는다. 서로 다른 관점의 기술은 함께 사용될 수 있으며, 성능·신뢰성은 독립된 하드웨어 자원이 아닌 시스템 전체의 평가축이다.

| 대상·평가축 | 핵심 질문 | 하위 지도 |

| Memory | 접근 속도·배치·주소 변환 문제를 어떻게 해결하는가? | [02. 메모리 계층과 가상 메모리](02-메모리-계층-가상메모리.md) |

**하위 지도의 역할:** 부모는 대상별 관점과 관계를 보여주고, 자식은 그 관점 안에서 구성 요소·작동 원리·기술 간 경계를 더 깊게 설명한다. 개별 기술은 서로 다른 질문에 답할 수 있으므로 반드시 순차적인 발전 단계로 해석하지 않는다.

## 3. 시스템의 실제 관계 — 분류와 동작을 구분한다

```text
           CPU (명령 실행)
            ↕       ↕
    Memory (명령·데이터)
            ↕
      I/O Controller
            ↕
      External Device
       └─ Storage 등

전체에 걸친 평가 → 성능 · 신뢰성 · 가용성
```

이 그림은 **개념적 상호작용**을 단순화한 것이다. 실제 시스템에서 CPU·Memory·I/O의 연결과 데이터 이동은 버스·인터커넥트·컨트롤러 구조에 따라 달라진다. 특히 DMA에서는 장치와 Memory 사이 데이터 전송에 CPU가 매번 개입하지 않아도 된다.

## 4. 이해 복원

1. CPU·Memory·I/O는 각각 어떤 자원이며 서로 어떻게 협업하는가?
2. CPU의 Pipeline과 Multicore는 어떤 서로 다른 수준의 병렬성을 설명하는가?
3. Memory의 Cache·Paging·Virtual Memory는 각각 어떤 문제를 해결하는가?
4. I/O의 Interrupt와 DMA는 왜 서로 다른 역할인가?
5. RAID·Partition·LVM·DAS/NAS/SAN은 왜 같은 종류의 기술이 아닌가?
6. 성능·신뢰성이 CPU·Memory·I/O와 같은 자원 분류가 아닌 이유는 무엇인가?

**복원 단서:** 대상(자원) → 관점(문제) → 구조·기술(해결 방법) → 다른 기술과의 관계.
