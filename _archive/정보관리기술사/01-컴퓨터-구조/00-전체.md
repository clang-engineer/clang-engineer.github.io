# 컴퓨터 구조 전체 개념지도

처음 이해하거나 흐름을 다시 따라가려면 [컴퓨터구조 스토리 학습](99-컴퓨터구조-스토리학습.md)에서 문제 상황과 질문을 따라간다.

컴퓨터 구조는 프로그램의 명령과 데이터가 실제 하드웨어에서 어떻게 처리되고, CPU·메모리·I/O의 속도와 용량 한계를 어떤 구조로 완화하는지를 본다.

## 빠른 복습 좌표

| 복습 축 | 핵심 관계·판단 단서 |
|---|---|
| CPU | ISA는 명령 인터페이스, Pipeline은 처리 단계 중첩; Hazard가 병렬성 한계 |
| 메모리 | Cache는 지역성으로 지연 완화, Paging은 불연속 배치, Virtual Memory는 주소 공간 분리 |
| I/O | Interrupt는 완료 통지, DMA는 CPU 개입을 줄인 데이터 전송 |
| 저장 | RAID는 중복·성능 설계, SSD의 FTL은 논리 주소와 NAND 배치를 연결 |
| 평가 | 처리량 ≠ 지연시간; Amdahl은 병렬화되지 않는 부분의 속도 향상 한계 |

**복습 방법:** 이 표에서 핵심 관계가 기억나지 않는 축만 아래 조망도와 연결된 하위 학습으로 내려간다. 상세 예제는 세부학습 본문에 남긴다.

## 1. 컴퓨터 구조 전체 좌표

```text
컴퓨터 시스템 — 명령을 실행하고 데이터를 이동·저장
│
├─ [1. 명령 실행 · CPU]
│  └─ ISA · Pipeline · Parallelism
├─ [2. 메모리 계층]
│  └─ Cache · Main Memory · Virtual Memory
├─ [3. I/O · 저장장치]
│  └─ Interrupt · DMA · SSD
└─ [4. 성능 · 신뢰성]
   └─ 처리량 · 지연 · 병목 · 장애

CPU ↔ Memory ↔ I/O : 실행 중 상호작용
성능·신뢰성 : 구성요소를 가로지르는 평가 축
```

CPU는 명령을 실행하고, Memory는 실행에 필요한 명령·데이터를 제공하며, I/O는 외부 장치와 데이터를 주고받는다. 성능·신뢰성은 이 구성요소 전체를 평가하는 **횡단 관점**이다.

```text
컴퓨터 구조
│
├─ 명령 실행과 CPU 병렬성
│   ├─ 컴퓨터 구성 / 폰노이만 ↔ Harvard
│   ├─ ISA / CISC ↔ RISC / 명령어 사이클
│   ├─ 파이프라이닝 / 해저드
│   └─ Superscalar ↔ VLIW / 병렬성 확대와 한계
│
├─ 메모리 계층과 가상 메모리
│   ├─ 지역성 / 캐시
│   ├─ Paging / Segmentation
│   └─ 가상 메모리 / MMU / TLB
│
├─ I/O와 저장장치
│   ├─ Interrupt / DMA
│   ├─ RAID / SSD / FTL
│   └─ DAS / NAS / SAN (연결·공유 구조)
│
└─ 성능과 신뢰성
    ├─ 처리량 / 응답시간 / CPI
    ├─ Amdahl 법칙 / SPEC
    └─ MTBF / MTTR / Watchdog
```

이 네 가지는 **컴퓨터 시스템의 구성·동작과 평가**를 조망하는 학습 축이다. 교재 목차가 아니라 CPU·Memory·I/O의 역할과 성능·신뢰성의 관계를 기준으로 구성한다.

## 2. 어디를 파고들 것인가

### 명령 실행과 CPU 병렬성

CPU가 명령을 어떻게 실행하고, 처리량을 높이기 위해 병렬성을 어떤 수준에서 확대하는지 본다.

```text
명령 실행
  ↓
파이프라이닝
  ↓
해저드
  ↓
명령·Core·Thread 수준 병렬성 확대
  ↓
Amdahl 법칙으로 한계 확인
```

→ [명령 실행과 CPU 병렬성 개념지도](01-명령실행-CPU-병렬성.md)

### 메모리 계층과 가상 메모리

메모리에서는 `속도`, `배치`, `주소 공간`이라는 서로 다른 문제를 구분한다.

```text
CPU-RAM 속도 격차 → 캐시
연속 배치 제약     → Paging / Segmentation
주소 공간 분리     → 가상 메모리
```

→ [메모리 계층과 가상 메모리 개념지도](02-메모리-계층-가상메모리.md)

### I/O와 저장장치

CPU가 느린 장치와 협업하는 방법과 지속 저장장치의 성능·가용성 문제를 본다.

```text
CPU 대기·개입 축소 → Interrupt / DMA
지속 저장           → RAID / SSD / FTL
저장장치 연결·공유  → DAS / NAS / SAN
```

→ [I/O와 저장장치 개념지도](03-IO-저장장치.md)

### 성능과 신뢰성

구조를 개선한 뒤 실제 효과와 한계, 장애 대응까지 시스템 수준에서 판단한다.

```text
측정
  ↓
병목 식별
  ↓
개선
  ↓
Amdahl 법칙으로 한계 확인
  ↓
MTBF / MTTR / Watchdog으로 신뢰성·가용성 검토
```

→ [성능과 신뢰성 개념지도](04-성능-신뢰성.md)

## 3. 과목 전체 연결

```text
              컴퓨터 시스템
                    │
       ┌────────────┼────────────┐
       ▼            ▼            ▼
    CPU·명령       Memory       I/O·저장
    실행·병렬성    계층·주소     장치·전송
       └────────────┼────────────┘
                    ▼
              성능 · 신뢰성
          처리량 · 지연 · 장애
```

CPU·Memory·I/O는 순차적인 학습 단계가 아니라 **서로 상호작용하는 구성요소**이고, 성능·신뢰성은 이들을 함께 평가하는 관점이다.

## 참고 — 먼저 알아둘 용어

전체 지도를 읽는 데 필요한 낯선 약어만 먼저 잡는다.

```text
ISA(Instruction Set Architecture)
= CPU가 이해하는 명령과 레지스터 등의 약속

MMU(Memory Management Unit)
= 가상주소를 물리주소로 변환하는 하드웨어

TLB(Translation Lookaside Buffer)
= 최근 주소 변환 결과를 빠르게 찾기 위한 Cache

DMA(Direct Memory Access)
= CPU의 반복 개입을 줄이고 장치와 메모리 사이의 데이터 전송을 지원하는 방식

FTL(Flash Translation Layer)
= SSD의 논리 Block 주소를 Flash의 실제 물리 위치와 연결하는 계층

CPI(Cycles Per Instruction)
= 명령 하나를 처리하는 데 필요한 평균 Clock Cycle 수

MTBF / MTTR
= 고장 사이의 평균 시간 / 장애 후 평균 복구 시간
```
