# I/O와 저장장치 개념지도

[컴퓨터 구조 전체 개념지도](00-전체.md)에서 **CPU와 외부 장치의 협업(I/O)** 및 **데이터의 지속 저장(Storage)**으로 내려가는 지도다. 둘은 관련되지만 하나의 발전 순서가 아니다.

## 1. 전체 관계 — 장치 사용과 저장

```text
CPU / Memory
     ↕
Device Controller
     ↕
External Device (SSD / HDD 등)
```

CPU는 Controller를 통해 장치에 작업을 요청한다. 데이터는 DMA 등으로 Device와 Memory 사이에서 이동할 수 있고, 완료는 Interrupt 또는 Polling 등으로 확인한다. 이는 **장치와 데이터를 주고받는 I/O**와 **데이터를 지속 저장하는 Storage**가 만나는 지점이다.

### 대상 → 관점 → 대표 기술

```text
I/O · Storage — 데이터 이동·저장
│
├─ I/O 처리
│  ├─ 기본 구성 → Controller / Device Register
│  ├─ 장치 접근 → MMIO / Isolated I/O
│  ├─ 상태 확인 → Polling / Interrupt
│  ├─ 데이터 전송 → Programmed I/O / DMA
│  └─ 처리 위임 → I/O Channel
│
└─ Storage
   ├─ 매체·주소 관리 → HDD / SSD / FTL
   ├─ 데이터 배치·보호 → RAID
   ├─ 공간 관리 → Partition / LVM
   └─ 연결·공유 → DAS / NAS / SAN
```

장치 접근·상태 확인·데이터 전송은 서로 다른 문제를 해결하며 조합할 수 있다. 저장공간 관리에서 GPT·MBR은 Partition Table의 형식으로, Partition·LVM과 같은 수준의 관리 방식은 아니다.

→ [I/O 처리 방식 세부학습](IO-처리-방식.md)

## 2. 저장장치 — 역할과 경계

| 관점 | 핵심 개념 | 구분할 질문 |
|---|---|---|
| 저장매체·내부 동작 | HDD / SSD · FTL | 실제 데이터를 어디에 저장하고 주소를 어떻게 매핑하는가? |
| 데이터 배치·보호 | RAID | 여러 Disk에 데이터를 어떻게 나누고 복제·복구하는가? |
| 디스크 영역·공간 관리 | GPT·MBR / Partition / LVM | 파티션 위치를 어떻게 기록하고, 공간을 나누거나 풀로 관리할 것인가? |
| 연결·접근 | DAS / NAS / SAN | 서버가 저장장치를 직접 쓰는가, 네트워크로 파일·블록을 제공받는가? |

- **RAID:** Striping은 병렬 I/O, Mirroring은 복제, Parity는 복구 정보에 초점을 둔다. RAID Level은 이 원리를 조합한다. → [RAID 세부학습](RAID-스트라이핑-미러링-패리티.md)
- **SSD·FTL:** Host가 보는 논리 Block 주소와 Flash의 실제 위치를 연결한다. → [SSD 세부학습](SSD-Form-Factor-Interface-Protocol-NAND.md)
- **DAS·NAS·SAN:** DAS는 직접 연결, NAS는 네트워크 파일 공유(NFS/SMB), SAN은 네트워크 블록 장치 제공(FC-SAN·IP-SAN 등)이다. 이는 RAID나 LVM의 대안이 아니라 **연결·접근의 분류축**이다.
