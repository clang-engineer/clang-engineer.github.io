# I/O와 저장장치 개념지도

[컴퓨터 구조 전체 개념지도](00-전체.md)에서 **CPU와 외부 장치의 협업(I/O)** 및 **데이터의 지속 저장(Storage)**으로 내려가는 지도다. 둘은 관련되지만 하나의 발전 순서가 아니다.

## 1. 전체 좌표 — 어떤 문제를 해결하는가?

```text
I/O와 저장장치
│
├─ [I/O 처리] CPU는 장치를 어떻게 사용하나?
│  ├─ 기본 구성 → Device Controller
│  │              └─ Device Register (제어·상태 정보)
│  └─ 처리 메커니즘
│     ├─ 상태·완료 확인 → Polling / Interrupt
│     ├─ 데이터 전송 책임 → Programmed I/O / DMA
│     └─ I/O 명령 처리 위임 → I/O Channel
│
└─ [저장장치] 데이터를 어떻게 저장·관리·공유하나?
   ├─ 매체·내부 주소 관리 → HDD / SSD · FTL
   ├─ 데이터 배치·보호 → RAID (Striping / Mirroring / Parity)
   ├─ 디스크 영역·공간 관리 → GPT·MBR / Partition / LVM (PV → VG → LV)
   └─ 연결·접근 구조 → DAS / NAS / SAN
```

**장치 컨트롤러·레지스터는 기본 구성 요소**이고, Polling·Interrupt·DMA·I/O Channel은 처리 메커니즘이다. 장치 컨트롤러에 제어 정보를 전달하고, DMA로 데이터를 전송하고, Interrupt로 완료를 확인하는 식으로 여러 메커니즘을 조합한다. 레지스터 주소 접근 방식(MMIO·Isolated I/O)은 세부학습에서 필요한 만큼만 다룬다.

→ [I/O 처리 방식 — 장치 제어·Interrupt·DMA·I/O Channel](IO-처리-Programmed-Interrupt-DMA-Channel.md)

## 2. 저장장치 — 역할과 경계

| 관점 | 핵심 개념 | 구분할 질문 |
|---|---|---|
| 저장매체·내부 동작 | HDD / SSD · FTL | 실제 데이터를 어디에 저장하고 주소를 어떻게 매핑하는가? |
| 데이터 배치·보호 | RAID | 여러 Disk에 데이터를 어떻게 나누고 복제·복구하는가? |
| 디스크 영역·공간 관리 | GPT·MBR / Partition / LVM | 파티션 위치를 어떻게 기록하고, 공간을 나누거나 풀로 관리할 것인가? |
| 연결·접근 | DAS / NAS / SAN | 서버가 저장장치를 직접 쓰는가, 네트워크로 파일·블록을 제공받는가? |

- **RAID:** Striping은 병렬 I/O, Mirroring은 복제, Parity는 복구 정보에 초점을 둔다. RAID Level은 이 원리를 조합한다. → [RAID 세부학습](RAID-스트라이핑-미러링-패리티.md)
- **SSD·FTL:** Host가 보는 논리 Block 주소와 Flash의 실제 위치를 연결한다. → [SSD 세부학습](SSD-Form-Factor-Interface-Protocol-NAND.md)
- **DAS·NAS·SAN:** DAS는 직접 연결, NAS는 네트워크 파일 공유(NFS/SMB), SAN은 네트워크 블록 장치 제공(FC-SAN·IP-SAN 등)이다. 이는 RAID나 LVM의 대안이 아니라 **연결·접근의 분류축**이다.

### 디스크 초기화부터 파일 사용까지 — GPT·MBR과 Partition

새 디스크를 OS에서 사용하도록 준비할 때는 **파티션 테이블 구성, Partition 생성, File System 생성(포맷), Mount**를 구분한다.

```text
Block Device (SSD / HDD / RAID 논리 장치)
        ↓
Partition Table → GPT / MBR (영역 정보를 기록하는 형식)
        ↓
Partition 생성 → 디스크 주소 범위 분할
        ↓
File System 생성 → ext4 / NTFS 등
        ↓
Mount → /data, C: 등에서 사용
```

GPT·MBR은 **Partition 자체가 아니라 파티션 정보를 기록하는 디스크 분할 형식**이다. Partition 없이 장치 전체에 File System을 만들 수도 있고, Partition을 LVM의 PV로 사용할 수도 있다.

**부팅과의 연결:** EFI System Partition(ESP)은 UEFI 부팅에 사용되는 특별한 Partition이다. **UEFI는 부팅 체계, GPT·MBR은 Partition Table 형식**으로 서로 다른 분류축이다. 부팅 과정의 상세 설명은 [부팅 구조 — BIOS·UEFI·Bootloader](./_보충학습/부팅-구조-BIOS-UEFI-Bootloader.md)에서 다룬다.

### Partition과 LV — 같은 역할, 다른 공간의 출처

**Partition과 LV는 모두 File System을 만들고 Mount하여 사용하는 논리적 저장공간**을 제공한다. 하지만 공간을 나누는 대상이 다르다.

```text
[Partition 방식]
Disk (1TB)
├─ Partition A (300GB) → File System → /home
└─ Partition B (700GB) → File System → /data

[LVM 방식]
Disk A (1TB) → PV A ─┐
                     ├─ VG (약 2TB)
Disk B (1TB) → PV B ─┘
                         ├─ LV A (300GB) → /home
                         └─ LV B (나머지 일부) → /data
```

| 관점 | Partition | LV (Logical Volume) |
|---|---|---|
| 공간의 출처 | 개별 Disk의 주소 범위 | VG에 모인 저장공간 |
| 실제 사용 | File System 생성·Mount 가능 | File System 생성·Mount 가능 |
| 여러 Disk에 걸친 공간 | Partition 자체로는 불가 | 여러 PV에 걸쳐 구성 가능 |
| 크기 변경 | Disk의 배치·인접 공간 등 제약 | VG 여유 공간에서 상대적으로 유연 |

즉 **Partition은 특정 Disk를 나눈 영역, LV는 VG에서 할당받은 논리 블록 장치**다. LV도 물리적 용량 한계를 없애는 것은 아니다.

### LVM의 세 구성 요소 — PV → VG → LV

```text
Disk 전체 / Partition / RAID 논리 장치
                  ↓
PV (Physical Volume)
= LVM이 관리하도록 초기화한 Block Device
                  ↓
VG (Volume Group)
= 하나 이상의 PV에서 공간을 모은 Pool
                  ↓
LV (Logical Volume)
= VG에서 할당해 실제 사용하는 논리 Block Device
                  ↓
File System → Mount
```

- **PV:** 이름에 Physical이 들어가지만 반드시 실제 물리 Disk 하나를 뜻하지 않는다. Partition이나 RAID 장치도 PV로 초기화할 수 있다.
- **VG:** 저장공간을 **모아 관리**한다.
- **LV:** VG의 공간을 **나누어 할당**한다.

**왜 VG가 있는데 LV가 또 필요한가?** VG는 아직 할당하지 않은 공간까지 포함하는 자원 풀이고, LV는 그중 실제로 사용할 공간이다. 예를 들어 600GB VG에서 LV 300GB와 200GB를 만들면 나머지 공간을 이후 할당·확장용으로 남길 수 있다(실제 가용 용량은 메타데이터 등에 따라 다름).

Partition은 LVM의 필수 선행 단계가 아니다. Disk 전체나 RAID 장치를 PV로 사용할 수도 있고, Partition을 PV로 사용할 수도 있다.

### RAID와 LVM — '묶기'의 목적이 다르다

```text
RAID → 여러 Disk에 데이터 배치·복제·패리티 보호
LVM  → 저장공간을 Pool로 통합하고 LV로 할당
```

예를 들어 여러 Disk를 RAID 5로 구성하고 그 논리 장치를 PV로 등록하여 VG·LV를 만들 수 있다. **RAID는 선택 사항**이며 LVM 자체의 RAID 기능도 있다. 일반적인 VG·LV 구성만으로 디스크 장애 보호가 보장되지는 않는다.

**인출 단서:** RAID = 배치·보호 / Partition = 개별 Disk 분할 / PV = LVM 관리 자원 / VG = 통합 Pool / LV = Pool에서 할당한 논리 장치.

## 3. 저장장치 구성 관계 — 실제로 어떻게 조합하는가?

아래는 **RAID 장치 위에 Partition과 LVM을 구성하는 한 가지 예**다. 위의 역할 분류와 달리, 실제 논리·물리 계층의 연결을 보여준다.

```text
Application
    ↓
File System
    ↓
LV (LVM 논리 장치)
    ↓
VG / PV (공간 풀·매핑)
    ↓
Partition (선택)
    ↓
RAID (선택)
    ↓
Physical Disk (HDD / SSD)
```

이 순서는 필수 구성이 아니다. Partition에 File System을 직접 만들 수도 있고, RAID 장치를 Partition 없이 PV로 등록할 수도 있다.

## 4. 인출 좌표

1. CPU가 장치를 제어할 때 **접근·상태 확인·데이터 전송**은 각각 어떤 질문인가?
2. GPT·MBR은 Partition과 무엇이 다르고, ESP는 왜 특별한 Partition인가?
3. RAID·Partition·LVM은 모두 저장공간을 다루는데 **무엇을 서로 다르게 해결하는가?**
4. LV가 Partition과 비슷한 역할을 하면서도 다른 이유는 무엇인가? PV는 반드시 물리 Disk인가?
5. VG와 LV를 구분하는 이유는 무엇인가?
6. DAS·NAS·SAN은 왜 RAID·LVM과 같은 분류축이 아닌가?
