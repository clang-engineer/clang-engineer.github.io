# I/O와 저장장치 개념지도

[컴퓨터 구조 전체 개념지도](00-전체.md)에서 **CPU와 외부 장치의 협업(I/O)** 및 **데이터의 지속 저장(Storage)**으로 내려가는 지도다. 둘은 관련되지만 하나의 발전 순서가 아니다.

## 1. 전체 좌표 — 어떤 문제를 해결하는가?

```text
I/O와 저장장치
│
├─ [I/O 처리] CPU는 장치를 어떻게 사용하나?
│  ├─ 기본 구성 → Device Controller
│  │              └─ Device Register (제어·상태 정보)
│  └─ 처리 메커니즘
│     ├─ 상태·완료 확인 → Polling / Interrupt
│     ├─ 데이터 전송 책임 → Programmed I/O / DMA
│     └─ I/O 명령 처리 위임 → I/O Channel
│
└─ [저장장치] 데이터를 어떻게 저장·관리·공유하나?
   ├─ 매체·내부 주소 관리 → HDD / SSD · FTL
   ├─ 데이터 배치·보호 → RAID (Striping / Mirroring / Parity)
   ├─ 공간 구성·추상화 → Partition / LVM (PV → VG → LV)
   └─ 연결·접근 구조 → DAS / NAS / SAN
```

**장치 컨트롤러·레지스터는 기본 구성 요소**이고, Polling·Interrupt·DMA·I/O Channel은 처리 메커니즘이다. 장치 컨트롤러에 제어 정보를 전달하고, DMA로 데이터를 전송하고, Interrupt로 완료를 확인하는 식으로 여러 메커니즘을 조합한다. 레지스터 주소 접근 방식(MMIO·Isolated I/O)은 세부학습에서 필요한 만큼만 다룬다.

→ [I/O 처리 방식 — 장치 제어·Interrupt·DMA·I/O Channel](IO-처리-Programmed-Interrupt-DMA-Channel.md)

## 2. 저장장치 — 역할과 경계

| 관점 | 핵심 개념 | 구분할 질문 |
|---|---|---|
| 저장매체·내부 동작 | HDD / SSD · FTL | 실제 데이터를 어디에 저장하고 주소를 어떻게 매핑하는가? |
| 데이터 배치·보호 | RAID | 여러 Disk에 데이터를 어떻게 나누고 복제·복구하는가? |
| 저장공간 구성 | Partition / LVM | Disk 영역을 나눌 것인가, 여러 저장 자원을 풀로 모아 할당할 것인가? |
| 연결·접근 | DAS / NAS / SAN | 서버가 저장장치를 직접 쓰는가, 네트워크로 파일·블록을 제공받는가? |

- **RAID:** Striping은 병렬 I/O, Mirroring은 복제, Parity는 복구 정보에 초점을 둔다. RAID Level은 이 원리를 조합한다. → [RAID 세부학습](RAID-스트라이핑-미러링-패리티.md)
- **SSD·FTL:** Host가 보는 논리 Block 주소와 Flash의 실제 위치를 연결한다. → [SSD 세부학습](SSD-Form-Factor-Interface-Protocol-NAND.md)
- **DAS·NAS·SAN:** DAS는 직접 연결, NAS는 네트워크 파일 공유(NFS/SMB), SAN은 네트워크 블록 장치 제공(FC-SAN·IP-SAN 등)이다. 이는 RAID나 LVM의 대안이 아니라 **연결·접근의 분류축**이다.

### Partition과 LVM — 무엇을 나누는가?

Partition은 **개별 Disk의 주소 공간을 영역별로 나누는 방식**이다. LVM은 하나 이상의 저장 자원을 **VG로 묶고 LV로 할당**한다.

```text
Disk / Partition / RAID 장치
          ↓
PV : LVM이 관리하는 저장 자원
          ↓
VG : 하나 이상의 PV를 묶은 자원 풀
          ↓
LV : VG에서 할당한 논리 Block 장치
          ↓
File System → Mount
```

**VG가 이미 묶었는데 왜 LV가 필요한가?** VG는 저장공간을 **모아 관리**하고, LV는 그 공간을 **실제로 사용할 논리 장치로 할당**하기 때문이다. 예를 들어 총 600GB 규모의 VG에서 LV 300GB와 200GB를 만들고 나머지 공간을 이후 할당용으로 남길 수 있다(실제 사용 가능 용량은 메타데이터 등에 따라 달라짐). LV 하나가 여러 PV에 걸칠 수도 있다.

Partition과 LV 모두 논리적인 구성이지만, **Partition은 특정 Disk의 영역**, **LV는 VG의 자원 풀에서 할당된 영역**이라는 차이가 있다. Partition 없이 Disk 전체나 RAID 장치를 PV로 사용할 수도 있다.

### RAID와 LVM — 둘 다 묶지만 목적이 다르다

```text
RAID → 데이터 배치·보호 (Level에 따라 장애 대응)
LVM  → 저장공간 통합·논리적 할당
```

예를 들어 여러 Disk를 RAID 5로 구성하고 그 장치를 PV로 등록한 다음 VG·LV를 만들 수 있다. **RAID는 선택적**이며, LVM 자체의 RAID 기능을 사용하는 구성도 가능하다. 일반적인 VG·LV 구성만으로 디스크 장애 보호가 보장되지는 않는다.

## 3. 저장장치 구성 관계 — 실제로 어떻게 조합하는가?

아래는 **RAID 장치 위에 Partition과 LVM을 구성하는 한 가지 예**다. 위의 역할 분류와 달리, 실제 논리·물리 계층의 연결을 보여준다.

```text
Application
    ↓
File System
    ↓
LV (LVM 논리 장치)
    ↓
VG / PV (공간 풀·매핑)
    ↓
Partition (선택)
    ↓
RAID (선택)
    ↓
Physical Disk (HDD / SSD)
```

이 순서는 필수 구성이 아니다. Partition에 File System을 직접 만들 수도 있고, RAID 장치를 Partition 없이 PV로 등록할 수도 있다.

## 4. 인출 좌표

1. CPU가 장치를 제어할 때 **접근·상태 확인·데이터 전송**은 각각 어떤 질문인가?
2. RAID·Partition·LVM은 모두 저장공간을 다루는데 **무엇을 서로 다르게 해결하는가?**
3. VG와 LV를 나누는 이유는 무엇이며, LV가 여러 PV에 걸칠 수 있는 이유는 무엇인가?
4. DAS·NAS·SAN은 왜 RAID·LVM과 같은 분류축이 아닌가?

**복원 단서:** I/O = 제어·상태·전송 / Storage = 매체·보호·추상화·연결.
