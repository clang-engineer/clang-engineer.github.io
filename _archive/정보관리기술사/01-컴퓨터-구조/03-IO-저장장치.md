# I/O와 저장장치 개념지도

이 문서는 [[00-전체|컴퓨터 구조 전체 개념지도]]에서 **I/O와 저장장치** 가지를 선택했을 때, CPU와 외부 장치가 협업하는 방법과 데이터를 지속적으로 저장하는 구조를 함께 파고들기 위한 지도다.

두 가지는 하나의 발전 순서가 아니다. **I/O는 CPU와 장치가 어떻게 협업하는가**, **저장장치는 데이터를 어떻게 지속적으로 저장하고 성능·가용성을 확보하는가**라는 서로 다른 큰 그림이다.

## 먼저 알아둘 용어

```text
Interrupt
= 장치가 CPU의 처리가 필요한 시점에 사건을 알리는 방식

DMA(Direct Memory Access)
= CPU의 반복 개입을 줄이고 장치와 메모리 사이의 데이터 전송을 지원하는 방식

RAID(Redundant Array of Independent Disks)
= 여러 Disk를 묶어 성능·가용성·용량 효율을 조절하는 구조

SSD(Solid State Drive)
= Flash Memory를 사용하는 반도체 기반 저장장치

FTL(Flash Translation Layer)
= SSD의 논리 Block 주소를 Flash의 실제 물리 위치와 연결하는 계층
```

처음에는 `Interrupt = 사건 알림`, `DMA = 데이터 전송의 CPU 개입 축소`, `RAID·SSD = 지속 저장` 정도의 위치부터 잡으면 된다.

## 1. 전체 좌표

```text
CPU 밖의 장치를 사용해야 함
│
├─ [CPU와 외부 장치의 협업]
│   │
│   ├─ CPU가 장치를 계속 확인하면 비효율
│   │   ↓
│   │  Interrupt
│   │
│   ├─ 대량 전송에 CPU가 계속 개입하면 비효율
│   │   ↓
│   │  DMA
│   │
│   └─ CPU가 장치 Register에 어떻게 접근하는가?
│       ↓
│      I/O 주소 지정
│
└─ [데이터의 지속 저장]
    │
    ├─ 여러 Disk를 어떻게 조합할 것인가?
    │   ↓
    │  RAID
    │   ├─ Striping
    │   ├─ Mirroring
    │   └─ Parity
    │
    └─ Flash 기반 저장장치는 논리 주소를 어떻게 관리하는가?
        ↓
       SSD
        └─ FTL
```

## 2. CPU가 장치를 계속 확인하지 않게 한다: Interrupt

```text
CPU가 장치 상태를 계속 확인
        ↓
Polling 부담
        ↓
장치가 필요한 시점에 알려주면?
        ↓
Interrupt
```

Interrupt는 장치가 CPU의 처리가 필요한 시점에 사건을 알린다. CPU는 장치를 계속 확인하는 대신 다른 일을 하다가 필요한 시점에 처리할 수 있다.

## 3. 대량 전송에서 CPU 개입을 줄인다: DMA

Interrupt로 사건을 알릴 수 있어도 대량 데이터를 CPU가 하나씩 옮기면 여전히 부담이 크다.

```text
대량 데이터 전송
        ↓
CPU가 매번 데이터를 옮기면 비효율
        ↓
DMA
        ↓
장치 ↔ 메모리 데이터 전송
        ↓
완료 시 Interrupt로 CPU에 알림
```

따라서 Interrupt와 DMA는 경쟁 관계가 아니다.

```text
Interrupt
→ CPU에 사건을 알림

DMA
→ 데이터 전송 과정의 CPU 개입 축소
```

## 4. CPU는 장치 Register에 어떻게 접근하는가

CPU가 장치를 제어하려면 장치 Register에 접근할 방법이 필요하다.

```text
I/O 주소 지정
├─ Memory-mapped I/O
│   └─ Memory 주소 공간에 장치 Register를 함께 배치
└─ Isolated I/O
    └─ Memory와 별도 I/O 주소 공간 사용
```

세부 명령어와 주소 계산보다 **Memory 주소 공간을 공유하는가, 별도로 두는가**의 차이를 중심으로 본다.

## 5. 여러 Disk를 묶어 성능과 장애에 대응한다: RAID

지속 저장에서는 단순 용량뿐 아니라 성능·장애·복구를 함께 본다.

```text
여러 Disk 사용
        ↓
어떻게 조합할까?
├─ Striping
│   └─ 데이터를 나눠 병렬 처리 → 성능
├─ Mirroring
│   └─ 같은 데이터를 복제 → 가용성
└─ Parity
    └─ 복구 정보를 저장 → 용량 효율과 복구
```

RAID Level은 이 기본 원리를 조합한 결과다.

```text
RAID 0  → Striping
RAID 1  → Mirroring
RAID 10 → Mirroring + Striping
RAID 5  → Striping + 분산 Parity
RAID 6  → Striping + 이중 분산 Parity
```

## 6. Flash의 물리 제약을 감춘다: SSD와 FTL

SSD는 Flash Memory를 기반으로 하며, Flash의 실제 물리 위치를 Host에 그대로 노출하지 않고 논리 Block 주소를 제공한다.

```text
Host의 논리 Block 주소
        ↓
FTL
        ↓
Flash의 실제 물리 위치
```

FTL은 논리 주소와 Flash의 물리 위치를 Mapping하고, Flash의 쓰기·삭제 제약을 관리하는 계층이다.

이 관계는 가상 메모리의 주소 변환과 비슷해 보일 수 있지만 목적과 계층이 다르다.

```text
가상 메모리
→ 프로세스 가상주소 ↔ RAM 물리주소

FTL
→ 저장장치 논리 Block ↔ Flash 물리 위치
```

## 7. 기억 흐름

```text
CPU 밖의 장치를 사용
│
├─ [장치와 협업]
│   CPU가 계속 확인하는 부담
│       ↓
│   Interrupt
│       ↓ 대량 데이터 전송의 CPU 개입도 줄이고 싶음
│   DMA
│
└─ [데이터를 지속 저장]
    ├─ 여러 Disk의 성능·장애 문제 → RAID
    └─ Flash의 물리 제약과 주소 관리 → SSD / FTL
```

`Interrupt → DMA → RAID → SSD`를 하나의 발전 순서로 외우지 않는다. **I/O 협업과 지속 저장이라는 두 가지 큰 그림 안에서 각 개념의 위치를 잡는 것이 핵심**이다.
