# I/O와 저장장치 개념지도

[컴퓨터 구조 전체 개념지도](00-전체.md)에서 **CPU가 외부 장치와 어떻게 협업하는가(I/O)**와 **데이터를 어떻게 지속적으로 보관하는가(Storage)**를 구분해 살펴본다. I/O는 장치를 사용하는 과정이고 Storage는 데이터를 보관하는 체계다.

## 1. 전체 관계 — 요청에서 데이터 보관까지

```text
CPU가 외부 장치에 작업 요청
             │
             ▼
     장치 제어기(Controller)
             │
             ▼
     외부 장치(SSD 등)
             │
             ├─ 작업 완료 알림 → Interrupt 등
             └─ 데이터 전송   ↔ Memory (DMA 등 활용 가능)

저장장치를 사용할 때는 별도의 관점이 추가됨
   ├─ 무엇에 저장?       → HDD / SSD
   ├─ 어떻게 배치·보호?  → RAID
   ├─ 공간을 어떻게 관리? → Partition / LVM
   └─ 어떻게 연결·공유?  → DAS / NAS / SAN
```

이 그림은 **요청·완료 알림·데이터 전송이 서로 다른 동작**임을 보여주는 개념도다. 실제 순서와 데이터 경로는 장치 및 시스템 구조에 따라 달라진다. 특히 DMA는 CPU가 매 데이터 전송에 개입하지 않도록 돕는다.

### I/O 처리 — 장치와 어떻게 협업하는가?

```text
I/O 처리
├─ 어디에 명령을 전달할까? → 장치 접근
│  └─ MMIO / Isolated I/O
├─ 작업이 끝났는지 어떻게 알까? → 상태 확인
│  └─ Polling / Interrupt
├─ 데이터를 누가 옮길까? → 전송 방식
│  └─ Programmed I/O / DMA
└─ 장치 제어를 얼마나 맡길까? → 처리 위임
   └─ I/O Channel
```

장치 접근·상태 확인·데이터 전송·처리 위임은 **같은 분류의 대안들이 아니라 서로 다른 질문**이다. 각 방식은 조합될 수 있다. → [I/O 처리 방식 세부학습](IO-처리-방식.md)

### Storage — 데이터를 어떻게 지속 보관하는가?

```text
Storage
├─ 저장 매체        → HDD / SSD (FTL: Flash 주소 매핑)
├─ 데이터 배치·보호 → RAID
├─ 저장 공간 관리   → Partition / LVM
└─ 연결·공유 방식   → DAS / NAS / SAN
```

RAID·Partition·LVM·DAS/NAS/SAN은 경쟁 기술이 아니라 **서로 다른 층위에서 조합 가능한 기술**이다. GPT·MBR은 Partition 정보를 기록하는 형식으로, Partition이나 LVM과 같은 분류축이 아니다.

## 2. 장치를 사용한 다음, 데이터를 어떻게 보관할까? — 저장장치

I/O가 **장치에 요청하고 데이터를 주고받는 과정**이라면, Storage는 **데이터를 오래 보관하고 관리하는 구조**다. SSD 같은 저장장치는 I/O의 대상이면서 동시에 저장매체이므로 두 관점이 만난다.

```text
프로그램의 저장 요청
        ↓
I/O: 장치에 명령 전달·데이터 전송·완료 확인
        ↓
Storage: 실제 데이터 보관
        ├─ 매체 선택 → HDD / SSD
        ├─ 보호·배치 → RAID
        ├─ 공간 구성 → Partition / LVM
        └─ 접근·공유 → DAS / NAS / SAN

※ 아래 네 항목은 순차 실행 단계가 아닌 설계 관점
```


| 관점 | 핵심 개념 | 구분할 질문 |
|---|---|---|
| 저장매체·내부 동작 | HDD / SSD · FTL | 실제 데이터를 어디에 저장하고 주소를 어떻게 매핑하는가? |
| 데이터 배치·보호 | RAID | 여러 Disk에 데이터를 어떻게 나누고 복제·복구하는가? |
| 디스크 영역·공간 관리 | GPT·MBR / Partition / LVM | 파티션 위치를 어떻게 기록하고, 공간을 나누거나 풀로 관리할 것인가? |
| 연결·접근 | DAS / NAS / SAN | 서버가 저장장치를 직접 쓰는가, 네트워크로 파일·블록을 제공받는가? |

- **RAID:** Striping은 병렬 I/O, Mirroring은 복제, Parity는 복구 정보에 초점을 둔다. RAID Level은 이 원리를 조합한다. **RAID 10이 모든 면에서 가장 효율적인 것은 아니다.** → [RAID 세부학습](RAID-스트라이핑-미러링-패리티.md)

  ```text
  RAID — 무엇을 우선할 것인가?
  ├─ 성능·전체 용량 우선 → RAID 0 (장애 보호 없음)
  ├─ 복제·가용성        → RAID 1
  ├─ 용량 효율·복구     → RAID 5 (1개 장애)
  ├─ 더 높은 장애 허용  → RAID 6 (2개 장애)
  └─ 쓰기 성능·가용성   → RAID 10 (Mirror + Striping)
  ```

  **선택 기준은 성능·용량 효율·장애 허용의 절충**이다. RAID 10은 패리티 갱신 부담이 없어 작은 Random Write에 유리한 경우가 있지만 용량 효율은 보통 50%다. RAID 5/6은 패리티를 활용해 용량과 장애 대응을 절충한다. 구체적인 디스크별 용량 계산·장애 조합·Write Penalty는 세부 문서에서 다룬다. RAID는 백업을 대체하지 않는다.
- **SSD·FTL:** Host가 보는 논리 Block 주소와 Flash의 실제 위치를 연결한다. → [SSD 세부학습](SSD-Form-Factor-Interface-Protocol-NAND.md)
- **DAS·NAS·SAN:** DAS는 직접 연결, NAS는 네트워크 파일 공유(NFS/SMB), SAN은 네트워크 블록 장치 제공(FC-SAN·IP-SAN 등)이다. 이는 RAID나 LVM의 대안이 아니라 **연결·접근의 분류축**이다.

## 3. 저장장치를 선택한 뒤 공간은 어떻게 관리할까?

저장매체가 있다고 곧바로 파일과 데이터를 편리하게 배치할 수 있는 것은 아니다. **디스크를 나누는 방식과 여러 저장공간을 묶어 관리하는 방식**을 구분해야 한다.

**RAID는 데이터 배치·보호, Partition은 디스크 영역 분할, LVM은 저장공간 Pooling·할당**을 담당한다. 서로 대체 관계가 아니며 조합할 수 있다. GPT·MBR은 Partition 정보를 기록하는 형식이고, PV·VG·LV는 LVM 내부의 관리 단위다.
