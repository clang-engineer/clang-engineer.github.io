# 컴퓨터 구조 스토리 학습 — 주문 요청을 처리하는 컴퓨터 안에서

> [전체 개념지도](00-전체.md)의 CPU·메모리·I/O와 성능·신뢰성의 관계를 주문 서버의 한 요청으로 이해한다. CPU → 메모리 → I/O가 일회성 단계라는 뜻이 아니라 **실행 중 계속 상호작용하는 구성요소**다.

## 1. 코드는 어떻게 CPU가 이해하는 명령이 될까?

주문 서버가 실행되자 CPU는 명령을 가져와 해석하고 실행한다.

CPU가 이해하는 기계어는 ISA에 따라 달라진다. ISA(Instruction Set Architecture)는 소프트웨어와 CPU 사이의 명령·레지스터 등 약속이다. CISC와 RISC는 명령어 설계 접근의 대표 비교축이다. 폰노이만·Harvard는 명령과 데이터의 저장·접근 구조를 구분하는 관점으로 ISA와 같은 분류가 아니다.

## 2. CPU가 빠르게 명령을 처리하려면 — Pipeline과 병렬성

주문 요청이 몰린다. 명령 하나를 끝낸 다음에만 다음 명령을 시작하면 자원이 놀 수 있다.

명령 처리의 효율을 높이려면 서로 다른 명령의 단계를 겹치는 방법을 생각할 수 있다. Pipeline은 명령 처리 단계를 중첩한다. 그런데 앞선 명령의 결과가 필요하거나 분기 결과가 불확실하면 **Hazard**가 발생한다.

하지만 파이프라인의 단계가 많다고 성능이 무조건 좋아지는 것은 아니다. 의존성·분기·자원 충돌이 한계가 된다. Superscalar와 VLIW는 명령 수준 병렬성을 활용하는 서로 다른 방식이고, 멀티코어·스레드 병렬성과도 구분한다. [명령 실행·CPU 병렬성 지도](01-명령실행-CPU-병렬성.md)에서 관계를 복원한다.

## 3. CPU가 빠른데 왜 주문 처리는 느릴까 — Cache와 Memory

CPU가 재고 데이터를 읽으려는데 메모리 접근이 오래 걸린다.

CPU와 RAM의 속도 격차를 줄이는 것이 다음 과제다. Cache는 시간·공간 지역성을 이용해 자주 쓰는 데이터를 빠르게 제공한다. 하지만 Cache가 크다고 모든 접근이 적중하지는 않는다.

여기서 Cache와 Virtual Memory가 같은 문제를 해결하는 기술인지는 구분해야 한다. Cache는 주로 접근 지연을 완화하고, Paging은 메모리 배치·관리 방식, Virtual Memory는 주소 공간을 물리 메모리와 분리하는 체계다. MMU는 주소 변환을 지원하고 TLB는 최근 변환 정보를 캐싱한다. [메모리 계층·가상 메모리 지도](02-메모리-계층-가상메모리.md)를 참고한다.

## 4. 주문 기록을 저장한다 — Interrupt·DMA·SSD

주문 결과를 저장장치에 기록해야 한다.

저장장치의 작업 완료를 기다리는 동안 CPU가 계속 개입할 필요는 없다. Interrupt는 완료 등 사건을 알리고 DMA는 CPU의 반복 개입을 줄여 장치와 메모리 사이 전송을 지원한다. 둘은 같은 기능이 아니다.

SSD 내부에서는 논리 주소와 NAND의 실제 위치를 연결해야 한다. FTL(Flash Translation Layer)이 논리 주소와 Flash 배치를 연결한다. RAID는 성능·중복 설계, DAS/NAS/SAN은 저장장치 연결·접근 구조다. 모두 같은 저장 기술 분류가 아니다. [I/O·저장장치 지도](03-IO-저장장치.md)에서 비교한다.

## 5. 무엇을 개선해야 실제 빨라질까 — 성능·신뢰성

CPU를 두 배 빠르게 바꿨지만 주문 응답시간은 거의 개선되지 않았다.

부품 하나를 개선해도 전체 성능 향상이 제한되는 이유는 다른 병목에 있다. 전체 처리시간 중 해당 부품이 차지하는 비중과 다른 병목 때문이다. Amdahl 법칙은 개선되지 않는 부분이 전체 속도 향상을 제한함을 설명한다. CPI, 처리량, 지연시간은 서로 다른 성능 지표다.

마지막으로 성능과 신뢰성도 별도로 평가해야 한다. 성능과 신뢰성은 별도 평가 관점이다. MTBF는 고장 사이 평균 시간, MTTR은 평균 복구 시간이며 Watchdog은 비정상 상태 감지·복구를 돕는 장치·기법이다. [성능·신뢰성 지도](04-성능-신뢰성.md)를 참고한다.

~~~text
CPU: 명령 실행·병렬성
  ↕ 명령·데이터 접근
Memory: Cache·주소 변환·배치
  ↕ 데이터 이동
I/O·Storage: Interrupt·DMA·SSD
[전 과정 평가] 지연·처리량·병목·신뢰성
~~~
