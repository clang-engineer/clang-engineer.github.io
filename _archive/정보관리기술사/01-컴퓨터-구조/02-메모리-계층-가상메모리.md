# 메모리 계층과 가상 메모리 개념지도

이 문서는 [컴퓨터 구조 전체 개념지도](00-전체.md)에서 **메모리 계층과 가상 메모리** 가지를 선택했을 때, `속도 격차 → 배치 문제 → 주소 공간 분리`라는 서로 다른 문제를 구분해 파고들기 위한 지도다.

## 먼저 알아둘 용어

```text
Paging
= 프로세스 주소 공간을 Page로, 물리 메모리를 Frame으로 나눠 불연속 배치하는 방식

Segmentation
= 프로그램의 논리적 구역을 가변 크기 Segment로 나눠 배치하는 방식

MMU(Memory Management Unit)
= CPU가 만든 가상주소를 물리주소로 변환하는 하드웨어

TLB(Translation Lookaside Buffer)
= 최근 주소 변환 결과를 빠르게 찾기 위한 Cache

```

처음에는 `캐시 = 속도`, `Paging = 배치·Mapping 기반`, `가상 메모리 = 주소 공간 분리`라는 세 축만 먼저 구분하면 된다. Page 적재·교체·Thrashing 같은 운영 정책은 운영체제 Memory 관리에서 중심적으로 다룬다.

## 1. 전체 좌표

```text
메모리 관련 문제
│
├─ CPU보다 RAM이 느림
│   ↓
│  메모리 계층
│   ↓
│  지역성
│   ↓
│  캐시
│
├─ 프로세스를 연속된 물리 메모리에 배치해야 함
│   ↓
│  메모리 할당
│   ├─ 연속 할당
│   └─ 불연속 할당
│       ├─ Paging
│       └─ Segmentation
│
└─ 프로세스 주소 공간과 실제 물리 위치를 어떻게 분리할까?
    ↓
   가상 메모리
    ├─ Virtual Address ↔ Physical Address
    ├─ Page Table
    ├─ MMU
    └─ TLB
```

캐시와 가상 메모리는 모두 계층과 매핑을 이용하지만 해결하려는 중심 문제가 다르다.

```text
캐시
→ 접근시간 단축

Paging
→ 물리 메모리의 연속 배치 요구 제거

가상 메모리
→ 프로세스 주소 공간과 물리 메모리를 분리
```

## 2. 속도 격차: 메모리 계층과 캐시

```text
CPU가 매우 빠름
        ↓
RAM 접근이 상대적으로 느림
        ↓
매번 RAM을 기다리면 성능 저하
        ↓
지역성(Locality) 활용
        ↓
캐시(Cache)
```

캐시를 실제로 운영하려면 다음 문제가 생긴다.

```text
어디에 넣을까?      → 매핑(Mapping)
자리가 없으면?      → 교체(Replacement)
수정하면 언제 반영? → 쓰기 정책(Write Policy)
```

멀티코어에서는 같은 데이터가 여러 Core의 Cache에 복제되면서 캐시 일관성(Cache Coherence) 문제가 추가되고, MESI 같은 Protocol로 복제본 상태를 관리한다.

세부학습: [캐시 메모리와 쓰기·일관성](캐시-메모리와-쓰기-일관성.md)

## 3. 배치 문제: 연속 할당에서 Paging으로

```text
연속 메모리 할당
        ↓
큰 연속 공간이 필요
        ↓
외부 단편화와 배치 제약
        ↓
"꼭 연속해서 배치해야 하나?"
        ↓
불연속 할당
├─ Paging
└─ Segmentation
```

Paging은 논리 주소 공간을 Page로, 물리 메모리를 같은 크기의 Frame으로 나눠 서로 떨어진 Frame에 배치할 수 있게 한다.

```text
Page 0 → Frame 4
Page 1 → Frame 1
Page 2 → Frame 7
```

이때 Page Table이 Page와 Frame의 대응 관계를 관리한다.

## 4. 주소 공간 분리: 가상 메모리

가상 메모리의 본질은 **Process가 보는 Virtual Address Space와 실제 Physical Memory 위치를 분리하고 Mapping하는 것**이다.

~~~text
CPU가 Virtual Address 생성
        ↓
       MMU
        ↓
   TLB에서 Mapping 검색
     ┌──┴──┐
   Hit    Miss
    │       ↓
    │   Page Table 조회
    │       ↓
    │   Mapping 확인
    │       │
    └───────┘
        ↓
Physical Address 생성
        ↓
Cache / RAM 접근
~~~

역할은 다음처럼 구분한다.

~~~text
Page Table
= Virtual Page → Physical Frame 기준 Mapping

TLB
= 최근 주소 변환 결과를 저장하는 Cache

MMU
= TLB와 Page Table을 이용해 주소 변환 수행
~~~

이 지도에서는 **주소 변환 구조와 비용**까지만 중심적으로 본다. Virtual Page가 RAM에 없을 때의 적재 정책, Frame 배분, Page Replacement, Thrashing은 운영체제의 Memory 관리가 중심 소유한다.

→ 운영체제 · Memory 관리  
Demand Paging → Page Fault → Frame Allocation / Replacement → Thrashing처럼 Physical Memory를 실제로 운영하는 정책을 더 볼 때 내려간다.

## 5. 서로 비슷해 보이는 개념의 경계

```text
캐시
= CPU-RAM 속도 차이를 줄이는 성능 계층

Paging
= Virtual Page와 Physical Frame을 Mapping할 수 있게 하는 대표 배치·Mapping 기반

가상 메모리
= Virtual Address Space와 Physical Memory를 분리하는 주소 공간 추상화

TLB
= 최근 주소 변환 결과를 저장하는 빠른 Cache
```

TLB가 Cache라고 해서 일반 Data Cache와 같은 역할을 하는 것은 아니다. TLB는 **주소 변환 결과**를 빠르게 찾기 위한 Cache다.

## 6. 기억 흐름

```text
[속도]
CPU ↔ RAM 격차
→ 지역성
→ 캐시

[배치]
연속 공간 요구
→ 불연속 할당
→ Paging / Segmentation

[주소 공간]
Virtual Address ↔ Physical Address
→ 가상 메모리
→ Page Table / MMU / TLB
→ Cache / RAM 접근

[운영 정책]
Demand Paging / Frame Allocation / Replacement / Thrashing
→ 운영체제 Memory 관리에서 Zoom-in
```
