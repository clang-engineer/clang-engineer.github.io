# 메모리 계층과 가상 메모리 개념지도

이 문서는 [컴퓨터 구조 전체 개념지도](00-전체.md)에서 **메모리 계층과 가상 메모리** 가지를 선택했을 때, `속도 격차 → 배치 문제 → 주소 공간 분리`라는 서로 다른 문제를 구분해 파고들기 위한 지도다.

## 1. 전체 좌표 — Memory의 세 관점

```text
Memory — 명령·데이터 제공
│
├─ 접근 속도 → Memory Hierarchy / Cache
│  └─ 지역성을 이용해 CPU–RAM 지연 완화
│
├─ 배치·분할 → 연속 할당 / Paging / Segmentation
│  ├─ Paging → Page를 떨어진 Frame에 배치 가능
│  └─ Segmentation → 논리 Segment별 구역 관리
│
└─ 주소 공간·변환 → Virtual Memory / Page Table / MMU / TLB
   └─ Paging은 Virtual Memory 구현에 활용되는 대표 매핑 기법
```

**Cache는 접근 지연, Paging·Segmentation은 배치·분할, Virtual Memory는 주소 공간 추상화**에 초점을 둔다. 서로 완전히 독립적인 기술 계층은 아니다. 전통적 Segmentation은 각 Segment 내부가 연속 배치되어 외부 단편화가 생길 수 있으며, Paging은 Virtual Memory를 구현하는 대표 기법이다.

### 핵심 용어

- **Paging:** Page 단위로 나누고 물리 Frame에 매핑하는 방식
- **Segmentation:** 논리적으로 의미 있는 가변 크기 Segment로 분할하는 방식
- **MMU:** 주소 변환 하드웨어
- **TLB:** 최근 주소 변환 결과를 저장하는 Cache

## 2. 속도 격차: 메모리 계층과 캐시

```text
CPU가 매우 빠름
        ↓
RAM 접근이 상대적으로 느림
        ↓
매번 RAM을 기다리면 성능 저하
        ↓
지역성(Locality) 활용
        ↓
캐시(Cache)
```

캐시를 실제로 운영하려면 다음 문제가 생긴다.

```text
어디에 넣을까?      → 매핑(Mapping)
자리가 없으면?      → 교체(Replacement)
수정하면 언제 반영? → 쓰기 정책(Write Policy)
```

멀티코어에서는 같은 데이터가 여러 Core의 Cache에 복제되면서 캐시 일관성(Cache Coherence) 문제가 추가되고, MESI 같은 Protocol로 복제본 상태를 관리한다.

세부학습: [캐시 메모리와 쓰기·일관성](캐시-메모리와-쓰기-일관성.md)

## 3. 배치 문제: 연속 할당에서 Paging으로

```text
연속 메모리 할당
        ↓
큰 연속 공간이 필요
        ↓
외부 단편화와 배치 제약
        ↓
"꼭 연속해서 배치해야 하나?"
        ↓
배치 방식
├─ Paging → 불연속 Frame 배치
└─ Segmentation → 논리 단위 분할(각 Segment 내부 연속 배치)
```

Paging은 논리 주소 공간을 Page로, 물리 메모리를 같은 크기의 Frame으로 나눠 서로 떨어진 Frame에 배치할 수 있게 한다. 반면 전통적인 Segmentation은 Segment마다 가변 크기의 연속 물리 영역을 할당하므로 외부 단편화가 발생할 수 있다. 두 기법을 똑같은 의미의 불연속 배치로 묶지 않는다.

```text
Page 0 → Frame 4
Page 1 → Frame 1
Page 2 → Frame 7
```

이때 Page Table이 Page와 Frame의 대응 관계를 관리한다.

## 4. 주소 공간 분리: 가상 메모리

가상 메모리의 본질은 **Process가 보는 Virtual Address Space와 실제 Physical Memory 위치를 분리하고 Mapping하는 것**이다. Paging은 이를 구현하는 대표 기법이며, Demand Paging은 필요한 Page를 적재하는 운영 정책이다. Virtual Memory가 Paging 뒤에 반드시 추가되는 단계는 아니다.

~~~text
CPU가 Virtual Address 생성
        ↓
       MMU
        ↓
   TLB에서 Mapping 검색
     ┌──┴──┐
   Hit    Miss
    │       ↓
    │   Page Table 조회
    │       ↓
    │   Mapping 확인
    │       │
    └───────┘
        ↓
Physical Address 생성
        ↓
Cache / RAM 접근
~~~

역할은 다음처럼 구분한다.

~~~text
Page Table
= Virtual Page → Physical Frame 기준 Mapping

TLB
= 최근 주소 변환 결과를 저장하는 Cache

MMU
= TLB와 Page Table을 이용해 주소 변환 수행
~~~

이 지도에서는 **주소 변환 구조와 비용**까지만 중심적으로 본다. Virtual Page가 RAM에 없을 때의 적재 정책, Frame 배분, Page Replacement, Thrashing은 운영체제의 Memory 관리가 중심 소유한다.

→ 운영체제 · Memory 관리  
Demand Paging → Page Fault → Frame Allocation / Replacement → Thrashing처럼 Physical Memory를 실제로 운영하는 정책을 더 볼 때 내려간다.

## 5. 서로 비슷해 보이는 개념의 경계

```text
캐시
= CPU-RAM 속도 차이를 줄이는 성능 계층

Paging
= Virtual Page와 Physical Frame을 Mapping할 수 있게 하는 대표 배치·Mapping 기반

가상 메모리
= Virtual Address Space와 Physical Memory를 분리하는 주소 공간 추상화

TLB
= 최근 주소 변환 결과를 저장하는 빠른 Cache
```

TLB가 Cache라고 해서 일반 Data Cache와 같은 역할을 하는 것은 아니다. TLB는 **주소 변환 결과**를 빠르게 찾기 위한 Cache다.
