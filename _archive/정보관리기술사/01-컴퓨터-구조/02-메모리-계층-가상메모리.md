# 메모리 계층과 가상 메모리 개념지도

[컴퓨터 구조 전체 개념지도](00-전체.md)에서 **메모리 계층 → 캐시 → 가상 메모리 → 반도체 메모리 기술**을 연결하는 지도다. 학습 순서와 물리적인 계층·분류는 구별한다.

## 1. 전체 좌표 — 접근 구조와 저장 기술

```text
CPU는 데이터를 빠르게 사용하고 싶다
          │
          ▼
① 속도·용량·비용을 모두 만족할 수 없네?
   └─ Register → Cache → RAM → SSD/HDD (메모리 계층)
          │
          ▼
② CPU와 RAM 사이가 느리네?
   └─ 지역성 활용 → Cache
      └─ Hit/Miss → 매핑·교체·쓰기 정책
          │
          ▼
③ 프로그램이 RAM의 실제 위치를 알아야 할까?
   └─ Virtual Memory: 주소 공간 추상화
      └─ Paging(Page ↔ Frame) → Page Table·MMU
                                   └─ 변환도 빨라야 → TLB

────────────────── 별도의 분류 관점 ──────────────────
④ 실제 데이터를 무엇으로 저장할까?
   ├─ 휘발성: SRAM(캐시) / DRAM(주기억장치)
   │          └─ Refresh → SDRAM(클럭 동기화) → DDR(양 에지)
   └─ 비휘발성: ROM / EEPROM / Flash
                             └─ NAND(대용량) / NOR(코드 읽기)
```

**읽는 순서:** 메모리 계층과 캐시(접근 속도) → 가상 메모리(주소 변환) → RAM·ROM·Flash(저장 기술). 이들은 순차 실행 단계가 아니라 서로 다른 관점이다.

**범위:** Paging 기반 가상 메모리의 주소 변환을 중심으로 설명한다. 할당·Demand Paging·Page Replacement·Thrashing 등 운영 정책은 [운영체제 메모리 관리](../02-운영체제/03-메모리-관리.md)에서 다룬다.

## 2. 메모리 계층과 캐시 — 속도 격차 완화

CPU(Central Processing Unit, 중앙처리장치)가 사용하는 RAM(Random Access Memory, 임의 접근 메모리)은 보통 DRAM으로 구현되고, 캐시는 주로 SRAM으로 구현된다.

```text
메모리 계층 (접근 성능 중심)

빠름·작음·비쌈
   [Register]       CPU 내부
       ↓
   [L1 / L2 / L3]   Cache (주로 SRAM)
       ↓
   [Main Memory]    RAM (주로 DRAM)
       ↓
   [SSD / HDD]      보조기억장치
느림·큼·저렴

※ ROM은 이 성능 계층에서 생략될 수 있는 펌웨어 저장 유형
```

```text
CPU가 매우 빠름
        ↓
RAM 접근이 상대적으로 느림
        ↓
매번 RAM을 기다리면 성능 저하
        ↓
지역성(Locality) 활용
        ↓
캐시(Cache)
```

캐시는 **시간 지역성(최근 사용한 데이터 재사용)**과 **공간 지역성(인접 데이터 접근)**을 이용한다. 요청한 데이터가 캐시에 있으면 Hit, 없으면 Miss다. Miss 시에는 하위 계층에서 데이터를 가져오며, 저장 가능한 위치가 이미 차 있다면 교체가 필요할 수 있다.

캐시를 실제로 운영하려면 다음 세 가지 질문이 생긴다.

```text
CPU 데이터 요청
      │
   Cache 조회
    ├─ Hit  → 즉시 사용
    └─ Miss → 하위 메모리 조회 → Cache Line 적재 → 사용
```


```text
캐시 운영 — 무엇을 결정하는가?
│
├─ ① 매핑(Mapping) — 어디에 저장할까?
│  ├─ 직접(Direct)        → 정해진 위치 한 곳
│  ├─ 완전 연관(Fully)    → 어느 위치나 가능
│  └─ 집합 연관(Set)      → 정해진 집합의 여러 Way
│
├─ ② 교체(Replacement) — 무엇을 내보낼까?
│  ├─ LRU(Least Recently Used) → 가장 오래 사용하지 않은 것
│  ├─ FIFO(First In, First Out) → 가장 먼저 들어온 것
│  └─ Random → 무작위 선택
│
└─ ③ 쓰기(Write Policy) — 언제 하위 계층에 반영할까?
   ├─ Write-through → 쓰기를 하위 계층에도 전달
   └─ Write-back    → 캐시에 먼저 쓰고 나중에 반영
                        └─ Dirty Bit: 미반영 변경 표시
```

**매핑은 지역성과 다르다.** 지역성은 캐시가 효과적인 이유이고, 매핑은 메모리 블록이 들어갈 캐시 위치를 정하는 규칙이다. 직접 매핑은 단순하지만 같은 위치를 두고 충돌 미스가 발생할 수 있고, 완전 연관은 배치가 자유롭지만 비교 회로가 복잡하다. 집합 연관은 두 방식의 절충이다.

교체 정책에서는 **LRU는 최근 사용 시점**, **FIFO는 최초 적재 시점**을 기준으로 한다. Write-back에서는 변경된 캐시 라인을 Dirty로 표시하고, 교체 등 필요 시 하위 계층에 기록한다. 쓰기 미스 시 캐시에 적재할지를 정하는 Write-allocate/No-write-allocate는 쓰기 반영 시점과는 별도의 정책 축이다.

세부 매핑 충돌 예시, 교체·쓰기 정책의 장단점은 [캐시 메모리와 쓰기·일관성](캐시-메모리와-쓰기-일관성.md)에서 이어진다.

멀티코어에서는 같은 데이터가 여러 Core의 Cache에 복제되면서 캐시 일관성(Cache Coherence) 문제가 추가되고, MESI(Modified, Exclusive, Shared, Invalid) 같은 프로토콜로 복제본 상태를 관리한다.

세부학습: [캐시 메모리와 쓰기·일관성](캐시-메모리와-쓰기-일관성.md)

### 캐시의 계층(Level)과 용도(Type)는 다른 분류다

```text
CPU 실행부
   ├─ L1 I-Cache → 명령어
   └─ L1 D-Cache → 데이터
          ↓
      L2 Cache    → 보통 통합 캐시
          ↓
      L3 Cache    → 보통 통합·코어 간 공유 캐시
          ↓
         RAM      → 명령어와 데이터
```

L1·L2·L3는 **속도·용량의 계층**이며, I-Cache·D-Cache·Unified Cache는 **저장 대상에 따른 유형**이다. 일반적인 PC CPU에서 L1은 명령어/데이터용으로 분리되고 L2·L3는 통합되지만, 실제 단계 수와 코어별 공유 범위는 CPU 설계마다 다르다. L1을 무조건 크게 만들지 않는 이유는 용량을 늘릴수록 접근 지연·칩 면적·전력 비용이 불리해질 수 있기 때문이다.

```text
CPU의 데이터 접근
L1 Hit → 사용
   Miss → L2 조회
              Miss → L3 조회
                         Miss → RAM 접근
```

이 흐름은 일반적인 계층 구조의 개념도이며 실제 조회·채움 정책은 설계에 따라 다르다. **시간 지역성**은 최근 사용한 데이터의 재사용 가능성, **공간 지역성**은 인접 주소의 접근 가능성이다. 캐시는 이 특성을 활용해 메모리 접근을 줄인다. Hit 비율이 높을수록 일반적으로 평균 메모리 접근시간이 감소한다. 데이터가 어느 레벨에 남는지는 단순 사용 빈도 순위가 아니라 접근 패턴·매핑·교체 정책·캐시 설계에 따라 결정된다.

## 3. 가상 메모리 — 물리 위치를 몰라도 실행할 수 있을까?

캐시는 **접근 속도**를 개선했지만 프로그램이 물리 RAM의 주소를 직접 관리해야 하는 문제까지 해결하지는 않는다. 프로그램마다 독립적인 가상주소 공간을 제공하고 실제 물리주소와 분리하는 것이 **가상 메모리(Virtual Memory)**다.

```text
프로그램이 사용하는 Virtual Address
               │
               ▼
     주소 공간을 물리 위치와 분리
               │
               ▼
   주소 변환이 필요해짐 → Paging
               │
        Page ↔ Frame
               │
       Page Table / MMU
               │
      변환 비용도 줄여야 함
               └────────→ TLB
```

### Page와 Frame — 주소 변환의 단위

**이 절부터는 Paging 기반 구현의 예시다.** 메모리 할당 방식 전체를 Paging 하나로 한정하는 것은 아니다.

프로그램은 **Virtual Address**를 사용하고, 하드웨어는 이를 실제 **Physical Address**로 변환해야 한다. 현대 시스템에서 널리 사용하는 Paging은 가상주소 공간을 Page, RAM을 Frame으로 나누고 대응시킨다.

```text
Virtual Page 0 → Physical Frame 4
Virtual Page 1 → Physical Frame 1
Virtual Page 2 → Physical Frame 7
```

**Page Table**은 이 대응 정보를 관리한다. 이 지도에서는 주소 변환에 필요한 이 관계만 다루고, 메모리 할당 방식과 Paging·Segmentation 비교는 [운영체제 메모리 관리](../02-운영체제/03-메모리-관리.md)에서 다룬다.

### MMU와 TLB — 주소 변환의 실행과 가속

MMU(Memory Management Unit, 메모리 관리 장치)는 주소 변환을 담당하며, TLB(Translation Lookaside Buffer, 주소 변환 캐시)는 최근 변환 결과를 보관한다.

가상 메모리의 핵심은 프로그램이 보는 가상주소 공간과 실제 물리 메모리의 위치를 분리하는 것이다. Paging은 대표 구현 방식이고 Demand Paging은 필요한 페이지를 적재하는 운영 정책이다.

~~~text
CPU가 Virtual Address 생성
        ↓
       MMU
        ↓
   TLB에서 Mapping 검색
     ┌──┴──┐
   Hit    Miss
    │       ↓
    │   Page Table 조회
    │       ↓
    │   Mapping 확인
    │       │
    └───────┘
        ↓
Physical Address 생성
        ↓
Cache / RAM 접근
~~~

**TLB Miss와 Page Fault는 다르다.** TLB에 매핑이 없더라도 Page Table에 유효한 매핑이 있으면 변환 가능하다. 해당 페이지가 RAM에 없으면 Page Fault 처리가 필요할 수 있다.

역할은 다음처럼 구분한다.

~~~text
Page Table
= Virtual Page → Physical Frame 기준 Mapping

TLB
= 최근 주소 변환 결과를 저장하는 Cache

MMU
= TLB와 Page Table을 이용해 주소 변환 수행
~~~

위 그림은 개념적 흐름이다. 실제 CPU에서는 캐시 조회와 주소 변환이 일부 중첩될 수 있으며, 모든 하드웨어가 그림처럼 완전히 순차적으로 실행되는 것은 아니다.

이 지도에서는 **주소 변환 구조와 비용**까지만 중심적으로 본다. Virtual Page가 RAM에 없을 때의 적재 정책, Frame 배분, Page Replacement, Thrashing은 운영체제의 Memory 관리가 중심 소유한다.

→ [운영체제 메모리 관리](../02-운영체제/03-메모리-관리.md): Allocation → Demand Paging → Page Fault → Frame Allocation / Replacement → Thrashing

## 4. 서로 비슷해 보이는 개념의 경계

```text
캐시
= CPU-RAM 속도 차이를 줄이는 성능 계층

Paging
= Virtual Page와 Physical Frame을 Mapping할 수 있게 하는 대표 배치·Mapping 기반

가상 메모리
= Virtual Address Space와 Physical Memory를 분리하는 주소 공간 추상화

TLB
= 최근 주소 변환 결과를 저장하는 빠른 Cache
```

TLB가 Cache라고 해서 일반 Data Cache와 같은 역할을 하는 것은 아니다. TLB는 **주소 변환 결과**를 빠르게 찾기 위한 Cache다.

## 5. 기억장치의 분류와 비휘발성 반도체 메모리

앞에서는 CPU가 **어떻게 메모리에 접근하는지** 살폈다. 이제 관점을 바꿔, 데이터를 **어떤 물리 기술로 저장하는지** 살펴본다. ROM(Read-Only Memory, 읽기 전용 메모리)은 전통적인 비휘발성 메모리 유형이며, Flash는 전기적으로 지우고 다시 기록할 수 있는 비휘발성 반도체 메모리다.

**분류축을 섞지 않는다.** 메모리 계층(Register → Cache → RAM → SSD/HDD)은 CPU 접근 성능 관점이며, 기억장치의 모든 종류를 나열한 계보가 아니다.

| 분류축 | 구분 예시 | 묻는 질문 |
|---|---|---|
| 시스템 역할 | 레지스터·캐시·주기억장치·보조기억장치·펌웨어 저장 | 어디에 사용하는가? |
| 휘발성 | 휘발성·비휘발성 | 전원을 꺼도 유지되는가? |
| 저장 기술 | 반도체·자기·광학 | 무엇으로 정보를 기억하는가? |

전통적인 교재에서는 주기억장치를 RAM·ROM으로 소개하지만, 현대 PC의 일반적인 실행용 주기억장치는 DRAM이고 펌웨어는 메인보드의 비휘발성 Flash 등에 별도 저장되는 경우가 많다. 따라서 **ROM이 성능 중심 메모리 계층도에 없다고 기억장치가 아닌 것은 아니다.**

### RAM·ROM·EEPROM·Flash의 관계

PROM(Programmable ROM)은 한 번 기록할 수 있고, EPROM(Erasable Programmable ROM)은 자외선으로 삭제하며, EEPROM(Electrically Erasable Programmable ROM)은 전기적으로 삭제·재기록할 수 있다. Flash는 EEPROM 계열로 블록 단위 삭제를 사용한다.

```text
반도체 메모리 (대표 유형)
├─ 휘발성
│  ├─ SRAM → 주로 Cache
│  └─ DRAM → 주로 Main Memory
└─ 비휘발성
   ├─ Mask ROM → 제조 시 내용 고정
   ├─ PROM → 1회 기록
   ├─ EPROM → 자외선 삭제·재기록
   └─ EEPROM 계열 → 전기적 삭제·재기록
      ├─ 일반 EEPROM → 작은 단위 수정에 유리
      └─ Flash → 블록 단위 삭제
         ├─ NOR Flash
         └─ NAND Flash
```

이는 **전통적인 ROM 계열의 학습용 분류**다. RAM(Random Access Memory)과 ROM(Read Only Memory)은 명칭상 접근·기록 특성을 가리키며, 휘발성과 완전히 동의어는 아니다. 특히 Mask ROM은 회로 구조로 정보를 보존하고, Flash는 절연된 구조에 전하를 가둬 비휘발성을 구현한다. 위 계보를 모든 기술의 직계 역사로 해석하지 않는다.

| 종류 | 기록·삭제 특성 | 주된 용도 |
|---|---|---|
| Mask ROM | 제조 후 변경 불가 | 고정 코드 |
| PROM | 1회 기록 | 변경 불필요한 데이터 |
| EPROM | 자외선으로 삭제 | 과거 펌웨어 등 |
| EEPROM | 전기적으로 작은 단위 삭제·재기록 | 설정값·소량 데이터 |
| Flash | 전기적으로 블록 단위 삭제 | 대용량 저장·펌웨어 |

**Flash는 SSD(Solid-State Drive, 반도체 저장장치) 자체가 아니라 반도체 저장 기술**이다. SSD·USB 메모리는 주로 NAND Flash를 이용한 장치이고, 현대 PC의 BIOS/UEFI 펌웨어는 주로 Flash 칩에 저장한다. 따라서 펌웨어용 Flash와 SSD는 같은 기술 계열을 서로 다른 목적으로 활용한 예다.

### NAND와 NOR — 무엇에 최적화했는가?

**왜 NAND와 NOR로 나뉘었을까?** 같은 비휘발성 Flash라도 **많은 데이터를 저렴하게 저장하는 일**과 **특정 주소의 코드를 빠르게 읽는 일**은 요구사항이 다르다. 이를 모두 한 구조로 최적화하기 어려워 서로 다른 셀 연결 방식이 사용된다.

```text
Flash에 요구하는 두 가지 일
             │
     ┌───────┴────────┐
     ▼                ▼
많이·저렴하게 저장   원하는 주소를 바로 읽기
     │                │
셀을 직렬로 연결     개별 셀 접근에 유리한 연결
     │                │
NAND Flash          NOR Flash
고집적·낮은 비용     임의 읽기·코드 접근
     │                │
SSD / USB           펌웨어 / XIP
```

즉, **NAND는 저장 밀도·비용을, NOR는 임의 읽기 접근성을 우선한 구조적 절충**이다. NAND와 NOR는 세대 순서나 상하위 관계가 아니라 서로 다른 설계 방식이다.

NAND(Not AND)와 NOR(Not OR)는 논리 게이트에서 유래한 이름으로, Flash 셀 연결 구조의 차이를 가리킨다. NOR Flash는 XIP(Execute In Place, 저장 위치에서 직접 코드 실행)에 유리하다.

```text
비휘발성 반도체 메모리 vs 자기 저장

Mask ROM → 회로 구조에 정보 고정
Flash    → 절연된 영역에 전하 저장
HDD      → 자기 상태로 정보 저장

Flash ┬→ NAND → SSD / USB (대용량)
      └→ NOR  → 펌웨어 (임의 읽기)
```


```text
Flash Memory
├─ NAND: 셀을 직렬 문자열(String)로 연결
│         → 고집적·대용량·페이지 기반 접근
│         → SSD / USB 메모리
└─ NOR: 셀별 임의 주소 읽기에 유리한 연결
          → 코드 읽기·XIP(제자리 실행)에 유리
          → 펌웨어 / 임베디드 시스템
```

| 비교 | NAND Flash | NOR Flash |
|---|---|---|
| 구조적 특징 | 셀의 직렬 연결 | 임의 주소 접근에 유리한 연결 |
| 강점 | 높은 집적도·낮은 비트당 비용 | 빠른 임의 읽기·메모리 매핑에 유리 |
| 일반적 접근 | 페이지 단위 읽기·프로그램, 블록 단위 삭제 | 작은 단위 임의 읽기, 블록/섹터 단위 삭제 |
| 대표 용도 | SSD·USB | 펌웨어·XIP |

NAND/NOR라는 이름은 셀의 연결 구조가 해당 논리 게이트의 구성과 닮은 데서 왔다. **NAND는 저장 용량, NOR는 코드 접근**으로 먼저 구별한다. 실제 성능·지원 동작은 칩 설계에 따라 달라진다.

**성안당 30번 복원:** 기억장치 분류축 구분 → RAM의 휘발성 → ROM 계열과 EEPROM의 전기적 재기록 → Flash의 블록 삭제·고집적 → NAND(대용량) / NOR(코드 접근).

## 6. SRAM·DRAM·SDRAM·DDR — 왜 서로 다른 RAM이 필요한가?

**캐시는 왜 빠른 SRAM을 쓰고, 주기억장치는 왜 DRAM을 쓸까?** 속도·집적도·비용의 절충 때문이다. SRAM(Static Random Access Memory, 정적 RAM)은 회로 상태로 정보를 유지하고, DRAM(Dynamic Random Access Memory, 동적 RAM)은 축전기 전하로 정보를 저장한다. SDRAM(Synchronous Dynamic Random Access Memory, 동기식 DRAM)은 메모리 클럭에 맞춰 동작하며, DDR(Double Data Rate, 이중 데이터 전송률)은 양쪽 클럭 에지를 활용한다.

**SRAM과 DRAM은 데이터를 기억하는 셀 구조의 차이**, **SDRAM과 DDR은 DRAM의 동작·전송 방식**을 구분한다. 같은 분류축에 나란히 놓지 않는다.

```text
RAM (일반적인 휘발성 반도체 메모리)
├─ SRAM (Static RAM)
│  └─ 회로 상태 유지 / Refresh 불필요 → 주로 CPU Cache
└─ DRAM (Dynamic RAM)
   └─ 축전기에 전하 저장 / Refresh 필요 → 주로 주기억장치
      └─ SDRAM (Synchronous DRAM) → 클럭과 동기화
         └─ DDR SDRAM → 클럭 양쪽 에지에서 데이터 전송
            ├─ DDR4
            └─ DDR5
```

### DRAM에 Refresh가 필요한 이유

```text
SRAM                           DRAM
회로 상태 유지                 축전기 전하 저장
      │                              │
Refresh 불필요                 시간 경과 → 전하 누설
      │                              │
CPU Cache                       Refresh로 복원
                                     │
                                 Main Memory
```


DRAM 셀은 **축전기(Capacitor)에 저장된 전하량**으로 데이터를 구분한다. 축전기는 작은 전기 저장통과 비슷하지만, 전원이 켜져 있어도 전하가 조금씩 **누설(Leakage)**된다. 전하가 너무 줄면 0과 1을 구분하기 어려워지므로, 데이터가 손실되기 전에 주기적으로 전하 상태를 복원하는 **Refresh**가 필요하다.

```text
DRAM: 전하 저장 → 시간 경과·전하 누설 → Refresh로 복원 → 반복
SRAM: 안정된 회로 상태로 기억 → 전원이 공급되는 동안 주기적 Refresh 불필요
```

**Static은 비휘발성이라는 뜻이 아니다.** SRAM과 DRAM은 모두 일반적으로 전원을 끄면 데이터가 사라진다.

| 구분 | SRAM | DRAM |
|---|---|---|
| 저장 원리 | 플립플롭 형태의 회로 상태 | 축전기 전하 |
| Refresh | 불필요 | 필요 |
| 특성 | 빠르지만 셀 면적·비트당 비용이 큼 | 고집적·대용량·비트당 비용이 낮음 |
| 대표 용도 | CPU Cache | 주기억장치 |

### Refresh 다음 질문 — 동작 타이밍을 어떻게 맞출까?

디지털 회로는 입력이 바뀐 뒤 결과가 안정되기까지 시간이 필요하다. **클럭(Clock)은 언제 상태를 확정하고 다음 동작으로 넘어갈지 정하는 타이밍 기준**이다. CPU 코어의 클럭과 메모리 인터페이스의 클럭은 같을 필요가 없다.

```text
CPU Core Clock → CPU 내부 상태 갱신 타이밍
Memory Clock   → 메모리 컨트롤러와 SDRAM의 명령·전송 타이밍
```

따라서 **SDRAM의 Synchronous는 CPU 코어 클럭에 직접 맞춘다는 뜻이 아니라, 메모리 인터페이스 클럭에 동기화한다는 뜻**이다.

### 전송 기회를 늘리려면? — DDR4·DDR5

```text
메모리 인터페이스 Clock
       ┌───┐   ┌───┐
_______│   │___│   │_______
       ↑   ↓   ↑   ↓
SDR    ●       ●        주기당 1회 전송
DDR    ●   ●   ●   ●    주기당 2회 전송

CPU Core Clock과 Memory Clock은 같을 필요 없음
```


**SDRAM**은 메모리 인터페이스 클럭에 맞춰 동작하는 DRAM이며, **DDR(Double Data Rate) SDRAM**은 클럭의 상승·하강 에지 모두에서 데이터를 전송한다. 같은 데이터 전송 클럭 기준으로 SDR보다 전송 기회가 두 배다. DDR4·DDR5는 이 DDR SDRAM의 세대별 규격이지, SRAM과 경쟁하는 별도 RAM 종류가 아니다.

```text
PC에서 'DDR5 RAM' 구매
→ DRAM 계열의 DDR5 SDRAM 모듈 구매
→ 용량(GB, Gigabyte)과 전송률(MT/s, MegaTransfers per second)은 서로 다른 사양
→ CPU·메인보드가 해당 DDR 세대를 지원해야 함
```

**성안당 36번 복원:** Cache는 왜 SRAM인가? (속도) → 주기억장치는 왜 DRAM인가? (집적도·비용) → DRAM Refresh의 원인(전하 누설) → SDRAM(동기화) → DDR(양쪽 에지 전송) → DDR4/DDR5(세대).

### 27번 비교의 핵심 축

| 비교 기준 | Cache | Virtual Memory |
|---|---|---|
| 목적 | CPU–RAM 접근 지연 완화 | 주소 공간 추상화·보호·효율적 메모리 관리 |
| 대상 | Memory Block / Cache Line | Virtual Page / Physical Frame (Paging 기반) |
| 원리 | 지역성에 기반한 복사본 재사용, Hit/Miss | Virtual Address → Physical Address 변환 |
| 주요 구성 | Cache 계층·Tag·매핑/교체/쓰기 정책 | Page Table·MMU·TLB |
| 관리 주체 | 주로 하드웨어 | OS와 하드웨어의 협력 |
| 주요 성능 이슈 | Cache Miss·충돌·쓰기 비용 | 주소 변환 비용·Page Fault·페이지 교체 |

**27번 답안에서는 26번의 세부 매핑 방식이나 페이지 교체 알고리즘을 길게 반복하지 않는다.** 목적과 동작 원리의 차이, 실제 메모리 접근에서 두 기술이 함께 쓰인다는 관계를 중심으로 설명한다. 가상 메모리의 페이지 교체·Thrashing 운영 정책은 [운영체제 메모리 관리](../02-운영체제/03-메모리-관리.md)에서 상세히 다룬다.
