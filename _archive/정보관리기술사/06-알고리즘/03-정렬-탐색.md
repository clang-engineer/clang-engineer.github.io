# 정렬·탐색 개념지도

이 지도는 [[00-전체|알고리즘 전체 개념지도]]에서 **데이터를 원하는 순서로 만들고, 저장된 데이터에서 원하는 값을 찾는 대표적인 처리 문제**를 함께 본다.

정렬과 탐색은 별개의 Algorithm 목록이 아니다. 데이터가 어떤 상태와 구조에 있는지가 사용할 수 있는 탐색 방법에 영향을 주고, 각 방법의 수행 비용은 [[02-알고리즘-분석]]과 연결된다.

## 1. 핵심 질문

```text
데이터가 있다
│
├─ 원하는 순서로 재배치하고 싶은가?
│   └─ Sorting
│
└─ 특정 Key를 가진 데이터를 찾고 싶은가?
    └─ Search
```

그리고 두 문제는 다시 연결된다.

```text
정렬되지 않은 데이터
        ↓
Sorting
        ↓
정렬된 상태
        ↓
정렬 상태를 이용할 수 있는 Search
```

따라서 Algorithm 이름보다 **입력 데이터의 상태 → 처리 방식 → 비용**을 먼저 본다.

## 2. Sorting은 같은 결과를 서로 다른 과정으로 만든다

Sorting의 목적은 Record나 Key를 정해진 순서로 배치하는 것이다.

성안당 범위에서는 Bubble, Selection, Insertion, Merge, Radix, Shell, Quick, Heap Sort와 외부정렬·병합 방식 등을 다룬다.

전체 관계에서는 개별 수행 절차를 나열하기보다 다음 질문으로 구분한다.

```text
Sorting Algorithm
│
├─ 어떤 방식으로 순서를 결정하는가?
│   ├─ 비교와 교환
│   ├─ 적절한 위치에 삽입
│   ├─ 분할 후 합병
│   ├─ 기준값을 이용한 분할
│   ├─ Heap 구조 이용
│   └─ 자릿값을 이용한 분류
│
├─ 입력이 Memory 안에서 처리 가능한가?
│   ├─ 내부 정렬
│   └─ 외부 정렬
│
└─ 수행 비용은 어떻게 다른가?
    └─ Time / Space Complexity
```

각 Algorithm이 어느 분류에 속하는지와 단계별 수행 과정은 세부학습에서 다룬다.

## 3. Heap은 자료구조와 Sorting이 만나는 지점이다

Heap Sort는 Tree 형태의 Heap 구조를 이용한다.

```text
Heap
= 특정 순서 조건을 유지하는 Tree 구조
        ↓
Root를 이용해 대상 선택
        ↓
구조 재정렬
        ↓
Heap Sort
```

따라서 Heap은 단순히 Sorting Algorithm 이름의 일부가 아니다.

```text
자료구조 관점
Heap
  ↓
Priority Queue 구현 등에 활용

Algorithm 관점
Heap
  ↓
Heap Sort에 활용
```

→ [[01-자료구조]] · [[04-트리-그래프]]

## 4. Search는 데이터 상태와 구조를 이용한다

Search는 주어진 Key를 가진 Record를 찾는 문제다.

```text
찾을 데이터가 있다
        ↓
현재 데이터는 어떤 상태인가?
│
├─ 순서에 대한 전제가 없음
│   └─ Sequential Search
│
├─ 정렬되어 있음
│   └─ Binary Search 등
│
├─ Tree로 구조화되어 있음
│   └─ Tree Search
│
└─ Hash 함수로 위치를 결정함
    └─ Hashing
```

즉 Search Algorithm의 선택은 데이터의 표현 방식과 독립적이지 않다.

## 5. Binary Search는 정렬 상태를 이용해 탐색 범위를 줄인다

Sequential Search는 데이터를 차례대로 확인한다. Binary Search는 정렬된 데이터에서 비교 결과를 이용해 다음 탐색 범위를 줄인다.

```text
정렬된 Search 범위
        ↓
중간 Key와 비교
   ┌────┴────┐
작음        큼
 ↓           ↓
한쪽 범위   반대 범위
        ↓
범위를 반복해서 축소
```

여기서 중요한 연결은 다음과 같다.

```text
Sorting
  ↓
정렬 상태 확보
  ↓
Binary Search가 이용할 수 있는 전제
```

정렬 비용까지 포함한 전체 선택이 항상 유리한지는 실제 문제 조건과 반복 Search 여부 등을 함께 판단해야 한다. 이 지도에서는 우선 **Binary Search가 정렬이라는 선행 조건을 이용한다**는 관계를 잡는다.

## 6. Hashing은 비교 순서보다 저장 위치 계산을 이용한다

Hashing은 Hash 함수를 이용해 Key를 저장 위치와 연결한다.

```text
Key
 ↓
Hash Function
 ↓
저장 위치
```

서로 다른 Key가 같은 위치로 대응되면 Collision이 발생한다.

```text
서로 다른 Key
   ↓       ↓
같은 Hash 위치
      ↓
Collision
      ↓
충돌 해결 방법 필요
```

Hashing은 Tree Search와도 다른 접근이다. Tree가 Node 사이의 관계를 따라 탐색한다면 Hashing은 Key로부터 위치를 계산하는 방식에 초점이 있다.

충돌 해결의 세부 기법은 세부학습에서 다룬다.

## 7. Sorting과 Search는 Complexity로 다시 비교한다

```text
데이터 상태 / 자료구조
        ↓
Algorithm 선택
        ↓
비교 · 이동 · 접근 횟수
        ↓
Time Complexity
        +
필요한 추가 구조
        ↓
Space Complexity
```

→ [[02-알고리즘-분석]]

따라서 Bubble, Quick, Binary Search 같은 이름 자체가 학습의 끝이 아니다. **왜 그 Algorithm이 해당 데이터에서 동작할 수 있고, 어떤 비용 특성을 만드는가**까지 연결해야 한다.

## 8. 다른 지도와의 연결

```text
[[01-자료구조]]
      ↓
데이터의 저장 구조와 상태
      ↓
Sorting / Search
      ↓
[[02-알고리즘-분석]]
= 수행 비용 비교

Tree 구조
  ↓
Tree Search / Heap
  ↓
[[04-트리-그래프]]
```

이 지도에서는 각 Sorting 단계나 Search 계산 문제를 모두 펼치지 않는다. **데이터 상태와 구조가 Algorithm 선택을 제한하고, 선택한 Algorithm은 다시 시간·공간 비용으로 평가된다**는 관계를 잡으면 된다.
