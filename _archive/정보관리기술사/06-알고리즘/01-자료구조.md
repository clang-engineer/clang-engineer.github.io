# 자료구조 개념지도

이 지도는 [[00-전체|알고리즘 전체 개념지도]]에서 **데이터를 어떤 형태와 관계로 표현하고, 그 구조에서 어떤 연산을 수행할 것인지**를 더 자세히 본다.

자료구조는 저장 모양만 구분하는 목록이 아니다. 데이터의 배치와 관계가 달라지면 접근·삽입·삭제 방식이 달라지고, 그 위에서 사용할 Algorithm의 동작과 비용도 달라진다.

## 1. 핵심 질문

```text
데이터를 다뤄야 한다
│
├─ 순서대로 모아 직접 위치로 접근하고 싶은가?
│   └─ Array
│
├─ Node 사이의 연결을 따라가며 구성하고 싶은가?
│   └─ Linked List
│
├─ 가장 나중에 넣은 것을 먼저 꺼내야 하는가?
│   └─ Stack
│
├─ 먼저 넣은 것을 먼저 꺼내야 하는가?
│   └─ Queue
│
├─ 계층 관계를 표현해야 하는가?
│   └─ Tree
│
└─ 더 일반적인 연결 관계를 표현해야 하는가?
    └─ Graph
```

핵심은 이름보다 **어떤 관계와 연산을 위해 그 구조를 선택하는가**다.

## 2. Array와 Linked List는 데이터 배치 방식이 다르다

```text
Array
= 연속된 위치를 기준으로 요소를 다룸

Linked List
= 각 Node가 다음 Node와의 연결 정보를 가짐
```

이 차이는 연산 방식으로 이어진다.

```text
Array
→ Index를 이용한 위치 접근
→ 중간 삽입·삭제 시 주변 요소 이동이 생길 수 있음

Linked List
→ 연결을 따라 Node에 접근
→ 연결 정보를 바꾸어 삽입·삭제
```

따라서 어느 구조가 항상 우수한 것이 아니라 **어떤 연산이 중요한가**에 따라 선택이 달라진다.

Linked List는 연결 방향과 수에 따라 단일·이중 연결 같은 형태로 확장될 수 있지만, 전체 관계 지도에서는 개별 형태를 모두 펼치지 않는다.

## 3. Stack과 Queue는 입출력 순서에 제약을 둔다

Stack과 Queue는 데이터를 저장한다는 점보다 **어떤 순서로 꺼낼 수 있는가**가 핵심이다.

```text
Stack
Push → [ A B C ] → Pop
                  ↑
              한쪽 끝

LIFO
= Last In, First Out
```

```text
Queue
Enqueue → [ A B C ] → Dequeue
           ↑           ↑
          Rear        Front

FIFO
= First In, First Out
```

이 제약은 Algorithm의 실행 순서를 표현하는 데 활용된다.

```text
Stack
├─ 함수 호출 / Recursion의 실행 흐름
├─ 산술식 처리
└─ DFS와 연결

Queue
└─ BFS와 연결
```

Queue는 저장 공간을 반복해서 사용하기 위한 Circular Queue, 양쪽 끝에서 삽입·삭제할 수 있는 Deque, 우선순위에 따라 꺼내는 Priority Queue 등으로 확장될 수 있다. 이들은 기본 Queue와 무엇이 달라지는지 필요한 세부학습에서 본다.

## 4. Priority Queue는 단순한 입력 순서가 아니라 우선순위를 다룬다

일반 Queue는 먼저 들어온 데이터가 먼저 나가지만 Priority Queue는 각 데이터의 우선순위를 기준으로 다음 대상을 선택한다.

```text
일반 Queue
입력 순서
  ↓
출력 순서 결정

Priority Queue
각 데이터의 Priority
  ↓
출력 순서 결정
```

Priority Queue를 구현하는 방법에는 Array, Linked List, Heap 등이 있다. 여기서 중요한 것은 **Priority Queue는 처리 규칙이고 Heap은 이를 구현할 수 있는 자료구조 중 하나**라는 경계다.

Heap의 Tree 구조와 정렬에서의 활용은 [[04-트리-그래프]]에서 다시 연결한다.

## 5. 선형 구조에서 비선형 관계 구조로 확장한다

Array·Linked List·Stack·Queue는 주로 데이터를 하나의 순서나 연결 흐름으로 다룬다. 하지만 데이터 사이에 계층이나 여러 방향의 연결 관계가 생기면 다른 표현이 필요하다.

```text
선형적인 관계
├─ Array
├─ Linked List
├─ Stack
└─ Queue

계층 관계
└─ Tree

일반적인 연결 관계
└─ Graph
```

Tree와 Graph에서는 단순히 데이터를 저장하는 것을 넘어 **관계를 표현한 뒤 어떤 순서로 방문하고 탐색할 것인가**가 중요해진다.

→ [[04-트리-그래프]]

## 6. 자료구조와 Algorithm은 함께 본다

자료구조를 선택하면 가능한 연산과 그 비용이 달라진다.

```text
문제의 데이터 관계
        ↓
자료구조 선택
        ↓
가능한 접근 · 삽입 · 삭제 방식
        ↓
Algorithm의 동작 방식
        ↓
Time / Space 비용
```

따라서 자료구조를 학습할 때는 정의만 기억하지 않고 다음 질문을 같이 본다.

```text
무엇을 표현하는 구조인가?
어떤 연산을 제공하는가?
그 연산은 구조의 어떤 특성을 이용하는가?
다른 구조를 사용하면 무엇이 달라지는가?
어떤 Algorithm과 연결되는가?
```

복잡도 자체의 분석 기준은 [[02-알고리즘-분석]]에서 본다.

```text

        ↓
자료구조
├─ Array / Linked List
├─ Stack / Queue
└─ 관계 구조
    ├─ Tree
    └─ Graph
        ↓
[[04-트리-그래프]]

자료구조 선택
        ↓
연산 비용
        ↓
[[02-알고리즘-분석]]

자료의 구조와 상태
        ↓
Sorting / Search 방법 선택
        ↓
[[03-정렬-탐색]]
```

이 지도에서는 각 자료구조의 구현 Code나 Pointer 조작 과정을 펼치지 않는다. **자료를 어떤 관계로 표현하는지와 그 선택이 Algorithm에 어떤 영향을 주는지**를 잡으면 된다.
