# 트리·그래프 개념지도

이 지도는 [[00-전체|알고리즘 전체 개념지도]]에서 **선형적인 순서만으로 표현하기 어려운 데이터 관계를 Tree와 Graph로 표현하고, 그 구조를 어떻게 탐색하는지**를 함께 본다.

Tree와 Graph는 자료구조이면서 동시에 Traversal과 Search Algorithm이 동작하는 기반이다.

## 1. 핵심 질문

```text
데이터 사이에 관계가 있다
        ↓
어떤 형태의 관계인가?
│
├─ 부모·자식 중심의 계층 관계
│   └─ Tree
│
└─ 더 일반적인 연결 관계
    └─ Graph
        ↓
관계를 표현했다면
어떤 순서로 Node / Vertex를 방문할 것인가?
        ↓
Traversal
```

핵심은 `Tree 종류`, `Graph 종류`를 나열하는 것이 아니라 **관계 표현 → Traversal/Search**의 연결이다.

## 2. Tree는 계층 관계를 표현한다

Tree는 Node 사이의 계층 관계를 표현한다.

```text
        Root
       /    \
    Child  Child
     /
  Child
```

Tree를 이해할 때는 구조와 Algorithm을 구분해서 연결한다.

```text
Tree
= 관계를 표현하는 Data Structure

Traversal
= Tree의 Node를 어떤 순서로 방문할지 정하는 Algorithm
```

Binary Tree에서는 전위·중위·후위 같은 Traversal 순서가 등장한다. 개별 방문 순서와 계산 과정은 세부학습에서 다룬다.

## 3. Stack과 Tree Traversal이 연결된다

Tree Traversal의 실행 과정은 방문하지 않은 경로로 돌아가기 위한 상태를 유지해야 한다.

Recursion으로 Traversal을 구현하면 함수 호출 상태가 Stack에 쌓인다.

```text
Tree Traversal
      ↓
하위 Node 방문
      ↓
이전 위치로 돌아와 다른 가지 방문
      ↓
호출 상태 유지 필요
      ↓
Recursion / Stack과 연결
```

따라서 [[01-자료구조]]의 Stack과 Tree Traversal은 서로 떨어진 Topic이 아니다.

## 4. Tree에 조건을 추가하면 특정 연산에 적합한 구조가 된다

Tree라는 기본 관계에 추가 조건을 두어 Search나 우선순위 처리에 활용할 수 있다.

```text
Tree
│
├─ Key의 배치 규칙을 둠
│   └─ Binary Search Tree
│
├─ 우선순위 조건을 둠
│   └─ Heap
│
└─ 여러 Key와 하위 Node를 관리하도록 확장
    └─ B-Tree 계열 / T-Tree
```

전체 지도에서는 B-Tree, B+Tree, B*Tree 등의 삽입·삭제 과정을 펼치지 않는다. 이들은 **Tree 구조에 조건을 추가하여 Search와 저장 구조의 목적에 맞게 확장한 계열**이라는 위치를 먼저 잡는다.

Tree 기반 Search는 [[03-정렬-탐색]]과 연결된다.

## 5. Graph는 더 일반적인 연결 관계를 표현한다

Graph는 Vertex와 Edge의 집합으로 관계를 표현한다.

```text
Graph G = (V, E)

V = Vertex 집합
E = Vertex 사이의 Edge 집합
```

Tree가 계층적인 관계를 중심으로 한다면 Graph는 방향 유무나 여러 연결을 포함한 더 일반적인 관계를 표현할 수 있다.

Graph Algorithm을 수행하려면 먼저 연결 관계를 저장할 방법이 필요하다.

```text
실제 관계
   ↓
Graph
   ↓
Computer에서 표현
├─ Adjacency Matrix
└─ Adjacency List
   ↓
Traversal / Algorithm 수행
```

즉 Graph의 표현 방법은 Traversal Algorithm이 접근할 실제 자료구조와 연결된다.

## 6. DFS와 BFS는 방문 순서를 다르게 만든다

Graph의 Vertex를 탐색하는 대표적인 두 방식은 DFS와 BFS다.

```text
Graph Traversal
├─ DFS
│   └─ 한 방향으로 깊게 진행한 뒤 돌아옴
│
└─ BFS
    └─ 가까운 Vertex부터 넓게 진행
```

이 둘은 [[01-자료구조]]의 Stack과 Queue에 직접 연결된다.

```text
DFS
↔ Stack

BFS
↔ Queue
```

따라서 Stack과 Queue의 입출력 규칙이 실제 Algorithm의 방문 순서를 어떻게 만드는지 함께 이해한다.

## 7. MST는 모든 Vertex를 최소 비용으로 연결하는 문제다

Graph Traversal이 Vertex를 방문하는 문제라면 Minimum Spanning Tree(MST)는 비용이 있는 Graph에서 **모든 Vertex를 연결하면서 전체 연결 비용을 줄이는 문제**다.

```text
Weighted Graph
      ↓
모든 Vertex를 연결해야 함
      +
전체 Edge 비용을 최소화
      ↓
Minimum Spanning Tree
```

성안당 범위에서는 MST를 구성하는 대표 Algorithm으로 Kruskal과 Prim을 다룬다.

```text
MST
├─ Kruskal
└─ Prim
```

각 Algorithm의 단계별 Edge 선택 과정은 세부학습에서 다룬다. 전체 관계에서는 **Graph 표현 → Traversal과 연결 문제 → MST**라는 위치를 잡는다.

## 8. Tree와 Graph의 경계를 잡는다

```text
Tree
= 계층 관계를 표현하는 데 적합
= Node 사이의 구조적 제약이 있음

Graph
= 일반적인 연결 관계를 표현
= 방향·비방향 등 다양한 Edge 관계를 가질 수 있음
```

그리고 두 구조 모두 저장 자체가 목적은 아니다.

```text
관계를 표현한다
      ↓
Tree / Graph
      ↓
어떤 순서로 방문할까?
      ↓
Traversal
      ↓
특정 목적의 Search / 연결 Algorithm
```

이 흐름이 자료구조와 Algorithm이 만나는 대표적인 지점이다.

## 9. 다른 지도와의 연결

```text
[[01-자료구조]]
├─ Stack ─────────→ Tree Traversal / DFS
└─ Queue ─────────→ BFS

Tree
├─ Search Tree ───→ [[03-정렬-탐색]]
└─ Heap ──────────→ Priority Queue / Heap Sort

Tree / Graph Algorithm
        ↓
수행 비용
        ↓
[[02-알고리즘-분석]]
```

이 지도에서는 Tree 종류별 세부 구조, Traversal 수행표, B-Tree 삽입·삭제, DFS/BFS 방문 순서 계산, Kruskal/Prim 수행 과정을 모두 펼치지 않는다. **관계를 어떻게 표현하고 그 구조 위에서 어떤 Algorithm이 동작하는지**를 잡으면 된다.
