# 알고리즘 분석 개념지도

이 지도는 [[00-전체|알고리즘 전체 개념지도]]에서 **같은 문제를 해결하는 여러 Algorithm의 자원 사용량을 어떻게 비교하고 판단할 것인지**를 더 자세히 본다.

## 1. 핵심 질문

```text
문제를 해결하는 Algorithm이 있다
        ↓
입력이 커지면 실행 비용은 어떻게 변할까?
        ↓
어떤 자원을 기준으로 볼까?
├─ 실행에 필요한 연산량 → Time Complexity
└─ 필요한 Memory         → Space Complexity
        ↓
입력 크기에 따른 증가 정도를 어떻게 표현할까?
        ↓
Big-O
```

Algorithm 분석의 핵심은 특정 Computer에서 몇 초가 걸렸는지를 외우는 것이 아니라 **입력 크기가 변할 때 필요한 자원이 어떤 형태로 증가하는지** 보는 것이다.

## 2. Time Complexity와 Space Complexity는 서로 다른 자원을 본다

```text
Time Complexity
= 입력 크기에 따라 실행에 필요한 연산량이 어떻게 증가하는가

Space Complexity
= 입력 크기에 따라 필요한 Memory가 어떻게 증가하는가
```

같은 문제를 해결하더라도 Algorithm에 따라 두 비용이 다를 수 있다.

```text
Algorithm A
├─ 연산량이 적음
└─ 추가 Memory가 큼

Algorithm B
├─ 연산량이 많음
└─ 추가 Memory가 작음
```

따라서 효율성은 하나의 숫자로만 판단하지 않고 문제의 조건과 필요한 자원을 함께 본다.

## 3. 입력 크기와 연산 횟수의 관계를 본다

Algorithm의 Code를 볼 때 모든 명령의 실제 CPU 시간을 계산하려는 것이 아니다. 입력 크기 `n`이 증가할 때 핵심 연산이 얼마나 증가하는지 본다.

```text
입력 크기 n
  ↓
반복 · 비교 · 이동 · 호출 등의 횟수
  ↓
입력 증가에 따른 연산량 변화
```

예를 들어 반복 구조가 중첩되면 입력 크기에 대한 연산 횟수의 증가 형태도 달라질 수 있다.

정확한 연산수 계산 문제는 세부학습에서 다루고, 이 지도에서는 **입력 크기와 비용을 함수 관계로 본다**는 관점만 잡는다.

## 4. Big-O는 비용의 증가 정도를 표현한다

Big-O 표기법은 입력 크기가 커질 때 Algorithm 비용이 증가하는 정도를 표현하는 데 사용한다.

```text
연산 횟수 함수
        ↓
입력 크기가 커질 때 지배적인 증가 형태 확인
        ↓
Big-O로 표현
```

전체 관계에서는 다음처럼 읽는다.

```text
Algorithm
  ↓
입력 크기 n 증가
  ↓
필요한 연산량 / Memory 증가
  ↓
증가율을 비교 가능한 형태로 표현
  ↓
Big-O
```

Big-O 계산 규칙이나 수식 전개 자체는 세부학습에서 다룬다.

## 5. 자료구조의 선택도 연산 비용에 영향을 준다

Algorithm의 비용은 처리 절차만의 문제가 아니다. 데이터를 어떤 자료구조에 저장했는지도 접근·삽입·삭제 비용에 영향을 준다.

```text
자료구조
  ↓
기본 연산의 특성
├─ 접근
├─ 삽입
├─ 삭제
└─ 탐색
  ↓
그 연산을 사용하는 Algorithm
  ↓
전체 비용
```

→ [[01-자료구조]]

따라서 `자료구조 → 연산 → Algorithm → Complexity`를 하나의 연결로 본다.

## 6. Sorting과 Search는 Complexity 비교가 드러나는 대표 영역이다

여러 Sorting Algorithm은 같은 정렬 결과를 만들지만 수행 과정과 필요한 공간이 다르다.

Search 역시 순차적으로 확인하는지, 정렬 상태를 이용하는지, 별도 구조를 이용하는지에 따라 수행 특성이 달라진다.

```text
같은 목적
Sorting 또는 Search
        ↓
서로 다른 Algorithm
        ↓
비교 · 이동 · 접근 방식 차이
        ↓
Time / Space Complexity 차이
```

→ [[03-정렬-탐색]]

즉 Complexity는 별도의 수학 Topic으로 끝나는 것이 아니라 **자료구조와 Algorithm을 선택할 때 다시 사용하는 판단 기준**이다.

## 7. 이 지도의 인출 좌표

```text
Algorithm을 평가한다
│
├─ 무엇을 기준으로?
│   ├─ Time
│   └─ Space
│
├─ 무엇에 따라 변하는가?
│   └─ Input Size n
│
├─ 무엇을 보는가?
│   └─ 자원 사용량의 증가 정도
│
└─ 어떻게 표현하는가?
    └─ Big-O
```

세부학습에서는 연산수 계산, 반복문의 Complexity 도출, 대표 Big-O의 증가 차이와 실제 Algorithm 비교로 내려간다. 이 지도에서는 **입력 크기 → 자원 사용량 → 증가율 표현 → Algorithm 비교**라는 관계를 기억하면 된다.
