# 알고리즘 전체 개념지도

알고리즘은 **문제를 계산 가능한 절차로 표현하고, 그 과정에서 사용할 데이터 구조와 처리 비용을 함께 판단하는 영역**으로 본다.

이 문서는 정렬·탐색 Algorithm의 이름이나 구현 Code를 외우기 위한 목차가 아니다. 먼저 **문제를 풀기 위해 데이터를 어떻게 표현하고, 어떤 절차로 처리하며, 그 절차의 효율을 어떻게 판단하는지** 큰 그림을 잡고 필요한 가지에서 더 자세히 내려간다.

## 1. 가장 먼저 잡을 큰 그림

```text
문제를 계산으로 해결하고 싶다
│
├─ 데이터를 어떤 형태로 표현하고 저장하지?
│   └─ 자료구조
│
├─ 해결 절차가 얼마나 효율적인지 어떻게 판단하지?
│   └─ 알고리즘 분석
│      └─ Time Complexity · Space Complexity · Big-O
│
├─ 같은 구조의 문제를 자기 자신으로 다시 표현할 수 있을까?
│   └─ Recursion
│
├─ 데이터를 원하는 순서로 만들려면?
│   └─ Sorting
│
├─ 원하는 데이터를 어떻게 찾지?
│   └─ Search · Hashing
│
├─ 계층 관계를 어떻게 표현하고 탐색하지?
│   └─ Tree
│
└─ 임의의 연결 관계를 어떻게 표현하고 탐색하지?
    └─ Graph
```

여기서 중요한 것은 개별 Algorithm 이름보다 **문제 표현 → 처리 절차 → 비용 판단**의 관계다.

```text
문제
  ↓
데이터를 어떤 구조로 표현할 것인가?
  ↓
자료구조
  ↓
그 구조에서 어떤 절차로 처리할 것인가?
  ↓
알고리즘
  ↓
그 처리에는 시간과 공간이 얼마나 필요한가?
  ↓
복잡도 분석
```

자료구조와 알고리즘은 별개의 암기 영역이 아니다. 같은 문제라도 데이터를 어떤 구조로 표현하는지에 따라 사용할 수 있는 연산과 비용이 달라진다.

## 2. 전체 좌표

```text
알고리즘
│
├─ 데이터 표현
│   ├─ Array / Linked List
│   ├─ Stack / Queue / Heap
│   └─ Tree / Graph / Hash
│
├─ 비용 판단
│   └─ Time / Space Complexity · Big-O
│
├─ 대표 처리 문제
│   ├─ Sorting → 비교 · 교환 · 분할 · Heap 등
│   └─ Search  → 순차 · Binary Search · Hashing
│
├─ 관계 구조 위의 Algorithm
│   ├─ Tree Traversal
│   ├─ DFS / BFS
│   └─ MST
│
└─ 횡단 문제분해 방식
    └─ Recursion ↔ Call Stack
```

Tree와 Graph는 자료구조이면서 동시에 Traversal·Search Algorithm이 동작하는 기반이므로 여러 가지에 걸쳐 나타날 수 있다.

## 3. 큰 학습 가지

```text
[[01-자료구조|자료구조]]
= 데이터를 어떤 관계와 형태로 표현하고 어떤 연산을 가능하게 할 것인가

[[02-알고리즘-분석|Algorithm 분석]]
= 입력이 커질 때 시간·공간 비용이 어떻게 증가하는가

[[03-정렬-탐색|정렬 · 탐색]]
= 데이터 상태에 따라 어떤 처리 방법을 선택하고 비용이 어떻게 달라지는가

[[04-트리-그래프|Tree · Graph]]
= 계층·연결 관계를 어떻게 표현하고 그 위에서 어떻게 탐색하는가
```

Recursion은 별도 하위 지도를 만들지 않는다. **같은 형태의 작은 문제로 분해하는 방식**과 **호출 상태가 Stack에 쌓이는 실행 특성**을 연결하는 횡단 Node로 두고, 필요하면 세부학습으로 직접 내려간다.

## 4. 권장 탐색 흐름

처음에는 `01 → 02`로 기반을 잡은 뒤 `03`, `04`에서 그 관계가 실제 문제에 어떻게 나타나는지 보는 것이 자연스럽다.

```text
01. 자료구조
"데이터를 어떤 관계와 형태로 표현할 것인가?"
        ↓
02. Algorithm 분석
"선택한 구조와 절차의 비용을 어떻게 판단할 것인가?"
        ↓
        ├──────────────────────┐
        ▼                      ▼
03. 정렬 · 탐색             04. Tree · Graph
"대표 처리 문제"            "관계 구조와 그 위의 Algorithm"
```

`03`과 `04`는 서로의 필수 다음 단계가 아니다. 둘 다 **자료구조와 Algorithm, Complexity의 관계를 구체적인 문제군에서 다시 확인하는 가지**다.

```text
학습등급표
"무엇을 얼마나 볼 것인가"
        ↓
알고리즘 전체 개념지도
"표현 · 처리 · 비용이 어떻게 연결되는가"
        ↓
01 ~ 04 하위 개념지도
"선택한 문제군의 관계를 더 촘촘히"
        ↓
세부학습
"구체적인 동작·계산·구현은 무엇인가"
```

전체 지도에서 모든 자료구조의 연산과 Algorithm 단계를 펼치지는 않는다. **대표 자료구조·처리 방법과 Complexity의 관계를 보고 기존 지식을 복원할 수 있는 정도**까지 잡는다.
