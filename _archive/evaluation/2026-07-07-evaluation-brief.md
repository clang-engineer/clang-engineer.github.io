## 1. 업무 성과

### 주요 업무 성과 (고객사 전달 산출물 중심)

상반기 대부분을 **순천향대학교병원(SCHMC) CDW 구축**에 현장 파견되어 수행. 처음에는 예정 작업자의 진행 지연으로 EMR 뷰어 작업에 대체 투입되었고, 이후 담당 인력 2명의 연이은 퇴사로 생긴 공백(연구검색·가명화·인증·레지스트리·헬프센터)까지 순차적으로 흡수해 홀로 재정비·안정화하고 **오픈(5/29)까지 완수**. 이후 본사(혜화) 복귀해 서울대병원 연구검색·K-ERAS 및 대외 과제(SHINE·건강정보고속도로)를 병행.

**월별 진행 요약**
- **1월** — 순천향 투입, 구 EMR(.NET) 분석·신규 EMR 착수, 타 솔루션(연구검색·가명화·인증) 인계
- **2월** — IRB(R-BAY) 연동, 타 솔루션→EMR 토큰 인증·조회 어댑터 개발
- **3월** — (순천향) 가명화 다기관 안정화·운영환경 구축, 중순 상주 철수 / (서울대) 복귀 후 서식지 적재 대응
- **4월** — (순천향) 운영기 이관(도메인·프록시·방화벽)·근무지 병행 / (서울대) 스누허브·서식지 적재 / (대외) SHINE 공공 이관
- **5월** — (순천향) EMR 다기관 조회·누락 서식·2차 인증 연동, **오픈(5/29)** / (서울대) K-ERAS 리뉴얼 마무리
- **6월** — (순천향) 운영 이슈·서식 가명화 모듈 / (서울대) REX 비정형 데이터 대응

**① 순천향 CDW 현장 구축 (메인)**
- **의무기록(EMR) 조회 화면 신규 구축** *(상반기 개발 비중 최대)* — 순천향 구 EMR(.NET)을 분석해 연구자가 진료기록을 바로 열람하는 웹 기반 조회 화면으로 신규 개발. 개인정보 가명화·마스킹 처리, 산하 4개 병원 다기관 조회로 확장, 토큰 인증 어댑터로 연구검색·레지스트리 등 여러 솔루션에 연동.
- **외부 인증 시스템 신규 연동 (IRB·2차 인증)** — 신규 IRB는 R-BAY, 병원 보안 요건인 2차 인증은 동은정보시스템과 협업해 각 병원 인증 체계 연동을 신규 구축. 두 외부 업체와 규격·동작을 맞추고 검증하는 커뮤니케이션 공수가 큰 작업.
- **가명화 시스템 안정화·다기관 대응 전면 재작업** — 인계 시점 미완성·다수 오류 상태에 가명 ID 누락(동시성)이 지속되던 것을 전면 재작업. 4개 병원 가명 ID 생성·적재 연동까지 새로 개발하고 동시성·오류·속도 문제를 해결해 안정화.
- **헬프센터 UI 전면 개편** — 공지·QnA·FAQ·댓글·게이트·사이드바 등 전면 개편(PM 요청).
- **중복 기능 공통 부품화** — 프로젝트마다 쌓이던 중복 코드 문제에 공통 부품화를 실험적으로 도입, 유지보수 개선 효과 확인.
- **운영 인프라 담당** — 운영 서버 2대·서비스 도메인 5개 연결·프록시·방화벽 등 병원 보안 요건 대응.

**② 서울대 연구검색 대응 (본사 혜화, 병행)**
- **외부 데이터허브(스누허브) 연동** — 비정형(문서·이미지) 데이터를 조회·다운로드해 스누허브로 전송하는 인터페이스. 일부 구현됐으나 오류가 많던 것을 인계받아 대부분 재정비·안정화하고, 전송 인증 오류·포맷(엑셀/CSV) 변환 등을 순차 해결 (애니모비 협업).
- **서식지 적재 모듈 재구축 (Logstash)** — 검사 판독문 등 긴 텍스트를 Elasticsearch에 적재하는 모듈. SQL 페이징 인덱싱 누락으로 재적재에 매번 일주일이 걸리던 것을 신규 구축해 **초기 적재 일주일 → 한 시간**으로 단축, 이후 증분 방식으로 전환.
- **가명 ID 누락 원인 규명·복구** — 누락 원인(동시성)을 규명하고 누락 대상 재생성 복구를 제안·주도해 누락분(약 1.8만 건)을 복구, 근본 원인은 서울대 코드에서 수정.
- **비정형 데이터 추출(REX) 성능 개선** — 조회가 크게 느려지던 원인(잘못된 처리 로직)을 바로잡아 해결하고, 다운로드 진행률을 단계별로 표시되도록 개선.

**③ 서울대병원 K-ERAS 개발 (개발 담당)**
- 2023년부터 **단독 개발·유지보수**해 온 임상연구 데이터 시스템(3년 계약 2년차)으로, 상반기 대규모 기능 추가·개선을 수행. 담당 교수로부터 만족 회신.
- **분석(Outcomes) 대시보드 신규 구축** — 연구 버전별 환자 수·수행률·합병증·재원기간·재수술/재입원율 비교 화면을 신규 구축. 이 외 입력 폼 강화·연구 상태 관리·계정 보안 강화·다크 테마 전면 개편.

**④ 대외 인프라·기타 병행**
- **SHINE** — 민간→공공기관 클라우드 서버 이관(주 업무), 도메인·보안 인증서·보안성 검토·계약 조율 병행.
- **건강정보고속도로** — 거점·에이전트 이슈 대응(주 업무), 보안 인증서 교체·접속자수 집계 병행.
- **기타** — 타 병원(계명대·강원대) 레거시 긴급 대응, 충북대 ISMS·제안서·사업 미팅·연구검색 권한 관리 개선 등 지원.

### 업무성과에 대한 본인 평가

**우수한 점**
- **여러 인력 공백을 연쇄적으로 흡수해 인계받은 미완성 작업까지 정상화** — 순천향 EMR·가명화 다기관, 서울대 스누허브·비정형 데이터 등 미완성·오류 상태를 원인 규명해 재작업.
- **일정 리스크 선제 관리** — 오픈 임박 시점에 추가 인력 요청·배정으로 순천향 일정 내 오픈 완수.
- **재현·추적이 어려운 문제의 근본 원인 규명** — 가명 ID 누락(동시성)·서식 인덱싱 누락(SQL 페이징) 등 원인 파악이 까다로운 이슈를 짚어 해결.
- **난도 높은 신규 개발 단독 완수** — 구 EMR(.NET) 웹 전환, 서식지 적재 재구축(일주일→한 시간) 등.
- **다중 과제 병행** — 순천향 현장 + 서울대 연구검색·K-ERAS + 대외 과제.
- 프론트엔드·백엔드·DB·인증·서버/클라우드 인프라까지 전 영역 직접 수행.

**보완이 필요한 점**
- 순천향 전용으로 급히 손댄 부분이 회사 공통 버전과 벌어져, 추후 재통합 정리가 필요. 처음부터 전용/공통 변경을 나눠 관리했다면 부담이 적었을 것.
- 촉박한 일정 탓에 기능 추가·오류 수정·구조 개선을 한꺼번에 진행한 구간이 있어 이력 추적이 다소 어려움. 작업 단위를 더 잘게 나눴다면 리뷰·인수인계가 쉬웠을 것.
- 여러 근무지·과제가 겹쳐 부하가 몰린 구간이 있었음. 향후 부하가 누적되기 전에 더 일찍 업무를 나누거나 상황을 미리 공유해 리스크를 줄이려 함.

### 협업 및 커뮤니케이션에 대한 본인 평가

**팀 내 협업 (일정/이슈 공유 포함)**
- 진행·이슈·리스크를 매일 보고·공유해 조기에 가시화하고, 다중 근무지 일정 변동을 사전 협의함.
- 전임자 퇴사로 인계받은 솔루션 문의가 몰리는 상황에서 확인 요청에 대응하며 동료들을 지원함.

**고객 커뮤니케이션**
- 순천향 현장에 상주·방문하며 고객사 담당(최서희 간사)에게 요구사항을 직접 확인해 진행함.
- 외부 협력사(애니모비·R-BAY·동은정보시스템)와 연동 규격·일정을 조율함.
- K-ERAS는 요구사항을 먼저 제안·조율하며 개발했고, 담당 교수로부터 긍정 피드백을 받음.

## 2. AI 활용 설문

1. **업무 시간 중 평균 AI 사용 비율:** 약 **70%**
2. **월간(최근 30일) 클로드 맥스 토큰 사용량:** 약 27.1M 토큰
3. **주로 사용하는 업무 영역:** 낯선/레거시 코드 파악(전임자 시스템·구 EMR(.NET) 분석), 코드 작성·리팩터링, 코드 리뷰·디버깅(오류 원인 규명), 개발 환경·설정 정리, 문서화(인수인계·자문 답변·보고서), 기술 리서치.
4. **AI 활용 생산성 향상 체감:** 약 **50%**
5. **(옵션) 가장 효과를 본 사례 1가지:**
   순천향 긴급 투입 시 전임자들이 남긴 낯선 시스템(EMR·연구검색·가명화·인증) 코드를 AI로 빠르게 파악하고 문제 원인을 짚어 재작업 속도를 크게 높인 것. 구 EMR(.NET) 분석·서식지 적재 재구축·가명 ID 누락 규명처럼 낯선 코드를 짧은 기간에 파고들어야 하는 작업에서 특히 효과.
6. **AI를 더 적극적으로 활용함에 있어서 어려운 점:**
   병원 폐쇄망/보안망 환경이라 현장에서는 외부 AI 도구 사용에 제약이 큼(반입·연결 통제). 의료 EMR·가명화 규정 등 도메인 특수성과 병원별 예외가 많아 프롬프트만으로 맥락 전달이 어렵고 결과를 그대로 신뢰하기 어려움.
7. **AI 활용에서 스스로 개선이 필요한 부분:**
   AI 결과를 그대로 쓰기보다 검증하는 습관을 더 체계화할 필요가 있음. 반복되는 맥락(도메인 규칙·프로젝트 구조·공통 부품)을 프롬프트·컨텍스트로 미리 정리해 재사용성을 높이는 부분.
8. **회사/팀 차원에서 필요한 지원·개선:**
   폐쇄망 환경에서 쓸 수 있는 AI 활용 가이드·보안 정책 정립. 팀 내 프로젝트 컨텍스트·도메인 규칙을 공유·재사용할 수 있는 형태로 축적하는 체계.
