`join-pane -s 2 -t 1`을 칠 때마다 잠깐 멈추게 된다. **2가 1로 가는 건가, 1이 2로 오는 건가?** `swap-pane -s 1 -t 2`는 또 뭐가 기준이지? 나만 그런 게 아니다. 이건 명령어를 외우지 못해서가 아니라, tmux의 **타겟 지정 문법**을 한 번도 제대로 잡지 않아서 생기는 혼란이다.

핵심은 두 가지뿐이다 — **`-s`/`-t`의 방향**과 **`session:window.pane` 주소 체계**. 이 둘은 join/swap만의 규칙이 아니라 `attach`·`move-window`·`select-pane`·부트스트랩 스크립트까지 tmux 전체를 관통한다. 한 번 잡으면 나머지가 전부 같은 문법으로 읽힌다.

## 1. `-s`는 움직이는 것, `-t`는 도착지

가장 먼저 방향을 고정한다.

| 플래그 | 의미 | 한 단어로 |
|---|---|---|
| `-s` | **s**ource | **움직이는** 패널/윈도우 (집어 오는 대상) |
| `-t` | **t**arget | **도착지** (기준이 되는 자리) |

이 한 문장이면 끝난다: **source가 target 쪽으로 간다.**

```sh
join-pane -s 2 -t 1    # 2번을 집어서 → 1번 옆에 붙인다 (2가 이동)
swap-pane -s 1 -t 2    # 1번과 2번의 자리를 맞바꾼다 (swap은 방향이 대칭)
```

`join`은 "source를 target으로 끌어온다"는 방향이 있고, `swap`은 자리 교환이라 어느 쪽을 `-s`로 두든 결과가 같다. 헷갈리는 건 주로 `join`이니, **"`-s`가 이사 간다"**만 기억하면 된다.

> `-s`를 생략하면 source가 **현재 패널**(또는 마크된 패널)로 잡힌다. 의도와 다르게 현재 패널이 딸려가는 사고가 여기서 난다. 스크립트나 키바인딩에선 `-s`를 **항상 명시**하는 게 안전하다.
{: .prompt-warning }

## 2. `session:window.pane` — 왼쪽부터 큰 단위

`-s`/`-t`에 넣는 값은 그냥 숫자가 아니라 **주소**다. 형식은 왼쪽부터 큰 단위 → 작은 단위다.

```
세션 : 윈도우 . 패널
work : 2      . 1
```

| 조각 | 예 | 생략하면 |
|---|---|---|
| `session` | `work`, `0-default` | **현재 세션** |
| `:window` | `:2`, `:editor` | **현재 윈도우** |
| `.pane` | `.1`, `.0` | **현재/활성 패널** |

즉 대부분은 다 안 쓰고 필요한 조각만 쓴다. 생략한 자리는 "지금 여기"로 채워진다.

```sh
-t 1            # 현재 세션의 '윈도우 1' (그 윈도우의 활성 패널)
-t .1           # 현재 윈도우의 '패널 1'      ← 점(.)의 유무가 갈림길
-t work:2       # work 세션의 윈도우 2
-t work:2.1     # work 세션, 윈도우 2, 패널 1  (완전한 주소)
```

여기서 가장 많이 밟는 지뢰가 **점(`.`)의 유무**다. `-t 1`은 *윈도우* 1이고, `-t .1`은 *현재 윈도우의 패널* 1이다. 같은 `1`인데 점 하나로 대상이 바뀐다.

> **번호가 헷갈리면 눈으로 확인하자.**
> - `Prefix q` → 각 패널에 번호가 크게 표시됨 (display-panes)
> - 상태바 왼쪽 숫자 = 윈도우 번호
> - `tmux list-panes` / `tmux list-windows` → 번호·이름 한눈에
{: .prompt-tip }

## 3. 번호 vs 이름 — join-pane의 함정

`join-pane`·`swap-pane`의 `-s`/`-t`는 엄밀히는 **패널**을 가리킨다. 그런데 `2`처럼 윈도우만 주면, tmux가 그 **윈도우의 활성 패널**로 알아서 풀어준다. 그래서 `join-pane -s 2 -t 1`이 "윈도우 2를 윈도우 1로"처럼 동작하는 것이다.

여기서 두 가지가 발목을 잡는다.

- **현재 윈도우를 source로 지정하면 에러난다.** 이미 그 자리에 있는 걸 자기 자신에게 합칠 수 없기 때문. source는 "다른 윈도우"여야 한다.
- 윈도우를 **이름**으로 줘도 되지만(`-s editor`), 이름과 번호를 섞어 쓰다 보면 어느 게 지금 몇 번인지 놓치기 쉽다. 확실하지 않으면 번호로 통일하는 편이 사고가 적다.

```sh
# 다른 윈도우(2)의 패널을 현재 윈도우로 좌우 분할해서 끌어오기
join-pane -s 2 -h

# 현재 패널을 3번 윈도우로 내보내기 (source에 현재 패널 '.'을 명시)
join-pane -s . -t 3

# 세션을 넘나드는 이동도 같은 문법 — 완전 주소만 쓰면 된다
join-pane -s 0-default:1 -t 1-workspace:1 -h
```

## 4. 상대 주소와 마크 — 번호를 안 세도 되는 길

매번 번호를 확인하기 귀찮다면, "현재 기준 상대 위치"와 "마크"를 쓰면 된다.

| 표기 | 뜻 |
|---|---|
| `!` | 직전에 있던 것 (last) |
| `+` / `-` | 다음 / 이전 (윈도우) |
| `.+` / `.-` | 다음 / 이전 패널 (순환) |
| `{marked}` | 마크해 둔 패널 |

가장 실용적인 건 **마크**다. `Prefix m`으로 패널 하나를 찍어(mark) 두면, `-s`를 생략한 `join-pane`/`swap-pane`이 그 마크된 패널을 자동으로 source로 쓴다. **"옮길 패널을 먼저 찍고(Prefix m), 목적지 윈도우로 가서 join"** — 번호를 한 번도 안 세고 패널을 이동시키는 흐름이다.

```sh
# 1) 옮기고 싶은 패널에서:  Prefix m   (마크)
# 2) 도착지 윈도우로 이동한 뒤 명령창(Prefix :)에서:
join-pane                 # -s 생략 → 마크된 패널이 자동으로 source
```

참고로 늘 쓰는 `Prefix {` / `Prefix }`도 사실 `swap-pane -U` / `-D`의 키바인딩이다. 이미 매일 swap을 쓰고 있었던 셈이다.

## 정리 — 외울 건 두 개뿐

- **`-s`는 움직이는 것, `-t`는 도착지.** source가 target으로 간다. (`swap`은 대칭)
- **주소는 `session:window.pane`, 왼쪽부터 큰 단위.** 생략하면 "지금 여기". 점(`.`)이 있으면 패널, 없으면 윈도우.

이 두 규칙은 tmux 명령 전반에 그대로 적용된다. 터미널 열 때마다 새 세션이 생기는 [자동 attach 함정](/posts/tmux/2026-07-03-tmux-auto-attach-new-session-every-time/)도 결국 `attach -t <타겟>`의 주소 문제이고, [부트스트랩 스크립트](/posts/tmux/2026-02-21-tmux-bootstrap/)에서 패널을 배치하는 것도 같은 `-s`/`-t` 문법이다. 전체 학습 순서는 [tmux 로드맵](/posts/tmux/2026-06-16-tmux-roadmap/)에서 볼 수 있다.
