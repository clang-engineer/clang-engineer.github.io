앞에서는 터미널 입력이 PTY와 `termios`를 거쳐 애플리케이션에 들어오는 방향을 봤다.

이번에는 반대 방향이다.

> **애플리케이션은 터미널 화면을 어떻게 바꾸는가?**

핵심 구조는 단순하다.

```text
애플리케이션
  ↓ stdout으로 문자 + 제어 시퀀스 출력
PTY
  ↓
터미널 에뮬레이터
  ↓ 일반 문자는 화면에 표시
     제어 시퀀스는 명령으로 해석
화면
```

즉 ANSI/VT 계열 제어 시퀀스는 **출력 바이트 스트림 안에 화면 제어 명령을 섞어 보내는 규칙**이라고 보면 된다.

```text
일반 문자
= 화면에 그대로 표시

제어 시퀀스
= 커서 이동, 화면 지우기, 색상 변경 같은 명령
```

TUI 앱이 GPU API로 픽셀을 직접 그리는 것이 아니라, 이런 바이트 스트림을 터미널 에뮬레이터에 보내 화면을 바꾸는 것이 핵심이다.

## 가장 단순한 예 — 문자와 명령이 같은 출력 스트림에 있다

```bash
printf 'hello\n'
```

은 일반 문자를 출력한다.

반면:

```bash
printf '\e[31mRED\e[0m\n'
```

은 문자 사이에 색상 변경 명령을 함께 넣는다.

터미널 에뮬레이터는 이 바이트를 파싱하면서 일반 문자는 표시하고 제어 시퀀스는 상태 변경 명령으로 처리한다.

```text
H e l l o ESC [ 3 1 m W o r l d ESC [ 0 m
          │                       │
          └─ 색상 변경 명령       └─ 속성 복구
```

이게 ANSI/VT 제어의 본질이다.

## ESC와 CSI — 명령은 어떻게 시작되는가

많은 터미널 제어 시퀀스는 `ESC` 바이트로 시작한다.

ASCII에서 `ESC`는 `0x1b`이며 셸에서는 흔히 다음처럼 표현한다.

```bash
\033
\e
\x1b
```

현대 터미널에서 특히 자주 보는 형태는:

```text
ESC [ ...
```

이고 이를 CSI(Control Sequence Introducer) 계열이라고 부른다.

예를 들어:

```text
ESC [ 2 J
```

은 화면 지우기 계열 명령이고,

```text
ESC [ 10 ; 20 H
```

는 커서를 특정 위치로 이동시키는 명령이다.

처음 읽을 때는 CSI 문법 자체를 외우기보다 **"ESC로 시작하는 바이트 시퀀스를 터미널이 화면 제어 명령으로 해석한다"**는 점만 잡으면 충분하다.

## 직접 실험 — 화면을 지우고 커서를 움직이기

화면 지우기:

```bash
printf '\e[2J\e[H'
```

커서를 특정 위치로 이동하고 문자열 출력:

```bash
printf '\e[5;10HHELLO'
```

색상 변경:

```bash
printf '\e[31mRED\e[0m\n'
```

이 세 예만으로도 중요한 점이 보인다.

```text
출력은 한 바이트 스트림인데
터미널이 일부는 문자로,
일부는 화면 제어 명령으로 해석한다.
```

## 터미널 에뮬레이터는 상태를 가진다

터미널 에뮬레이터는 단순한 프린터가 아니다.

내부적으로 다음 같은 상태를 가진다.

```text
커서 위치
현재 문자 속성
화면 셀
스크롤 영역
동작 모드
```

제어 시퀀스는 이 상태를 바꾼다.

```text
애플리케이션 출력
  ↓
터미널 파서
  ↓
터미널 상태 변경
  ↓
화면 갱신
```

그래서 같은 문자 출력도 이전에 어떤 명령을 보냈는지에 따라 다른 위치·색상으로 보일 수 있다.

## Alternate Screen — Neovim을 나가면 원래 화면이 돌아오는 이유

Neovim, `less`, `htop` 같은 전체 화면 프로그램을 종료하면 이전 셸 화면이 다시 나타나는 경우가 많다.

이때 흔히 사용하는 것이 **대체 화면(Alternate Screen)**이다.

```text
기본 화면
셸 기록이 보이는 화면

    ↕ 모드 전환

대체 화면
Neovim 같은 전체 화면 UI
```

TUI 앱은 시작할 때 대체 화면으로 들어갔다가 종료하면서 기본 화면으로 돌아올 수 있다.

이것도 결국 터미널 에뮬레이터의 상태를 바꾸는 제어 시퀀스의 한 예다.

## 커서를 숨기고 다시 보이는 것도 같은 원리다

TUI 앱은 렌더링 중 실제 커서를 숨기거나, 필요할 때만 다시 표시할 수 있다.

```text
앱 시작
  ↓
대체 화면 전환
커서 숨김
  ↓
렌더링
  ↓
커서 복구
기본 화면 복귀
  ↓
앱 종료
```

termios 설정과 마찬가지로 이런 터미널 상태도 프로그램이 정상 종료할 때 복구하는 것이 중요하다.

## 입력 쪽에서도 escape sequence가 쓰인다

escape sequence는 출력 전용 개념이 아니다.

터미널 에뮬레이터는 방향키 같은 특수키를 애플리케이션에 보낼 때도 여러 바이트의 시퀀스를 사용할 수 있다.

예를 들어 위쪽 방향키는 흔히 다음과 비슷한 형태다.

```text
ESC [ A
```

그래서 같은 세션에서 양방향으로 서로 다른 의미의 시퀀스가 오갈 수 있다.

```text
애플리케이션 → 터미널
= 화면 제어 명령

터미널 → 애플리케이션
= 특수키 입력 시퀀스
```

앞의 `termios` 문서에서 raw mode가 키 이벤트를 만들어주는 것이 아니라, 애플리케이션이 이런 바이트 스트림을 직접 해석할 수 있게 해주는 기반이라고 한 이유가 여기서 연결된다.

## ANSI와 VT라는 이름은 왜 같이 나오는가

DEC의 VT 계열 터미널, 특히 VT100은 현대 터미널 관행에 큰 영향을 줬다.

이후 ANSI/ECMA 계열 표준과 실제 VT/xterm 호환 관행이 섞이면서 다음 표현이 함께 사용된다.

```text
ANSI escape code
VT sequence
terminal control sequence
```

처음 학습할 때는 세 용어의 역사적 차이를 깊게 외우기보다 **"터미널 에뮬레이터가 해석하는 화면 제어용 바이트 시퀀스"**라는 공통 역할을 먼저 잡는 편이 중요하다.

## 여기부터는 심화 — 화면을 효율적으로 갱신하기

여기까지 이해했다면 ANSI/VT의 핵심 모델은 잡은 것이다.

```text
애플리케이션
→ 문자 + 제어 시퀀스 출력
→ 터미널 에뮬레이터가 해석
→ 화면 상태 변경
```

아래는 TUI 렌더러가 이 제어 시퀀스를 어떻게 효율적으로 사용하는지에 대한 연결 내용이다.

### 변경된 부분만 다시 그리기

화면 한 글자만 바뀌었다면 화면 전체를 지우고 다시 출력할 필요는 없다.

```text
이전 화면 상태
   ↕ 비교
새 화면 상태
   ↓
변경된 위치 계산
   ↓
커서 이동 + 필요한 문자만 출력
```

이 아이디어는 뒤의 curses와 현대 TUI 렌더러에서 **가상 화면 / 차이 렌더링**으로 더 구조화된다.

### 왜 화면이 덜 깜빡이는가

성숙한 TUI 렌더러는 보통 이전 화면과 새 화면을 비교해서 변경된 셀만 갱신하고, 불필요한 커서 이동과 출력을 줄인다.

중요한 것은 ANSI/VT 자체가 이런 차이 계산을 해주는 것이 아니라는 점이다.

> **ANSI/VT는 화면을 제어하는 명령 수단이고, 무엇을 얼마나 갱신할지 결정하는 것은 그 위의 curses나 TUI 렌더러다.**

## 그런데 앱이 제어 시퀀스를 전부 하드코딩하면 안 되나

간단한 실험이라면 가능하다.

```bash
printf '\e[2J\e[H'
```

하지만 실제 애플리케이션에서는 다음 문제가 생긴다.

```text
이 터미널이 해당 기능을 지원하는가?
같은 기능의 시퀀스가 항상 같은가?
색상을 몇 개 지원하는가?
대체 화면을 지원하는가?
특수키는 어떤 시퀀스를 보내는가?
```

그래서 터미널별 차이를 프로그램 코드에 직접 넣는 대신 capability 정보를 데이터베이스로 분리하는 계층이 등장했다.

```text
애플리케이션
  ↓
TERM / terminfo
  ↓
현재 터미널에 맞는 제어 시퀀스
  ↓
터미널
```

이게 다음 문서의 주제다.

## 지금까지 연결

입력과 출력을 함께 놓으면 다음처럼 볼 수 있다.

```text
                 입력
키보드
  ↓
터미널 에뮬레이터
  ↓
PTY
  ↓
termios 규칙
  ↓
애플리케이션
  ↓
문자 + ANSI/VT 제어 시퀀스 출력
  ↓
PTY
  ↓
터미널 에뮬레이터
  ↓
화면
                 출력
```

핵심은 다음 한 문장으로 정리할 수 있다.

> **터미널 앱은 입력 바이트 스트림을 받고, 화면을 바꾸기 위한 문자와 제어 시퀀스를 다시 출력한다.**

## 다음 단계 — TERM과 terminfo

이제 다음 질문으로 넘어간다.

> **터미널마다 지원 기능과 제어 시퀀스가 다르면 애플리케이션은 어떻게 호환성을 유지할까?**

여기서 `TERM`, termcap, terminfo, `tput`이 등장한다.
