SCP(Secure Copy)는 SSH 채널 위에서 파일을 복사하는 명령. 별도 데몬 없이 ssh가 켜진 서버면 그대로 쓸 수 있다.

## 로컬 → 원격

```sh
scp ./localfile user@host:/remote/path/
```

대상이 디렉토리면 끝에 `/`를 붙여둬야 헷갈리지 않는다.

## 원격 → 로컬

```sh
scp user@host:/remote/file ./
```

## 디렉토리 전체 — `-r`

```sh
scp -r ./localdir user@host:/remote/path/
```

## SSH 포트가 22가 아닐 때 — `-P` (대문자)

```sh
scp -P 2222 ./localfile user@host:/remote/path/
```

`ssh -p`와 다르게 SCP는 대문자 `-P`. 자주 헷갈리는 지점.

## 키 파일 지정 — `-i`

```sh
scp -i ~/.ssh/id_ed25519 ./localfile user@host:/remote/path/
```

## 자주 쓰는 옵션

| 옵션 | 의미 |
|---|---|
| `-P {port}` | SSH 포트 |
| `-r` | 디렉토리 재귀 |
| `-i {keyfile}` | 개인키 |
| `-C` | 전송 중 압축 |
| `-l {Kbit/s}` | 대역폭 제한 |
| `-v` | 디버그 로그 |
| `-q` | 진행률 숨김 |

## 큰 디렉토리는 rsync 고려

scp는 파일마다 새 메타 교환을 한다. 디렉토리가 크거나 재전송이 잦으면 `rsync`가 더 낫다 — 변경분만 보내고, 중단 후 이어받기도 된다.

```sh
rsync -az -e ssh ./src/ user@host:/dst/
```

## OpenSSH 8.x 이후 노트

OpenSSH 8.0부터 scp 프로토콜은 "지원은 되지만 권장하지 않는다"는 입장. 9.0부터는 내부적으로 SFTP를 쓴다. 동작은 같지만 새 코드라면 `sftp`나 `rsync`를 첫 후보로 두는 게 무난하다.
