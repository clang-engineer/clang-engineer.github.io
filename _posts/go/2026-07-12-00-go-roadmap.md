Go 문법과 기본 기능을 처음 익힐 때는 공식 **[A Tour of Go](https://go.dev/tour/)**를 따라가면 된다. 브라우저에서 코드를 실행하며 패키지와 기본 문법, 타입, 메서드·인터페이스, 제네릭, 동시성을 연습할 수 있다. 한국어로 읽고 싶다면 [커뮤니티 번역판](https://ko-go-dev.shuijingwanwq.com/tour/basics/1)을 참고할 수 있다. 이 번역 사이트는 Go 프로젝트가 운영하는 공식 한국어판이 아니라 비공식 번역이다.

이 블로그는 Tour를 다시 풀어 쓰기보다, **C++에서 Go로 넘어올 때 기존의 직관이 어디까지 통하고 어디서 달라지는지**를 설명한다. 필요한 주제만 골라 읽으면 된다.

## C++에서 Go로 옮길 때 볼 차이

| 주제 | C++에서 익숙한 출발점 | Go에서 다시 볼 점 | 관련 글 |
|---|---|---|---|
| 프로그램 구성 | 헤더, 소스 파일, 빌드 타깃 | 디렉터리의 package, module 경로, 대소문자 export | [package·module과 C++ 헤더](./2026-07-12-go-basics-package-module.md) |
| 타입과 추상화 | class, 상속, virtual 함수 | struct와 method, 암묵적 interface 만족, embedding, method set | [struct·method·interface](./2026-07-12-go-struct-method-interface.md) |
| 자료구조 | vector, unordered_map, string | slice의 backing array 공유, map 순회 순서, byte와 rune | [slice·map·string](./2026-07-12-go-slice-map-string.md) |
| 실패와 정리 | exception, destructor, RAII | error 반환, defer, panic/recover의 서로 다른 역할 | [error·defer·panic/recover](./2026-07-12-go-error-handling-defer.md) |
| 동시성 | thread, future, mutex | goroutine, channel, sync, context의 책임과 협력적 취소 | [goroutine·channel·context](./2026-07-12-go-concurrency-goroutine-channel.md) |
| 일상적인 코드 | 팀별 라이브러리와 도구 선택 | 표준 라이브러리, Go 관용구, 내장 테스트·도구 | [Go다운 코드](./2026-07-12-go-stdlib-idiom-testing.md) · [Go 도구](./2026-07-12-go-tooling.md) |

C++ 개념은 Go를 빠르게 이해하기 위한 비교점이다. 두 언어의 기능이 비슷한 목적을 가질 수는 있지만, 수명·타입·실행 방식까지 같은 의미라고 가정하지 않는다.

## 이렇게 사용하기

- Go를 처음 접한다면 Tour에서 문법과 기본 기능을 직접 연습한다.
- C++ 코드와 비교하다 막힌 주제를 위 표에서 찾아 관련 글을 읽는다.
- `go build`, `go test`, `go fmt`, module 명령은 [Go 도구 참고 글](./2026-07-12-go-tooling.md)에서 필요할 때 찾아본다.
- 모든 글을 순서대로 읽을 필요는 없다. Go 코드를 읽거나 작성하면서 생긴 질문에 맞춰 필요한 글만 보면 된다.

## 이 블로그에서 설명하는 범위

Tour에서 다루는 문법을 다시 강의하는 대신, 이 글 묶음은 Go의 규칙이 실제 설계와 코드에 어떤 영향을 주는지에 집중한다. 예를 들어 interface가 구현 선언 없이 만족되는 이유, slice를 복사했을 때 내부 배열이 공유될 수 있는 이유, context가 goroutine을 강제 종료하지 않는 이유처럼 다른 언어의 습관만으로는 놓치기 쉬운 부분을 설명한다.
