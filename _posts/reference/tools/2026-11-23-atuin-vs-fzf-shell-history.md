fzf의 `Ctrl-R`로도 이전 명령을 찾을 수 있다. 그런데 셸 설정에서는 fzf를 유지하면서 히스토리 검색 바인딩을 Atuin에 맡겼다. 이것은 fzf 전체를 다른 도구로 대체한 결정이 아니다. **후보 목록에서 고르는 기능과, 명령을 실행 맥락까지 붙여 보관하는 기능을 나눈 것**이다.

비교할 문제는 “어느 도구가 더 좋은가”가 아니라 **셸에서 이전 명령을 어떤 정보로 다시 찾을 것인가**다. 단순한 명령 문자열 검색이면 fzf로 충분하고, 디렉터리·세션 같은 실행 맥락을 남겨 범위를 좁히려면 Atuin을 선택할 이유가 생긴다.

> 아래 기능 설명은 2026-11-23에 확인한 공식 문서를 기준으로 한다. 현재 설정의 역할 분담과 선택 기준을 설명하며, 검색 속도나 생산성 향상을 측정한 벤치마크·장기 사용 후기는 아니다. 동기화도 이 글의 전제가 아니다.
{: .prompt-info }

## 같은 Ctrl-R이지만 저장 책임이 다르다

[fzf](https://github.com/junegunn/fzf)는 후보 목록을 받아 대화형으로 검색·선택하는 범용 도구다. 기본 셸 통합의 `Ctrl-R`은 셸 히스토리에서 명령을 골라 입력줄에 가져온다. 명령 이력의 보존 범위와 세션 간 공유는 셸의 히스토리 설정에 달려 있다.

[Atuin](https://docs.atuin.sh/18.25/)은 셸 연동을 통해 명령을 별도 SQLite DB에 기록한다. SQLite는 별도 DB 서버 없이 로컬 파일에 데이터를 보관하는 데이터베이스다. Atuin은 명령 문자열 외에도 실행 디렉터리·시각·소요 시간·종료 코드·호스트·셸 세션을 기록한다. 검색 UI는 이 기록을 사용해 범위를 좁힐 수 있다.

여기서 비교하는 fzf는 **기본 셸 히스토리 통합**이다. 별도 수집기와 DB를 만들고 그 결과를 fzf에 전달할 수도 있지만, 그 경우 이력을 수집·관리하는 책임은 fzf 밖의 구성에 있다. “fzf로는 맥락 검색이 절대 불가능하다”가 아니라 “기본 통합이 그 기록 관리까지 맡지는 않는다”가 정확하다.

| 비교축 | fzf 기본 Ctrl-R | Atuin 셸 연동 |
|---|---|---|
| 기록 원본 | 셸 히스토리 | 별도 SQLite DB의 명령 이력 |
| 검색 맥락 | 기본적으로 셸이 제공한 명령 목록 | 디렉터리·세션·호스트 등 기록 범위 필터 |
| 실행 정보 | 셸의 기록 형식·설정에 의존 | 실행 시각·소요 시간·종료 코드 등을 함께 기록 |
| 선택 확정 | 명령을 입력줄로 가져옴 | 기본 Enter는 즉시 실행, Tab은 편집할 입력줄로 가져옴 |
| 기기 간 이력 공유 | 별도 구성 필요 | 선택적 종단 간 암호화 동기화 제공 |
| 추가 관리 | 기존 셸 히스토리와 fzf 통합 | 셸 연동과 DB 보관·이관, 사용할 경우 동기화 설정 |

## 문자열이 아니라 실행 장소로 찾고 싶을 때

여러 프로젝트에서 비슷한 명령을 실행하면 명령 문자열만으로는 원하는 이력을 구분하기 어렵다. 예를 들어 여러 저장소에서 실행한 `docker compose` 명령 중 **현재 프로젝트에서 썼던 명령**을 찾는 상황을 생각할 수 있다. 이는 사용 상황을 설명하기 위한 예시이지 실제 이력이나 측정 결과는 아니다.

Atuin의 [검색 UI](https://docs.atuin.sh/18.25/guide/basic-usage/)에서는 `Ctrl-R`로 필터 모드를 순환해 전체 기록·현재 호스트·디렉터리·저장소·세션 등의 범위를 바꿀 수 있다. 저장소 필터와 디렉터리 필터는 같은 범위가 아니다. 저장소 단위 작업과 특정 하위 디렉터리 작업 중 무엇을 다시 찾는지에 맞춰 선택해야 한다.

반대로 최근 명령의 일부만 기억해서 다시 입력하는 흐름이면, 이미 쓰는 fzf의 퍼지 검색만으로 해결할 수 있다. 실행 맥락을 사용하지 않는데 DB와 연동을 추가하면 관리할 요소만 늘어난다. Atuin의 가치는 퍼지 검색이라는 이름 자체보다 **어떤 정보를 기록하고 검색 조건으로 사용할 수 있는가**에 있다.

## fzf는 남기고 키의 담당을 나눈다

현재 셸 설정은 fzf를 먼저 초기화하고 Atuin을 나중에 초기화한다. 두 도구가 모두 정의하는 `Ctrl-R`을 Atuin이 맡도록 한 순서다. 역할은 다음처럼 나뉜다.

- **Ctrl-R → Atuin:** 실행했던 명령 검색.
- **Ctrl-T → fzf:** 파일·경로를 골라 명령줄에 삽입.
- **Alt-C → fzf:** 디렉터리를 골라 이동.

fzf를 제거하면 히스토리 외의 파일 선택·파이프라인 활용까지 잃게 된다. 따라서 이것은 둘 중 하나만 설치해야 하는 문제가 아니다. Neovim 내부 picker 선택은 [Telescope와 fzf의 경계](../../neovim/2026-07-03-telescope-vs-fzf.md), Tab 완성의 후보와 UI 분리는 [zsh 자동완성과 fzf-tab](../../shell/2026-11-19-zsh-completion-and-fzf-tab.md)에서 별도로 다룬다.

초기화 순서만 보고 다른 키가 모두 그대로라고 단정해서는 안 된다. Atuin은 기본적으로 위쪽 화살표에도 검색을 연결할 수 있다. 이 글의 역할 분담은 주요 세 키에 관한 설명이며, 기존 방향키 동작을 유지하려면 [키 바인딩 설정](https://docs.atuin.sh/18.25/configuration/key-binding/)도 확인해야 한다.

또 하나의 전환 차이는 **선택 후 동작**이다. Atuin 기본 UI에서 Enter는 선택한 명령을 즉시 실행하고 Tab은 편집하도록 입력줄에 가져온다. fzf에서처럼 먼저 인자를 확인하려는 경우에는 Tab을 사용하거나, Atuin의 `enter_accept` 설정으로 Enter의 동작을 바꿀 수 있다. 서버 작업이나 삭제 명령을 고를 때는 검색 결과를 찾는 것과 재실행 승인을 구분하는 편이 안전하다.

## 기록이 풍부해지면 보관 책임도 커진다

Atuin은 로컬 기록만으로 사용할 수 있고 동기화는 선택 사항이다. 공식 문서는 동기화 시 종단 간 암호화를 제공한다고 설명하지만, **암호화와 기록할 내용을 제한하는 정책은 다른 문제**다. 명령 인자에는 토큰이나 내부 주소가 들어갈 수 있고 디렉터리·호스트 정보도 민감할 수 있다. 동기화를 쓰지 않아도 로컬 DB를 보관·백업할 때 이 점을 고려해야 한다.

도입 전에는 [기록 필터 설정](https://docs.atuin.sh/18.25/configuration/config/#history_filter)으로 제외할 명령·경로를 확인한다. 기존 셸 히스토리의 import도 과거 기록을 가져오는 작업이지, 과거에 저장하지 않은 실행 맥락을 복원하는 작업은 아니다. 도구를 제거할 때도 키 바인딩을 되돌리는 일과 이미 쌓인 DB를 보관·삭제하는 일은 따로 판단해야 한다.

설치·초기화·검색 명령의 빠른 참조는 [Atuin 치트시트](https://github.com/clang-engineer/devkit/blob/main/reference/cheatsheets/atuin.md)와 [fzf 치트시트](https://github.com/clang-engineer/devkit/blob/main/reference/cheatsheets/fzf.md)에 둔다. 여기서는 옵션 전체보다 선택에 영향을 주는 경계만 남긴다.

## 선택과 재검토 조건

**최근 명령을 문자열로 찾는 것으로 충분하다면 fzf를 유지한다.** 별도 기록 DB가 필요하지 않고 기존 셸 이력 정책을 그대로 쓸 수 있다. **프로젝트·디렉터리·세션을 기준으로 다시 찾는 흐름이 필요하다면 Atuin에 히스토리를 맡기고 fzf를 다른 선택 작업에 남긴다.**

현재 구성은 후자처럼 역할을 나눈 상태다. 다만 설정이 적용됐다는 사실만으로 실제 검색 효율이 높아졌다고 결론내리지는 않는다. 대표 작업에서 필터를 사용하는지, 명령을 편집한 뒤 실행하는 흐름이 맞는지 확인해야 선택의 효과를 평가할 수 있다.

여러 기기의 이력을 모을 필요가 생기거나, 명령·경로의 보관 정책이 바뀌거나, 실제로는 맥락 필터를 거의 사용하지 않는다면 다시 비교할 시점이다. 후보를 늘리기 전에 요구와 관리 비용을 함께 보는 방법은 [공통 도구 평가 기준](2026-11-16-open-source-tool-evaluation-signals.md#2026-11-23-보강--도구-비교를-같은-판단-틀로-남기기)으로 이어진다.
