북마크가 수백 개라고 생각했는데 로컬 Chrome 프로필의 `Bookmarks` 파일을 열어 보니 몇 개밖에 없었다. **보이는 UI와 조사한 로컬 파일의 규모가 다르다**는 사실이 첫 단서였다. 2026년 당시 사용한 macOS 프로필에서는 계정 동기화 북마크가 다른 로컬 저장 파일에도 나타났다. 다만 이 파일 이름과 내부 구조는 Chrome의 공개 데이터 수정 API가 아니다. 버전·프로필·동기화 상태에 따라 달라질 수 있으므로 직접 고쳐서 계정 데이터에 반영하는 방법으로 취급하지 않는다.

## 왜 파일을 직접 수정하지 않았나

당시 로컬 저장 파일을 수정해도 Chrome을 다시 열면 동기화 상태가 우선 적용돼 변경이 되돌아오는 경험을 했다. 로컬 파일의 노드 ID도 안정적인 사용자 식별자가 아니었다. 브라우저가 관리하는 파일에 쓰는 방식은 그 시점의 UI 상태와 동기화 서버를 함께 다루지 못한다. **공식 UI로 내보낸 HTML을 백업하고, 정리한 HTML을 공식 UI로 가져온 뒤 화면에서 검토**하는 경계가 더 안전하다.

이것은 기존 북마크를 제자리에서 갱신하는 작업이 아니다. **가져오기는 추가 작업**이므로, 기존 폴더를 지우기 전에 새 폴더가 온전히 들어왔는지 확인해야 한다. Google의 [북마크 가져오기·내보내기 안내](https://support.google.com/chrome/answer/96816?hl=en)는 북마크 관리자에서 HTML을 내보내고 파일을 선택해 가져오는 경로를 설명한다. 기존 북마크가 있으면 가져온 항목이 별도 영역에 추가될 수 있으니 실제 위치를 화면에서 확인한다.

## 분류보다 먼저 보존과 규모 확인

1. Chrome 북마크 관리자에서 현재 북마크를 **HTML로 내보내 별도 위치에 백업**한다. 동기화 중이라면 다른 기기의 상태도 파악한다. 링크에는 로그인·개인 문서 주소가 섞일 수 있어 이 HTML은 공개 저장소에 올리지 않는다.
2. 북마크 바와 기타 북마크의 링크·폴더 수를 각각 센다. 로컬 파일만 분석하고 UI의 전체 개수와 맞지 않으면 그 파일을 전체 데이터로 간주하지 않는다.
3. 이미 잘 분류된 폴더는 보존하고, 최상위에 흩어진 링크와 너무 잘게 나뉜 폴더부터 다룬다. URL과 제목으로 임시 분류한 결과는 사람이 검토한다. 분류 실패 항목은 버리지 않고 검토 폴더에 둔다.
4. 제목의 중복 접두사나 사이트명 꼬리표를 걷어 내되, 같은 제목을 가진 **다른 URL**이나 제목에 필요한 구별 정보가 있는지 확인한다. 회사·개인용 분류명과 URL은 이 글에 싣지 않는다.

내 사례에서는 수백 개의 링크를 먼저 대분류로 묶고, 자주 쓰는 개발 링크만 몇 개의 하위 주제로 나눴다. 최상위 폴더 수를 줄인 것이 목적이었지, 모든 북마크를 자동으로 삭제한 것이 아니다. 폴더의 이름과 부모 폴더로 정리 대상을 찾는 편이 임시 로컬 노드 ID에 의존하는 것보다 견고했다.

당시 작업 기록에서는 약 767개를 검토해 쓰레기 후보 29개와 끊어진 링크 후보 36개를 사람이 확인한 뒤 702개로 줄였다. 가져오기 후 검색 결과도 다시 확인하며 약 660개까지 정리했다. 이 숫자는 자동 삭제의 성공률이 아니라, **분류와 삭제를 별도 단계로 나눠 검토한 한 번의 사례**다.


## 죽은 링크와 중복을 조심스럽게 판정

일괄 요청의 `403`·`429`는 로그인·봇 차단·속도 제한일 수 있으므로 **죽은 페이지라는 증거가 아니다**. `404`·`410`이나 DNS 실패도 일시적 장애·접근 권한·이전 URL의 리다이렉트를 고려해야 한다. 자동 검사 결과를 ‘삭제 후보’로만 표시하고, 중요한 링크는 브라우저에서 직접 열어 최종 판단했다. 방문 횟수가 0이라는 숫자 역시 ‘사용하지 않는다’는 확실한 근거가 아니었다.

## 가져온 뒤에야 기존 항목 정리

정리된 HTML을 Chrome 메뉴의 **북마크 및 목록 → 북마크 및 설정 가져오기**로 한 번 가져온다. 메뉴 이름과 위치는 버전에 따라 달라질 수 있으니 [공식 가져오기 절차](https://support.google.com/chrome/answer/96816?hl=en)를 따른다. 가져온 폴더에서 링크 수와 주요 하위 폴더·대표 링크를 확인하고, 다른 동기화 기기에서도 결과가 나타나는지 살핀다. 실수로 같은 HTML을 두 번 가져왔다면 새로 생긴 중복 영역부터 구분한다.

그다음에만 옛 폴더와 중복 링크를 북마크 관리자에서 선택·삭제한다. [Chrome의 북마크 편집·이동·삭제 안내](https://support.google.com/chrome/answer/188842?hl=en)에 따르면 삭제한 북마크는 되돌릴 수 없으므로 백업을 유지한 채 작은 묶음으로 처리한다. 검색 결과에 같은 문자열을 포함한 다른 중요한 링크까지 섞일 수 있으니 검색어만 믿고 전체 삭제하지 않는다.

핵심은 **백업 → 전체 규모 확인 → 검토 가능한 분류 → HTML 가져오기 → 확인 후 옛 항목 삭제**다. 동기화 브라우저의 내부 파일을 공개 편집 API처럼 취급하지 않으면, 규모가 큰 정리에서도 원본을 잃을 위험을 크게 줄일 수 있다.
