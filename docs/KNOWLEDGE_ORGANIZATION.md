# 저장소 공통 지식 구성 원칙

이 문서는 `_posts`, `_archive`, 학습 문서, 기술 정리 등 저장소에서 **개념과 지식을 어떤 단위로 묶고 나눌지** 정하는 공통 원칙이다.

문체·용어·표기는 [`WRITING_STYLE.md`](WRITING_STYLE.md)를 따르고, 특정 자료 형식에 별도 작성 규칙이 있으면 이 원칙 위에 해당 규칙을 추가로 적용한다.

핵심 기준은 **주제명·목차·분량이 아니라, 함께 보았을 때 이해가 더 좋아지는가**이다.

## 1. 함께 이해하면 좋은 개념을 하나의 단위로 묶는다

문서나 Section의 경계는 개별 Keyword 수에 맞추지 않는다.

여러 개념을 함께 보았을 때 각각의 위치·원리·차이·경계가 더 잘 이해된다면 하나의 설명 단위로 묶을 수 있다.

```text
함께 보면 이해가 좋아지는 관계
├─ 상위 ↔ 하위
├─ 문제 → 해결 → 한계 → 확장
├─ 개념 A ↔ 개념 B 비교·대안
├─ 개념 사이의 경계
├─ 선행 → 의존
└─ 실제 시스템에서의 조합·합류
```

개념 수가 적거나 관계가 단순하더라도 함께 보는 편이 이해에 도움이 되면 묶을 수 있다.

반대로 같은 분야나 같은 교재 Chapter에 있다는 이유만으로 서로의 이해에 도움이 되지 않는 개념을 한 문서에 억지로 묶지 않는다.

## 2. 스토리는 관계 표현 방식 중 하나일 뿐이다

실제 문제·원인·해결·한계·확장 관계가 있다면 그 흐름을 살려 설명한다.

```text
문제
  ↓
해결 개념
  ↓
새 한계
  ↓
확장 개념
```

하지만 모든 개념을 하나의 이야기나 발전 순서로 만들 필요는 없다.

관계에 따라 적절한 형태를 선택한다.

```text
스토리형 : 문제 → 해결 → 한계 → 확장
비교형   : A ↔ B ↔ C
계층형   : 상위 → 하위
경계형   : 서로 비슷해 보이는 개념의 역할·범위 구분
조합형   : 여러 개념이 실제 시스템에서 합류
```

> **스토리를 만들기 위해 관계를 왜곡하지 않는다. 관계가 있다면 그 관계가 읽히게 한다.**

## 3. 복잡성이나 분량만으로 분리하지 않는다

다음 이유만으로 문서를 나누지 않는다.

- 파일이 길어졌다.
- Keyword가 여러 개다.
- 교재에서 별도 Topic으로 나뉘어 있다.
- 개념마다 파일 하나를 대응시키고 싶다.

반대로 관계가 복잡하지 않더라도 함께 설명할 때 이해가 좋아진다면 하나의 문서나 Section으로 유지할 수 있다.

분리 여부는 다음 질문으로 판단한다.

> **이 내용을 따로 보았을 때보다 함께 보았을 때 개념을 더 정확하고 쉽게 이해할 수 있는가?**

## 4. 큰 그림과 상세 설명은 필요에 따라 Zoom한다

넓은 영역을 한 문서에 모두 펼치거나 모든 Topic마다 하위 문서를 만들지 않는다.

```text
큰 그림
  ↓
함께 탐색할 가치가 있는 연관 개념 묶음
  ↓
필요한 부분만 Zoom-in
  ↓
상세 원리·동작·예제
```

중간 단계는 고정된 계층이 아니다. 연관 개념을 한 번 더 함께 보는 것이 이해에 도움이 될 때만 만든다.

따라서 어떤 영역은 `큰 그림 → 상세 설명`으로 바로 내려갈 수 있고, 다른 영역은 중간에 하나 이상의 관계 지도가 필요할 수 있다.

## 5. 문서 형식보다 이해 단위를 우선한다

같은 원칙을 자료의 목적에 맞게 적용한다.

- 게시글: 독자가 하나의 문제나 개념 관계를 끊기지 않고 이해할 수 있는 범위를 우선한다.
- 학습 문서: 함께 공부할 때 기억과 이해가 좋아지는 개념 흐름을 우선한다.
- 개념지도: 연관 개념의 위치·관계·이동 경로를 한눈에 탐색할 수 있는 범위를 우선한다.
- 설계·운영 문서: 하나의 판단·문제·변경·운영 맥락을 이해하는 데 필요한 정보를 함께 둔다.

형식이 다르더라도 **문서 구조가 개념 관계를 가리지 않도록 한다.**

## 6. 상세화하면서 상위 구조도 다시 보정한다

처음 만든 분류나 문서 구조를 완성된 정답으로 보지 않는다.

상세 내용을 공부하거나 작성하면서 새로운 관계·경계·의존성을 발견하면 상위 문서와 큰 그림도 다시 보정한다.

```text
큰 그림에서 위치와 관계 파악
  ↓
상세 내용 이해
  ↓
새로운 관계·경계 발견
  ↓
상위 구조 보정
  ↓
새로운 인접 개념 탐색
```

지식 구조는 상세화할수록 고정되는 것이 아니라 **더 정확한 관계를 반영하며 정교해진다.**

## 7. 한 문장 원칙

> **주제명이나 분량에 맞춰 지식을 기계적으로 나누지 않고, 함께 보았을 때 이해가 좋아지는 개념 관계를 하나의 단위로 묶되 실제 관계가 없는 개념을 억지로 연결하지 않는다.**
